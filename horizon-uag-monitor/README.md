# Horizon UAG Monitor (Windows 11 트레이 모니터)

전세계 데이터센터(기본 12개)에 배치된 **VMware Horizon UAG / Virtual App 포탈**의
**443 포트 도달성·TLS 인증서 만료·HTTPS 응답속도**를 주기적으로 점검하고, **자체 SQLite DB**에
시계열로 누적하는 **Windows 11 시스템 트레이 상주 프로그램**입니다.

- **닫기(X)** 를 누르면 종료되지 않고 **시스템 트레이에서 계속 실행**됩니다.
- 트레이 메뉴의 **종료** 를 눌러야만 프로그램이 실제로 끝납니다.
- 트레이 아이콘 색상이 전체 상태(초록=정상 / 노랑=주의 / 빨강=위험)를 실시간 반영합니다.

## 기능
- **443 포트 모니터링**: TCP 연결 지연(도달성) 측정.
- **TLS 인증서 만료 감시**: 남은 일수 표시, 임계(기본 30일) 이하면 '주의'.
- **HTTPS 상태·응답속도**: HTTP 상태코드와 응답시간(ms) 측정, 임계 지연 초과 시 '주의'.
- **웹 포탈 모니터링**: UAG 외에 **별도 웹 포탈**도 대상으로 추가 가능. 대상마다
  **유형(UAG/포탈)·프로토콜(https/http)·포트**를 지정하고, 선택적 **콘텐츠 키워드**로
  포탈 페이지가 실제로 정상 로딩되는지(본문에 키워드 포함) 검증한다.
- **세계지도 '글로벌 사이트 현황'**: 대상(사이트)을 위경도로 지도에 상태 색상 점으로 표시.
  **도시명 입력 → 좌표 자동(오프라인)**, **내 위치(사용자) 지정** 시 사용자→사이트 arc와
  사이트별 RTT를 지도에 표시. 지도/카드/표 3가지 보기 전환.
- **표 정렬**: 표 보기에서 컬럼 제목 클릭으로 정렬(다시 클릭 시 오름/내림 토글), 자동 새로고침에도 유지.
- **자체 DB(SQLite)**: `%LOCALAPPDATA%\HorizonUagMonitor\monitor.db` 에 이력 저장(WAL, 기본 1년 보존).
- **대상 관리**: 12개 데이터센터 기본 시드 + 추가/수정/삭제, 데이터센터·주기·타임아웃 지정.
- **이력 뷰**: 대상별 1일/7일/30일/90일/365일 응답지연 산점 차트 + 정상률/평균/최대 통계.
- **CSV 내보내기**, **Windows 시작 시 자동 실행**(선택).
- **화면 가장자리 알람**(v1.1): '주의'·'위험'이 생기면 화면 위/아래/왼쪽/오른쪽 가장자리에 띠가 뜨고,
  **클릭해서 끄기 전까지 깜빡입니다.** 설정 › 알람 탭에서 켬/끔 · 위치 · 두께(px) · 길이(%) · 깜빡임 간격(ms)을
  지정하고 **미리보기**로 확인합니다. 트레이 메뉴 › 알람 끄기로도 끌 수 있습니다.
- **데이터·로그 폴더 지정 + 자동 이동**(v1.1): 설정 › 데이터·로그 폴더 탭에서 `monitor.db` · `error.log` ·
  `alarm.log` 를 저장할 폴더를 정합니다. 폴더를 바꾸고 저장하면 자동으로 옮깁니다.

## 알람 동작
| 상황 | 알람 |
|---|---|
| 대상이 '주의' 또는 '위험'이 됨 | 띠가 깜빡임(위험=빨강, 주의=노랑, 섞이면 빨강) |
| 띠를 클릭 / 트레이 › 알람 끄기 | 그 시점의 알람이 모두 '확인됨' — 깜빡임 중지 |
| 확인한 뒤 같은 상태가 이어짐 | 다시 울리지 않음 |
| 정상으로 돌아왔다가 다시 나빠짐 / 주의 → 위험으로 악화 / 다른 대상에 새 장애 | 다시 울림 |
| 위험 → 주의로 나아짐 | 다시 울리지 않음 |
| 프로그램을 켠 직후 | 최근에 점검된 결과만 알람이 됨(점검 주기의 3배, 최소 3분 — 예전 기록으로 울리지 않음) |

알람은 **주 모니터**에 표시됩니다. 발생·악화·확인·해소는 데이터 폴더의 `alarm.log` 에 남습니다.

## 데이터·로그 폴더
기본은 `%LOCALAPPDATA%\HorizonUagMonitor` 입니다. 설정에서 다른 폴더를 지정하면 그 위치는
`%LOCALAPPDATA%\HorizonUagMonitor\location.json` 에 기록됩니다(DB 를 열려면 위치를 먼저 알아야 하므로 DB 안에 둘 수 없습니다).

폴더 이동 순서(어느 단계든 실패하면 예전 폴더를 그대로 계속 사용):
1. 점검 — 전체 경로인지, 쓸 수 있는지, 여유 공간이 충분한지, 대상 폴더에 이미 `monitor.db` 가 있는지.
2. 복사 — 점검은 멈추지 않고 계속됩니다(별도 연결로 `VACUUM INTO`).
3. 따라잡기·검증 — 복사 중 쌓인 점검 결과를 짧게 잠금을 잡고 반영한 뒤 무결성·행 수를 확인.
4. 새 위치 기록 → 연결 전환 → 예전 폴더의 `monitor.db`(+`-wal`/`-shm`)와 로그 파일 삭제.

대상 폴더에 이미 `monitor.db` 가 있으면 **덮어쓰지 않습니다.** 그 DB 를 쓰도록 전환(예전 폴더는 그대로)하거나 취소만 가능합니다.
지정한 폴더를 시작할 때 쓸 수 없으면(드라이브 분리·네트워크 끊김) 기본 폴더로 시작하고 사유를 알립니다.
`--db <파일>` 로 실행하면 폴더 설정은 비활성입니다.

## 테스트
알람 판정 · 알람 설정 · 저장 폴더 · 폴더 이동은 화면과 무관해 어느 OS 에서든 돕니다.
```powershell
dotnet test horizon-uag-monitor/tests/UagMonitor.Tests.csproj
```

## 상태 판정
| 상태 | 조건 |
|---|---|
| 정상(초록) | 443 TCP 연결 + HTTP 2xx/3xx + 인증서 여유 + 응답 지연 정상 |
| 주의(노랑) | 도달하나 HTTP 비정상 / 인증서 임박·만료 / 응답 지연 과다 / TLS 오류 |
| 위험(빨강) | 443 TCP 연결 실패(포트 미도달) |

> UAG는 사설/자체 서명 인증서가 흔하므로 **신뢰 검증 실패로 대상을 '위험' 처리하지 않고**
> 도달성·만료일만 기록합니다(인증서 검증 자체는 별도 확장 여지).

## 빌드 (Windows, .NET 8 SDK 필요)
단일 실행 파일(.exe, 설치형 런타임 불필요, Win11 x64):

```powershell
# 저장소 루트에서
cd horizon-uag-monitor
dotnet publish -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
# 산출물: horizon-uag-monitor\publish\HorizonUagMonitor.exe
```
또는 `powershell -ExecutionPolicy Bypass -File build.ps1`.

## 다운로드(빌드 산출물)
GitHub Actions(`horizon-monitor-release.yml`)가 windows-latest에서 빌드해 릴리스에 게시합니다:

- `https://github.com/noainred/The.DVC/releases/download/horizon-monitor/HorizonUagMonitor.exe`

## 최초 사용
1. 실행하면 기본 12개 데이터센터 대상이 **비활성·자리표시자 주소**로 들어 있습니다.
2. **설정(대상 관리)** 에서 각 대상의 **호스트/IP를 실제 UAG 주소로 수정**하고 **활성** 체크.
3. 주기(기본 60초)마다 자동 점검되며, 창을 닫아도 트레이에서 계속 동작합니다.
