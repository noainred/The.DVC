# SAN 스토리지 성능 — 운영 안내

> 도구 `#/tools/san-storage`(메뉴 스토리지 › SAN 스토리지 성능 · v2.948~). 설계 · 구현 기록은 `docs/design/san-storage-perf/README.md`, 규칙은 `docs/rules/sanswitch.md`.
> 이 문서는 **운영자가 화면을 읽고 설정하는 법**만 다룬다. 값의 계산 근거가 궁금하면 설계 README §4 · §10 을 본다.

## 1. 무엇을 보는가

| 축 | 출처 | 주기 | 무엇 |
|---|---|---|---|
| **스위치 측** | SAN 스위치 포트 사용량(`portperfshow` 상당 · 포트 사용량 수집) | 설정 › 수집 주기·임계 › SAN 스위치 포트 사용량(기본 5분) | 어레이 포트에 실제로 흐른 바이트/초 — 팹 A/B 합산 · 디렉터 · 포트별 · 회선 사용률 · 편중 |
| **어레이 측** | 스토리지 수집기(REST)의 5분 표본 — PowerMax FE 디렉터 · PowerStore 노드 · Unity SP(+ 포트) | 설정 › 스토리지 수집 주기의 노드 부하 표본 주기(기본 5분) | 어레이가 스스로 보고하는 busy% · IOPS · 응답 시간 · 큐 깊이 · CPU · 호스트 처리량 |

두 축은 **시리얼**로 짝을 짓는다. 스위치가 본 어레이(네임서버 심볼릭 이름 `SYMMETRIX::<시리얼>` 등)와 스토리지 모니터링에 등록한 장비의 시리얼이 같아야 어레이 측 값 · 용량 · 알람이 붙는다. 짝이 없으면 화면이 '등록 스토리지 짝 없음' 이라고 말한다 — 0 이 아니다.

## 2. 준비(처음 켤 때)

1. **SAN 스위치 등록** — 특수 기능 › SAN 스위치 모니터링에 스위치를 등록하고 포트 사용량 수집을 켠다(엣지에 위임한 법인은 엣지가 수집해 올린다).
2. **스토리지 장비 등록(REST)** — 스토리지 모니터링 › 장비에 PowerMax(Unisphere) · PowerStore · Unity 를 **REST** 로 등록한다. SSH 로 수집하는 변형(uemcli · pstcli)은 어레이 측 성능 경로가 없다.
3. **표본 토글** — 장비 편집 폼의 '디렉터 · 노드 · SP 성능 표본 수집(5분)' 이 켜져 있는지 본다(기본 켬). CSV 가져오기 · 내보내기의 `nodeLoad` 칸으로 일괄 관리할 수 있다(비우면 유지).
4. **시리얼 확인** — 현황 표의 '등록 스토리지 짝 없음' 이 뜨면 스토리지 장비의 시리얼(PowerStore 는 appliance serviceTag)과 어레이 이름의 시리얼을 맞춘다. 어레이 이름이 시리얼이 아니면 **분류 · 매핑** 탭에서 관리자가 어레이 종류 · 디렉터를 지정한다.
5. **벤더 응답 확인** — 어레이 측 파서는 벤더 문서 기준이다. 실장비에서 값이 비면 `docs/design/san-storage-perf/CAPTURE-GUIDE.md` 대로 응답을 캡처해 전달한다(상세 ② 패널의 '문서 기준 · 실장비 확인 전' 알약과 수집 상태의 `probe.fields · errors` 가 어디까지 읽었는지 말한다).

## 3. 현황 탭 읽는 법

- **지금** = 수집 주기 안에서 팹 A/B 표본이 다 모인 마지막 칸의 값. 없으면 '—'(0 이 아니다). 부분 합(한쪽 팹만 온 칸)은 그리지 않는다.
- **회선 사용률** = 송수신 합 ÷ 연결 포트 속도 합. FC 는 전이중이라 이론상 200% 까지 간다.
- **편중** = 디렉터 하나가 어레이 평균의 1.4배 이상(24시간 평균 · 디렉터 평균 500 Mb/s 이상일 때만). 호스트 멀티패스 쏠림 · 볼륨 노드 친화도 · 한쪽 포트 다운이 흔한 원인이지만 화면은 단정하지 않는다.
- **상태** — 정상 / 표본 지연(주의) / 엣지 미보고 / 표본 없음 / 부분 합(확인 불가). 확인 불가는 정상도 장애도 아니다.
- **용량 × 성능** 보기 — 짝 지은 등록 스토리지의 사용률 · 30일 증가 · 소진 예상(스토리지 증가량 화면과 같은 계산)과 성능을 한 표에. 사분면 라벨(찼고 바쁨 · 찼는데 한가함 · 바쁜데 여유 · 여유 · 한가함)은 **표시 규칙(용량 80% · 회선 20%)** 이지 판정이 아니다.
- 검색 칸은 이름 · 시리얼 · 스위치로 거른다. 헤더 ⌘K 검색에서 두 글자 이상 치면 'SAN 스토리지 성능에서 찾기' 행이 뜬다.

## 4. 상세 화면

- **기간** — 실시간 1시간(자동 갱신) · 24시간 · 7일 · 30일 · 90일 · 1년. ◀ 이전 / 다음 ▶ 으로 같은 길이의 과거 창을 본다(과거 창은 자동 갱신하지 않는다). **임의 구간**은 시작 · 끝(최대 366일)을 넣고 '구간 보기'.
- **보관** — 15분 집계 31일 · 1시간 집계는 설정의 보관 기간까지. 원본 보관 밖은 집계 표로 내려간다(원본 폴백 없음).
- **디렉터 · 컨트롤러별** — 포트 심볼릭 이름의 셋째 조각(`SYMMETRIX::시리얼::FA-1D 4`)으로 묶는다. 못 읽은 포트는 '(구분 못 함)' — 추정하지 않으며 분류 · 매핑 탭에서 지정한다. Unity 처럼 셋째 조각이 없는 포트는 조닝 별칭(`Unity_SPA0_p8`)으로 SPA/SPB 를 찾는다.
- **요일 × 시간** — 지난 7일 1시간 평균. **평소와 다름** 테두리 · 차트의 고리는 지난 4주 같은 요일 · 시간 칸 평균에서 허용 폭(기준 설정 '자기 기준선 — 평소와 다름 허용 폭' · 기본 ±50% · 비우면 끔)을 벗어난 칸이다. 표본 3개 미만 칸 · 0.5 Gb/s 미만 차이는 판정하지 않는다. 기준선은 판정 항목이 아니다(점검 종합을 바꾸지 않는다).
- **어레이가 보고하는 디렉터 · 컨트롤러 성능(②)** — 단위 카드(SAN 디렉터 묶음과 대조한 배지) · 선 차트 · 포트 표 · 보고 대조(어레이 호스트 처리량 합 대 스위치 지금, 차이 %). 차이의 원인(FC 프레임 헤더 · 제어 트래픽 · 한쪽 계측 누락)은 단정하지 않는다. 값이 비면 사유가 적힌다(시리얼 불일치 · SSH 수집 · 토글 꺼짐 · 표본 없음 · 오래됨 · 지표 없음).
- 머리의 **호스트별 플로우 ↗** 는 Flow Vision 화면으로 가며 이 어레이 포트 WWN(최대 8개)을 타깃으로 미리 고른다(호스트 · HBA 는 거기서 고른다). **스토리지 경로 ↗** 는 데이터스토어 · 경로 점검.

## 5. 성능 점검 탭

- **판정표** — 스위치 측 4항목(디렉터 편중 · 팹 비대칭 · 회선 포화 · 수집 상태) + 어레이 측 5항목(디렉터 busy · 응답 시간 · 큐 깊이 · 노드/SP CPU · 보고 대조). 표시는 ● 정상 · ▲ 주의 · ✕ 이상 · **? 확인 불가** · — 해당 없음.
- **확인 불가의 뜻** — 값은 보이되 기준이 없거나(비움), 표본 · 짝이 없어 판정하지 않은 것. **정상이 아니다.** 종합 '정상(미확인 N)' 은 '확인한 항목은 정상' 이라는 뜻이다. 어레이 측 값이 하나도 없으면 먼저 §2 를 본다.
- **기준(임계값) 설정**(관리자) — 기본값은 벤더 문서 값만 넣었고(출처 열), 못 찾은 항목은 **비움(판정 안 함)** 이다. 숫자 칸과 슬라이더가 같은 값이다. 비우려면 칸을 지운다(빈 칸 = 비움이 아니라 기본값으로 되돌림이니 '비움' 은 null 저장 — 화면의 '비움' 단추).
  - PowerMax busy 70 · 큐 75(Unisphere 건강 점수) · Unity SP CPU 70/90(Best Practices) · PowerStore CPU 50/70(업그레이드 전 점검 KB — 간접 근거) · 회선 포화 70(Brocade MAPS)/90(제안).
- **이력** — 판정이 바뀌었거나 마지막 기록에서 1시간이 지났을 때만 한 건씩 적는다(알림 틱 · '지금 판정'). 최근 7일 변화와 어레이별 최근 N회 · 상태 전이(악화 · 호전 · 이제 확인됨 · 확인 불가로)를 본다. '확인 불가 → 정상' 은 호전이 아니라 '이제 확인됨' 이다.
- **알림** — 현황 · 점검과 같은 판정을 포트 사용량 수집 주기(하한 5분)마다 돌려 **상태가 바뀐 순간만** 법인 단위로 보낸다(정상 → 주의 · 주의 → 이상 · 회복 · 보고 끊김). 채널 · 수신자는 설정 › 알림의 규칙. 첫 실행은 기준만 잡는다. 엣지는 보내지 않는다.
- **월간 보고서** — 매달 정한 날 · 시각(포탈 시각)에 판정표 · 주의/이상 항목 · 상위 어레이 · 기준 표를 **자급형 HTML** 로 메일에 첨부한다(메일 종류 'SAN 스토리지 성능 월간 보고서'). 화면의 '미리보기(HTML)' 와 'PDF 로 저장'(브라우저에서 벡터 PDF — 임베드 한글 글꼴) 도 있다. 놓친 회차는 몰아서 보내지 않는다.

## 6. 공개 API(외부 모니터링)

`GET /api/v1/san-storage/arrays` · `GET /api/v1/san-storage/check` — 분류 `san` 키가 필요하고, vCenter 범위를 지정한 키는 403 `needs-full-scope`(법인 축이라 범위로 나눌 수 없다). 필드 · 예시는 `docs/API-PUBLIC.md` 7-9 · 7-10. `nowBps` 가 null 인 행을 0 으로 그리지 않는다.

## 7. 문제 해결

| 증상 | 먼저 볼 것 |
|---|---|
| 현황 표가 비어 있다 | SAN 스위치 포트 사용량 수집이 켜져 있는가 · 엣지 위임 법인이면 엣지가 올리는가(수집 상태 알약 · 엣지 미보고 수) |
| 어레이가 '호스트' 로 분류됐다 | 심볼릭 이름이 어레이 규칙(`::` 포함)과 다르다 — 분류 · 매핑 탭에서 '어레이' 로 지정 |
| 어레이 측 값이 '—' | §2 의 시리얼 · REST · 토글 · 캡처 순서로. 상세 ② 의 사유 문구가 어느 단계인지 말한다 |
| 보고 대조가 늘 '주의' | 어레이 호스트 처리량과 스위치 측 차이가 30% 이상 — 어느 한쪽 계측 범위(일부 포트만 등록 · 복제 트래픽)를 먼저 의심 |
| 알림이 오지 않는다 | 알림 모달의 '알림 켬' · 최소 수준 · 설정 › 알림의 채널 · 상태가 실제로 바뀌었는가(같은 상태는 다시 보내지 않는다) |
| 월간 보고서가 안 왔다 | 보고서 모달의 '마지막 틱' · '마지막 발송' · 메일 설정(SMTP) · 놓친 회차는 기록만 남는다 |

## 8. 파일 · 보존

`CONFIG_DIR` 아래 — `storage-perf-check.json`(기준) · `san-storage-map.json`(분류 · 매핑) · `san-storage-notify.json`/`-state.json`(알림) · `san-storage-report.json`/`-state.json`(보고서) · `san-storage-check.db`(점검 이력 — 어레이당 최근 48건). 포트 사용량 표본은 SAN 스위치 포트 사용량 DB(설정의 보관 기간), 어레이 측 표본은 노드 부하 표(스토리지 수집 설정의 보관 기간)에 있다. 백업 · 복원은 포탈 백업 절차를 따른다.
