## 보류 1건 (조치 안 함 — 사유)

- **발견 12(Low)**: svcmon 비-HTTP 점검의 실행시점 SSRF 재검증. 처음엔 각 점검 앞에
  `ssrfBlockReasonResolved`(추가 DNS 조회)를 넣었으나, 그 함수는 **타임아웃이 없어** DNS 가 느리거나
  막힌 환경에서 매 점검마다 폴러를 지연/정지시킨다(테스트 스위트가 실제로 멈추는 것으로 확인 —
  CLAUDE.md 성능 불변조건 '매 폴링 이벤트 루프 블로킹 금지'와도 상충). 되돌리고 보류했다.
  - 잔여 위험은 **낮다**: 저장 시점 `ssrfBlockReason`(store.js `validateEndpoint`)이 이미 루프백/
    링크로컬을 차단하고 RFC1918 만 허용하므로, 리바인딩으로 새로 얻는 표적은 좁다.
  - 올바른 조치: `dns.lookup`(타임아웃 명시) + `ipBlockReason` 으로 해석·검증한 뒤 **그 IP 로 직접
    접속(host 핀)** — uagmon `fetchUagStats` 패턴. 각 점검 케이스(tcp/cert/banner/ldap/ntp/dns)의
    접속부를 IP 핀으로 리팩터해야 하므로 별도 작업으로 분리한다.
