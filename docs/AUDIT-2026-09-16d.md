# 보안 감사 — 저장 파일 · 저장 데이터 · 외부 공격면 (v2.538, 2026-09-16)

4차. 사용자 요청 "저장되는 파일에 대한 보안 점검 · 저장된 데이터의 안전함 점검 · 외부 해킹으로부터
안전한지 점검". 세 축을 전부 봤고, ③은 **목 서버를 인증 켠 채 띄워 무인증으로 실제로 찔렀다**
(소스에 가드가 있다는 것과 요청이 실제로 막힌다는 것은 다르다 — v2.506 교훈).

**결과: critical 0 · high 0 · medium 2 · low 2 — 4건 모두 수정.** 경로 탈출·무인증 열거·브루트포스·
XFF 우회·응답 헤더·오류 핸들러는 전부 준수.

## 방법

| 축 | 어떻게 봤나 |
|---|---|
| ① 저장 파일 | `configDir` 에 쓰는 JSON **113개 파일 전수표**(모듈 · `sealSecretsDeep` 유무 · `mode 0600` 유무 · 비밀 참조 수)를 기계로 뽑고, `pwRefs>0 && seal=0` 인 후보를 파일을 열어 판정 |
| ② 저장 데이터 | SQLite `CREATE TABLE` 의 비밀 컬럼(0건) · 사용자 비밀번호 해시(scrypt) · 세션 서명(HMAC) · 봉인 키 파일 권한 · 비밀 포함 export 게이트 · 로그의 비밀 출력 · 백업 번들 내용 |
| ③ 외부 공격면 | `AUTH_ENABLED=true` 목 서버에 무인증 HTTP 요청: API 14경로 열거, 공개 라우트 본문, 토큰 없는 중앙/수집 엔드포인트, 경로 탈출 8변형(`--path-as-is` 포함), 헤더, 잘못된 JSON, 로그인 12회 연속 실패, XFF 스푸핑, **15MB 무토큰 본문 ×1·×6 동시**(RSS 측정), WS 업그레이드 |

## [medium] 토큰 없는 요청도 16MB JSON 을 파싱했다

| | |
|---|---|
| 위치 | `index.js` — `app.use('/api/central/<12경로>', BIG_JSON)` · `app.use('/api/svcmon/targets/import', BIG_JSON)` 등 14 마운트 |
| 사실 | 이 파서들은 라우터의 토큰 검사보다 **먼저** 돈다. 무토큰 요청도 본문을 끝까지 읽고 `JSON.parse` 한 뒤에야 403/401 을 받았다. |
| 실측 | 무토큰 15MB `POST /api/central/inventory` → **HTTP 403, 0.12초, RSS 171→225MB**. **6건 동시 → RSS 409MB**(+238MB). `/api/svcmon/targets/import` 도 401 을 파싱 뒤에 냈다. 대조군 `/api/vms` (1MB 파서) → **413 즉시**. 동시 6건 파싱 중 다른 요청 지연 0.01→0.11초 |
| 영향 | 토큰 없이 프로세스 메모리를 밀어 올릴 수 있다. 소켓 동시성만이 상한이다. 치명적 크래시까지는 실측하지 않았다(정직 기록 — 6건에서 멈췄다) |
| 조치 | `util/bigJsonGate.js` — **파싱 전에** `resolveCentralAuth(req).ok`(중앙 토큰) / `resolveTokenUser(bearer)`(세션)만 보고, 없으면 `next()` 로 넘겨 본문을 읽지 않는다. 이어지는 전역 1MB 파서가 Content-Length 만 보고 413. 마운트 줄은 그대로(v2.517·v2.520 테스트가 고정). **권한 판정이 아니다** — 인증은 여전히 각 라우터 |
| 재실측 | 무토큰 3MB → **413**(파싱 전) · 유효 토큰 3MB → 413 아님 · 무토큰 `{}` → 403(예전과 동일). 회귀 테스트가 **실제 서버를 띄워** 이 셋을 본다 |

## [medium] 백업 번들과 엣지 설정 push 가 `portal.env` 의 키·토큰을 그대로 실었다

| | |
|---|---|
| 위치 | `backup/service.js collectConfigDir`(`.json` + `.env` 전부) · `agent/configPush.js`(같은 함수로 엣지 설정을 중앙에 push) · `central/agentConfig.js`(엣지별 파일을 `central-agent-config.json` 에 보관) |
| 사실 | 운영 `CONFIG_DIR=/etc/vmware-portal` 에는 설치기가 만든 `portal.env` 가 있고(`packaging/offline/install.sh:93`) 거기에 **`AUTH_SECRET`**(세션 서명 키 — 있으면 관리자 토큰 위조)·`SECRETS_KEY`(봉인 키 — 번들 안 암호문을 전부 연다)·`CENTRAL_TOKEN`/`EDGE_TOKEN` 이 들어간다(`install.sh:96` 이 AUTH_SECRET 을 씀). 번들은 이것을 그대로 담았고, 엣지 30곳의 `portal.env` 도 중앙 한 파일에 모였다. 확장자 없는 `auth-secret`·`secrets-key` 파일은 **제외**돼 있었다(`ALLOW_EXT`) — 즉 설계는 키를 빼려 했는데 env 경로를 놓쳤다 |
| 영향 | 번들 다운로드는 소유자 게이트 + '자격증명 포함' 감사 기록이지만, **번들 하나 = 전체 탈취**였다. 봉인 모드를 켜도 번들에 봉인 키가 같이 들어가 무의미했다 |
| 조치 | `util/envRedact.js`(순수) — 키 이름이 `SECRET|TOKEN|PASSWORD|PASSWD|PASSPHRASE|PRIVATE_KEY|API_KEY|_KEY` 로 끝나는 값만 표식으로 바꾼다. **줄은 남긴다**(복원 시 현재 파일 값으로 이어 붙이고, 현재에 없으면 그 줄을 버린다 — 빈 값으로 AUTH_SECRET 을 덮어쓰면 전 세션 무효). 가린 개수·키를 번들(`central.redacted`)·응답·화면이 말한다. **수신(중앙)에서도 가린다** — 구버전 엣지는 그대로 보낸다 |
| 남긴 것(의도) | JSON 안의 장비 비밀번호는 **그대로** — 번들의 존재 이유가 복원이고, 키·토큰과 달리 설치기가 재생성하지 못한다 |

## [medium/low] 비밀을 담는 파일 4종이 봉인 대상에 없었다

`configDir` 전수표에서 `pwRefs>0 && seal=0` 인 후보 9개를 열어 보니 4개가 실제 비밀을 평문으로 가졌다:

| 파일 | 비밀 | 모듈 |
|---|---|---|
| `agent-assignments.json` | 위임 IP 스캔의 **iDRAC 비밀번호** | `central/assignments.js` |
| `guest-scans.json` | 게스트 로그인 스캔 예약의 **게스트 OS 계정**(`guestPass`) | `security/guestScanScheduler.js` |
| `upgrade.json` | 원격 업그레이드 소스 토큰 | `upgrade/settings.js` |
| `packages.json` | 패키지 저장소 토큰 | `upgrade/packageSettings.js` |

나머지 5개는 준수였다(열어 확인): `auth.json` 은 bind 비밀번호를 저장하지 않고 사용자 자신의 비밀번호로
bind · `central-agent-tokens.json` 은 **sha256 해시** · `central-agent-users.json` 은 `passwordHash` ·
`idrac-scan-settings.json` 은 주기만 · `security-session.json` 은 정책 문자열.

v2.500 M4(`bm-storage.json`)와 같은 계열의 재발. 조치: load `openSecretsDeep` + save `sealSecretsDeep` +
`SECRET_FILES` 등록. 실측: 암호화 모드에서 4파일 모두 디스크는 `enc$1$…`, 로드는 평문. 기본 정책이
`plain` 이라 **기본 설치는 동작 불변**(봉인 모드를 켠 현장에서만 이제 실제로 봉인된다). 4파일 모두
이미 `.gitignore` 에 있었다(확인).

## 정보 — 고치지 않았고 그 이유

- **`secrets-policy` 기본 `plain`**: 하위호환 설계. 자가진단(`security/selfCheck.js`)이 `warn` 으로
  표시한다. 기본을 바꾸면 키 파일 없는 멀티노드가 깨진다 — 운영 결정 사항.
- **CSP 는 `CSP` env 로만**, 세션 토큰은 `localStorage`: XSS 시 토큰 탈취 완화가 없다. 3D 그래프·
  차트 라이브러리(인라인 스타일/워커)와 충돌 없는 CSP 를 만들려면 별도 작업(Chromium 으로 화면별 검증
  필요). 이번 축(저장·무인증)이 아니다.
- **`/api/auth/config` 가 setup 미완료 동안 초기 비밀번호 파일 경로를 무인증으로 준다**: 값이 아니라
  경로이고, 관리자 OTP 등록이 끝나면 사라진다(`setupState`). 코드 주석이 근거를 적고 있다.
- **WS 토큰은 쿼리스트링**(브라우저 WS 는 헤더를 못 붙인다) — 프록시 접근 로그에 남을 수 있다.
  단기 티켓으로 바꾸는 것은 별건.
- **`/dl` 무인증·레이트리밋 제외**: 업그레이드 소스 배포가 목적(공개 설계).

## 보지 않은 것 (정직 기록)

- 실장비·실제 운영 호스트. 파일 권한은 이 환경의 목 CONFIG_DIR 로만 실측했다(umask 다르면 다르다 —
  단 `atomicWriteFileSync` 는 `openSync(mode)`+`chmodSync` 로 umask 와 무관하게 0600 을 만든다).
- 무토큰 대용량 본문으로 **실제 크래시**(OOM)까지는 밀어붙이지 않았다 — 6건 동시에서 멈췄다.
- `secrets-key` 가 설정 파일과 같은 호스트에 있다는 한계는 모듈 머리말이 이미 적고 있다(`SECRETS_KEY`
  env 로 분리 가능).
- 봉인 모드에서 **기존 평문 값의 일괄 전환**은 `migrateSecretFiles` 가 `SECRET_FILES` 를 돌며 한다 —
  새로 등록한 4파일도 그 경로를 탄다(코드 확인). 실제 전환은 실행하지 않았다.
