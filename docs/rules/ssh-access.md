# SSH 공용 접속 2단계(v3.10.0) 상세 규칙 — 두 사람 승인 · 키 로그인 설정 · 키 거두기 · 보호 장치 · 알림

> `server/src/sshaccess/CLAUDE.md` 의 요약을 풀어 쓴 것이다(폴더 CLAUDE.md 15KB 상한 — `claudeMdSize`). 근거 점검 기록은 세션 점검 보고(A~E · 반증)의 항목 번호로 적는다.
> 언제 읽나: server/src/{sshaccess,approval}/ · bmusage/onboard/{keyStore,keyBundle,importAnalyze}.js · routes/api/sshAccess.js · web/src/views/SshAccessSettings.jsx 를 고칠 때.

## 규칙

- **두 사람 승인(`approval/store.js` · `twoPerson.js`)**: 요청자 ≠ 승인자는 **서버가 강제**(`AP.identityKey` — 소문자 · AD `D\a` · `a@d` 를 뗀 신원 비교 · 점검 A2) · 승인은 요청 지문(digest)에 묶인다 · 시한 24시간 · 본문에 비밀 없음 ·
  `approvals.json` 을 못 읽으면 새 요청 · 승인 · 돌려보내기 모두 거절(503 — 404 아님) · 모르는 kind 는 실행하지 않는다 · 실행 실패 = `failed` + 뒷정리(`discard`) · 결과 기록 실패는 응답에 `recordFailed` ·
  10분 넘게 ‘승인됨’ 에 멈춘 요청은 `interrupted`(실행 여부 모름 — 만료와 다른 문구) · 끝난 기록은 **끝난 시각** 순으로 자른다 · 승인 · 돌려보내기 사전 검사는 **OTP 앞**(`approvalPrecheck` · 점검 A10).
  승인 대상 쓰기는 `twoPerson.submit` 으로 승인 대기(202)가 될 수 있다 — 새 키 변경 경로도 같은 길로(우회 금지). 7b 키 라우트의 `twoPersonFirst` 게이트는 승인이 아니라 409 로 돌려보낸다.
  **요청 본문은 실행할 상태에 묶는다**: 법인 재개 = 그때의 중지 시각(`stopAt` — 다시 걸린 중지를 풀지 않는다 · A6) · 키 저장소 다시 읽기 = 그때의 디스크 sha256(`expectSha` · A5).
- **승인 전의 키는 `pending`** — 접속에 쓰지 않고 **고를 수도 없다**: CSV 온보딩(`importAnalyze`) · bm-storage `bmBindCheck` · 서버 키 고르기 · 공통 계정 모두 활성만 받는다(점검 A7 · D-2).
  돌려보냄 · 만료로 지울 때도 `REFS.deleteKeyIfUnused`(사용처가 있으면 남긴다). 7b 키 등록 · 교체 · 삭제 라우트는 두 사람 승인이 켜져 있으면 409(`guards.twoPersonRedirect`).
  ⚠ 내림 설치(v3.10 → v3.9)는 `pending` 을 모른다(옛 normKey 는 retired 가 아니면 active) — 내리기 전에 승인 대기 요청을 끝내거나 취소할 것(릴리스 노트에 적었다).
- **보호 장치(`guards.js` · 상태 파일 guards)**: 두 사람 승인 · 서버 쪽 제한 **기본 켬** · 상태 파일을 못 읽으면 켠 것으로 본다 · 인증을 끈 설치는 두 사람 승인을 적용하지 않는다 ·
  **승인할 사람이 0명이면 요청을 만들지 않는다**(409 `no-approver` — 대기 키 저장 · 받는 곳 평문 삭제 **전에** · 점검 C-7). 끄는 요청의 ‘본인 OTP 로 바로’ 지름길은
  `otherOwners` 0명 **그리고** ‘승인할 수 있는 소유자 둘’ 을 본 적이 없을 때(`pairSeen` 아님)만 — 다른 소유자를 강등 · 범위 지정 · 목록에서 빼 ‘승인 불가’ 로 만든 뒤 혼자 끄던 길(점검 A1 · 반증 R3)을 막는다.
  (첫 수정의 ‘목록 기준(listedOtherOwners)’ 은 반증 R3 · R4 로 버렸다 — 아래 ‘반증 1차’ 절.) 켜는 쪽은 바로 · 끄는 쪽이 실패하면 응답이 `partial.applied` 로 켠 것을 밝힌다. `approvals.json` · `ssh-access-state.json` 은 백업 복원에서 뺀다(`RESTORE_EXCLUDE`).
- **authorized_keys 원격 스크립트(`akScript.js` — 순수 · 테스트가 실제 bash · dash 로 돌린다)**: 고정 틀 + 엄격히 검사한 글자(공개키 type · base64 · 키 id · 서버가 본 접속 주소)만 끼운다(작은따옴표 · 역슬래시 · 줄바꿈 불가) ·
  스크립트는 base64 로 싸서 `echo … | base64 -d | /bin/sh` 한 줄(로그인 셸이 tcsh 여도 같은 문법) · **임시 파일에 다 쓰고 줄 수 · 남길 줄 cksum · 마지막 줄을 대조한 뒤에만 `mv`**
  (`cat tmp > f` 는 파일을 먼저 비워 디스크 가득 · busybox awk 의 0 종료에서 authorized_keys 가 0 바이트가 됐다 — 점검 B-F1) · 줄 판정은 awk `index`(LC_ALL=C · 앞 공백 · 끝 CR 무시 — grep 은 NUL 한 바이트에 줄을 숨겼다 · B-F2a) ·
  **심볼릭 링크 · 일반 파일 아님 · 못 읽음 · 못 씀은 실패**(거두기가 ‘없음’ 으로 끝나면 키가 계속 들어간다 · B-F2b) · 관리자가 옵션을 바꾼 포탈 줄(우리 꼴이 아닌 줄)은 바꾸지 않는다(B-F4) ·
  되돌림은 **우리가 더한 그 줄만 지우고 바꾸기 전 포탈 줄을 다시 넣는다**(사본 파일 · 파일 전체 되쓰기 없음 — B-F6) · 그 줄이 이미 없으면 아무것도 하지 않는다.
- **키 로그인 흐름(`keyLogin.js`)**: 줄 더하기 → 끊고 키로 재접속 확인 → 실패 시 되돌림 · **자동 재시도 금지**(비밀번호 password 방식 한 번 — 구형 알고리즘 재시도 포함 `passwordOnly`) ·
  **서버 쪽 제한(`from=` + 포워딩 금지)을 자동으로 빼고 다시 넣지 않는다** · 제한 없던 포탈 줄을 제한 줄로 바꾸는 것은 **첫 접속이 그 키가 아닐 때만**(되돌릴 접속이 있어야 한다 · B-F5) ·
  접속마다 시한(`withDeadline(legDeadlineMs)` — 세션을 실제로 끊는다) · 바꾸는 명령을 보낸 뒤 답이 없으면 `uncertain`(‘바꾼 것 없음’ 이라고 하지 않는다 · B-F3) · 엣지가 수집하는 서버 제외 ·
  1회 비밀번호는 작업 메모리에만 · 작업 칸은 넣기 · 거두기 **따로**(긴급 거두기가 넣기에 막히지 않는다) · 같은 키 거두기는 넣기 작업을 멈춘다 · 서버 자물쇠 · 멈추기(OTP 없음 — 줄이는 방향) ·
  서버 · 키는 **그 서버 차례에 다시 읽는다**(moved · key-changed) · 묶기 직전 키가 활성인지 다시 본다 · 공개키 ↔ 지문이 맞지 않으면 넣지도 거두지도 않는다(복원 번들 바꿔치기 · 점검 A3) · 데모 모드는 거절.
- **등록부 쓰기(키 묶기 · 저장 비밀번호 지우기)는 `service.js` 가 넘겨 주는 함수로만** — `keyLogin.js` · 라우트는 등록부를 직접 쓰지 않는다(소스 스윕).
- **사건 · 알림(`state.js` · `notify.js`)**: 서버마다 생기는 사건(key-login-set · key-lines-removed)은 **중요 사건이 아니다** — 작업마다 요약 하나(key-job-done · key-revoke-done)를 남긴다(점검 C-3 · D-5) ·
  메일은 작업 요약 한 통(서버마다 보내지 않는다 — 포탈 전체 시간당 한도 · C-4) · 기록에 남은 사건만 알린다 · 받는 곳 ‘본 표지’ 는 12자 해시(사건 300자에 20개 — D S-2) ·
  메일 종류 `ssh-key` · 5초 모아 한 통 · 본문에 비밀 없음 · 데모 모드 제외 · 실패는 삼키고 마지막 결과만.
- **복원 합치기(`keyBundle.mergeRedactedKeyStore`)**: 개인키 · passphrase · **공개키 · 알고리즘 칸** · 폴더 · 기능 · 퇴역은 지금 파일의 같은 지문 키에서 · 공통 계정 비밀번호는 가렸든 아니든 번들에서 받지 않는다(점검 A3 · A4).
- **엣지 재배포(`importAnalyze`)**: ‘개별:계정’ 행은 계정 이름만 정한다 — 같은 계정으로 이미 키를 쓰는 서버의 키를 떼지 않는다(점검 D-3 — 키 로그인 설정이 비밀번호를 지운 서버가 인증 수단 없이 남았다).
- **결정 대기(설계 공백 — 사용자 결정)**: 활성화 승인 뒤 폴더 · 허용 기능 넓히기는 본인 OTP 만으로 된다(점검 A8 — 넓히기를 승인 대상으로 할지).

## 반증 1차(6ce017ad 대상) 반영 — 되돌리지 말 것

- **서버 쪽 자물쇠 + mv 뒤 확인**(R1): 넣기 · 거두기 칸을 나누자 같은 파일을 두 작업이 동시에 바꿔 한쪽 갱신이 사라졌다(거두기 ‘removed’ 인데 키가 남음 — dash 200회 중 189회).
  `~/.ssh/.authorized_keys.portal.lock`(mkdir — 원자적) 을 분류 읽기부터 mv 까지 잡고(15초 · 2분 지난 자물쇠는 치움), 포탈 안 열쇠는 등록부 id 가 아니라 **주소:포트**.
  사람 · 구성 관리 도구는 이 자물쇠를 모른다 — mv 뒤 다시 읽어 원하는 상태가 아니면 `raced`(성공이라고 하지 않는다).
- **같은 키 거두기 중에는 넣기를 시작하지 않는다**(R2 — 409 `revoking`) · 거두기가 시작되면 같은 키 넣기는 멈춘다 · 거두기 칸은 키마다(최대 3 — D2).
- **두 사람 승인을 혼자 끄는 지름길**(R3 · R4): 목록 기준(첫 수정)은 다른 소유자를 목록에서 빼면 혼자 끌 수 있었고(R3), 화면에서 뺄 수 없는 파일 · 중앙 배포 소유자가 있으면 잠겼다(R4).
  지금은 **승인할 수 있는 소유자 둘을 한 번이라도 본 설치(`pairSeen`)는 혼자 끌 수 없다** — 소유자가 실제로 한 명인 설치만 지름길. 한계: 기동 전 · 첫 관측 전에 다른 소유자를 승인 불가로 만든 경우.
  AD 의 UPN 접두와 sAMAccountName 이 다른 두 철자는 같은 신원으로 묶지 못한다(디렉터리 조회 없이 알 수 없음 — 추정 한계).
- **이번에 넣은 사건은 자르지 않는다**(R5 — 중요 사건이 기록을 채우면 받는 곳 새 파일 사건이 넣자마자 잘려 알림이 영영 나가지 않았다).
- **골라 보낸 서버도 상한을 넘으면 `over-limit` 으로 밝힌다**(R6) · 복원 합치기는 키 id 와 공통 계정의 묶음 칸(종류 · 법인 · 계정명 · 기본 키)도 지금 값(R7).
- **root 로그인도 소유자 쓰기 비트가 없는 파일(444)은 바꾸지 않는다**(R8) · `from=` 값이 단일 주소일 때만 우리 꼴(R9 — 넓힌 관리자 줄은 custom).
- **거두기는 키 id 와 무관하게 그 공개키의 포탈 줄 전부**(R10 — 지웠다 다시 등록한 키) · 신호로 끊겨도 임시 파일 · 자물쇠를 치운다(R11 — dash SIGHUP 에서 15회 중 1회는 여전히 남는다: 무해한 숨김 파일).
- **거두기 멈추기는 OTP**(D1 — 유출 키가 남는 방향) · **같은 비밀번호의 거부를 센다**(D3 — 1회 비밀번호 두 번 거부 → 작업 멈춤, 공통 계정 비밀번호 거부 → 그 계정 서버는 건너뜀).
- 남긴 것(추정 · 낮음): busybox awk 가 NUL 뒤를 버리면 검증이 그대로 통과한다(D4 — mawk · gawk 는 보존) · 키 저장소 다시 읽기의 sha 확인과 읽기가 파일을 두 번 연다(D6) ·
  받는 곳 옛 표지(경로|sha)에 공백이 있으면 업그레이드 뒤 한 번 다시 알린다(D7).

## 반복 1회차(5축 점검 · d4d9b2e8) 반영 — 되돌리지 말 것

- **승인자 셈**(A1 · A2 · A3): 계정은 **글자 그대로** 찾는다(`requireSettingsOwner` 가 정확 일치) · 대소문자만 다른 로컬 계정이 있는 이름은 AD 이름으로도 세지 않는다 ·
  쓰기 범위(writeVcenters)가 있으면 승인자가 아니다 · 같은 글자만 하나로 센다(신원으로 접으면 다른 두 사람이 한 명이 됐다) ·
  **pairSeen 은 로컬 계정 둘 또는 실제 승인(다른 사람이 승인함)으로만** 선다 — 로그인할 수 없는 AD 이름(퇴사자 · 오타) 하나가 pairSeen 을 영구히 세워 소유자 한 명 설치가 잠겼다.
  pairSeen 을 내리는 화면 · API 는 두지 않는다(복구: 상태 파일을 고친 뒤 ‘상태 파일 다시 읽기’ — 소유자 + OTP · 또는 승인할 소유자를 세운다).
- **SSH 공용 접속 쓰기는 조회 · 쓰기 범위가 모두 무제한인 소유자만**(A3 — `isFullReadWriteScope` · 403 `write-scope`).
- **OTP 앞 사전 검사**(A5): 승인할 사람 없음 · 같은 요청 대기 · 승인 기록 손상 · 중지 아님 · 키 상태 · 넣는 중인 키 · 데모 — `SVC.prechecks` · `keyJobPrecheck`. 판정은 본 함수가 다시 한다.
- **멈추기 OTP**: 거두기 작업, 그리고 옛 키 교체가 붙은 넣기 작업(남은 서버에 옛 키가 남는다 — A4).
- **원격 자물쇠 주인 표**(B1 · B3 · B4): `~/.ssh/.authorized_keys.portal.lock/owner` = 호스트:pid:시각(호스트 = 이름/부팅 id/pid 이름공간 — 2회차 B2) · mv 직전 `owns` 아니면 `locklost`(바꾸지 않음) ·
  치우기는 같은 호스트에서 pid 없음 / 표 시각 10분 초과 / 표 없음 5초 — 옮긴 뒤 표를 다시 본다 · find 를 쓰지 않는다(444 판정은 `ls -ld`) · 경합이 아닌 mkdir 실패는 바로 `notwritable`.
- **mv 직전 원본 재대조**(B10 — 다르면 `changed`, 원본 그대로) · 남는 틈은 그 한 줄과 mv 사이뿐이다(자물쇠를 모르는 쓰기는 완전히 막을 수 없다).
- **결과 모름을 바꾼 것 없음으로 말하지 않는다**(B5 · B9 · B11): 시작 표지 `##KL begin` 만 오면 `begun` → uncertain · `raced`(mv 뒤 확인 실패)도 uncertain · 되돌림 · 옛 키 지우기를 모르면 ‘모릅니다’.
- **파일 유무도 자물쇠 안에서**(B2) · 되돌림 확인 기대값 = 옛 줄 안의 원하는 줄 수(B8) · 바꿀 것이 없으면 자물쇠 없이 답한다(쓸 수 없는 ~/.ssh 에서도 ‘있음’) — **자물쇠 폴더가 없을 때만**(2회차 B1).
- **판정 기준은 `~/.ssh/authorized_keys` 한 파일**(B6): authorized_keys2 · AuthorizedKeysCommand · 홈 밖 AuthorizedKeysFile 로 같은 키가 들어오면 ‘출발지 제한 적용’ · ‘지움’ 은 그쪽을 모른다 — 화면 · 문서가 밝힌다.
- **재시작 뒤 중단 기록**(B7): 바꾸기 전에 `ssh-key-jobs-inflight.json` 에 적고 끝나면 지운다 · 기동 때 남은 것은 `key-job-interrupted` 사건(중요 · 메일).

- **대화형 칸**(B3-3): 비밀번호 글이 있고 OTP 글이 없는 가리는 칸 먼저(‘One-time password’ 칸에 넣었다).
- **자격은 그 차례에 다시 푼다**(C3-1): 확인 · 되돌림 · 옛 키 지우기 직전 — 그 사이 법인 사용 중지가 걸렸으면 그 키로 접속하지 않고 넣은 줄을 되돌린다.
  1회 비밀번호의 계정 이름은 짐작하지 않는다(공통 계정을 확인할 수 없으면 보내지 않음 — 서버 칸 · root 로 넘어갔다) · 거두는 중인 키로 키 고르기 · 교체하지 않는다(409 `revoking`).
- **사건 · 메일**: 알림이 붙기 전(기동 직후)의 사건도 모았다가 넘긴다(C3-2) · 다시 쓸 사건 대기열이 넘치면 서버별 사건부터 버리고 수를 메일에(C3-3).
- **기록 파일 읽기 오류는 손상이 아니다**(C3-4 · C3-5 · C3-6): 진행 기록은 못 적으면 경고 · 키 점검 항목, 사용 기록 · 서버에서 읽은 키 기록은 원본을 옮기지 않고(다시 읽히면 합침), 승인 기록은 파일이 없어지면 읽기 오류 표지를 푼다.
- **화면**(E3): vCenter 목록에 없는 법인도 서버 · 공통 계정 · 키 폴더 · 중지가 가리키면 보인다(‘(vCenter 목록에 없음)’) · 다시 중지 결과(`added` · `addFailed`) · ‘중지 기록 갱신’ ·
  키 로그인 설정 상한은 API 값(`limits`) · OTP 앞에서 거절(E3-7) · 강제 명령 실패에 ‘제한 끄기’ 안내를 붙이지 않는다(E3-5).
- **복원과 승인**(D3-3): 복원이 대기 키의 id 를 바꿨으면 실행 · 버리기는 지문이 같은 대기 키(하나일 때)를 쓴다 · 포탈 DB 안내에 SSH 상태 파일 2종(D3-1).
- 사용자 결정 대기(결함 아님): 쓰기 범위를 좁힌 소유자의 연결 시험 · 키 읽기(fullRW 를 붙일지) · ‘1회 비밀번호 두 번 거부 → 멈춤’ 을 작업을 넘어 기억할지.
