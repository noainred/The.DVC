# SSH 공용 접속 2단계(v3.10.0) 상세 규칙 — 두 사람 승인 · 키 로그인 설정 · 키 거두기 · 보호 장치 · 알림

> `server/src/sshaccess/CLAUDE.md` 의 요약을 풀어 쓴 것이다(폴더 CLAUDE.md 15KB 상한 — `claudeMdSize`). 근거 점검 기록은 세션 점검 보고(A~E · 반증)의 항목 번호로 적는다.
> 언제 읽나: server/src/{sshaccess,approval}/ · bmusage/onboard/{keyStore,keyBundle,importAnalyze}.js · routes/api/sshAccess.js · web/src/views/SshAccessSettings.jsx 를 고칠 때.

## 규칙

- **두 사람 승인(`approval/store.js` · `twoPerson.js`)**: 요청자 ≠ 승인자는 **서버가 강제**(`AP.identityKey` — 소문자 · AD `D\a` · `a@d` 를 뗀 신원 비교 · 점검 A2) · 승인은 요청 지문(digest)에 묶인다 · 시한 24시간 · 본문에 비밀 없음 ·
  `approvals.json` 을 못 읽으면 새 요청 · 승인 · 돌려보내기 모두 거절(503 — 404 아님) · 모르는 kind 는 실행하지 않는다 · 실행 실패 = `failed` + 뒷정리(`discard`) · 결과 기록 실패는 응답에 `recordFailed` ·
  10분 넘게 ‘승인됨’ 에 멈춘 요청은 `interrupted`(실행 여부 모름 — 만료와 다른 문구) · 끝난 기록은 **끝난 시각** 순으로 자른다 · 승인 · 돌려보내기 사전 검사는 **OTP 앞**(`approvalPrecheck` · 점검 A10).
  승인 대상 쓰기는 `twoPerson.submit` 으로 승인 대기(202)가 될 수 있다 — 새 키 변경 경로도 같은 길로(우회 금지). 7b 키 라우트의 `twoPersonFirst` 게이트는 승인이 아니라 409 로 돌려보낸다.
  **요청 본문은 실행할 상태에 묶는다**: 법인 재개 = 그때의 중지 시각(`stopAt` — 다시 걸린 중지를 풀지 않는다 · A6) · 키 저장소 다시 읽기 = 그때의 디스크 sha256(`expectSha` · A5).
- **승인 전의 키는 `pending`** — 접속에 쓰지 않고 **고를 수도 없다**: CSV 온보딩(`importAnalyze`) · bm-storage `bmBindCheck` · 서버 키 고르기 · 공통 계정 모두 활성만 받는다(점검 A7 · D-2).
  돌려보냄 · 만료로 지울 때도 `REFS.deleteKeyIfUnused`(사용처가 있으면 남긴다). 7b 키 등록 · 교체 · 삭제 라우트는 두 사람 승인이 켜져 있으면 409(`guards.twoPersonRedirect`).
  ⚠ 내림 설치(v3.10 → v3.9)는 `pending` 을 모른다(옛 normKey 는 retired 가 아니면 active) — 내리기 전에 승인 대기 요청을 끝내거나 취소할 것(릴리스 노트에 적었다).
- **보호 장치(`guards.js` · 상태 파일 guards)**: 두 사람 승인 · 서버 쪽 제한 **기본 켬** · 상태 파일을 못 읽으면 켠 것으로 본다 · 인증을 끈 설치는 두 사람 승인을 적용하지 않는다 ·
  **승인할 사람이 0명이면 요청을 만들지 않는다**(409 `no-approver` — 대기 키 저장 · 받는 곳 평문 삭제 **전에** · 점검 C-7). 끄는 요청의 ‘본인 OTP 로 바로’ 지름길은
  `otherOwners` 0명 **그리고** `listedOtherOwners` 0명(목록의 다른 소유자 — 로그인 수단 없는 시드 noainred 만 뺀다)일 때만 — 다른 소유자를 강등 · 범위 지정 · 삭제해 ‘승인 불가’ 로 만든 뒤 바로 끄던 길(점검 A1)을 막는다.
  그런 계정은 소유자 목록에서 빼는 것(소유자 + OTP · 감사)이 먼저다. 켜는 쪽은 바로 · 끄는 쪽이 실패하면 응답이 `partial.applied` 로 켠 것을 밝힌다. `approvals.json` · `ssh-access-state.json` 은 백업 복원에서 뺀다(`RESTORE_EXCLUDE`).
- **authorized_keys 원격 스크립트(`akScript.js` — 순수 · 테스트가 실제 bash · dash 로 돌린다)**: 고정 틀 + 엄격히 검사한 글자(공개키 type · base64 · 키 id · 서버가 본 접속 주소)만 끼운다(작은따옴표 · 역슬래시 · 줄바꿈 불가) ·
  스크립트는 base64 로 싸서 `echo … | base64 -d | /bin/sh` 한 줄(로그인 셸이 tcsh 여도 같은 문법) · **임시 파일에 다 쓰고 줄 수 · 남길 줄 cksum · 마지막 줄을 대조한 뒤에만 `mv`**
  (`cat tmp > f` 는 파일을 먼저 비워 디스크 가득 · busybox awk 의 0 종료에서 authorized_keys 가 0 바이트가 됐다 — 점검 B-F1) · 줄 판정은 awk `index`(LC_ALL=C · 앞 공백 · 끝 CR 무시 — grep 은 NUL 한 바이트에 줄을 숨겼다 · B-F2a) ·
  **심볼릭 링크 · 일반 파일 아님 · 못 읽음 · 못 씀은 실패**(거두기가 ‘없음’ 으로 끝나면 키가 계속 들어간다 · B-F2b) · 관리자가 옵션을 바꾼 포탈 줄(우리 꼴이 아닌 줄)은 바꾸지 않는다(B-F4) ·
  되돌림은 **우리가 더한 그 줄만 지우고 바꾸기 전 포탈 줄을 다시 넣는다**(사본 파일 · 파일 전체 되쓰기 없음 — B-F6) · 그 줄이 이미 없으면 아무것도 하지 않는다.
- **키 로그인 흐름(`keyLogin.js`)**: 줄 더하기 → 끊고 키로 재접속 확인 → 실패 시 되돌림 · **자동 재시도 금지**(비밀번호 password 방식 한 번 — 구형 알고리즘 재시도 포함 `passwordOnly`) ·
  **서버 쪽 제한(`from=` + 포워딩 금지)을 자동으로 빼고 다시 넣지 않는다** · 제한 없던 포탈 줄을 제한 줄로 바꾸는 것은 **첫 접속이 그 키가 아닐 때만**(되돌릴 접속이 있어야 한다 · B-F5) ·
  접속마다 시한(`withDeadline(legDeadlineMs)` — 세션을 실제로 끊는다) · 바꾸는 명령을 보낸 뒤 답이 없으면 `uncertain`(‘바꾼 것 없음’ 이라고 하지 않는다 · B-F3) · 엣지가 수집하는 서버 제외 ·
  1회 비밀번호는 작업 메모리에만 · 작업 칸은 넣기 · 거두기 **따로**(긴급 거두기가 넣기에 막히지 않는다) · 같은 키 거두기는 넣기 작업을 멈춘다 · 서버 자물쇠 · 멈추기(OTP 없음 — 줄이는 방향) ·
  서버 · 키는 **그 서버 차례에 다시 읽는다**(moved · key-changed) · 묶기 직전 키가 활성인지 다시 본다 · 공개키 ↔ 지문이 맞지 않으면 넣지도 거두지도 않는다(복원 번들 바꿔치기 · 점검 A3) · 데모 모드는 거절.
- **등록부 쓰기(키 묶기 · 저장 비밀번호 지우기)는 `service.js` 가 넘겨 주는 함수로만** — `keyLogin.js` · 라우트는 등록부를 직접 쓰지 않는다(소스 스윕).
- **사건 · 알림(`state.js` · `notify.js`)**: 서버마다 생기는 사건(key-login-set · key-lines-removed)은 **중요 사건이 아니다** — 작업마다 요약 하나(key-job-done · key-revoke-done)를 남긴다(점검 C-3 · D-5) ·
  메일은 작업 요약 한 통(서버마다 보내지 않는다 — 포탈 전체 시간당 한도 · C-4) · 기록에 남은 사건만 알린다 · 받는 곳 ‘본 표지’ 는 12자 해시(사건 300자에 20개 — D S-2) ·
  메일 종류 `ssh-key` · 5초 모아 한 통 · 본문에 비밀 없음 · 데모 모드 제외 · 실패는 삼키고 마지막 결과만.
- **복원 합치기(`keyBundle.mergeRedactedKeyStore`)**: 개인키 · passphrase · **공개키 · 알고리즘 칸** · 폴더 · 기능 · 퇴역은 지금 파일의 같은 지문 키에서 · 공통 계정 비밀번호는 가렸든 아니든 번들에서 받지 않는다(점검 A3 · A4).
- **엣지 재배포(`importAnalyze`)**: ‘개별:계정’ 행은 계정 이름만 정한다 — 같은 계정으로 이미 키를 쓰는 서버의 키를 떼지 않는다(점검 D-3 — 키 로그인 설정이 비밀번호를 지운 서버가 인증 수단 없이 남았다).
- **결정 대기(설계 공백 — 사용자 결정)**: 활성화 승인 뒤 폴더 · 허용 기능 넓히기는 본인 OTP 만으로 된다(점검 A8 — 넓히기를 승인 대상으로 할지).
