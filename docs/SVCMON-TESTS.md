# 성능점검 — 테스트 유형 상세

성능점검 탭에서 등록할 수 있는 점검 유형 15종의 프로토콜·판정 기준·파라미터를 정리한 문서입니다.
아키텍처·용량 산정은 [SVCMON-ARCHITECTURE.md](SVCMON-ARCHITECTURE.md) 참고.

- 구현: `server/src/svcmon/checker.js` (외부 의존성 없음 — Node 표준 라이브러리 + undici)
- 모든 점검은 실패해도 격리되어 `실패(bad)` 로만 기록됩니다(폴러가 죽지 않음)
- 상태 3단계: **Ok** / **Warning**(임계 근접·부분 이상) / **No answer·Error**(실패), 중지는 `Disabled`

---

## 공통 파라미터

| 필드 | 설명 |
|---|---|
| 점검 이름 | 목록에 표시되는 이름. HostMonitor 처럼 `2. Ping: 192.168.10.55` 식으로 번호를 붙여도 됩니다 |
| 유형 | 아래 15종 중 하나 |
| 주기(초) | **최소 10초**, 최대 86400초(1일). 항목 수가 많으면 주기를 늘리는 것이 서버 부하에 직접 영향 |
| 사용/중지 | 중지하면 점검하지 않고 `Disabled` 로 표시(등록은 유지) |

대상(호스트)은 점검이 아니라 **대상 단위**로 등록하며, 한 대상 아래 여러 점검을 둡니다.
대상의 호스트/IP 는 등록 시 **SSRF 가드**를 통과해야 합니다 — 사내망(RFC1918)은 허용,
루프백(127.x)·링크로컬(169.254.x)·메타데이터 주소·우회 표기(10진수·IPv4-mapped)는 차단합니다.

## 1. 네트워크

### Ping (ICMP)
- **방식**: OS `ping` CLI 1회 실행(raw 소켓 권한 불필요). CLI 가 없는 환경은 TCP 폴백.
- **판정**: 응답 있으면 Ok(응답값 = RTT `1.828 ms`), 없으면 No answer.
- **타임아웃**: 4초.
- ⚠️ **부하 주의**: 프로세스를 띄우는 유형이라 동시 실행이 제한됩니다(`SVCMON_PROC_CONCURRENCY`,
  기본 64). 1만 대 규모에서 전부 ping 을 걸면 이 값이 병목이 됩니다 — TCP 점검 병용을 권장.

### Trace (traceroute)
- **방식**: `traceroute -n`(Windows `tracert -d`) 실행 후 홉 수 파싱.
- **판정**: 마지막 홉이 `* * *` 면 Warning(미완료), 홉 수가 `maxHops` 초과면 Warning, 그 외 Ok.
- **파라미터**: `maxHops`(기본 15, 최대 64). 타임아웃 25초.
- 경로 변화 감시용이며 주기를 길게(300초+) 두는 것을 권장합니다.

### TCP 포트
- **방식**: TCP 연결만 시도하고 **바이트를 보내지 않고** 끊습니다(대상 로그 오염 방지).
- **판정**: 연결 성공 Ok / 실패·타임아웃 No answer. 타임아웃 4초.
- **파라미터**: `port`(필수).
- 사내 서비스 가동 판정에 가장 안전한 기본 방식입니다(로그인 리다이렉트·401 에 영향 없음).

### UDP 프로브
- **방식**: 지정 페이로드를 UDP 로 보내고 응답 패킷을 기다립니다.
- **판정**: 응답 있으면 Ok(`응답 N bytes`), 없으면 No answer(4초).
- **파라미터**: `port`(필수), `payload`(선택 — 비우면 `\r\n`).
- UDP 는 무응답이 정상인 서비스도 있어(단방향 syslog 등) 대상 선정에 주의가 필요합니다.

## 2. Web

### HTTP / URL
- **방식**: GET, 리다이렉트 미추적(`redirect: manual`). 타임아웃 8초.
- **판정**:
  1) `expectStatus` 지정 시 정확히 일치해야 Ok, 아니면 실패
  2) 미지정이면 500 미만을 Ok(로그인 리다이렉트 302·401 을 살아있음으로 봄)
  3) `keyword` 지정 시 본문에 없으면 **Warning**(응답은 오지만 내용이 깨진 상태 탐지)
  4) `warnMs` 초과 시 Warning(느린 응답)
- **파라미터**: `url`(필수, http/https), `keyword`, `expectStatus`, `warnMs`, `insecure`(자체서명 허용)
- 본문은 최대 256KB 만 읽습니다. `insecure` 는 **그 요청에만** 적용됩니다(전역 TLS 오염 금지).
- 실행 직전 SSRF 재검증 — DNS 가 나중에 루프백으로 바뀌는 경우를 막습니다.

### SOAP / XML
- **방식**: `POST` + `Content-Type: text/xml`, `SOAPAction` 헤더. 본문 미지정 시 빈 Envelope.
- **판정**: HTTP 와 동일 + `keyword` 로 응답 XML 내용 확인.
- **파라미터**: `url`, `body`(최대 4000자), `soapAction`, `keyword`

### SSL 인증서 만료
- **방식**: TLS 핸드셰이크 후 `valid_to` 를 읽고 즉시 종료(`rejectUnauthorized:false` — 만료·자체서명
  인증서도 날짜를 읽어야 하므로).
- **판정**: 이미 만료 → 실패(`만료됨 (N일 경과)`), `warnDays` 이내 → Warning(`D-N`), 그 외 Ok.
- **파라미터**: `port`(기본 443), `warnDays`(기본 30)

### 도메인 만료 (whois)
- **방식**: `whois.iana.org:43` 질의 → `refer:` 참조 서버 1회 추적 → `Registry Expiry Date` 등 파싱.
- **판정**: 인증서와 동일 규칙(`warnDays` 기본 60). 파싱 실패는 Warning.
- **파라미터**: `record`(도메인명, 비우면 대상 호스트)
- ⚠️ TLD 별 whois 응답 형식이 달라 파싱 실패가 있을 수 있습니다. 주기를 길게(1일) 두세요.

## 3. 이름·시간·디렉터리

### DNS 질의
- **방식**: 대상(또는 `server`)을 **네임서버로 지정**해 A/AAAA 질의(타임아웃 4초, 재시도 없음).
- **판정**: 결과 있으면 Ok(`name → 1.2.3.4 · 12ms`), 없으면 실패. `expect` 지정 시 결과에 그 IP 가
  없으면 Warning(DNS 하이재킹·오설정 탐지).
- **파라미터**: `record`(조회할 이름), `server`(비우면 대상 호스트), `expect`

### NTP 오프셋
- **방식**: SNTP(UDP 123) 48바이트 1회 질의 → `서버시각 − 로컬시각` 계산.
- **판정**: |오프셋| > `badMs`(기본 5000) 실패 / > `warnMs`(기본 1000) Warning / 그 외 Ok.
- **파라미터**: `server`(비우면 대상 호스트), `warnMs`, `badMs`
- 시간 오차는 vCenter 인증·OTP 실패의 흔한 원인이라 관리 서버에 걸어 두는 것을 권장합니다.

### LDAP bind
- **방식**: 익명 simple bind(BER 직접 인코딩) 후 `resultCode` 확인.
- **판정**: `0`(성공)·`48`·`49`(인증 거부지만 **서버는 응답함**) → Ok. 그 외/무응답 → 실패.
- **파라미터**: `port`(기본 389)
- 익명 bind 를 막은 AD 도 "살아있음"으로 정확히 판정하기 위해 48/49 를 Ok 로 봅니다.

## 4. 배너 검사 (E-Mail · SSH)

연결 후 서버가 보내는 **인사말 1줄**을 읽어 프로토콜이 정상 동작하는지 확인합니다.
포트만 열린 좀비 프로세스를 걸러냅니다(TCP 점검으로는 구분 불가).

| 유형 | 기본 포트 | 기대 패턴 | 비고 |
|---|---|---|---|
| SMTP | 25 | `220 …` | 587(submission)·465 도 가능 |
| POP3 | 110 | `+OK …` | 995(TLS)는 배너가 암호화되어 실패 → TCP 점검 권장 |
| IMAP | 143 | `* OK …` | 993(TLS)는 위와 동일 |
| SSH | 22 | `SSH-2.0-…` / `SSH-1.99-…` | 버전 문자열이 응답값에 그대로 남아 패치 추적에도 유용 |

- **판정**: 패턴 일치 Ok(응답값 = 배너 원문) / 불일치 **Warning**(`예상외 응답: …`) / 무응답 실패.
- **파라미터**: `port`, `send`(연결 후 보낼 명령 — 예 `EHLO test`), `keyword`(응답에 포함되어야 하는 문자열)
- 최대 2KB 만 읽고 즉시 끊습니다.

## 5. 다음 단계 예정 (엔진 미구현)

추가 메뉴에 회색으로 표시되며 아직 선택할 수 없습니다. HostMonitor 목록 기준 우선순위:

| 그룹 | 필요한 엔진 | 열리는 점검 |
|---|---|---|
| SNMP Get / Table / Trap | SNMP v2c BER 인코더 | 인터페이스 상태·트래픽, Cisco·Juniper·F5·Netscaler 헬스/온도/팬/전원, NetApp·QNAP·Synology, **UPS 7종**, 프린터 |
| IPMI / Redfish | 기존 `idrac/redfish.js` 확장(벤더 중립화) | Redfish Health/Temp/Fans/Voltage/Power, HP iLO, RMCP Ping |
| Database 세션 | 각 DB 프로토콜 핸드셰이크 | MySQL·PostgreSQL·MSSQL·Oracle 세션 수락 확인 |
| SSH 명령 실행 | 기존 `proxy/sshExec.js` 재사용 + 자격증명 보관 설계 | Drive Free Space, CPU/메모리, 프로세스 수, 파일 존재·크기, 로그 감시(UNIX 14종 대체) |

SNMP 를 먼저 구현하면 장비류 점검 대부분이 **OID 프로파일 추가만으로** 열립니다.

## 참고 — 왜 이 유형들을 먼저 골랐나

원본 HostMonitor 는 150종 이상을 제공하지만, 그중 다수는 이 포탈에 **이미 더 깊은 형태로 존재**하거나
사내 환경과 무관합니다:

- VMware ESXi/게스트 8종 → vCenter 수집이 성능 시계열·알람·용량 예측까지 제공(중복)
- HDD SMART·하드웨어 헬스 → iDRAC Redfish 수집이 이미 담당
- 인증서 만료 → 특수 기능의 인증서 만료 감시(vCenter·NSX)와 별개로, 여기서는 **임의 호스트** 대상
- Windows WMI/레지스트리/백신/업데이트 → PC 관리 영역(포탈 목적과 불일치)
- Active Script(임의 스크립트 실행) → 보안상 채택하지 않음

즉 위 15종은 **"사내에서 실제로 쓰이는데 포탈에 없던 것"** 을 우선 채운 결과입니다.
