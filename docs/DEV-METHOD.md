# 개발 방법론 — The.DVC 포탈을 Claude Code 로 개발하는 방식(v2.677 기준)

> 이 문서는 v2.5xx~v2.676 의 실제 작업 기록(커밋·릴리스 노트·감사 보고서 48편·CLAUDE.md)과
> 사용자와 나눈 '모델·에포트·토큰·시간' 대화를 검토해 만든 **운영 규칙**이다.
> 숫자는 근거를 함께 적었다. 측정하지 않은 값은 **(추정)** 으로 표시한다.

---

## 0. 왜 바꾸는가 — 지금 방식에서 확인된 사실 다섯 가지

| # | 사실 | 근거 |
|---|---|---|
| F1 | **CLAUDE.md(루트)가 39만 자 · 5,035줄**이다. 세션을 시작할 때마다, 그리고 매 턴 문맥에 통째로 실린다. 그중 4,665줄(62~4,727행)이 '운영 환경' 절 아래의 릴리스별 사고 기록이다 | `wc` 실측(2026-10-01). 토큰 환산은 약 15만~25만 **(추정)** — 한글 비중(12.9만 자)이 커서 폭이 넓다 |
| F2 | 문맥이 그만큼 차서 **긴 작업은 거의 매번 요약(compaction)을 거친다.** 요약 뒤에는 세부(정확한 코드·오류 문구)를 다시 읽어야 한다 | 이번 세션도 v2.676 작업 중 요약됐다 |
| F3 | **작업 시간과 토큰은 비례하지 않는다.** 시간의 큰 몫은 CI·릴리스 워크플로 대기·전량 테스트·Chromium 검증이고, 이때 토큰은 거의 쓰이지 않는다. 토큰은 ① 읽는 양 ② 도구 호출 수 × 그때의 문맥 크기 ③ 출력 길이에 비례한다 | 사용자와의 대화(v2.676 단계별 표) |
| F4 | **감사 회차의 상당수가 '직전 릴리스가 만든 결함' 을 찾았다.** v2.594~v2.632 의 회차 기록마다 '◯◯ 이 만든 회귀' 항목이 있다(예: v2.600 RECENT2600-01, v2.601 RECENT2601-01, v2.621 RECENT-01/02, v2.631 R2631-01) | CLAUDE.md 회차 절 · `docs/AUDIT-*.md` |
| F5 | **같은 종류의 결함이 반복된다.** `Number(null)===0`(9회 이상 기록) · 형제 라우트의 범위(scope) 누락 · BIG_JSON 미등록 · 화면 문구 백틱(6회) · `text-transform: uppercase` · 엣지 수신 정제 화이트리스트 누락 | CLAUDE.md 각 절의 '재발' 기록 |

**결론**: 개선할 축은 셋이다. ① 매 턴 실리는 문맥(F1·F2) ② 대기 시간 사용법(F3) ③ 반복 결함을 '기억' 이 아니라 **자동 검사**로 막는 것(F4·F5).

## 1. 작업 등급 — 요청을 받으면 먼저 등급을 정한다

| 등급 | 예 | 모델 · 에포트 | 검증 | 릴리스 |
|---|---|---|---|---|
| **S 질문** | "이게 왜 이래?", 설명·견적 | Sonnet · low | 코드 근거만 | 없음 |
| **M 단일 기능·버그** | 화면 1개 수정, 라우트 1개 추가 | Sonnet · medium (동시성·권한이 걸리면 Opus) | 변경 모듈 테스트 + 커밋 전 전량 1회 + 화면이면 Chromium 1라운드 | 있음 |
| **L 기능 묶음** | 새 도구(서버+화면+엣지 경로) | 설계·서버 Opus · high / 화면·문구 Sonnet · medium | M + 엣지·범위 계정 경로 + A/B | 있음 |
| **XL 감사·리팩터** | "전체 점검", "아키텍처 개선" | 발견 Sonnet · medium(축별 병렬) / 반증·수정 Opus · high | 축별 변이 검증 + 전량 | 있음 |

- 등급은 **작업 현황 표의 `난이도` 열**과 같은 뜻이다(낮음=S, 보통=M, 높음=L·XL).
- 30분을 넘길 것 같으면(L·XL 대부분) 착수 전에 검증 수준을 묻는다(CLAUDE.md 사용자 선호).
- 모델은 `/model` 로 세션 단위로 바꾸고, 단계마다 바꾸려면 **워크플로**("workflow로 해줘")를 쓴다 — `agent({model, effort})` 가 단계별 지정을 받는 유일한 경로다. 하위 에이전트(Agent 도구)는 모델만 받는다.

## 2. 표준 파이프라인 — 8단계

각 단계에 **누가(모델)** · **무엇을 남기는가(산출물)** · **토큰 절약 규칙**을 둔다.

### ① 요청 정리 (메인 세션)
- 작업 현황 표 + 등급. 모호하면 질문 1회(선택지는 **시간이 실제로 갈리는 축**).
- 산출물: 표 1개.

### ② 조사 (S·M: 메인이 직접 / L·XL: Explore·하위 에이전트)
- **grep → 필요한 줄만**(`sed -n A,Bp`) 읽는다. 파일 통째 읽기는 300줄 이하일 때만.
- 넓은 탐색(파일 10개 이상)은 하위 에이전트에 맡기고 **결론만** 받는다 — 탐색 덤프가 메인 문맥에 쌓이지 않게.
- 하위 에이전트 지시문에는 **맥락을 다시 적는다**(대화 맥락을 모른다). 결과는 scratchpad 파일에도 쓰게 한다(CLAUDE.md 2026-09-11 사고 — 30분 무응답이면 직접 조사로 전환).
- 산출물: '고칠 곳' 목록(파일:줄).

### ③ 설계 (L·XL 만, Opus · high)
- **판정 함수 하나 · 문구 모듈 하나**(CLAUDE.md 반복 규약). 서버는 `code`+근거, 웹이 문장.
- '이 값을 못 읽으면?' '범위 계정이면?' '엣지 위임이면?' 세 질문에 답을 적는다 — F5 의 대부분이 여기서 빠졌다.
- 산출물: 계획 5~15줄(사용자 승인 필요 시 plan).

### ④ 구현
- 서버 로직·동시성·권한 = Opus, 화면·문구·문서 = Sonnet 으로 나눌 수 있다(워크플로일 때).
- **파일이 겹치지 않게** 나눈다. 겹치면 병렬로 하지 않는다(v2.604 백업 경로 공유 사고).

### ⑤ 검증 (가장 시간이 많이 드는 단계 — 순서가 핵심)
1. 변경 모듈 테스트만(`node --test server/test/<파일>` ≈ 2초).
2. **변이 검증**: 고친 줄을 되돌리면 새 테스트가 실패하는가. 기준판은 **작업 시작 커밋**(`git show <base>:경로`) — HEAD 로 하면 거짓 통과(v2.598 기록).
3. 화면이면 `vite build` 1회 → Chromium **한 라운드에 몰아서** 1440/400 · admin/범위 계정 · 콘솔 오류 · 가로 넘침 · 스크린샷 판독.
4. 커밋 직전에만 전량 `npm test` + web vitest + lint(병렬로 동시에 돌린다).
- 생략한 검증은 보고에 적는다.

### ⑥ 문서·생성물
- 라우트 변경 → `node scripts/api-doc.mjs` · 설정 파일 → `config-doc` · 환경변수 → `env-doc` · docs/*.md 추가 → `arch-doc.mjs` · 의존성 → `third-party-notices.mjs`. **CI `--check` 가 막는 것들이다** — 마지막에 한꺼번에 돌린다.
- 릴리스 노트 + 버전 3파일.

### ⑦ 릴리스 (대기 단계 — 토큰을 쓰지 않는다)
- PR → CI → 머지 → release.yml → `versions.json` 확인.
- 대기는 **폴링하지 않는다**: CI 는 PR 구독 이벤트, 릴리스는 `send_later`(약 10분 뒤 1회 확인). 그 사이에 다음 작업의 ②조사를 진행할 수 있다.

### ⑧ 기록 (가장 중요한 장기 비용 결정)
- 새 교훈은 **CLAUDE.md 본문에 단락으로 쌓지 않는다**(→ 3절). 다음 중 하나로 남긴다:
  1. **자동 검사로 만들 수 있으면 테스트**(소스 스윕·라우터 스택 검사·`archScan` 규칙). — 1순위
  2. 그 디렉터리에서만 필요한 규칙이면 **그 디렉터리의 CLAUDE.md**(`server/CLAUDE.md` 처럼 그 아래를 만질 때만 실린다).
  3. 사건 기록은 `docs/LESSONS/<영역>.md` 또는 감사 보고서.
- 루트 CLAUDE.md 에는 **한 줄 규칙 + 링크**만 더한다.

## 3. 문맥(토큰) 다이어트 — 효과가 가장 큰 한 가지

**루트 CLAUDE.md 를 '항상 필요한 것' 만 남기고 나머지를 옮긴다.**

| 남길 것(목표 300~500줄) | 옮길 곳 |
|---|---|
| 프로젝트 개요 · 빌드·테스트 명령 · 운영 규모 · 사용자 선호 · 정직 원칙 | 루트 CLAUDE.md 유지 |
| 성능 메커니즘 '유지할 것' 목록(한 줄씩) | 루트 유지 + 상세는 `docs/LESSONS/perf.md` |
| 도메인별 사고 기록(스토리지·SAN·CVP·iDRAC·bmusage·IPMS·V4~V6 …) | `docs/LESSONS/<도메인>.md` — **필요할 때 grep 으로 읽는다** |
| 서버 경로 규칙 | `server/CLAUDE.md`(이미 있음 — 자동 로드) |
| 웹 경로 규칙(프론트 회귀 방지) | `web/CLAUDE.md` 신설(웹을 만질 때만 로드) |
| 감사 회차 절(v2.589~v2.632) | 이미 `docs/AUDIT-*.md` 에 같은 내용 — 루트에서는 링크만 |

- 기대 효과(추정): 매 턴 문맥이 수십만 자 → 수만 자로 줄어 **요약(compaction) 빈도·재읽기 비용이 크게 준다.**
- 위험: 옮긴 규칙을 다음 세션이 **안 읽고 어긴다.** 대책 — ① 옮기기 전에 규칙마다 '자동 검사가 있는가' 를 표시하고, 없는 것 중 중요한 것은 테스트로 먼저 만든다 ② 루트에 '도메인 작업 전 `docs/LESSONS/<도메인>.md` 를 grep 하라' 를 1줄로 남긴다.
- **이 이전은 사용자 승인 후 별도 작업으로 한다**(규칙 소실 위험이 있는 구조 변경이므로).

## 4. 반복 결함을 기억 대신 검사로 막는다 (F4·F5 대응)

| 반복 결함 | 지금 상태 | 다음 단계 |
|---|---|---|
| `Number(null/'')===0` | `numOrNull` 서버·웹 대조 테스트 있음 | 새 수치 필드는 `numOrNull` 만 — 스윕 확대(`Number(x) \|\| 0` 전수) |
| 형제 라우트 범위(scope) 누락 | `audit2612a` 스윕 · 런타임 `archScan` | 새 라우터 파일 위치와 무관하게 스윕 대상에 자동 포함되는지 확인 |
| 직전 릴리스 회귀 | 감사 때마다 '직전 diff 회귀 축' 을 첫 축으로 | **릴리스 직후 그 diff 만 보는 가벼운 리뷰 1회**(Sonnet medium, 10분)를 파이프라인 ⑦ 뒤에 고정 |
| 문구 백틱·`**` 노출·uppercase | `uiText.test.js` 스윕 | 유지 |
| BIG_JSON·엣지 정제 화이트리스트 | 경로별 테스트 | '새 엣지 필드 = 정제기에도' 를 스키마 대조 테스트로 |
| 400px 넘침·찌그러짐 | Chromium 수동 | 핵심 화면 10개 자동 스크린샷 + 넘침 측정 스크립트(`scripts/ui-smoke`) 신설 후보 |

감사(XL) 운영 규칙:
- 축은 **직전 diff 회귀 → 새 기능 → 범위/보안 → 결측 표시 → 성능** 순.
- 확정 건수가 두 회차 연속 줄고 대부분 low 면 **감사를 멈추고 기능 개발로 돌아간다**(수확 체감). 반증 근거는 함께 적는다.

## 5. 사용자 요청 템플릿 — 이렇게 주시면 왕복이 준다

```
[목표] 무엇을 / 왜 (화면이면 캡처)
[범위] 이 화면만 | 서버까지 | 엣지 경로까지
[검증] 전체 | 표준 | 빠르게(생략 사실 보고)
[모델] 기본 | "workflow로: 설계 opus high, 화면 sonnet medium, 검증 sonnet medium"
[릴리스] 함께 | 묶어서 나중에
```

- 작은 요청 여러 개는 **한 릴리스로 묶으면** 릴리스 대기(⑦)가 한 번만 든다.
- "한번 더"(감사 반복)는 회차마다 확정 건수를 보고 4절 중단 기준으로 판단한다.

## 6. 도입 순서 (제안)

1. 이 문서 채택 + 루트 CLAUDE.md 에 링크 1줄 — **이번 커밋**.
2. 루트 CLAUDE.md 이전(3절) — 사용자 승인 후 별도 작업. 예상 1~2시간 **(추정)**, 이전 전 '자동 검사 없음' 규칙 목록부터.
3. 릴리스 직후 경량 리뷰(4절)를 다음 기능 릴리스부터 적용.
4. `scripts/ui-smoke` (자동 스크린샷·넘침) — 반복 Chromium 시간을 줄이는 후보.

## 7. 이 문서의 한계 (정직 기록)

- 단계별 토큰·시간 수치는 대화 중 추정이었다 — 정확한 계측값은 이 환경에 노출되지 않는다.
- CLAUDE.md 토큰 환산은 글자 수 기반 추정이다. 프롬프트 캐시로 **비용**은 줄지만 **문맥 점유**는 그대로다.
- 3절 이전의 효과(요약 빈도 감소)는 이전 뒤 실제 세션으로 확인해야 한다.
