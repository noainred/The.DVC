# 작업 기록 — VMware Global Monitoring Portal (The.DVC)

> 이 문서는 이번 작업 세션에서 진행한 모든 작업을 **초보자도 이해할 수 있게** 정리한 기록입니다.
> "무엇을 · 왜 · 어떻게 고쳤는지"를 릴리스(버전) 순서대로 친절하게 설명합니다.
> 최종 버전: **v2.195.0** · 기준일: 2026-07-31
> 후속 기록: [WORKLOG-2026-08-01.md](WORKLOG-2026-08-01.md) (v2.196 ~ v2.204 — 권한 세분화·로그인 테마·계정 정책)

## 0. 이 문서를 읽는 법

- 각 작업은 **버전 번호(vX.Y.Z)** 로 묶여 있습니다. 하나의 요청 = 하나의 버전 = 하나의 PR(코드 묶음)입니다.
- **"왜"** 는 무엇이 불편했는지, **"무엇을"** 은 어떻게 바꿨는지를 뜻합니다.
- 모든 기능 작업은 아래의 **표준 절차**를 똑같이 거쳤습니다:
  1. 코드 수정 → 2. 검증(`npm run verify` = 단위테스트 + 웹빌드) → 3. 버전 올리기(3개 package.json) + 릴리스 노트 작성 →
  4. 커밋·푸시 → 5. PR 생성·병합 → 6. 릴리스 게시(GitHub Actions) → 7. `versions.json` 이 새 버전으로 바뀌는지 확인.
- 7번까지 끝나야 **운영 포탈이 원격으로 새 버전을 자동으로 받아** 업그레이드됩니다.

## 2. 릴리스별 상세 설명

### v2.182.0 — 서버 NIC "모델 0종" 수정 + vCenter NIC 별도 컬럼
- **왜**: 원격(엣지) 수집 서버 971대에서 NIC(랜카드) 모델이 전부 "0종/정보없음"으로 나왔습니다.
- **원인**: 엣지가 중앙으로 인벤토리를 압축해 보낼 때(`compactInv`) NIC 정보(`nics`)를 통째로 빼먹고 있었습니다.
- **무엇을**: 압축 인벤토리에 `nics`를 포함시켜 근본 해결. 더해서 vCenter가 직접 수집한 NIC(pnic + PCI 장치)를
  **별도 컬럼**으로 나란히 보여줘, iDRAC 수집값과 교차 확인할 수 있게 했습니다.

### v2.183.0 — 최근 검색어 표시
- **왜**: 자주 쓰는 검색어를 매번 다시 타이핑해야 했습니다.
- **무엇을**: 화면에 들어갈 수 있는 만큼 최근 검색어를 한 줄로 보여줘 클릭 한 번으로 재검색.

### v2.184.0 — Edge 배포 에이전트 현황 표 정렬
- **왜**: Edge 노드 배포 상태 표가 정렬되지 않아 원하는 항목을 찾기 어려웠습니다.
- **무엇을**: 열 머리글 클릭으로 정렬(오름/내림) 기능 추가.

### v2.185.0 — 수집 서버 토큰 강제 동기화
- **왜**: 중앙과 엣지의 인증 토큰이 어긋나면(403 불일치) 엣지가 데이터를 못 올립니다. 이걸 수동으로 맞추기 번거로웠습니다.
- **무엇을**: 화면에서 버튼 한 번으로 SSH를 통해 엣지의 토큰을 중앙 값으로 즉시 교정하는 기능 추가.

### v2.186.0 — 토큰 강제 동기화 버그 수정
- **왜**: 위 기능이 기본 포트가 아닌 별도 포트(예: :4001)로 뜬 인스턴스(AZ-IRS)에서는 엉뚱한(기본) 인스턴스만 고쳤습니다.
- **무엇을**: 리슨 중인 실제 포트로 프로세스를 역추적(`ss`→PID→systemd 유닛→EnvironmentFile)해 **정확한 인스턴스**를 교정하도록 수정.

### v2.187.0 — 헤더 vCenter 상태 OK 녹색 표시
- **왜**: 모든 vCenter가 정상이어도 눈에 띄는 표시가 없었습니다.
- **무엇을**: 전부 정상이면 헤더에 초록색 "OK"를 표시해 한눈에 안심할 수 있게.

### v2.188.0 — 호스트 상세 "VM N대 보기" 가독성 개선
- **왜**: 글자가 빽빽하고 대비가 약해 읽기 어려웠습니다.
- **무엇을**: 글자 크기·간격·색 대비를 조정해 가독성 개선.

### v2.189.0 — 라이선스 만료일 통합 확인
- **왜**: 제품마다 라이선스 만료일을 따로 확인해야 해 놓치기 쉬웠습니다.
- **무엇을**: vCenter의 모든 제품 키(ESXi/vSphere·vCenter·vSAN·VCF/VVF) + NSX Manager +
  **Horizon Connection Server**(REST 직접 수집, 10분 캐시)를 **한 화면**에 모았습니다.
  만료/90일 임박/정상/영구로 분류하고, 남은 기간(D-일수) 정렬·CSV 내보내기 제공.

### v2.190.0 / v2.191.0 — 보안 하드닝 1·2차
> 외부 보안 감사(2026-06-27, 확정 69건)에서 지적된 항목들을 두 번에 걸쳐 일괄 수정했습니다.
- **전역 TLS 검증 끄기 제거**: 자체서명 vCenter를 위해 프로세스 전체의 인증서 검증을 꺼두던 위험한 설정을 없애고,
  꼭 필요한 곳(vCenter/NSX/자체 업그레이드)만 **국소적으로** 허용.
- **역할(RBAC) 강제**: 상태를 바꾸는 모든 요청(POST/PUT/DELETE)에 관리자/운영자 권한 검사를 붙임(원격 콘솔 포함).
- **서버측 토큰 폐기**: 비밀번호·역할 변경이나 계정 삭제 시 이미 발급된 토큰을 **즉시 무효화**(tokenVersion).
- **엣지별 개별 토큰**: 하나의 공유 토큰으로 모든 자산 자격증명을 끌어오던 넓은 권한을,
  **엣지마다 다른 토큰**으로 좁혀 유출 시 피해를 최소화(무중단 이관 가능).
- **WAN TLS 기본 검증 ON**, **번들 sha256 필수**, **SSRF 방어 강화**(내부망 탐침·메타데이터 차단),
  **자격증명 파일 원자적 쓰기**, **AD 그룹→역할 완전일치**, **OTP 1회용 + 실패 잠금** 등.

### v2.192.0 — 이중 스크롤바 제거 + 인사이트 VM 링크

### v2.193.0 — 바로가기 카드 블링크 2배

- **무엇을**: 반짝임 지속시간을 1.5초 → 3초로 2배.

### v2.194.0 — iDRAC 스캔 로그 하위메뉴 + Platform 탭 복귀
- **왜**: 주기/수동 iDRAC 스캔이 "최근 결과 1건"만 남아 이전 실행 이력을 볼 수 없었습니다.
  또 vCenter 상세로 들어간 상태에서 상단 Platform을 눌러도 전체 목록으로 못 돌아갔습니다.
- **무엇을**:

    중앙직접/위임·스캔/발견/등록 대수·소요·오류)을 표로, **전체(통합)** 또는 **법인별**로 조회. 서버에 영속
    저장(최근 2,000건, 재시작에도 유지). 위임 스캔은 "요청"과 "결과 회신"을 각각 기록(요청 ID로 짝). 비밀번호는 미기록.
  - vCenter 상세에서 상단 **Platform** 재클릭 시 전체 vCenter 카드 목록으로 복귀.

### v2.195.0 — 보안 재감사 3차 (이번 세션의 마지막 릴리스)
> 전체 소스를 **4개 도메인**(인증/권한 · 주입/SSRF · TLS/업그레이드 무결성 · 프론트/동시성)으로 **병렬 재감사**했습니다.
> **결론: v2.190/191 하드닝은 회귀 없이 유지되고 있으며, 신규 CRITICAL/HIGH 취약점은 없었습니다.** 아래 실질 결함을 수정:

| 심각도 | 문제(왜) | 수정(무엇을) |
|---|---|---|
| MEDIUM | 자격증명 파일(`vcenters`/`nsx`/`collectors`/`users`.json)이 **손상되어 읽기 실패**하면 조용히 빈 목록으로 시작 → 다음 저장이 원본을 빈 값으로 덮어써 **전 자격증명 영구 유실** | 로드 실패 시 손상본을 `<파일>.corrupt.<시각>`으로 **보존**하고 경고(수동 복구 가능). 공용 헬퍼 `preserveCorrupt()` 신설 후 4개 파일에 적용 |
| MEDIUM-LOW | 중앙↔에이전트 공유 비밀(CENTRAL_TOKEN)을 담는 `portal.env`가 **비원자적 쓰기** → 크래시 시 토큰 유실 | 원자적 쓰기(`atomicWriteFileSync`)로 전환 |
| LOW | "설정 소유 계정" 경계가 **화면에서만** 걸려, 소유자가 아닌 관리자가 API를 직접 호출해 소유자 목록을 갈아치울 수 있었음 | 서버에서도 소유자만 변경하도록 `requireSettingsOwner` 미들웨어로 강제 |
| LOW | 중계 진단(relay-test)·Horizon 테스트가 **DNS 이름 우회** SSRF에 취약(169.254.169.254로 해석되는 이름) | 이미 async인 두 경로를 **DNS 해석까지 검사**하는 `ssrfBlockReasonResolved`로 교체 |
| LOW | 세션 보안 설정 파일 비원자적 쓰기 | 원자적 쓰기로 전환 |
| MEDIUM(잔여) | 브라우저 RDP 접속 시 **비밀번호가 WebSocket URL 쿼리스트링**에 실려 상위 프록시 로그·브라우저 히스토리에 잔존 가능 | **1회용 단기 티켓**(`rdpTicket.js`, 60초·인메모리) 도입 — 접속 직전 `POST /remote/rdp-ticket`으로 발급받아 쿼리엔 **티켓 ID만** 싣고 게이트웨이가 조회. 실패 시 구경로로 폴백(가용성 무회귀) |

- **감사 방식**: 도메인별 독립 감사 에이전트 4개를 동시에 돌려 각 발견을 실제 익스플로잇 경로로 검증 → 확정된 것만 수정.
- **검증**: 서버 단위테스트 **446건 통과**(`preserveCorrupt`·`rdpTicket` 신규 테스트 포함) + 웹 빌드 성공.
- **잔여 백로그**(다음에): 번들 Ed25519 서명 · TOFU 인증서 핀닝 · vCenter/iDRAC TLS 기본값 상향 ·
  설정 소유자 검사를 전 설정 라우트로 확대 · 웹 의존성 취약점 · 웹 E2E 테스트.

## 4. 작업 방식 (참고)

- **항상 표준 절차** 준수: 수정 → `npm run verify` → 버전업 → 커밋/푸시 → PR → 병합 → 릴리스 게시 → `versions.json` 확인.
- **squash 병합으로 인한 브랜치 분기**는 매번 `origin/main`에서 새 브랜치로 커밋을 cherry-pick하고,
  개발 브랜치에 `-X ours`로 재조정 후 트리 동일성(패리티 0)을 확인하는 방식으로 안전하게 해소.
- **릴리스 게시**가 누락되면 자동 업그레이드가 멈추므로, 매번 `versions.json`의 `latest`가 새 버전으로 바뀌는지 확인.
