## 동작 변화(사용자에게 보이는 것)

- 범위 관리자는 설정 소유자 목록에 있어도 소유자 등급 동작(공유 중앙 토큰·백업·비밀 정책·세션 보안·메일 설정)에서 403 이다.
- mock 데모 계정은 위 응답에서 operator 판본을 받고, svcmon 결과 로그 CSV 를 받지 못한다. 1MB 를 넘는 본문은 403 대신 413 이다.
- 엣지 위임(site)·점검중·비활성 vCenter 의 성능 창·사용률·스파크라인·라이트사이징은 중앙이 로그인하지 않는다 — 사유를 보여 주고 성능 창은 자동 갱신을 멈춘다
  (예전에는 중앙에서 site vCenter 로 직접 닿는 현장이면 열렸다).
- FC HBA 사용률: 데이터율의 110% 까지는 100%(보정 표지), 그 위는 '—' 이고 알림은 초과로 본다.
- IP 대장·ipam.db 에 FQDN ESXi 호스트의 관리 IP 행이 생긴다(외부 리더가 보는 내용이 바뀐다 — 스키마는 그대로).
- IP 관리상태 일괄 적용은 무효 토큰이 하나라도 있으면 전체를 거부한다(400).
- svcmon NTP 는 미동기·KoD 를 이상으로, LDAP 의 8·53 은 '정책 거부 — 서버는 응답 중'(정상)으로 본다.
- SAN 팬·PSU 장애 라벨은 개수만이다(엣지 판정이라 위임 장비는 엣지 업그레이드 필요 — 중앙 알림 제목은 옛 '정상' 을 뗀다).
- 같은 이름 클러스터는 화면에서 데이터센터를 붙인 이름으로 보이고, 토폴로지 노드 id 가 바뀐다(ref 로 묶인 경우).
- 코어 라이선스·비용·이전 준비도·호스트/VM 구성 점검이 읽지 못한 vCenter 를 '하한' 으로 밝히고 CSV 끝에 한 줄을 더한다.

### 회귀 검토가 바꾼 동작(사용자에게 보이는 것)

- VM 추이: `vm-track.db` 에 `skip_detail` 열(기동 때 자동 추가 · 옛 행 NULL = 예전 판정) · 범위 계정 추이의 새 슬롯은 범위 안 vCenter 의 실제 사유로 센다.
- FC HBA: 명목 기준(표준 데이터율 표에 없는 속도) 포트가 100% 를 넘으면 그 포트 사용률만 비고 서버 대표값·알림은 나머지 포트 기준(v2.743 동작으로 복귀) · 2^53 넘는 카운터가 다시 처리량을 낸다.
- 관리 화면 '연결 테스트'·'토큰 강제 동기화' 재검증은 엣지 export 503 을 다시 묻지 않는다 — ⚠ 엣지 앞 HAProxy 가 백엔드 재시작 중 내는 503 도 재시도하지 않는다(예전 여유 0.4+0.8초).
- 등록부 오류: 엣지 상태·중앙 보류 기록·자동 등록 거절 문구가 원문이 아니라 요약('JSON 형식 오류' + 위치). 비-admin 에게는 분류 문구만.
- IP 대장 `/tools/ipam`·시트의 호스트 행: `owner` 대신 `hasOwner`·`ownerId`·`ownerName`(키 집합 변경) · 호스트 상세는 클릭 때 조회(inv.hosts 없는 역할은 권한 안내).
- 낭비 엑셀 내보내기: 점검중·엣지 위임·비활성·인증 정지 vCenter 의 근거 리포트를 만들지 않는다(로그인 0) — 엣지 위임이 대부분인 현장은 리포트가 크게 준다.
- NTP: stratum 0 응답의 문구가 거부·미동기·'시각을 주지 않음' 셋으로 나뉜다. LDAP 8·53 을 Ok 로 본 것이 v2.743 판정의 반전이라는 사실을 문서에 적었다.
- install.sh: 하드 링크·16MiB(`VP_CFG_MAX_BYTES`) 초과 설정 파일은 경고 후 건너뛴다 · 설치 중 패키지 node 를 root 로 4~8회 실행한다.
- 등록부·설정 파일 손상 사유: 엣지 export 503(`detail`·`error` 요약 + `registryError{code,line,column,position,sysCode}` 추가) · 파트 장애 보류 사유 · 중앙 등록부·설정 손상 503 detail · `preserveCorrupt` 콘솔 줄 · 서비스 점검 '설정 파일' 표가 원문이 아니라 'JSON 형식 오류(N번째 줄 M번째 칸)' 같은 요약을 싣는다. V8 이 위치를 주지 않는 형식이면 'JSON 형식 오류' 만 남는다 — 원문은 보존본 파일을 열어 본다. 중앙 puller 는 2.743 엣지가 보낸 원문 detail 도 요약한다.
- IP 시트(`/tools/ipam/sheet`) VM 칸: `owner` 대신 `hasOwner:true`(목록 VM 행과 같은 모양) — 'VM 정보 보기' 는 창을 열 때 `/vms/lookup` 으로 조회한다(inv.vms 없는 역할은 버튼 없음).
- IP 스캔 /24 제안 응답 `totals.hostMgmtRejected`(관리 IP 를 판정이 거부한 호스트 수) 추가 · 호스트·VM 구성 점검의 '읽지 못한 vCenter' 배너는 비활성만 건너뛴 경우 뜨지 않는다.

### 최종 검토가 바꾼 동작(사용자에게 보이는 것)

- 서버 콘솔·`journalctl` 의 설정·등록부 파싱 실패 줄이 원문 대신 'JSON 형식 오류(N번째 줄 M번째 칸)' 같은 요약이다(원문은 보존본 파일을 연다).
- 베어메탈 사용률 상태(`/tools/bm-usage`·`/activity`·`POST /collect` 응답)의 등록부 오류는 관리자에게 위치 숫자, 그 밖의 역할에는 분류 문구만 보인다.
- 파트 장애 화면의 '등록부를 읽지 못함' 보류 사유: 비-admin 에게는 분류 문구 + `reasonDetailHidden:true`.
- install.sh·vmware-portal-verify: 설정 사본이 ACL·xattr 을 다시 지킨다(v2.743 의 `cp -a`·`sed -i` 와 같은 결과) · 패키지 node 가 비정상 종료해도 cp 폴백으로 계속한다 · portal.env 가 하드 링크·16MiB 초과·링크·FIFO 이면 RMA 요청 값과 서명 정책 값을 읽지 않고 알린다(넓히지 않는 쪽) · 설치 한 번에 프로세스가 10여 개 늘어난다(측정하지 않았다).
- 범위 계정의 원격 접속: 허용 vCenter 호스트의 관리 IP(IP 대장 호스트 행이 보여 주는 IP)로 probe·quick-connect 가 된다(예전 403). VM 원격 접속 버튼은
  범위 밖 대상을 회색 '범위 밖 대상(계정 권한)' 으로 보이고 '방화벽/포트' 를 안내하지 않는다.
- VM 추이: 다시 조회 중에는 버튼이 잠기고 '다시 조회 중…' 을 말한다 · 403 이면 권한 안내만 보인다.
- 라이선스 만료 표: 1280·1024px 에서 '상태' 열이 다시 보인다(400px 의 줄 높이 개선은 그대로).
- 호스트·VM 구성 점검 CSV 의 마지막 줄이 '판정하지 않음 · 그 vCenter 의 판정 결과는 이 목록에 없음' 으로 말한다('합계는 하한' 이 아니다).
- VM 추이 보존 정리: 결과 필드 `keepPages` 대신 `keepLookups`(묶음 기준 조회 횟수) — 남는 행은 같다.

### 최종 검토에서 고치지 않은 것

- **RD-R3(반증 — 조사만 고침)**: `fleetHoldOutcome` 이 `statusOnly:true` 응답의 `kept` 가 숫자가 아니면 '유지합니다' 로 판정한다 — 재현은 되지만 그 입력이 지금 제품에서
  나오지 않는다(중앙 2.744 는 언제나 숫자 `kept` 를 싣는다). 판정은 바꾸지 않았고, 수가 없을 때 '목록를' 이 되던 조사만 고쳤다(`a8990ec`, `audit2744rd` 단언 추가).
- **RV-4(판단 필요)**: 명목 기준 FC 포트가 표본 시각 오차로 100% 를 조금 넘으면(100.5%) 대표값·알림에서 빠지고 다른 포트의 낮은 값이 대표값이 된다 — v2.743 과 같은 결과이고
  설계(명목 기준은 실제 데이터율을 모른다)로 문서화돼 있다. 바꾸려면 '명목 기준 포화를 어떻게 볼지' 를 정해야 한다.
- FB 가 남긴 것: `POST /tools/bm-usage/collect` 가 비-admin 에게 `_last` 의 관리 주소를 가리지 않는다는 가설은 재현하지 못했다 · 엣지 export 오류 요약이 두 벌이다
  (`puller.exportFailError` ↔ `collectorsDc.edgeExportErrorText` — 문구 상수는 하나를 쓴다).
- FF 가 남긴 것: 큰 정리(30만 행 중 40%)의 최장 정지 90~135ms 는 두 판 모두 COMMIT(WAL 체크포인트로 추정 — 확인하지 않았다) · (ts, rowid) 커서는 같은 ts 행이 많으면 커서 앞을 다시 훑는다
  (같은 ts 20만 행에서 1회 41ms).
- FH 가 남긴 것: SELinux enforcing·Rocky 9 coreutils 8.32·실제 `setfacl` ACL·실제 root 로 install.sh 통째 실행은 확인하지 못했다(함수·구간만 꺼내 임시 폴더에서 돌렸다 · coreutils 9.4 · ext4) · `vp_cfg_create` 는 CONFIG_DIR 의 기본 ACL 을 상속하지 않는다(서비스 계정이 그 ACL 로 권한을 넓힐 수 있어 안전한 쪽이라 두었다).
- FE 의 880px 기준은 목 데이터로만 정했다 · FA 의 각주 화면은 목 데이터에 FC HBA 가 있는 베어메탈이 없어 Chromium 으로 보지 못했다(단위 테스트만).

## 정직 기록 — 확인하지 못한 것

- 실장비: Linux fc_host 의 -1 표지 실제 출현 빈도 · 실제 NTP 서버의 KoD 응답 · AD 의 resultCode 8·53 실제 응답 · Unity spinfo 의 긴 밑줄 줄 · 같은 이름 클러스터를 가진 실 vCenter.
