## 주요 확정 항목

- **INJPKG-01(high)** 오프라인 `install.sh` 가 CONFIG_DIR 의 파일(portal.env·settings-owners.txt·rma env·이전 설정·서명 키 설정)을 링크 확인 없이 root 로
  chown·chmod·쓰기 했다 — 서비스 계정이 그 자리에 심볼릭 링크를 심으면 다시 설치할 때 root 가 임의 파일을 서비스 계정 소유로 만든다(로컬 권한 상승).
  이제 `vp_cfg_*` 함수만 쓴다: lstat 으로 링크·일반 파일 아님·하드 링크를 건너뛰고(경고), 쓰기는 root 전용 임시 폴더에서 만든 뒤 rename 한다.
- **AUTHZ-01** v2.743 의 남은 형제: 라우트가 `role === 'admin'` 을 직접 봐서 mock 데모 계정이 중계 토폴로지의 haproxy.cfg 원문(stats auth 비밀번호)·SSH 계정·
  HAProxy 점검 주소·svcmon 엣지 출처·ping 엣지 주소 등을 받았다. 16파일을 `isAdminDetailUser` 로 바꿨고 소스 스윕이 남은 직접 비교를 허용 목록(사유)과 대조한다.
- **AUTHZ-02** 설정 소유자 목록에 든 **범위 관리자**가 공유 CENTRAL_TOKEN 평문을 읽고 백업(전 법인 자격증명)을 만들고·내려받고·복원했다 —
  `requireSettingsOwner` 가 이제 전체 범위 계정만 통과시킨다. 저장 응답과 세션 보안 화면이 범위 계정 소유자를 경고한다(`ownerWarnings`).
- **EDGE-01** v2.743 은 엣지 iDRAC 등록부 손상 때 export 만 막았다 — fleet push 는 빈 베어메탈 목록을 보내 중앙이 그 엣지 목록을 지웠고, 파트 장애 push 는 장비를 빼서
  '재배정·등록 삭제' 로 보류했다. 이제 fleet 은 상태 전용 보고(중앙 2.744.0 이상) + 중앙이 직전 목록 만료를 24시간 미루고, 파트 장애는 `registry-unreadable` 로 보류한다.
- **RECENT-01**(v2.743 회귀) VM 수량 추이가 비활성·캐시 없는 점검중 vCenter 를 매 슬롯 '빠짐' 으로 세 경영 보기 VM 추이가 영구히 비었다. 부분 합은 다시 읽힐 사유(pending·unreachable)만.
- **RECENT-02**(v2.743 회귀) FC 분모를 데이터율로 바꾼 뒤 포화 포트(100% 초과)가 null 이 되어 서버 대표값이 다른 포트의 낮은 값으로 떨어지고 HBA 알림이 울리지 않았다.
- **DEV-01** FC HBA 통계의 '-1 표지'(0xffffffffffffffff)를 실제 카운터로 읽어 약 491 PB/s 가 원시 표본과 5년 일 롤업 최대에 남았다.
- **DEV-02** SAN 팬·PSU 그룹 파트가 장애여도 라벨이 '팬 3/4 정상' 이라 파트 장애 화면·critical 알림 제목이 '정상' 이라고 말했다.
- **DEV-03** svcmon NTP 점검이 LI·stratum·mode 를 보지 않아 동기를 잃은 서버를 '정상 · 0ms' 로, KoD 응답을 '오프셋 −4조 ms' 로 보고했다.
- **VC-01** IP 원장이 FQDN 으로 등록된 ESXi 호스트의 관리 IP 를 쓰지 않아 그 IP 가 'Scanned / (네트워크 스캔)' 미지 장비로 보였다.
- **VC-02** 다른 데이터센터의 같은 이름 클러스터가 합쳐져 vSAN 분할(crit)·구성 드리프트·용량 합계가 거짓으로 나왔다.
- **VC-03** 코어 라이선스·비용 배분·이전 준비도가 첫 수집 중·불통 vCenter 를 0 으로 섞은 부분 합을 전체 합계로 보였다.
- **VC-04** 주문형 성능 조회가 인증 정지만 보고 '직접 수집 대상인가' 를 보지 않아 점검중·엣지 위임 vCenter 에도 로그인했다.
- **INJPKG-02** Unity `svc_diag -s spinfo` 제목 블록 정규식이 긴 밑줄 줄에서 재앙적 역추적 — 스토리지 폴러가 멈출 수 있었다.
- **WEB-01·02** VM 추이가 선택을 바꾼 뒤에도 이전 범위 수치를 새 이름으로 보였다 · IP 관리상태 일괄 적용이 잘못 친 IP 를 조용히 버리고 '성공' 으로 닫혔다.

## 동작 변화(사용자에게 보이는 것)

- 범위 관리자는 설정 소유자 목록에 있어도 소유자 등급 동작(공유 중앙 토큰·백업·비밀 정책·세션 보안·메일 설정)에서 403 이다.
- mock 데모 계정은 위 응답에서 operator 판본을 받고, svcmon 결과 로그 CSV 를 받지 못한다. 1MB 를 넘는 본문은 403 대신 413 이다.
- 엣지 위임(site)·점검중·비활성 vCenter 의 성능 창·사용률·스파크라인·라이트사이징은 중앙이 로그인하지 않는다 — 사유를 보여 주고 성능 창은 자동 갱신을 멈춘다
  (예전에는 중앙에서 site vCenter 로 직접 닿는 현장이면 열렸다).
- FC HBA 사용률: 데이터율의 110% 까지는 100%(보정 표지), 그 위는 '—' 이고 알림은 초과로 본다.
- IP 대장·ipam.db 에 FQDN ESXi 호스트의 관리 IP 행이 생긴다(외부 리더가 보는 내용이 바뀐다 — 스키마는 그대로).
- IP 관리상태 일괄 적용은 무효 토큰이 하나라도 있으면 전체를 거부한다(400).
- svcmon NTP 는 미동기·KoD 를 이상으로, LDAP 의 8·53 은 '정책 거부 — 서버는 응답 중'(정상)으로 본다.
- SAN 팬·PSU 장애 라벨은 개수만이다(엣지 판정이라 위임 장비는 엣지 업그레이드 필요 — 중앙 알림 제목은 옛 '정상' 을 뗀다).
- 같은 이름 클러스터는 화면에서 데이터센터를 붙인 이름으로 보이고, 토폴로지 노드 id 가 바뀐다(ref 로 묶인 경우).
- 코어 라이선스·비용·이전 준비도·호스트/VM 구성 점검이 읽지 못한 vCenter 를 '하한' 으로 밝히고 CSV 끝에 한 줄을 더한다.
