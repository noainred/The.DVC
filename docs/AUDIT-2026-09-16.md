# 보안 감사 2026-09-16 — 자격증명·비밀 추적 (v2.535)

사용자 요청: v2.534 릴리스 후 **보안 튜닝·개선·문서화**. 감사 도메인은 사용자가 고른
**자격증명·비밀 추적** 한 축이다(라우트 권한·SSRF·DB 위생은 이번 범위 밖 — 3절의 '보지 않은 것' 참조).

- **대상**: 마지막 보안 감사(v2.503, `docs/PERF-AUDIT-2026-09-13.md`) 이후 미감사 구간 —
  기준 커밋 `f969601` 이후 `server/src` 에 **신규 64파일 · 14,752줄 추가**. 그 코드가 손대는
  기존 경로(등록부·라우트·감사로그)와 웹의 비밀 취급도 함께 봤다.
- **방법**: 정적 코드 추적 2갈래(신규 파일 담당 / 기존 경로·기계적 위생 담당) + **모든 확정 주장은
  다시 열어 대조**했다. 런타임 검증(실제 HTTP·엣지 push 실행)은 하지 않았다.
- **결과**: **critical 0 · high 0 · medium 1 · low 3**. 전부 조치했다.

## 1. 확정 결함과 조치

### [medium] Horizon 세션 폴러에 '인증 실패 정지' 가 없다 — AD 계정 자가 잠금 경로

| | |
|---|---|
| 위치 | `horizon/sessionPoller.js`(수집 루프) · `horizon/sessionCollect.js:82` |
| 사실 | `collectServerSessions` 가 401/403 을 `kind:'auth'` 로 **정확히 분류하는데 아무도 소비하지 않았다.** 폴러는 화면 표시용 `errors` 에 담을 뿐 다음 주기에 같은 AD 계정으로 `POST /rest/login` 을 다시 보냈다. |
| 영향 | 주기 기본 5분·하한 60초(`horizon/sessionSettings.js`) → **서버 1대당 하루 288~1,440회 실패 로그인**, 서버 N대면 N배. |
| 시나리오 | admin 이 Horizon 등록 비밀번호를 한 글자 틀리게 저장하면 포탈이 스스로 그 **AD 서비스 계정을 잠근다**. 비밀번호 회전·만료로도 비의도적으로 발생한다. |
| 근거 | 같은 위험 때문에 스토리지에는 `storage/authGuard.js`(v2.528)가 있고 `storage/poller.js:118-123` 이 401/403 에서 주기 수집을 멈춘다. **Horizon 에만 그 대칭이 없었다.** 루트 CLAUDE.md Horizon 절은 "자동 재시도 금지(AD 계정 잠금)" 을 명시한다. |

★ **정직 구분**: 한 주기 안의 재시도는 없었다(서버당 1회). 즉 '자동 재시도 금지' 문구의 **문자적**
위반은 아니다. 문제는 **주기적 반복을 멈추는 장치가 스토리지에만 있었다는 비대칭**이다.
이 현장 AD 잠금 임계치는 확인하지 못했으므로 **영향 크기는 추정**이다.

**조치** — 저장/판정 코어를 `util/authGuard.js` 로 올리고(파일명만 주입하는 팩토리) 스토리지는
위임, Horizon 이 같은 것을 쓴다. 20줄을 복사했으면 다음 도구에서 또 빠진다(CLAUDE.md '코어는 하나다').
- **수동 실행은 막지 않는다**(`trigger !== 'manual'` 일 때만 건너뜀) — 비밀번호를 고쳤는지 확인할
  길을 없애면 안 된다.
- **조용히 멈추지 않는다** — `kind:'auth-stopped'` + `authStopped{since,attempts,reason}` 을 레코드에
  실어 화면이 말한다. 웹 `horizonSessionText.js` 에 tone(red)·조치 문구(자동 재개 방법) 추가.
  ⚠ **배지와 조치 문구만으로는 부족했다** — Chromium 스크린샷을 읽고 상세 모달이 '멈췄다' 만 말하고
  **언제부터·몇 회**를 말하지 않는 것을 발견했다(v2.528 규약이 요구하는 세 가지 중 둘이 빠져 있었다.
  수치·테스트로는 잡히지 않는 종류다). `authStopNote()` 를 더해 `3시간 전부터 정지 · 실패 7회 ·
  마지막 시도 5분 전 · 사유: …` 를 적는다. 횟수를 못 읽으면 **'0회' 라고 말하지 않는다**
  (`Number(null) === 0` — v2.525 규약).
- **자격증명이 바뀌면 자동 재개**(`credHash` 비교 — 평문 미포함).
- 실패 주기의 수치는 **null**(0 은 '사용자 0명' 이라는 거짓).
- ⚠ **작업 로그에는 기록하지 않는다** — 매 주기 건너뜀을 링버퍼에 넣으면 상한을 비이벤트로
  소진한다(`sanswitch/perfActivityLog.js` 의 REST 장비 규약과 같은 판단).
- 정지 파일은 도구마다 **따로**(`horizon-auth-stops.json` / `storage-auth-stops.json`) — 한 파일에
  섞으면 두 도구의 id 가 충돌해 엉뚱한 대상이 멈춘다.

## 2. 준수 확인 — 이미 방어가 있어 결함이 아닌 것

문서에 적는 이유: 다음 감사가 같은 곳을 다시 파지 않게 하고, **되돌리면 안 되는 것**을 남기기 위해.

- **응답 비밀 미포함**: `util/bulkRun.js publicRun`(run 은 비번을 들지만 응답은 line/name/host/
  status/reason/ms/hint 만, TTL 15분) · `sanswitch/testRuns.js sanitize` · `horizon/horizon.js` ·
  `storage/registry.js listDevices` · `sanswitch/registry.js` · `util/bulkImport.js`(report 는
  `hasPassword` 불리언만) · `util/bulkText.js`(경고는 **키 이름**만 되울림, 값 없음).

  대량 가져오기가 폐기 사실을 `skipped` 로 **사용자에게 알린다**. 신규 설정 스토어 4종은

  캐시형 4종은 **의도적으로** `preserveCorrupt` 미사용(v2.516 규약, 머리말에 사유 명시).

  `execAnswered` 의 `answers` 는 **횟수(숫자)** · 링버퍼 3종은 `util/activityLog.js` 고정 필드

## 3. 미확정·보지 않은 것 (정직 기록)

**의심으로 남긴 것**(결함이라 단정하지 않음 — 조치 안 함):
1. **`extra.credFp` 노출 등급** — `storage/poller.js` 가 계정명 + **비번 길이** + 16비트 해시를
   스냅샷에 싣고 그 응답은 `requirePerm('tools')`(operator 기본 보유)다. `server/CLAUDE.md` 의
   "지문만" 규칙에는 **부합**하지만 '길이' 는 추측 공간을 좁힌다. adminOnly 로 좁힐지는 별건 판단.
2. **Horizon `latest` 의 계정명이 보존기간 대상이 아니다** — prune 은 `hz_series` 만 돈다.
   수집을 끄면 마지막 관측 계정 목록이 무기한 남는다. CLAUDE.md 설계("계정명은 최신 1건에만")와
   **일치하므로 규칙 위반은 아니고** 개인정보 관점의 관찰이다(`curuser/db.js` 도 같은 구조).
3. **SSH 장비 등록부의 idKeys 가 `host` 만** — `sshPort`·`username` 변경은 보지 않는다
   (v2.503 S-1 은 idKeys 를 '최종 요청 대상을 만드는 모든 필드' 로 규정). **low** 로 판정했다:
   포트만 바꿔 빼내려면 그 장비 IP 에서 포트를 장악해야 하고 username 변경은 같은 호스트로만 간다.
   고치지 않고 기록만 남긴다(고치면 정상 편집이 비번 재입력을 요구하게 되는 트레이드오프가 있다).

**보지 않은 것**:
- **런타임 검증 없음** — 전부 정적 코드 추적이다(HTTP 요청·엣지 push 를 실행하지 않았다).
- 이 현장 **AD 잠금 임계치** 미확인 → medium 항목의 영향 크기는 추정이다.
- **git 이력**에 과거 비밀이 커밋됐는지는 조사 범위 밖(현재 트리만 확인).
- `pyportal/` 은 범위 밖. `web/` 은 비밀 취급만 봤다.
- 위임 엣지가 **실제로 받는 설정 본문**을 관찰하지 못했다(코드 기준 판정).
- 이번 도메인이 **자격증명·비밀 추적 하나**이므로 라우트 권한·scope·SSRF·주입·성능은 보지 않았다.
  신규 라우트의 RBAC 은 훑는 과정에서 '상태변경=admin, 조회=tools' 형태임을 확인했지만 **전수
  감사가 아니다** — 그 도메인이 필요하면 별건으로 돌릴 것.
