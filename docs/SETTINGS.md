# 설정 화면 안내 — 모든 탭·모든 설정 (v2.583)

포탈 상단 **설정** 메뉴의 43개 화면을 화면 순서대로 설명한다(목록의 진실의 원천은 `web/src/views/Settings.jsx` 의 `SUB`). 각 항목은
**무엇을 하는가 → 어디에 저장되는가 → 관련 환경변수 → 권한 → 주의사항** 순이다.

- 파일은 전부 `CONFIG_DIR`(설치본 기본 `/etc/vmware-portal`) 아래에 만들어진다 → [설정·데이터 파일 레퍼런스](CONFIG-FILES.md)
- 환경변수는 `portal.env` 에 `KEY=값` 으로 넣고 서비스를 재시작한다 → [환경변수 레퍼런스](ENV.md)
- 설정 화면 전체는 `settings` 권한이 필요하고(기본 admin 전용), 일부는 **설정 소유자**(`settings-owners.txt`)만 접근한다.
- 설정 메뉴 밖에 있지만 설정에 해당하는 화면(**DB 저장 경로 변경** 등)은 문서 끝 [부록 A](#부록-a-설정-메뉴-밖의-설정)에 있다.

> **역할 3종**: `admin`(전체) · `operator`(조회 + 도구 + 원격접속·콘솔) · `viewer`(조회 + 인사이트).
> 세부 권한은 아래 *메인포탈 사용자 관리* 에서 역할별로 켜고 끌 수 있다.

## 🖥️ vCenter 관리

### 1. DataCenter(법인) — `#/settings/datacenter-admin`
- **무엇**: 법인(DataCenter)을 만들고 vCenter·iDRAC 장비를 그 아래로 배정한다. 화면 곳곳의 '법인' 필터와 지도 배치가 이 정의를 따른다. 표시 순서도 여기서 정한다.
- **저장**: `datacenters.json`(정의·순서·vCenter → 법인 할당 `assign`), iDRAC 장비의 법인은 각 장비 레코드(`idrac.json` 의 `datacenterId`)에 기록
- **권한**: `settings`
- **주의**: 법인을 지우면 그 아래 장비의 배정이 풀려 '미배정'으로 표시된다(장비 자체는 남는다).
- **개요(Overview) 법인별 서버 표의 귀속(v2.583)**: vCenter 에 매이지 않은 **물리 전용 서버**(엣지가 스캔으로 등록한 베어메탈 등)는 이름·서비스태그로 ESXi 호스트와 맞출 수 없어, 예전에는 전부 '법인 미귀속' 으로 빠지고 법인별 '물리 전용' 열이 0 이었다. 이제 기존 귀속(등록부 vCenter · 호스트 이름 · 서비스태그)으로 못 찾은 서버만 ① 관리자 지정 귀속(`fleet-assign.json` — 특수 기능 › 통합 서버 인벤토리의 베어메탈 행 '법인(vCenter)') ② **이 화면의 법인 ↔ vCenter 할당에서 그 서버의 법인에 vCenter 가 정확히 하나**일 때 그 vCenter 행 순으로 귀속한다. 법인의 vCenter 가 둘 이상이거나 없으면 추측하지 않고 `<법인> · vCenter 미지정` 행에 따로 세며, 법인조차 모르는 서버만 표 아래 '법인 미귀속' 행에 남는다(합계 항등식은 그대로). 기존에 귀속되던 서버의 귀속은 바뀌지 않는다.

### 2. vCenter 등록·관리 — `#/settings/vcenter-admin`
- **무엇**: 수집 대상 vCenter 를 등록·수정·삭제한다. 주소·계정·타임아웃·수집 on/off·지리 좌표(지도 표시용)를 설정하고, 데이터 소스(`live`/`mock`)를 바꾼다.
- **저장**: `vcenters.json`(계정은 봉인 저장), 표시 순서는 `vcenter-order.json`
- **환경변수**: `DATA_SOURCE`(live|mock|auto) · `COLLECT_CONCURRENCY`(동시 수집 수, 기본 8) · `VCENTERS_EXAMPLE_FALLBACK`(예제 템플릿 폴백, 기본 꺼짐)
- **권한**: `settings`
- **주의**: `DATA_SOURCE=auto` 는 접속 실패 시 **가짜 데이터로 폴백**한다 — 운영에서는 `live` 를 쓸 것(v2.443/444 에서 중앙이 목업 유입을 차단하도록 보강). vCenter id 는 한 번 정하면 바꾸지 않는 것이 좋다(시계열 DB·추이가 id 기준).

### 3. vCenter 연결 테스트 — `#/settings/vcenter-test`
- **무엇**: 등록된 vCenter 로 TCP → TLS → API 로그인까지 단계별로 시도해 어디서 막히는지 보여준다. 중계(HAProxy) 경유 구성이면 평문/무응답/리셋을 구분해 원인과 조치를 제시한다(v2.439).
- **저장**: 없음(즉시 실행)
- **권한**: `settings`(관리자)
- **주의**: SSRF 가드가 사설/루프백 주소를 막는다. 진단은 읽기 전용이다.

### 4. NSX 관리 — `#/settings/nsx-admin`
- **무엇**: NSX Manager 를 등록해 논리 스위치·라우터·방화벽 정보를 수집한다. 연결 테스트와 중계 프록시 경유 설정을 지원한다.
- **저장**: `nsx.json`(주소·계정, 봉인 저장)
- **환경변수**: `NSX_TLS_REJECT_UNAUTHORIZED`(자세한 내용은 [ENV.md](ENV.md))
- **권한**: `settings`(조회는 `inv.nsx`)
- **주의**: NSX 는 vCenter 와 별도 자격증명이다. 중계 뒤에 있으면 프록시를 지정해야 하며, SSRF 가드가 사설 대역 직접 접근을 검사한다.

## 🗄 수집 서버

### 5. iDRAC 서버 등록 — `#/settings/idrac-admin`
- **무엇**: Dell iDRAC 장비를 등록해 전력·온도·하드웨어 인벤토리를 수집한다. 대역(IP 범위) 스캔으로 자동 발견하고, 법인별로 스캔을 위임할 수 있다.
- **저장**: `idrac.json`(장비·계정) · `idrac-scan-ranges.json`(대역) · `idrac-scan-settings.json` · `idrac-inventory.json`(하드웨어 캐시) · `idrac-power.db`(전력 시계열)
- **환경변수**: `IDRAC_POLL_CONCURRENCY`(동시 폴 상한, 기본 16) · `IDRAC_SCAN_INTERVAL_MS`(자동 스캔 주기, 기본 6시간·0 이하면 끔) · `IDRAC_SENSOR_SAMPLES` · `IDRAC_TIMEOUT_MS`(기본 15초)
- **보존**: `IDRAC_RETENTION_DAYS`(기본 90일 — 원본·롤업 공통 상한) · `IDRAC_RAW_RETENTION_DAYS`(**원본만** 따로 짧게. 기본 `0` = 끔. 켜면 과거 원본이 대량 삭제되므로 위 지표 수집 탭의 경고를 함께 볼 것)
- **용량 감축(v2.451)**: 전력값도 온도와 같은 **변화분만 저장**(dead-band)이 적용된다 — 직전 저장값과 **3W 미만** 차이면 원본 행을 남기지 않는다(`METRICS_DEADBAND_POWER_W`). 값이 그대로여도 **30분마다 1행**은 남겨 '수집 중단'과 구분하고, 시간당 롤업(`power_hourly`)은 생략분까지 전부 반영하므로 전력 대시보드·FinOps 집계(kWh·비용)는 그대로다.
- **권한**: `settings`
- **주의**: 전력 시계열은 90일 수렴 시 수억 행이 된다(운영 실측 `idrac-power.db` 26.9GB). 스캔은 대역이 넓을수록 오래 걸린다(위임 스캔 권장).

### 6. 스캔 로그 — `#/settings/idrac-scan-log`
- **무엇**: iDRAC 스캔의 실행 이력을 본다. 법인별 최근 결과에 **발견 / 등록 / 스캔 수량과 성공·실패·대기**가 표시된다(v2.441~442, 등록 수는 빨간색 강조).
- **저장**: `idrac-scan-log.json`
- **권한**: `settings`
- **주의**: 위임 스캔은 에이전트가 결과를 회신해야 수량이 채워진다 — '대기'는 실패가 아니다.

### 7. 지표 수집 — `#/settings/metrics`
- **무엇**: 샘플러 주기와 보존기간, VM 성능 추적 대상 vCenter를 정한다. vCenter별 DB 사용량을 보고 개별 삭제도 할 수 있다.
- **저장**: `metrics.json`(주기·보존) · `vmperf.json`(VM 성능 대상·보존) · `host-temp.db`(온도·GPU·DS·메모리 공용 시계열) · `vmperf/<vc>-<해시>.db`
- **환경변수**: `TEMP_SAMPLE_INTERVAL_MS`(샘플 주기, 기본 60초) · `TEMP_RETENTION_DAYS`(기본 1830일 ≈ 5년) · `VMPERF_*`
- **권한**: 조회는 로그인 사용자, **변경·삭제는 admin**

#### 보존기간이 두 개인 이유 (v2.451)

화면에 보존 입력이 **둘**이다. 저장 구조가 두 층이기 때문이다.

| 입력 | 대상 테이블 | 기본값 | 환경변수 | 무엇이 남나 |
|---|---|---|---|---|
| **원본 보존일** | `samples`(분 단위) | **0 = 끔** | `TEMP_RAW_RETENTION_DAYS` | 실제 측정 시각의 개별 값 |
| **보존일** | `samples_hourly`(시간당 롤업) | 1830일(≈5년) | `TEMP_RETENTION_DAYS` | 시간별 **평균·최소·최대** |

> ⚠️ **원본 보존일은 기본으로 꺼져 있다(v2.453).** v2.451 은 기본값을 90일로 켰다가 5년치가 쌓인
> 34.3GB DB 에서 **업그레이드 직후 수억 행이 삭제 대상**이 되어 포탈이 멈췄다(실제 운영 장애 —
> 서비스는 `running` 인데 accept 큐가 차서 웹이 타임아웃). 삭제 자체는 이제 청크로 나눠
> 이벤트 루프를 양보하지만, **과거 데이터를 대량으로 지우는 동작은 운영자가 직접 켜야 한다.**
> 켤 때는 서버 로그에 삭제 진행이 남고, 한 주기에 다 지우지 않고 여러 주기에 걸쳐 진행된다.

- 용량의 대부분은 원본이다. 원본만 짧게 두고 롤업을 길게 두면 **장기 추이는 그대로 보이면서** 파일 증가가 멈춘다.
- 60분 이상 버킷으로 조회하는 화면은 이미 롤업을 읽으므로, 원본을 줄여도 **화면이 달라지지 않는다**.
- `0`(기본)이면 '원본도 보존일을 따름' = v2.450 이전과 같은 동작이다. 켜려면 일수를 넣는다.

#### 변화분만 저장 (dead-band, v2.451)

온도는 보통 `27, 27, 27, 27…` 로 이어지는데 1분마다 전량 저장돼 `host-temp.db` 가 **34.3GB**(운영 실측)까지 자랐다. 그래서 **직전에 저장한 값과의 차이가 임계 미만이면 원본 행을 남기지 않는다**.

- **임계**: 온도 `METRICS_DEADBAND_TEMP_C`(기본 0.5℃) · 전력 `METRICS_DEADBAND_POWER_W`(기본 3W)
- **최대 간격**: `METRICS_DEADBAND_MAX_GAP_MS`(기본 30분) — 값이 그대로여도 이 간격마다 1행은 남긴다. 안 그러면 '수집이 멈춘 것'과 '값이 안 변한 것'을 구분할 수 없다.
- **롤업은 생략분까지 전부 갱신**한다 — 시간당 1행이라 용량 부담이 없고, 평균·최소·최대가 정확히 남아 생략된 미세 진동도 관측된다.
- **끄기**: 임계에 `0` 을 넣으면 그 계열은 전량 저장으로 되돌아간다.
- **대상은 온도·전력뿐**이다. 사용률·용량 계열(GPU 사용률·데이터스토어 사용량 등)은 대상이 아니다(값이 실제로 계속 움직여 생략이 왜곡을 만든다).
- **한계(정직하게)**: 생략된 구간의 **분 단위 원본은 복원되지 않는다** — 그 시간대의 평균·최소·최대만 남는다. 임계보다 작은 진동을 분 단위로 봐야 하는 분석이 필요하면 임계를 `0` 으로 두고 끌 것.

- **주의**: 대상에서 vCenter 를 빼면 그 DB 파일을 지워 용량을 즉시 회수한다(되돌릴 수 없다). v2.448 부터 파일명에 해시가 붙어 id 가 비슷한 vCenter 끼리 서로를 지우던 문제가 없다. **보존기간을 줄여도 `.db` 파일 크기는 즉시 줄지 않는다** — 이유와 대처는 [부록 A](#부록-a-설정-메뉴-밖의-설정) 참조.

### 8. 스토리지 수집 주기 — `#/settings/storage-intervals`
- **무엇**: 스토리지 장비 수집·push·설정 pull 주기를 **중앙에서 배포**한다. 엣지는 매 틱 이 값을 다시 읽어 즉시 반영한다.
- **저장**: `storage-intervals.json`
- **기본값**(`storage/intervals.js` `INTERVAL_SPEC`): 장비 수집 **1시간**(v2.531 에 10분 → 1시간) · 중앙 전송(push) 5분 · 중앙 설정 수신(pull) 5분 · 영역(쿼터/공유) 전수 수집 1시간. 상한은 24시간이다.
- **환경변수**: `STORAGE_POLL_MS` · `STORAGE_PUSH_MS` · `STORAGE_CONFIG_PULL_MS` · `STORAGE_AREAS_MS`(현장 값). 실효값은 중앙 배포값 > 현장 `portal.env` > 기본값 순이고, 엣지에서 `STORAGE_INTERVALS_LOCAL=1` 이면 중앙 배포를 무시한다. 어느 쪽 값인지 화면이 밝힌다.
- **권한**: `settings`
- **주의**: **중앙이 지정한 키만 내려간다** — 전 키를 채워 보내면 각 법인이 `portal.env` 로 잡아둔 현장 설정을 덮어쓴다. 하한(60초 / 영역수집 10분)은 서버가 강제하고, 빈 값·0 은 '미지정'으로 버린다.

### 9. 전원 꺼짐 점검 — `#/settings/power-off-check`
- **무엇**: 몇 시간마다 스냅샷의 **전원 꺼진 VM** 을 기록할지 정한다(기본 켜짐·6시간, 1~168시간). 이 기록이 특수 기능 › Optimization › 전원 꺼짐 표의 **'꺼진 지 N일'** 에 '점검' 출처로 쓰인다 — 처음 꺼진 것으로 보이면 그 시각을 현재 꺼짐 구간의 시작으로 남기고, 다시 켜지거나 삭제되면 지운다. '지금 점검' 으로 즉시 1회 실행하고 최근 결과(꺼진 VM 수·새 구간·해제)를 본다.
- **저장**: `power-off-check.json`(설정) · `vm-track.db` 의 `power_off_seen` 표(관측)
- **권한**: 조회 `tools` · 변경/수동 점검 `admin`
- **주의**: 실제 꺼진 시각은 직전 점검과 그 점검 사이이므로 **정밀도 = 점검 주기**(화면엔 `≥ N일 · 점검` 하한). vCenter 전원 이벤트(로그 보관, 정확)가 있으면 그쪽이 우선한다. vCenter 를 다시 조회하지 않고 스냅샷만 읽으므로 자주 돌려도 부하가 거의 없다. 저장 즉시 반영(재시작 불필요).

### 9-1. VM 실시간 스파이크 수집 — `#/settings/vmseries`
- **무엇**: ESXi 가 보관하는 **20초 실시간 표본**(약 60분 버퍼)을 주기(기본 50분)마다 받아, 임계(기본 CPU 50% · 메모리 active 50% · Ready 5%/vCPU · 벌룬/스왑 > 0) **이상인 순간의 모든 카운터 값**(CPU 사용률/MHz/Ready · 메모리 usage/active/consumed/벌룬/스왑 · 디스크·네트워크 처리량)을 남긴다. 임계 미만 순간은 저장하지 않는다 — 평균·p95 는 vCenter 롤업이 맡고(롤업은 평균을 보존), 이 수집은 롤업이 없애는 **20초 최대·스파이크 횟수·지속시간**을 남긴다. 결과는 특수 기능 › Optimization › 자원 축소 근거 리포트의 **`Local + vCenter`** 템플릿(기존 리포트는 `vCenter Only`)에서 본다.
- **범위**: `모든 vCenter`(전원 ON VM 전부 + 호스트 전부) 또는 `특정 vCenter 선택`. 선택한 vCenter 는 **전체** 또는 **범위 선택** — 클러스터·폴더·호스트·VM 을 복수 선택한다(클러스터/호스트 선택 = 그 위의 VM 포함, 폴더 = 하위 폴더 포함). 대상은 **매 주기 스냅샷에서 다시 해석**하므로 선택한 폴더에 VM 이 새로 생기면 자동 포함된다. 위임(엣지) vCenter 는 중앙 설정이 엣지로 내려가(10분 pull) 엣지가 수집해 중앙으로 push 한다(`/api/central/vmseries`, gzip + 700KB 청크).
- **저장**: `vmseries.json`(설정) · **`vmseries/<vCenter id>-<해시>.db`** — vCenter 마다 **독립 파일**(사용자 요구). 대상에서 빼면 파일째 삭제해 용량을 즉시 회수한다. 순간은 50분치를 BLOB 1행으로 패킹(`spikes`), 시간별 관측 표본 수(`cover`)를 따로 두어 화면이 **'스파이크 0' 과 '미측정' 을 구분**한다. 보존 기본 60일.
- **권한**: 조회 `tools`(범위 계정은 자기 vCenter 만) · 변경·지금 수집·데이터 삭제 `admin`. 도구 게이트 키는 `waste`.
- **주의**:
  - **기본 꺼짐(opt-in)** — 28 vCenter 전체에 실시간 QueryPerf 를 업그레이드만으로 시작하지 않는다. 켜기 전에 범위를 정하고, 첫 배포는 vCenter 1~2개로 실측 후 확대를 권한다.
  - **주기 50분은 겹침 10분** — ESXi 버퍼가 60분이라 한 주기를 놓치면 그 vCenter 의 40분 구간은 **복구되지 않는다**(화면 커버리지가 그 구멍을 '미측정' 으로 그린다). 30분 이하로 두면 1회 실패는 무손실. 하한 20분·상한 60분.
  - 각 표본은 **20초 평균**이라 그보다 짧은 스파이크는 희석된다(1초 100% 는 5% 로 보인다). '초단위' 는 vCenter 경로로는 불가능하다.
  - **권고 vCPU/메모리 산정은 vCenter 롤업 기준 그대로**다 — 20초 최대를 `최대 > p95 × 1.5` 규칙에 넣으면 거의 모든 VM 이 스파이크형이 되어 권고가 전반적으로 커진다. Local 값은 표시·경고용이며 반영 규칙은 데이터를 본 뒤 정한다.
  - 임계를 바꿔도 과거는 재계산되지 않는다(버린 표본은 없고, 그 시점부터 새 임계로 저장). DB 크기는 임계 이상 표본 수에 비례해 **워크로드마다 다르다** — 화면은 예측값 대신 실측 크기와 마지막 수집 결과를 보인다. 디스크 여유가 `VMSERIES_MIN_FREE_GB`(기본 5) 아래면 그 주기 저장을 건너뛰고 상태에 남긴다.
  - 데모(mock) 모드는 수집하지 않는다(없는 스파이크를 지어내지 않음). 리포트는 `데모(mock) 합성 데이터` 배지와 함께 합성값을 보인다.

### 15. 수집 서버(원격) — `#/settings/collectors`
- **무엇**: 원격 법인의 엣지 포탈을 '수집 서버'로 등록해 중앙이 데이터를 당겨온다. 연결 상태·수신 통계·이름 충돌·인증 거부를 배지로 보여주고, 배지를 누르면 원인·근거·해결 절차가 나온다(v2.437).
- **저장**: `collectors.json`(URL·토큰) · 수신 통계는 메모리
- **환경변수**: `COLLECTOR_TIMEOUT_MS` · `CENTRAL_REQUIRE_AGENT_TOKEN`
- **권한**: `settings`
- **주의**: 토큰이 어긋나면 엣지가 401/403 을 낸다 — **401 은 대개 엣지가 구버전**이라는 뜻이다(경로 없음). '진단'으로 엣지가 실제로 받는 값을 확인할 수 있다.
- **진단 창 구성(v2.571)**: 배지를 누르면 **문제 요약 → 요청 경로 → 해결 순서 → 증거 → 접힌 상세**(최근 거부 내역·원문 위치) 순으로 보인다. 요청 경로(요청 서버 IP → 결과 → 이 엣지)는 인증 거부 카드에만 있다. 바로가기 '⚙ 수집 서버 설정'(편집 창)과, 인증 거부 카드에는 '🔎 토큰 점검 열기'(특수 기능 › 포탈 점검 › 토큰 점검)가 있다.
- **'빈 인벤토리' 배지(v2.560)**: 누르면 원인·엣지 상태·로그·조치를 보여 주는 창이 열린다. 원인을 조치가 다른 것끼리 나눠 판정한다 — mock 데이터 / 엣지 상태 미확인(**판정하지 않는다**) / vCenter 등록 0개 / mock 이라 전송 제외 / vCenter 접속 실패 / push 실패 / 첫 수집 중(**기다리면 되는 유일한 경우**) / 그 vCenter 가 실제로 비어 있음 / 원인 미확정. 창을 여는 것만으로는 엣지로 요청이 나가지 않는다 — 엣지 상태·로그는 버튼을 눌러야 가져온다(특수 기능 › 엣지 로그와 같은 경로·같은 토큰이라 새 네트워크 허용이 필요 없다).

## 👤 User Control

### 19. 메인포탈 사용자 관리 — `#/settings/users`
- **무엇**: 계정 생성·역할 변경·비밀번호 재설정·2FA(TOTP) 관리, **역할별 기능 권한 매트릭스**, **데이터 범위(vCenter 제한)**, **특수 기능 도구별 접근**을 설정한다.
- **저장**: `users.json`(해시·TOTP 시크릿) · `permissions.json`(매트릭스·역할별 도구 거부·사용자별 도구 재정의 `users`)
- **권한**: `users.manage`
- **권한 키 18종**: `dashboard` · `inv.hosts` · `inv.vms` · `inv.datastores` · `inv.networks` · `inv.nsx` · `inv.alarms` · `tools` · `insights` · `svcmon` · `remote.access` · `vm.console` · `vm.reconfig` · `vm.provision` · `guest.deploy` · `settings` · `upgrade` · `users.manage`
- **역할별 '도구별 접근' 표(v2.573)**: 특수 기능 카탈로그 **전체**(현재 86개 — 진실의 원천 `web/src/views/specialToolsList.js`)가 행으로 나온다. v2.572 까지는 카드에 관리자 전용 표시(`adminOnly`)가 붙은 25개를 표에서 뺐는데, 그 표시는 **카드 표시 관례이고 접근제어가 아니다** — 조회 API 가 `tools` 권한만 요구하는 도구(예: 스토리지·PDU)는 operator 가 주소로 직접 열 수 있는데 표에 없으니 끌 방법이 없었다. 이제 그런 행에 '관리자 표시' 배지가 붙고, 체크를 끄면 그 역할은 주소로 직접 호출해도 막힌다. 업그레이드 뒤 새로 보이는 행이 operator·viewer 에 체크돼 있는 것은 **권한이 바뀐 것이 아니라 원래 그랬던 것이 보이게 된 것**이다.
- **사용자별 특수기능 접근(v2.555)**: 계정마다 '제한 없음(역할 기준)' / '고른 것만 허용'(**허용 목록** — 나머지는 카드·내비·⌘K 팔레트에서 **숨긴다**) / '고른 것만 추가 차단'(**거부 목록** — 역할 거부에 더해 막고, 기존처럼 회색 잠금) 중 하나를 고른다. 판정은 서버 `auth/permissions.js` `effectiveToolAccess` 하나가 소유하고, API 집행·로그인 응답·화면 숨김이 같은 값을 쓴다.
  - ⚠ 허용 목록은 **앞으로 추가되는 도구도 차단**한다(거부 기본값 — 거부 목록과 방향이 반대다).
  - ⚠ 허용 목록 + **빈 목록 = 특수기능 전면 차단**이다('제한 없음' 이 아니다). 거부 목록 + 빈 목록은 '제한 없음(역할 기준)' 과 같아 저장하지 않는다.
  - 허용 목록은 역할 거부와 합치지 않는다(관리자가 "이것만" 이라고 명시한 것이므로). 다만 상위 게이트인 `tools`(특수 기능) 기능 권한은 여전히 필요하고, 그 역할에 없으면 창이 경고한다. **admin 계정과 없는 계정에는 걸 수 없다**(400 + 사유).
  - 허용 목록에서 관리자 표시 도구를 고르면 카드는 보이지만 **서버 권한은 넓어지지 않는다** — 조회 API 가 admin 을 요구하는 도구는 열 때 403 이다(창이 미리 적는다).
- **주의**: **도구별 접근 거부는 v2.448 부터 서버가 집행한다** — 그 전에는 화면에서만 숨겨져 API 직접 호출이 통과했다. 단 서버가 막는 것은 `auth/toolAccess.js` 에 경로가 매핑된 도구뿐이고, 매핑되지 않은 도구는 화면에서만 숨는다(사용자별 창이 그 개수를 밝힌다). 데이터 범위를 건 계정은 전체 합계 조회가 막힌다(범위 밖 데이터가 섞이기 때문).

- **무엇**: Active Directory/LDAP 연동을 설정한다(도메인·서버·검색 필터·그룹↔역할 매핑). 연결 테스트를 제공한다.
- **저장**: `auth.json`
- **환경변수**: `AD_ENABLED` · `AD_URL` · `AD_DOMAIN` · `AD_ADMIN_GROUP` · `AD_OPERATOR_GROUP` · `AD_VIEWER_GROUP` · `AD_USER_FILTER` · `AD_TIMEOUT_MS`
- **권한**: admin
- **주의**: LDAP 필터 값은 RFC 4515 로 이스케이프된다(필터 인젝션 방지). v2.448 부터 이 파일도 원자적으로 쓰고 손상 시 원본을 보존한다 — 그 전에는 파일이 깨지면 조용히 AD 로그인이 꺼졌다.

## 🛡️ Security

### 22. 세션 보안 — `#/settings/session-security`
- **무엇**: 세션 만료 시간, 단일 세션 강제(ID 공유 금지), 로그인 실패 잠금, OTP 의무화를 설정한다.
- **저장**: `security-session.json` · `active-sessions.json`(현재 세션)
- **권한**: admin
- **주의**: OTP 의무화를 켜면 미등록 사용자는 등록 화면으로 강제 이동한다.

### 23. 자격증명 저장 방식 — `#/settings/secrets`
- **무엇**: 장비 비밀번호를 평문으로 둘지 **봉인(암호화)** 할지 정하고, 전환을 실행한다.
- **저장**: `secrets-policy.json` · 키는 `secrets-key`
- **권한**: admin(설정 소유자 권장)
- **주의**: **`secrets-key` 를 잃으면 봉인된 비밀은 복호할 수 없다** — 백업에 반드시 포함할 것. 비밀 값은 어떤 API 응답에도 실리지 않는다.

### 24. 연동 키(외부 포탈 조회 API) — `#/settings/api-keys`
- **무엇**: 다른 포탈이 이 포탈의 데이터를 읽는 **전용 API 키**를 발급·폐기한다. 키마다 허용 분류(인벤토리 지표 / 용량·사용량 추이 / 장애·알람 현황)·vCenter 범위·만료일·분당 상한을 정한다. 상대 포탈은 `X-Api-Key` 헤더로 `/api/v1/...` 을 호출하고, `GET /api/v1/` 로 그 키가 쓸 수 있는 목록을, `GET /api/v1/openapi.json` 으로 규격을 스스로 확인한다.
- **저장**: `api-keys.json`(**해시만** — 평문은 발급 응답에만 있다)
- **권한**: 조회 admin · 발급/수정/폐기/삭제 admin+**설정 소유자**
- **주의**: **조회 전용**이다 — 이 키로는 어떤 값도 바꿀 수 없다. 키 값은 **발급 직후 한 번만** 표시되고 서버는 해시만 보관하므로 잃으면 재발급해야 한다. 허용 분류는 **거부 기본값**이라 앞으로 추가되는 엔드포인트도 분류를 켜지 않으면 자동으로 차단된다(도구 권한의 거부목록과 방향이 반대다). vCenter 범위를 지정하면 **법인 축이 없는 자원**(스토리지 장비·증가량)은 403 이다 — 빈 목록을 주면 '장비 0대' 라는 거짓이 되므로 거절한다. `CENTRAL_TOKEN`·`COLLECTOR_TOKEN` 을 재사용하지 말 것(그 토큰은 수집 데이터와 설정 배포 권한까지 준다).

### 25. 이상동작 탐지 — `#/settings/anomaly`
- **무엇**: 사용량·이벤트의 이상 패턴 탐지 임계와 대상 vCenter 를 설정한다.
- **저장**: `anomaly` 관련 설정(`alerts.json` 과 연동)
- **권한**: admin

### 26. 호스트 접근 제어 — `#/settings/host-access`
- **무엇**: 이 서버(포탈 호스트)에 **누가 접근할 수 있는지**를 포탈에서 통제한다 — ① SSH 열림/허용목록(IP·CIDR)/완전 차단(+선택: sshd 서비스 중지) ② 웹(포탈 포트 + 선택한 80/443) 열림/허용목록 ③ OS 방화벽 추가 규칙(포트·프로토콜·accept/drop/reject·출발지). 엔진은 firewalld(기본 존 rich rule). 설계·한계·함께 쓰면 좋은 오픈소스는 [HOST-ACCESS.md](HOST-ACCESS.md).
- **저장**: `host-access.json`(초안·확정본·확정 대기) · 실제 규칙은 firewalld 영구 설정
- **권한**: 조회 admin · 초안/계획 admin+설정 소유자 · **적용/확정 admin+설정 소유자+본인 OTP**
- **주의**: 적용은 **런타임에만** 반영되고 확정 대기(1~30분, 기본 5분) 안에 '확정' 하지 않으면 자동으로 되돌린다(잠금 사고 방지). 웹 허용목록은 **요청자 IP 가 포함돼야** 적용되며 웹 '완전 차단' 은 없다(포탈 자체가 잠김). sshd 를 중지하면 남는 경로는 콘솔(iDRAC/IPMI)뿐이니 먼저 확보할 것. 서비스 계정 sudoers(`/etc/sudoers.d/vmware-portal-hostaccess`)는 install.sh 가 설치하며 **업그레이드로 올라온 서버는 root 가 화면이 안내하는 줄을 한 번 추가**해야 한다.

### 27. 보안 자가진단 — `#/settings/security-self-check`
- **무엇**: **지금 이 서버의** 보안 상태를 조회할 때마다 다시 읽어 항목별로 보여준다 — 로그인 정책과 사용자별 재정의 개수, 고권한 계정 OTP 등록 현황, 초기 admin 비밀번호 파일 잔존, 자격증명 파일 권한(0600), `portal.env` 권한, 자격증명 저장 방식(평문/암호화), 손상 보존 파일(`*.corrupt.*`), **보호를 끄는 환경변수**(AUTH_ENABLED·WAN_TLS_INSECURE·UPGRADE_ALLOW_UNVERIFIED·OTP_ROLE_ENFORCE·RMA_ALLOW_* 등), 세션 보안 설정.
- **왜**: 특수 기능의 '프로그램 보안·완성도 점검' 은 2026-08-08 외부 점검 결과를 **코드 상수로 굳혀 둔 과거 스냅샷**이다. 그 뒤 여러 지적이 실제로 수정됐는데도 화면에는 그대로 남아, 이미 해결된 항목을 현재 결함으로 읽게 만들었다(테스트 결과까지 "543 pass / 4 fail" 로 낡아 있었다). 이 화면은 반대로 매번 실제 값을 읽는다.
- **저장**: 없음(조회 전용 — 읽기만 하고 아무 것도 바꾸지 않는다)
- **권한**: admin
- **표시 원칙(정직)**: ① **점수를 만들지 않는다** — 상태별 개수와 항목만 보인다. ② 확인하지 못한 항목은 '확인 못 함' 이고 그 이유를 함께 보인다(없는 것을 정상으로 칠하지 않는다). ③ `risk` 는 '위험' 이 아니라 **'보호 꺼짐'** 으로 쓴다 — 운영상 필요해 켠 스위치일 수 있다. ④ 조치 방법이 있는 항목만 조치 문구를 보인다.
- **주의**: 이 화면은 **설정 값·파일 권한·환경변수만** 확인한다 — 코드 취약점 점검이나 침투테스트가 아니다. 파일 내용은 읽지 않고 `stat` 만 보며, 비밀 값과 계정명은 응답에 싣지 않는다(계정 열거 단서 금지).
- **새 완화 스위치를 만들면** `server/src/security/selfCheck.js` 의 완화 스위치 목록(RELAX_SWITCHES 상수)에 추가할 것 — 그러지 않으면 '켜 둔 줄 몰랐다' 가 반복된다(회귀 테스트가 최소 구성을 고정한다).

### 30. 메일 발송 — `#/settings/mail`
- **무엇**: 포탈의 **모든 기능이 함께 쓰는** SMTP 설정(v2.454). 알림·일일 리포트·폴더 사용량 리포트가 여기 설정을 따르며, **기능별로 켜고 끄거나 수신자를 따로 지정**할 수 있다. 기능마다 SMTP 를 따로 두면 같은 값을 여러 번 입력하게 되고, 한쪽만 고쳐 놓고 "왜 이 알림만 안 오지" 를 겪는다.
- **저장**: `mail.json`(SMTP 계정은 봉인 저장)
- **권한**: 조회는 `settings`, **저장과 메일 테스트는 설정 소유자** — 릴레이 계정이 유출되면 사내 메일 위조에 쓰이므로 백업·통합 계정과 같은 등급으로 본다.
- **동작**: 평문 연결이면 서버가 광고한 STARTTLS 로 **승격한 뒤** 인증 정보를 보낸다. 한글 제목은 RFC 2047, 본문은 UTF-8 base64.
  - ⚠ **v2.574 부터**: 'STARTTLS 사용'(기본 켜짐) 상태에서 계정이 설정돼 있는데 서버가 STARTTLS 를 **광고하지 않으면 발송을 중단**한다(계정·비밀번호를 평문으로 보내지 않는다 — 중간자가 EHLO 응답에서 그 한 줄만 지우는 STARTTLS 제거 공격 방지). 업그레이드 뒤 메일이 멈췄다면 서버에서 STARTTLS 를 켜거나 465(암시적 TLS)를 쓸 것.
  - 계정이 없는 사내 릴레이는 그대로 진행한다(새어 나갈 비밀이 없다). 관리자가 'STARTTLS 사용' 을 끈 경우도 진행하되, 메일 진단 추적에 **평문(base64) 전송 사실**을 적는다.
- **주의**:
  - 외부 라이브러리 없이 포탈이 **직접 SMTP 로** 보낸다. **OAuth2 · DKIM 서명 · 첨부파일은 지원하지 않는다**(사내 릴레이를 상대하는 범위).
  - **전역 스위치가 상위**다 — 이걸 끄면 기능별 토글과 무관하게 모든 메일이 멈춘다.
  - 시간당 발송 한도(기본 60건)가 있다. 알림 폭주(수십 대 동시 다운)로 릴레이가 포탈을 차단하는 것을 막기 위함이며, 한도를 넘긴 메일은 '건너뜀' 으로 이력에 남는다.
  - 알림을 메일로 받으려면 **설정 › 알림에서 '메일 사용'** 도 함께 켜야 한다(두 스위치가 모두 켜져야 나간다).
  - **특수 기능 › 메일 진단**(v2.455)에서 같은 설정을 고치면서 테스트 발송의 **SMTP 대화를 단계별로** 볼 수 있다(연결·STARTTLS·인증·수신자 중 어디서 막혔는지). 로그에 비밀번호는 나오지 않는다 — 서버가 인증 단계를 `<redacted>` 로 가려서 보낸다.

### 31. 특수 기능 카테고리 — `#/settings/tool-categories`
- **무엇**: 특수 기능이 **86개**(v2.583 기준 — 진실의 원천은 `web/src/views/specialToolsList.js`)라 한 화면에 다 깔면 찾기 어렵다. 서버/네트워크/스토리지/가상화처럼 **직접 만든 카테고리**로 묶어 섹션별로 보여준다(v2.455).
- **중복 소속이 정상이다** — 한 기능을 여러 카테고리에 넣을 수 있다. 예: '서버 온도'(키 `esxitemp`)는 *서버*이자 *가상화*, '폴더 사용량'은 *스토리지*이자 *리포트*.
- **저장**: `tool-categories.json`
- **권한**: 저장은 `settings`(admin). 조회는 로그인 사용자 — 특수 기능 화면이 자기 배치를 그리려면 읽어야 한다(도구 키와 이름뿐이며 접근 권한을 넓히지 않는다).
- **사용법**: '카테고리 보기 사용'을 켜고 → '추천 분류로 시작'을 누르거나 '+ 추가'로 직접 만든 뒤 → 오른쪽에서 기능을 체크한다. 각 기능 카드에 **현재 속한 카테고리**가 표시돼 중복을 한눈에 볼 수 있다.
- **주의**:
  - 기본은 **꺼짐**이다 — 업그레이드만으로 화면 배치가 바뀌지 않는다.
  - **어느 카테고리에도 없는 기능은 '기타'로 모인다**(사라지지 않는다). 새 기능이 추가됐을 때 분류하기 전까지 화면에서 없어지면 기능이 죽은 것처럼 보이기 때문이다.
  - 권한이 없어 안 보이는 기능은 섹션에서 빠지고, 그래서 비게 된 카테고리는 **제목까지 숨긴다**.
  - '추천 분류로 시작'은 불러오기만 한다 — **저장을 눌러야** 반영된다(기존 분류가 버튼 한 번에 날아가지 않게).
  - 메뉴 빠른 찾기로 **검색 중일 때는 섹션을 나누지 않는다**(중복 소속이라 같은 카드가 여러 번 나와 오히려 느리다).

### 32. 신규 포탈 보기 — `#/settings/v4-portal`
- **무엇**: UI 개편 시안(`Design/uiredesign/` 아트보드 8장)을 구현한 **신규 포탈(version_4)** 로 들어가는 입구. **V4** 버튼(또는 '새 창에서 열기')을 누르면 `#/v4` 로 전환된다. 라이트 테마 · 좌측 IA 트리 11그룹 · **9화면** — 전사 현황 `#/v4/overview` · 법인 비교 `compare` · 전력/비용 `power` · 컴퓨트 `compute` · 스토리지 `storage` · 네트워크 `network` · 물리·설비 `facility` · 알람 센터 `alarms` · 기능 찾기 `tools`. 기존 화면은 개발용으로 그대로 남고 '개발 포탈 ↗' 로 돌아온다.
  - v2.490 에 V3(6화면)로 시작해 **v2.508 에 V4 로 승격**했다. 옛 딥링크 `#/v3` · `#/v3/<화면>` 은 `#/v4/...` 로 자동 이동하고, 이 설정 탭의 옛 키 `v3-portal` 도 `v4-portal` 로 넘긴다 — 저장해 둔 북마크가 죽지 않는다.
- **보기 모드**: 상단에서 **경영 보기 ↔ 엔지니어 보기**를 전환한다. 바꾸는 것은 랜딩·내비 펼침·표 기본 행수(경영 10 / 엔지니어 50)·추이 기간(90일 / 7일)·원시 열(vCenter ID·서비스태그·moref) 노출·수집 상태 바 펼침뿐이다. **권한·데이터 범위·임계값(75/90%)은 두 모드가 같다.** 패널 구성이 달라 호출하는 API 집합은 다를 수 있지만 모드를 바꿔서 접근 권한이 생기거나 사라지지는 않는다. 우선순위는 `?view=exec|eng`(그 탭만, 저장 안 함) → `localStorage['vmportal.viewMode']` → 역할 기본값(admin·viewer → 경영, operator → 엔지니어).
- **기능 찾기**: `⌘K` / `Ctrl+K` 커맨드 팔레트. 이름뿐 아니라 **키**(`gpu`·`ipam`·`rma`) · **분류명** · **옛 이름**(`aka`, 예: 낭비 → Optimization)으로도 찾는다. 도구 화면 자체는 기존 개발 포탈 `#/tools/<키>` 에서 열린다 — 그 키는 `toolsDenied` 값이자 서버 집행 매핑이라 메뉴 이름이 바뀌어도 그대로다.
- **저장**: 보기 모드만 브라우저 `localStorage` 에 저장(서버 설정 값 없음). 코드는 `web/src/version_4/` 에 분리.
- **권한**: 진입은 로그인 사용자 누구나(설정 메뉴 노출 규칙을 따름). 화면 안의 각 API 는 기존 권한(`tools`·`insights`·admin 전용 `/admin/*` 등)을 그대로 적용하며, 권한 없는 API 는 **호출하지 않고**(403 을 만들지 않는다) 그 패널에 무엇이 필요한지 적는다. `tools` 권한이 없는 계정은 용량·회수·추이 패널이 잠긴다.
- **주의**: 실 API 만 읽는다. 수집 API 가 없는 항목(**계약 전력 대비 %** · 사이트 간 백본 회선 · 펌웨어 기준선 준수율 · SLA/가용률 · 자원의 금액 환산)은 **그리지 않고 왜 없는지 화면에 적는다**. 고아 VMDK 는 실행마다 vCenter SOAP 왕복이 있어 폴링하지 않고 **버튼으로 1회 스캔**하며, 결과는 '삭제 대상' 이 아니라 **'확인 필요 후보'** 다. 시안 글꼴(Pretendard·JetBrains Mono)은 외부 CDN 을 쓰지 않으므로 설치된 글꼴 → 시스템 글꼴 순으로 폴백한다.

### 35. 폴더 사용량 리포트 — `#/settings/dir-usage`
- **무엇**: 엣지 서버에 마운트된 공유 폴더의 **하위 폴더별 사용량**을 주기마다 수집해 **Top N**을 뽑고, 지정한 주소로 메일을 보낸다(v2.454). 집계 단위는 **하위 폴더 이름**이다 — `/mnt/share/hong` 이면 사용자 `hong`. 파일 소유자(uid) 기준이 아니다(전체 파일을 훑어야 해 NFS 에서 수십 분~시간이 걸린다).
- **실행 주체**: 그 법인의 **RMA 에이전트**가 현지에서 `du -x -b --max-depth=1` 을 돌리고 결과만 회신한다. 고지연 회선(폴란드·미국 동부)에 부담이 없다.
- **저장**: `dirusage.json`(대상·수신자) · `dirusage.db`(스캔 이력). **SMTP 는 여기 없다** — 위 *메일 발송* 이 소유하고 이 기능은 그것을 쓴다(수신자를 비우면 그 화면의 기능별/기본 수신자로 간다).
- **환경변수**: `DIRUSAGE_TICK_MS`(틱, 기본 60초) · `DIRUSAGE_JOB_TIMEOUT_MS`(엣지 회신 대기, 기본 15분) · `DIRUSAGE_DB_PATH`
- **권한**: `settings`(조회·저장·실행). 비밀 값이 없으므로 소유자 게이트는 *메일 발송* 화면이 담당한다.
- **주의**:
  - ⚠️ **엣지에서 경로를 먼저 허용해야 한다** — 대상 엣지의 `portal.env` 에 `RMA_FILE_ROOTS=/var/log,/mnt/share` 처럼 넣고 RMA 를 재시작한다. 이 목록 밖 경로는 엣지가 거부하며 **중앙 설정으로 열 수 없다**(현장 담당자 opt-in 이 설계).
  - `du` 는 대용량 공유에서 **수 분**이 걸린다. 주기는 시간 단위이며 최소 1시간이다.
  - 저장은 **Top N + 요약만** 한다. Top N 밖 폴더는 그 시점 '기타'에 합산될 뿐이라 나중에 커져도 **과거 값을 소급해 볼 수 없다**.
  - 직전 수집이 없으면 증감을 표시하지 않는다(0 으로 채우지 않는다).
  - 메일 테스트는 *메일 발송* 화면 한 곳에서 한다 — 기능마다 테스트 버튼이 따로 있으면 어느 SMTP 를 시험한 것인지 헷갈린다.

### 38. 서버 성능 측정 — `#/settings/perf-monitor`
- **무엇**: 요청 지연(라우트별 p50/p95/p99·최대·느린 건수), 이벤트 루프 정체 추이, 진행 중 요청, hang 기록을 본다. '지금 측정' 은 `setImmediate` 왕복으로 현재 루프 응답성을 즉시 잰다.
- **왜**: "'불러오는 중…' 이 3분 이상 지속될 때가 있다" 는 신고를 **근거로** 다루기 위한 화면이다. 느린 요청의 사유를 **기다림(외부 응답 — 고RTT vCenter 는 정상)** 과 **막힘(동기 CPU 가 이벤트 루프를 붙잡음 — 튜닝 대상)** 으로 구분해 보여준다. 브라우저가 보고한 '화면 로딩' 기록과 그 시각의 서버 사실(진행 중 요청·활성 작업·RSS)을 나란히 두어 원인을 귀속한다.
- **저장**: `perf-monitor.json`(임계·보관 설정) · `perf-hangs.ndjson`(hang 이벤트 — 재시작 후에도 조회)
- **진행상태 표시 임계(v2.501)**: 대기가 이 시간(기본 **3초**, 1~60초)을 넘으면 화면이 **무슨 작업을 기다리는지** 보여준다 — 화면 로딩 표시에는 작업 이름·건수·각 대기 시간이 줄로 붙고, 우하단 진행 표시가 버튼 동작(저장·연결 테스트·엑셀 생성·배포)의 대기도 같은 방식으로 보인다. 사용자 요구 "대기가 3초 이상이면 구체적으로 어떤 작업을 하는지 보여줄 것" 의 적용이며, 이 숫자는 화면에 하드코딩하지 않고 여기서 내려간다.
- **요청 ID — '누가 지연시키는가'(v2.583)**: 대기가 위 임계를 넘은 요청은 로딩 표시의 작업 줄 아래에 **실제 요청**(메서드 + 식별자를 가린 경로) · **요청 ID** · **서버 쪽 상태**가 붙는다. 서버 상태는 셋이다 — **서버가 처리 중**(지연 주체는 서버의 그 작업) / **서버는 이미 응답**(전송·브라우저 처리를 기다리는 중) / **서버에 기록 없음**(서버에 도달하지 않았거나, 서버가 재시작됐거나, 최근 완료 기록 2,000건에서 밀려났다 — 셋을 구분할 수 없어 단정하지 않는다).
  - 브라우저가 ID 를 만들어 `X-Request-Id` 헤더로 보내고, 서버는 형식(영숫자로 시작하는 4~40자 `[A-Za-z0-9._-]`)이 맞으면 그 값을 그대로 쓴다(아니면 서버가 만든다). 서버는 같은 ID 를 응답 헤더로 돌려주고, 이 화면의 **느린 요청·hang 기록**과 진단·로그의 요청 로그 줄 끝(`#<ID>`)에 함께 남긴다.
  - 이 화면의 **'요청 ID 찾기'** 에 로딩 화면에서 본 값을 넣으면 느린 요청·hang·진행 중 목록을 그 ID 로 거르고, **'서버 기록 조회'** 로 서버의 현재 상태를 묻는다(`GET /api/perf/req-status?ids=` — 한 번에 최대 20개). 이 조회는 **자기 요청만** 보이고 admin 은 전부 본다(ID 는 식별용이지 권한 근거가 아니다).
  - 로딩 화면의 상태 조회는 임계를 넘긴 요청(최대 5개)만 **5초에 한 번**이다. 구버전 서버(404)·권한 거부(403)면 그 세션 동안 조회를 멈춘다.
- **환경변수**: `LOOP_LAG_MONITOR`(0 이면 루프 계측 끔) · `LOOP_LAG_WARN_MS` · `LOOP_LAG_INTERVAL_MS` · `PERF_HANG_LOG_MAX_LINES` · `PERF_HANG_LOG_MAX_PER_MIN` · `PERF_CLIENT_COOLDOWN_MS`
- **권한**: admin
- **주의**: 계측은 요청당 Map 등록·카운터 증가만 하고(상시 O(1)) **임계 초과만** 기록한다. 임계를 낮추면 기록이 늘어 메모리·로그 파일이 커진다. 라우트별 통계는 프로세스 메모리라 재시작하면 초기화되고, hang 기록만 파일로 남는다. 백분위는 17버킷(1ms~60초 경계 16개 + 초과 1 — `perf/stats.js` `BUCKETS_MS`) 히스토그램의 **선형 보간 근사**이며 정확값이 아니다. 롱폴(RMA)·데이터스토어 탐색처럼 오래 걸리는 것이 정상인 라우트는 월타임 기준 '느린 요청' 에서 제외한다.

### 39. 로그 분석(개선점) — `#/settings/log-analysis`
- **무엇**(v2.583): 포탈 로그를 읽어 **개선점**을 뽑는다. 개선점은 네 종류다 — ① **규칙**(카탈로그에 맞은 문장 — 뜻·조치·관련 화면 링크가 있다) ② **HTTP**(요청 로그의 5xx · 413 · 429 · 401/403 · 5초 이상 느린 응답을 경로별로 — 경로마다 최대 지연 요청의 요청 ID 를 함께 보여 서버 성능 측정에서 그 요청을 찾게 한다) ③ **미분류**(규칙에 없는 경고·오류) ④ **노이즈**(한 문장이 로그의 큰 몫을 차지해 필요한 줄을 가리는 것). 탭은 개선점 · 태그별 · 반복 문장 · 규칙 목록이다.
- **왜**: 현장은 폐쇄망이라 서비스 저널을 밖으로 가져갈 수 없다(화면 덤프만 가능했다). 그래서 포탈이 자기 로그를 직접 읽고, 다른 서버의 로그는 붙여넣어 같은 엔진으로 분석한다.
- **규칙 카탈로그**: 직접 작성한 규칙(`server/src/loganalysis/rules.js`)과 **코드 전수 스캔으로 추출한 규칙**(`catalog.js` — 수집·엣지·인증·업그레이드 경로의 로그 문장 118개)을 함께 쓴다. 각 규칙은 그 문장을 찍는 소스 파일과 고정 조각을 갖고, 테스트가 ① 표본이 정규식에 맞는지 ② 표본이 **다른 규칙에 먼저 잡히지 않는지** ③ 소스에 그 문장이 아직 있는지를 매번 확인한다. 한 줄은 **처음 맞는 규칙 하나**에만 세므로 순서가 곧 분류다 — GPU 게스트 수집의 VM별 실패는 세부 원인(게스트 로그인·VMware Tools·전원·결과 파일 다운로드 등)을 일반 규칙보다 먼저 본다. 규칙 목록 탭의 '출처' 열이 직접 작성/코드 스캔과 '엣지 로그에서만 찍히는 문장' 을 구분한다.
- **원천 5가지**:

| 원천 | 무엇 | 구간·상한 |
|---|---|---|
| **누적(이 포탈)** — 기본 | 로그 줄이 들어오는 순간 시간 단위로 집계한 것. 재시작해도 이어진다 | 1·6·24·72·168시간(최대 7일) |
| **최근 로그(메모리)** | 메모리 링 버퍼 1,000줄. 요청 로그가 섞여 몇 분이면 밀려난다 | 그 시점의 1,000줄 |
| **서비스 저널** | 이 서버의 `journalctl -u <유닛>` 을 포탈이 직접 실행(셸을 거치지 않고 인자 고정) | 1·6·24·72시간 · 30만 줄 · 80MB · 90초(넘으면 멈추고 **잘렸다고 밝힌다**) |
| **붙여넣기** | 다른 서버(엣지 등)의 journalctl·tail 출력 | 8MB · 20만 줄(넘으면 앞쪽 줄을 버리고 그 개수를 밝힌다) |
| **엣지 로그** | 특수 기능 › 엣지 로그에서 **이미 가져온 보관분** | 보관분 그대로(없으면 먼저 가져오라고 안내) |

- **저장**: `log-analysis-stats.json`(누적 집계 — 시간 버킷 최대 168개, 바뀐 경우 10분마다 + 종료 시 저장). 재생성 가능한 통계라 손상되면 보존하지 않고 새로 시작하되 그 사실을 화면에 밝힌다. 저널·붙여넣기·엣지 분석 결과는 저장하지 않는다.
- **환경변수**: `LOGANALYSIS_LIVE`(`0` 이면 누적 집계를 켜지 않는다 — 화면이 그 사실을 말한다) · `PORTAL_SYSTEMD_UNIT`(저널을 읽을 유닛 이름, 기본 `vmware-portal`. 형식이 틀리면 기본값을 쓴다)
- **권한**: admin + **전체 범위 계정**(vCenter 제한 계정은 403) — 로그에 전 법인의 호스트명·IP·VM 이름·엣지 이름이 그대로 있다. 서비스 저널 읽기는 감사 로그에 남는다.
- **주의**:
  - ⚠️ 서비스 계정(설치본 `vmportal`)은 보통 **시스템 저널을 읽을 권한이 없다**. 그때 journalctl 은 경고와 함께 빈 출력을 주는데, 화면은 그것을 '로그 없음' 이라 말하지 않고 조치(서버에서 `usermod -aG systemd-journal <서비스 계정>` 후 서비스 재시작)를 적는다. '저널 파일 자체가 없음'·'journalctl 없음(systemd 가 아닌 환경)' 도 따로 구분한다. 그 전까지는 누적 또는 붙여넣기를 쓴다.
  - 저널·붙여넣기처럼 **수준(INFO/WARN/ERROR) 표시가 없는 원천**에서는 경고·오류를 **키워드로 추정**하고 그 사실을 밝힌다 — '경고 0' 이라 말하지 않고 '수준 정보 없음' 이다.
  - 모든 개수는 **분석한 구간 안에서**다 — 화면 상단의 범위(분석 줄 수·첫/끝 시각·잘림 여부)를 먼저 볼 것. 최근 로그(메모리)는 몇 분 분량이라 추세 판단에는 누적을 쓴다.
  - 표본 문장은 비밀처럼 보이는 값을 가리지만 **자유 문장이라 완전히 가릴 수는 없다** — 화면을 외부에 공유할 때 확인할 것.
  - 폴링하지 않는다(화면을 열 때 1회 + 버튼). 저널 읽기는 동시에 하나만 돈다(연타가 저널 스캔을 곱하지 않게).

## 부록 A. 설정 메뉴 밖의 설정

설정 메뉴에는 없지만 **동작을 바꾸는 화면**이다. 특수 기능(도구) 메뉴에 있다. 수집 on/off·주기·보존처럼 그 기능 안에서만 바꾸는 설정은 [A-3](#a-3-특수-기능-화면-안에-있는-설정)에 모았다.

### A-1. 포탈 DB — 용량 확인과 저장 경로 변경 (특수 기능 › 포탈 DB)

- **무엇**: `CONFIG_DIR`(과 옮긴 뒤에는 `dbDir`)에 있는 파일별 크기·용도·디스크 여유를 보고,
  **시계열 DB 저장 경로를 다른 볼륨으로 옮기는 스크립트를 생성**한다.
- **왜 필요한가**: 디스크를 쓰는 것은 거의 전부 `.db` 다. 운영 실측으로
  `host-temp.db` 34.3GB · `idrac-power.db` 26.9GB 였고 남은 여유가 6.3GB 였다.
- **저장**: `db-location.json`(경로 하나만 담는다) → 기동 시 `config.dbDir` 로 읽힌다.
  기동 로그에 `▸ db dir:` 로 실제 사용 경로가 찍힌다(v2.451).
- **권한**: admin (`settings`)

**옮겨지는 파일** — `insights/dbLocation.js` 의 `MIGRATABLE` 이 진실의 원천이며 현재 18종이다:
`host-temp.db` · `idrac-power.db` · `ping-monitor.db` · `capacity.db` · `vm-track.db` ·
`storage-history.db` · `sanswitch-perf.db` · `rma-history.db` · `rma-tests.db` · `dirusage.db` ·
`pdu.db` · `guest-disk.db` · `curuser.db` · `san-health.db` · `horizon-sessions.db` ·
`part-faults.db` · `bm-usage.db` · `link-check.db`
(+ 디렉터리 `vmperf/` · `vmseries/` — `MIGRATABLE_DIRS`).

**의도적으로 안 옮기는 파일**:
- `ipam.db` — 외부 프로그램이 경로를 고정으로 알고 직접 읽는 공유 원장이다.
- `vcenter-logs.db` — 로그 보관 설정에서 별도로 통제한다.

**절차** (스크립트는 화면이 만들어 주고, 실행은 서버에서 root 로 한다):
1. 새 경로를 입력하고 **사전 점검**을 누른다 — 쓰기 가능·여유 공간·systemd 하드닝 위반을 검사한다.
2. **서비스 계정**을 확인한다(기본 `vmportal`). 설치본에서 유닛 이름은 `vmware-portal`,
   실행 계정은 `vmportal` 로 **서로 다르다** — 계정을 잘못 넣으면 옮긴 파일을 서비스가 못 쓴다.
3. 생성된 스크립트를 서버에서 실행한다: 서비스 중지 → 복사 → 소유권 변경 → `db-location.json` 기록 → 재시작.
4. 재시작 후 이 화면에서 새 경로의 파일 크기가 보이는지 확인하고, 그 다음에 옛 경로의 파일을 지운다.

> ⚠️ **사전 점검이 막는 경로**: 서비스 유닛이 `ProtectSystem=full`(/usr·/boot·/etc 읽기전용)과
> `ProtectHome=true`(/home·/root 접근 차단)로 하드닝돼 있다. 이 경로들을 고르면 파일은 옮겨지지만
> **서비스가 기동하지 못한다** — 그래서 미리 거부한다(v2.451). `/data`·`/var/lib` 같은 별도 볼륨을 쓸 것.

### A-2. DB 파일이 작아지지 않는 이유와 대처

보존기간을 줄이거나 dead-band 를 켜도 **`.db` 파일 크기는 즉시 줄지 않는다.** 과장 없이 말하면:

- SQLite 의 `DELETE` 는 페이지를 **빈 공간으로 표시**할 뿐 파일을 잘라내지 않는다.
  그 공간은 이후 쓰기에 재사용되므로, 실제 효과는 **"더 커지지 않고 멈춘다"** 이지 "작아진다"가 아니다.
- 파일을 실제로 줄이려면 `VACUUM` 이 필요한데, `VACUUM` 은 **원본 크기만큼의 여유 공간**을
  임시로 사용한다. 34GB DB 를 줄이려면 34GB 이상이 비어 있어야 한다.
- 따라서 여유가 부족한 상태에서 순서는 **① 경로를 큰 볼륨으로 옮긴다(A-1) → ② 거기서 `VACUUM`** 이다.
  반대로 하면 공간이 모자라 VACUUM 이 실패한다.

### A-3. 특수 기능 화면 안에 있는 설정

설정 메뉴에 없지만 그 기능의 수집 여부·주기·보존을 바꾸는 설정이다. 수집 스위치는 전부 **기본 꺼짐(opt-in)** — 업그레이드만으로 장비·vCenter 에 새 세션이 열리지 않는다. 값은 서버가 하한·상한을 강제한다.

## 자주 묻는 것

**Q. 설정을 바꿨는데 반영이 안 된다**
대부분은 즉시 반영된다. `portal.env` 는 **서비스 재시작**이 필요하다. 스토리지·SAN 수집 주기는 중앙 배포값이 현장 설정보다 우선한다.

**Q. 어떤 파일을 백업해야 하나**
설정 › 포탈 백업이 전부 담는다. 수동이라면 최소한 `portal.env` · `auth-secret` · `secrets-key` · `users.json` · `vcenters.json` · `collectors.json`.

**Q. 계정을 잠갔는데 다시 들어가려면**
`portal.env` 에 `AUTH_ENABLED=false` 를 넣고 재시작하면 인증 없이 들어갈 수 있다(임시 조치). 이때 `AUTH_DISABLED_ROLE=viewer` 로 낮춰 두는 것이 안전하다. 복구 후 반드시 되돌릴 것.

**Q. DB 용량이 너무 크다**
거의 전부 시계열 `.db` 다. ① 특수 기능 › 포탈 DB 에서 어떤 파일이 큰지 확인하고 ② 설정 › 지표 수집에서
**원본 보존일**을 줄이고(롤업은 그대로 두면 장기 추이가 유지된다) ③ 필요하면 저장 경로를 큰 볼륨으로 옮긴다.
**보존기간을 줄여도 파일이 바로 작아지지는 않는다** — 이유는 [부록 A-2](#a-2-db-파일이-작아지지-않는-이유와-대처).

**Q. 온도 그래프에 점이 듬성듬성해졌다**
v2.451 부터 값이 거의 변하지 않으면 원본을 저장하지 않는다(변화분만 저장). 조회 시 마지막 값을 유지해
이어 그리므로 선은 끊기지 않는다. 분 단위 원본이 반드시 필요하면 `METRICS_DEADBAND_TEMP_C=0` 으로 끈다.

**Q. 권한을 줬는데 화면이 안 보인다**
기능 권한(매트릭스) · 데이터 범위(vCenter 제한) · 도구별 접근(역할의 거부 목록, 또는 그 계정의 사용자별 허용·거부 목록) 세 가지가 각각 작용한다. 사용자별 **허용 목록**에 없는 도구는 회색 잠금이 아니라 **아예 숨는다**. 화면에 "권한이 없습니다" 대신 필요한 권한과 요청 방법이 안내된다(403 은 오류가 아니라 정책대로 동작한 것이다).

**Q. '어제'·일 롤업의 날짜 경계나 내려받은 파일명의 날짜가 한국 날짜와 하루 어긋난다**
서버가 계산하는 하루 경계(스토리지 증가량·베어메탈 사용률·통신 점검의 일 롤업 등)와 서버가 만드는 파일명·날짜는 `PORTAL_TZ_OFFSET_MIN`(분, 기본 `540` = UTC+9)을 따른다(v2.582 — `server/src/util/dayKey.js`). 브라우저가 만드는 내려받기 파일명은 그 PC 의 시간대를 따른다. `0` 은 UTC 로 유효한 값이다. 예전 이름 `STORAGE_GROWTH_TZ_OFFSET_MIN`·`BMUSAGE_TZ_OFFSET_MIN`·`LINKCHECK_TZ_OFFSET_MIN` 도 호환으로 읽지만 새 이름이 우선하고, ±840분 밖의 값은 무시된다. 기동 시 한 번 읽으므로 바꾸면 재시작이 필요하다.

**Q. 브라우저 개발자 도구에 Content-Security-Policy 위반이 찍힌다**
v2.577 부터 CSP 가 **기본으로 켜져** 있다 — 세션 토큰이 브라우저 저장소에 있어 XSS 한 번이면 탈취되므로 완화 수단을 기본으로 둔다. `/intro` 소개 페이지만 완화된 정책을 쓴다. 정책을 바꾸려면 `portal.env` 에 `CSP=<정책 문자열>`, 끄려면 `CSP=off`(권장하지 않는다 — XSS 완화가 사라진다). 어느 쪽이든 재시작이 필요하다.
