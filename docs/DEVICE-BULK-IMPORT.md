## 1. 빠른 답 — 선택 항목을 비우는 방법

| 형식 | 비우는 방법 | 예 |
|---|---|---|
| **CSV** | 칸을 **비웁니다**(쉼표를 붙여 씁니다) | `…,ssh,22,443,,WA,…` |
| **CSV** | 또는 `-` 를 넣습니다 *(v2.516부터)* | `…,ssh,22,443,-,WA,…` |
| **CSV** | 또는 **그 열 자체를 넣지 않습니다** | 헤더에서 `vfId` 를 빼면 됩니다 |
| **자유텍스트(위치형)** | `-` 를 넣습니다 | `brocade SW-01 10.0.0.1 admin ssh 22 443 - WA …` |
| **자유텍스트(탭·`\|`·쉼표)** | 칸을 비워도 됩니다 *(v2.516부터)* | `brocade⇥SW-01⇥…⇥443⇥⇥WA⇥…` |
| **자유텍스트(키=값형)** | **아예 적지 않습니다** | `type=brocade name=SW-01 host=10.0.0.1 계정=admin` |

> ⚠ **v2.515 이하에서 겪는 문제**
> · CSV 에 `-` 를 넣으면 `Virtual Fabric ID 는 1~128 정수만 가능합니다` 오류가 났습니다.
> · 탭·`|`·쉼표로 나눈 자유텍스트에서 **중간 칸을 비우면 뒤 값이 한 칸씩 밀렸습니다**(경고도 없이).
>   엑셀에서 vfId 칸을 비운 채 복사하면 vfId 에 그 다음 값(법인 `WA`)이 들어가 같은 오류가 났습니다.
> 둘 다 v2.516 에서 고쳤습니다.

## 2. SAN 스위치 열

열 순서는 `server/src/sanswitch/bulk.js` 의 `COLUMNS` 가 진실의 원천입니다.

```
type, name, host, username, collectMethod, sshPort, httpsPort, vfId,
datacenter, agent, enabled, note, password
```

| 열 | 필수 | 값 | 비우면 |
|---|---|---|---|
| `type` | ✅ | `brocade` (구현된 타입만 — 카탈로그의 '예정' 타입은 거부) | 오류 |
| `name` | ✅ | 표시명 1~64자. `< > " '` 는 쓸 수 없음 | 오류 |
| `host` | ✅ | IP 또는 호스트명 **만**. `http://`·`:443`·선행 `-` 불가 | 오류 |
| `username` | ✅ | 접속 계정 | 오류 |
| `collectMethod` | | `ssh` 또는 `rest` | 그 타입의 기본값으로 보정 |
| `sshPort` | | 1~65535 | 기본 **22** |
| `httpsPort` | | 1~65535 (REST 수집일 때만 사용) | 기본 **443** |
| `vfId` | | **Virtual Fabric 1~128** | 없음(VF 미사용) — `0` 은 오류 |
| `datacenter` | | 법인 **이름 또는 ID**(둘 다 해석) | 미지정 |
| `agent` | | 엣지 이름 | **중앙이 직접 수집** |
| `enabled` | | `true`/`false` (`0`·`no`·`비활성` 도 false) | `true` |
| `note` | | 메모 200자 | 없음 |
| `password` | 신규는 ✅ | 접속 비밀번호 | **기존 비밀번호 유지**(수정 시) |

**스토리지는 `httpsPort`·`vfId` 가 없고** 나머지는 같습니다(`server/src/storage/csv.js` `CSV_COLUMNS`).

### 식별 키 — 같은 장비인지 판정하는 기준

| 도구 | 키 | 이유 |
|---|---|---|
| **SAN 스위치** | **`host` 단독** | `sanswitch/registry.js saveDevice` 가 **host 중복을 거부**합니다(type 무관). `host+type` 으로 판정하면 '드라이런 통과 → 저장 예외' 가 됩니다 |
| 스토리지 | `host` + `type` | 같은 host 에 다른 타입 장비를 등록하는 사례가 있습니다 |

키가 같으면 **수정(update)**, 없으면 **추가(add)** 입니다. 한 파일 안에 같은 키가 두 번 나오면
**뒤 행을 오류**로 봅니다(어느 행이 저장될지 모호한 채 덮어쓰지 않습니다).

## 3. 자유텍스트 세 가지 표기

한 파일에 섞어 써도 됩니다. `#` 로 시작하는 줄과 빈 줄은 무시합니다.

```text
# ① 위치형 — 열 순서대로. 구분자는 탭 · | · 쉼표 · 공백 중 아무거나. 빈칸은 `-`
brocade  WA-SAN-01  10.30.0.11  admin  ssh  22  -  -  WA  agent-WA  true  "팹 A"  ChangeMe!1

# ② 키=값형 — 아는 항목만. 순서 무관, 한글 키도 됨
type=brocade name=OC2-SAN-01 host=10.40.0.11 계정=admin 비밀번호=ChangeMe!3 법인=OC2

# ③ 헤더형 — 첫 줄에 열 이름을 적으면 그 순서로 읽음(엑셀에서 헤더까지 복사한 경우)
host  name  type  username
10.40.0.12  OC2-SAN-02  brocade  admin
```

**구분자 판정 순서**: 탭 → `|` → 쉼표 → 공백. 뒤집으면 엑셀 붙여넣기가 깨집니다.

**한글 별칭**(CSV 헤더·키 모두): `타입` `표시명`/`이름` `ip`/`fqdn` `계정` `비밀번호` `수집방식`
`포트` `법인`/`dc` `엣지`/`수집주체` `활성` `메모` `vfid`/`vf`

값에 공백이 있으면 `"따옴표"` 로 묶습니다. `:` 는 **아는 필드 이름일 때만** 키 경계로 봅니다 —
그래서 WWN(`50:06:01:…`)·시각(`12:30`)·`host:443` 이 값 안에 있어도 안전합니다.

## 4. 3단계 흐름

| 단계 | 하는 일 | 주의 |
|---|---|---|
| **① 형식 검증** | 저장하지 않고 행별 `추가`/`수정`/`오류` 판정 + **어디를 어떻게 고칠지** 조언 | 판정은 실제 저장과 **같은 함수**(`deviceInputIssue`)를 씁니다 — 통과했으면 저장도 됩니다 |
| **② 연결 테스트**(선택) | 저장 **전에** 행마다 실제 로그인 | 동시 4대·장비당 60초. **자동 재시도 없음**(잘못된 비번 반복 = 계정 잠금). 진행 중에는 ①③ 이 잠깁니다 |
| **③ 선택 등록** | 체크한 행만 저장 | 등록하지 않은 행은 **사유와 함께** 표시됩니다 |

### '테스트 불가' 는 '실패' 가 아닙니다

**엣지 위임 장비**(`agent` 를 지정한 장비)는 중앙에서 직접 닿을 수 없어 연결 테스트를
**시도하지 않습니다**. 실패로 보이면 멀쩡한 자격증명을 의심하게 되므로 따로 표시합니다.

- 화면 **기본 선택에서 빼지 않습니다** — 등록해야 엣지가 수집합니다.
- 다만 **'연결 성공한 행만 등록'** 을 켜면 서버가 `ok` 인 줄만 저장하므로 **'테스트 불가' 도
  함께 제외**됩니다. 화면이 그 사실을 문장으로 밝힙니다.

### 비밀번호

- **내보내기에는 비밀번호가 없습니다**(CSV·자유텍스트 모두). 내보낸 파일을 고쳐 다시 가져오면
  기존 비밀번호가 유지됩니다.
- 가져올 때 `password` 를 비우면 **기존 값 유지**, 값을 넣으면 교체입니다. 신규 등록은 필수입니다.
- ⚠ **host 를 바꾸면 기존 비밀번호를 이월하지 않습니다**(보안 규칙 — host 바꿔치기로 자격증명이
  다른 서버로 전송되는 것을 막습니다). host 를 바꾸는 행은 비밀번호를 다시 적으세요.

## 5. 자주 나오는 오류와 조치

| 오류 문구 | 원인 | 조치 |
|---|---|---|
| `Virtual Fabric ID 는 1~128 정수만 가능합니다` | `0`·범위 밖·숫자 아님, 또는 **열이 밀려** 다른 값이 vfId 에 들어감 | 1절의 '비우는 방법'. 탭 구분이면 칸 수를 확인 |
| `host 형식 오류 — IP/호스트명만` | `http://10.0.0.1/` 처럼 URL·포트를 넣음 | 주소만 남깁니다 |
| `host 차단: …` | 루프백·링크로컬 등 차단 대역 | 사내 대역(RFC1918) 주소를 씁니다 |
| `알 수 없는 타입 '…'` / `미구현 타입` | 오타 또는 카탈로그의 '예정' 타입 | 조언에 후보 목록이 나옵니다 |
| `파일 내 중복 — N행과 같은 host` | 같은 장비를 두 번 적음 | 둘 중 하나를 지우거나 host 를 고칩니다 |
| `필수 헤더 'name' 과 'host' 가 없습니다` | 헤더 줄이 없거나 구분자가 다름 | 샘플을 받아 헤더를 확인합니다 |
| `비밀번호가 없습니다 — 신규 등록이면 …` | ② 연결 테스트에서 저장 비번도 없는 신규 행 | `password` 열에 비밀번호를 적습니다 |

'고치면 좋을 값' 으로 따로 안내하는 것들(검증은 통과하지만 의심스러운 값):
전각 문자(`　`·`Ａ`), 워드·메일에서 복사한 스마트 인용부호(`‘ ’ “ ”`), `host` 끝의 `/`.

## 5-b. Horizon 연결 서버 열 (v2.525)

| 열 | 필수 | 설명 |
|---|---|---|
| `id` | ✅ | **동일 서버 판정 키**. 이 값이 같으면 수정, 없으면 추가 |
| `name` |  | 표시 이름(비우면 id) |
| `host` | ✅ | **`https://커넥션서버` 형식**(다른 두 도구와 달리 URL 이 정답입니다) |
| `username` | ✅ | AD 계정 |
| `domain` | ✅ | AD 도메인 |
| `timeoutMs` |  | 조회 시한(기본 15000) |
| `enabled` |  | `true`/`false`(기본 true) |
| `password` | 신규 ✅ | 비우면 기존 값 유지 |

⚠ **식별 키가 `id` 단독인 이유**: Horizon 등록은 `id` 로 갱신하고 **host 중복을 거부하지 않습니다**
(스토리지는 `host+type`, SAN 스위치는 `host`). 그래서 같은 host 를 가진 다른 id 는 정상 구성으로 보고,
같은 `id` 가 두 줄이면 **오류**로 막습니다(어느 쪽이 저장될지 모호합니다).

⚠ **접속처를 바꾼 행은 비밀번호를 다시 적어야 합니다.** `host`·`username`·`domain` 중 하나라도 바뀌면
보안 규칙에 따라 저장된 비밀번호를 승계하지 않습니다 — 비워 두면 `password는 필수입니다` 로 막히고,
저장은 됐지만 비밀이 폐기된 행은 등록 결과의 '등록하지 않은 행' 목록에 사유로 표시됩니다.

⚠ Horizon 은 **타입 열이 없습니다** — 검증 결과 표에 '타입' 열이 나타나지 않는 것이 정상입니다.
