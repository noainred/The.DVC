| 정적 스윕 | 재진입 가드 없는 `setInterval` 후보 · 상한 없는 모듈 수준 Map/Set |

훅 작성에서 실제로 겪은 것: ① `import { readFileSync } from 'node:fs'` 형태의 이름 바인딩은 `fs.readFileSync` 를
덮어도 패치되지 않는다 — `module.syncBuiltinESMExports()` 가 필요하다 ② IPAM 쓰기 워커도 `--import` 를 물려받아
**같은 파일에 덤프를 덮어썼다** — 스레드·PID 별 파일명이 필요하다 ③ 누적 '839회/분 readFileSync(body-parser)' 는
기동 시 CJS 모듈 로딩 839개가 같은 프레임(`TracingChannel.traceSync`)으로 묶인 것이었다 — 창 단위로 재면 0.

## C. 고치지 않은 것과 이유

- **SQL 실행 계획 73문**: 테이블 풀스캔은 `ip_records COUNT(*)`(진단) · `capacity_history/daily` 0바이트 행 정리(1회) · `power_samples` 최신값 JOIN 의 서브쿼리 스캔(v2.292 `withLatestCache` 가 이미 시드 1회로 막는 경로)뿐 — **폴링 경로 풀스캔 0**.
- **동기 fs 60초 창**: `idrac/registry.js` `existsSync`+`statSync` **16회/분**이 최대 — 파일 mtime 으로 캐시를 무효화하는 의도된 검사(µs 단위)라 고치지 않았다. 그 아래는 전부 ≤5회/분.
- **`setInterval` 무가드 후보 7곳**: `loopLag`·`idracScanJobs.reap`·`gpu/store gc`·`portalDb sample` 은 동기 콜백, `alerts.tick`·`backup.safeBackup`·`proxy/expiry` 는 자체 가드 또는 시간 단위 주기 — 결함 아님.
- **상한 없는 모듈 수준 Map/Set**: 정적 스윕 **0건**.
- 화면 각주 `엣지 장비는 config pull(≤5분) 후 … push(≤5분)` 의 숫자 하드코딩은 기존 문구다(CLAUDE.md '주기 숫자를 문구에 박지 말 것' 위반) — 이번 범위 밖으로 남긴다. 400px 에서 빈 목록 표의 안내 문장이 스크롤 래퍼 안에서 잘려 보이는 것도 기존(v2.575 `minWidth`) 동작이다.

## E. 정직 기록

- 힙·fd 영향은 재지 않았다 — 핸들 48개 상한이 실제로 여는 것은 vCenter 수만큼(33)이고, 그 이상은 이전과 같은 LRU 다.
- BUG-D 의 중앙 수신은 라우트 단위 테스트가 아니라 **모듈 단위**(storageEdge)로 고정했다. 실제 엣지(v2.581)가 올라간 뒤 첫 push 로 `edgeReports` 가 채워지는지 확인할 것.
- 훅 계측은 목 서버 기준이다 — 운영에서는 폴러 종류·주기가 달라 fs 빈도 상위 목록이 다를 수 있다. 다만 TUNE-D 는 파일 수(vCenter 수)에만 의존하므로 운영에서도 성립한다.
