### H-1. admin이 슈퍼관리자 OTP를 재바인딩해 계정 탈취 (권한 상승)
- **위치**: `server/src/routes/admin/users.js:66-73`, `server/src/auth/auth.js:525-540`(beginTotpEnroll)·`571-592`(confirmTotpEnroll)
- **설명**: `POST /api/admin/users/:username/totp/begin` 은 `adminOnly` 만 걸려 있고
  `beginTotpEnroll()` 이 **평문 secret + otpauthURL 을 응답으로 반환**한다(QR 발급용). 이어
  `.../totp/confirm` → `confirmTotpEnroll()` 이 그 pending 시크릿을 활성 시크릿으로 교체하는데,
  이 함수에는 superuser/설정소유자/타 admin 을 막는 가드가 없다. 대비로 `disableTotp()`
  (auth.js:605)는 `if (u.superuser && !force)` 로 슈퍼관리자를 명시 보호한다 — begin/confirm
  경로에만 보호가 빠진 비대칭.
- **실패 시나리오**: 일반 admin(A)이 `begin`으로 `noainred`의 새 시크릿을 획득 → 유효 TOTP 계산
  → `confirm` 으로 OTP를 A 통제 시크릿으로 교체(기존 폰 OTP 무효). `isOtpOnlyUser` 참이라
  passwordHash 도 삭제 → A가 새 OTP로 `noainred`(슈퍼관리자=자동 settingsOwner) 로그인 →
  탈취. `requireSettingsOwner` 경계(secrets 정책·세션보안·백업)까지 넘는 admin→owner 상승.
- **근거**: `confirmTotpEnroll` 내 `u.totpSecret = pending; u.totpEnabled = true;` 앞에 대상
  보호 가드 없음.

### H-2. finops·power-breakdown 물리서버 전력 scope 미적용 (전 함대 유출)
- **위치**: `server/src/routes/insights.js:38-71`, `insights/finops.js:76-92,119`, `insights/powerBreakdown.js:58-69,128`
- **설명**: 두 라우트는 `scopeSlice` 로 스냅샷(hosts/vcenters)만 좁히지만,
  `allMeasuredPower()`(idrac/service.js)는 hosts 인자와 무관하게 **전 등록 물리 서버 전력을 전량
  반환**한다. 범위 밖 vCenter 귀속 서버는 `resolveServerVcenter` 매핑 실패로 `'(미매핑)'` 강등되어
  **집계에 포함·노출**된다. 같은 파일 `/insights/fleet` 은 범위 계정을 403으로 막았는데 이 둘은 아님.
- **실패 시나리오**: vCenter A만 허용된 계정이 `GET /api/insights/power-breakdown` 호출 →
  B·C 사이트 iDRAC 서버 수백 대의 이름·서비스태그·모델·소비전력이 `servers[]`로 반환. `/finops`
  의 `totals`로 전사 전력·비용·CO2 총량도 노출. "vCenter 귀속 없는 데이터는 범위 계정 미노출"
  불변조건 위반.

### H-3. 그래프 API가 NSX 매니저 레지스트리를 scope 없이 노출
- **위치**: `server/src/insights/graph.js:60-66`, `server/src/routes/insights.js:236-244`
- **설명**: `buildGraph` 는 scoped 스냅샷을 받지만 NSX 노드는 `listNsxRegistry()`(전 등록 매니저)
  에서 직접 만든다. 필터는 `if (vcFilter && m.vcenterId !== vcFilter) continue` 인데 vcFilter는
  **사용자 scope가 아니라 쿼리 파라미터**다. 범위 계정이 vcenterId 없이 호출하면 전 NSX
  매니저(이름·host·버전·상태·region)가 노드로 추가된다(같은 계정이 `/api/nsx`에서는 차단되는 정보).
- **실패 시나리오**: vCenter A만 허용된 계정이 `GET /api/insights/graph` → 전 사이트 NSX 매니저
  이름/호스트/버전이 응답 nodes에 포함. v2.320 NSX scope 불변조건 우회.

### H-4. pcap 다운로드 전면 불능 — 미정의 `ts` (v2.190 회귀)
- **위치**: `server/src/net/tcpdump.js:162`
- **설명**: `runPcapCapture` 반환문이 `capture-${peer}-${ts}.pcap` 을 쓰는데 함수 내 `ts` 선언이
  없다. git 이력상 v2.190.0 보안 하드닝 커밋(`a4f3aa4`, 예측불가 파일명)이 `const ts = Date.now()`
  줄을 지우면서 참조만 남겼다. 반환 객체 조립 시 `ReferenceError: ts is not defined`.
- **실패 시나리오**: pcap 캡처 요청 → 원격 캡처·base64 회수·파일 삭제까지 성공 → 반환 조립에서
  ReferenceError → withSsh 프라미스 reject → 라우트 500. **v2.190 이후 pcap 다운로드는 한 번도
  성공한 적이 없다.**

### H-5. pyportal — 포트 오타 URL 1건이 헬스체크 전체를 정지 (로컬 재현됨)
- **위치**: `pyportal/hub/ssrf.py:99`(원인), `ssrf.py:26-51`(저장 시 미검증), `health.py:68·133`(전파)
- **설명**: `normalize_url` 이 스킴·호스트만 검사하고 **포트를 검사하지 않아** `https://host:99999/x`,
  `https://host:8o80/x` 가 저장된다. `resolve_and_check` 가 `socket.getaddrinfo(host, parts.port …)`
  에서 `parts.port` 를 try 없이 평가 → CPython은 범위 밖/비숫자 포트에서 `ValueError` 를 던진다
  (로컬 검증: `Port out of range 0-65535`, `Port could not be cast … '8o80'`). `check_one` →
  `check_many` 의 `future.result()` 로 재던져져 **그 주기 전체 결과 유실**. IP 리터럴 URL은
  `parts.port` 를 안 타서 무사 — 호스트명 URL만 해당.
- **실패 시나리오**: viewer가 오타 URL 등록 → 자동 점검이 매 주기 traceback만 찍고 **모든 링크**
  점검·이력·알림 중단(대시보드는 낡은 latest 표시 = 조용한 모니터링 정지). 수동 "지금 점검"은
  전체 400. 해당 바로가기를 지울 때까지 지속.

### H-6. svcmon — Linux trace 점검이 미도달을 ok로 오판
- **위치**: `server/src/svcmon/checker.js:233,240`
- **설명**: Linux 인자는 홉당 프로브 1개(`-q 1`)라 무응답 홉은 `" 5  *"`(별표 1개)인데, 도달 판정은
  `!/\*\s*\*\s*\*/.test(last)` 로 **별표 3개 연속**일 때만 미도달로 본다. 프로브 1개라 별표 3개는
  구조적으로 못 나온다 → 마지막 홉이 전부 무응답이어도 `reached=true`. Windows(tracert 3프로브)
  에서는 정상이라 개발에서 안 보이고 **운영(오프라인 패키지 = Rocky Linux 9)에서만** 오판.
- **실패 시나리오**: 도달 불가 호스트에 trace 점검 등록 → 전 홉 `*` → 정규식 불일치 → `ok('15 hops')`.
  죽은 경로가 초록(ok)으로 표시 — 이 저장소가 최악으로 규정한 '거짓 정상'.

### 주요 중간 항목 상세

**M-1. 엣지 로그 연합 결과 GET에 소유권/scope 없음** — `checksLogs.js:132`
POST `/tools/vclogs/federate` 는 `inUserScope(...)` 로 범위 밖을 404로 막지만, 결과 GET은
`reqId` 존재만 확인하고 `getLogQueryResult(reqId)` 를 그대로 반환한다. 소유권 검증용
`vcenterOfReq(reqId)` 가 존재하는데 이 UI GET 경로에선 미사용. `newReqId()` 는
`lq_<Date.now()>_<seq>` 로 **예측 가능**(TTL 2분). 범위 Y 계정이 전체 범위 사용자가 vCenter X에
발급받은 reqId를 폴링 → X의 로그 행 수신(수평 권한 우회).

**M-2. vc.id 콜론 오파싱** — `vmMetrics.js:61`
이 저장소는 `vc.id` 에 콜론 포함 사례를 문서화했고(`toolsCapacity.js:451` 은
`v.id.slice(vcenterId.length+1)` 안전 패턴 사용), vmMetrics/upgrade-tools는 여전히
`id.indexOf(':')` 첫 콜론 split. `vc.id="site:1"`, VM id=`"site:1:vm-123"` → `vcId="site"` →
`find(v=>v.id===vcId)` 실패 → 404. 콜론 포함 vCenter의 VM 메트릭/호스트 메트릭/콘솔이 전부
안 열린다. scope 검사는 `vm.vcenterId` 로 하므로 유출은 없고 기능이 깨진다.

**M-4. `/api/remote/rdp/:id` 권한·소유자·scope 없음** — `remote.js:257`
`authMiddleware` 만 통과하면 임의 매핑 id로 `.rdp`(proxyHost:publicPort 또는
targetHost:targetPort)를 받는다. `requirePerm('remote.access')` 없어 viewer도 호출 가능,
소유자 검사(v2.313)·targetHost scope(v2.320)도 없다. `.rdp` 가 가리키는 HAProxy publicPort는
게이트웨이를 안 타는 무인증 TCP 포워딩이라 좌표 자체가 실질 접속 정보. 무소유 매핑 id는
`GET /mappings` 로 노출됨.

**M-5. `/api/ping` 조회 scope 미적용** — `ping.js:52`
마운트가 `authMiddleware, requireEnrolled` 뿐이고 파일에 `scopedVcenterIds` 호출이 없다.
`seedVcenterTargets` 가 자동 등록한 전 vCenter 관리 host(FQDN/IP)·이름·RTT·가용성이 노출.
v2.322가 `/tools/ip-ping` 에 scope+`requirePerm('tools')` 를 걸었던 것과 상충.

**M-7. alerts.json 손상 리셋 → 웹훅 시크릿 유실** — `alerts.js:45`
Slack/Teams/webhook URL(시크릿, 0600 저장)을 담는데 로드 catch가 `preserveCorrupt` 없이
DEFAULTS로 떨어진다. 손상 직후 채널 전부 disabled로 알림 무음 중단, 이후 임계 하나만 저장해도
`channels: cur.channels`(=빈 URL)로 원자적 덮어써 손상 원본 영구 소거.

**M-10. 로그 연합 큐 claim→ack 미적용** — `logQueries.js:42`
`takeLogQueries` 가 인출 즉시 `pending.delete(vc)`(1단계). claim 기한·reap·재시도 상한 없음.
`getLogQueryResult` 는 결과 없으면 무조건 `{state:'pending'}`(unknown/error 없음). 엣지가 인출
직후 재시작하거나 결과 POST 실패(`logQueryWorker.js:42` `.catch(()=>{})`)하면 유실 → UI 영구
pending. CLAUDE.md의 claim→ack 불변조건 위반.

**M-15. 로그 폴러 커서 정체** — `logs/poller.js:63`
수집 커서는 `db.lastTs()`(저장된 행 MAX ts)로만 전진하는데 이벤트는 저장 전 `minSeverity` 로
필터된다. `minSeverity='error'` + 마지막 error 이후 info/warning이 maxPerPoll(5000) 초과 누적
→ 매 폴 같은 오래된 5000개(전부 폐기)만 재수집, lastTs 영원히 정체 → 벽 너머 error 영구 미수집
+ 매 폴 동일 구간 재전송(vCenter 부하 낭비).

**M-16. NSX region 'Unknown' scope 우회** — `nsx/scope.js:16`
scope.js 주석은 "빈 region 제외"라지만 **빈 문자열만** 막는다. NSX·vCenter 등록부 normalize가
region 미입력 시 `'Unknown'`(truthy)을 채운다. region 없는 vCenter가 허용 목록에 있고 무귀속
NSX 매니저(region='Unknown')가 있으면 `allowedRegions` 에 'Unknown' 진입 → 무귀속 매니저의
게이트웨이/세그먼트/DFW/보안그룹 + group-members(멤버 VM·IP)까지 노출.

**M-29. parseRange /0 오해석** — `ipam/settings.js:66`
`Number('')===0` 이라 `"10.0.0.0/"` 오타가 mask=0을 통과 → `{lo:0,hi:2^32-1}`. ignore 목록에
들어가면 모든 IP를 숨겨 `buildIpamRows` 가 빈 rows 반환 → `store.syncLedger` 가 **외부 프로그램이
읽는 ipam.db를 빈 원장으로 교체**. 형제 파서(scan.js, rangePolicies.js)는 `bits>=8` 로 거부.

**M-30. 스캔 결과 타입 미검증 영속 오염** — `scanStore.js:155`
`/api/central/ip-scan-result` 가 `h.ip` 만 `isIpv4` 검증, `openPorts`/`services` 타입 미검증
저장·영속. 소비처는 배열 전제: `ledger.js:333` `(r.openPorts||[]).join` — 문자열이면 throw →
`buildSubnetSheets` 전체 throw(시트/xlsx 500), `netmap.js:31` `.map` → 넷맵 500. 에이전트
토큰 보유 오작동 클라이언트가 `{openPorts:'x'}` 1건 보고 → 서브넷 시트·넷맵 무제한 500,
**프로세스 재시작으로도 복구 안 됨**(파일 수동 수정 필요).

**M-32. allMeasuredPower 신선도 검사 소스 누락** — `idrac/service.js:133`
v2.287에서 `POWER_STALE_MS`(2h) 필터를 iDRAC-직접 루프에만 넣음. OME 경로는 ts 검사 없고
`enabled:false` 돼도 인메모리 캐시 잔류, 원격 경로도 ts 미검사. OME 서버 1대(500대 관리) 장애 시
마지막 측정 수백 kW가 Overview·FinOps 총 소비전력에 재시작 전까지 계속 합산.

**M-38. 템플릿 apply만 capacity 사전 거부 없음** — `routes/svcmon/templates.js:136`
capacity.js 헤더는 "대량 등록·CSV·**템플릿 적용**이 커밋 전에 계산, reject는 400"이라 명시.
import/generate는 준수하지만 apply는 `applyTemplate()`(커밋) **이후** `judgeCapacity` 를 계산만
하고 거부 안 함. preview는 신규 예정분을 `addedTests` 에 안 넣어 '넘치는' 구성을 ok로 표시.

## 부록: 재확인된 회귀 방지(이상 없음)

감사 중 아래 불변조건은 유지되고 있음을 코드로 확인했다(오탐 방지 기록):

- **scope/RBAC 대부분 정상**: `applyFilters` scope 선강제, IPAM 쓰기 4중 게이트, `/nsx`·provision·
  host-power·ip-ping·waste 의 404 은닉/403 구분(위 유출 항목만 예외).
- **SQL 바인딩**: logs/metrics/vmtrack/ipam 전부 prepared statement, CSV는 수식 인젝션 가드.
- **JWT**: alg 헤더 미신뢰·HMAC 재계산·`timingSafeEqual`·`exp` 항상 검증. TOTP replay 방지
  (minCounter), 로그인 계정별 잠금.
- **폴러 재진입 가드**: store/idrac/metrics/logs/nsx/gpu/svcmon/ipam 폴러와 수동 실행 API 공유.
- **prune 스로틀 + ts 단독 인덱스**, **SQLite WAL PRAGMA**(ipam.db만 예외 유지), **전력 latest
  캐시 우회 쓰기 없음**, **power_hourly 증분 upsert**.
- **IPAM 워커**: ipam.db WAL 미전환, record.js 단일 컬럼 정의 공유, 워커 실패 인라인 폴백.
- **프론트 훅 규칙**(조기 return 위 선언) 전 파일 위반 0건, XSS(dangerouslySetInnerHTML) 0건.
- **pyportal**: 쿠키 GET/HEAD 한정, 임의 URL 점검 로그인 필수, IP별 잠금, 본문 선drain,
  리다이렉트 미추적, IP 핀, custom 삭제 불가+reassign.
