## 2. 개선 포인트 — v2.417.0 에서 전부 적용 ✅

아래 11건은 v2.417.0 에서 적용했다(요약: SSH 세션 취소 `withDeadline`/signal · 스토리지 장비당 타임아웃 ·
perfPoller 타임아웃+probe · SAN push gzip/청크 · 엣지 perf 부재 표시 · `exec()` 출력 상한 · `storage-data`
소유권 · RMA 이력 sqlite · `__none__` 센티널 · scopeLabel 문구 · StorageMonTool Cell 승격).
원문(적용 전 분석)은 기록으로 남긴다.

### (기록) v2.416 시점의 남은 개선 포인트와 근거

### 서버
1. **SSH 장비 타임아웃이 세션을 끊지 않는다** — `sanswitch/poller.js withTimeout` 은 `Promise.race` 뿐이라 120초 후에도
   `withSsh` 세션이 최대 ~8.5분 계속 돈다(명령 10개 × 45초 + 접속 60초). 그동안 풀이 다음 장비로 넘어가 `SANSW_CONCURRENCY`
   초과, 다음 주기가 같은 장비에 두 번째 세션. 권고: `withSsh` 에 AbortSignal/`conn.end()` 를 전달하는 취소 경로 추가
   (storage 폴러도 동일 구조). 크래시는 없음(race 가 rejection 흡수).
2. **perfPoller 장비당 타임아웃 부재**(주석과 불일치) — 상한 접속 60초 + 후보 6개 × captureMs(≤60초) = 최대 7분/장비,
   동시 2. 스위치가 많으면 한 주기가 수십 분. 권고: 1번과 같은 취소 경로 + `FOS_DIRS` 후보를 v2.413 capability probe
   결과로 대체(부재 장비에서 6×sampleSeconds 낭비 제거).
3. **엣지 SAN push 가 1MB 본문 한도 대비 무압축·무분할** — 문제 포트 64개 × ~625B ≈ 40KB/장비, 오래된 스위치는
   `link_fail>0` 이 흔해 상한을 채우기 쉬움 → 한 엣지 ~25대면 413, `resilientFetch` 는 413 을 재시도하지 않아 중앙
   데이터가 낡은 채 멈춤. 권고: 인벤토리 push 처럼 gzip + 장비 단위 분할(규모 의존).
4. **엣지 위임 스위치의 portperfshow 데이터가 중앙에 없다** — perf 설정·DB 는 노드 로컬이고 `push.js` 는 perf 샘플을
   올리지 않는다. 중앙 '법인 스토리지 사용량 통합' 이 엣지 법인을 고르면 `unavailable:false` 인 빈 시리즈("트래픽 없음"
   처럼 보임). 권고: 응답에 '이 법인 N대는 엣지 수집 — 데이터 없음' 표시(단기), perf 샘플 슬림 push(장기).
5. **`proxy/sshExec.js exec()` 는 stdout 누적 상한이 없다**(`execCapture` 만 2MB 캡) — 고장 장비가 25~45초 동안 출력을
   흘리면 메모리 증가. v2.409 이전부터 전 SSH 수집기 공통(영향 추정). 권고: exec 에도 상한 + 초과 시 채널 종료.
6. **`storage-data` 도 L-1 과 같은 소유권 필터 없음** — `sanswitch-data` 에만 적용했다. 권고: `saveEdgeStorage` 에도 위임
   장비 id 필터 + collectedAt clamp.
7. **`/tools/sanswitch/test` 의 60초 withTimeout 이 SSH 세션을 취소하지 않음**(admin 전용, 자원 문제) — 1번과 동일 조치로 해결.
8. **RMA 후속**: 결과 이력이 인메모리(재시작 시 소실, 300건) — 감사로그에는 실행 사실이 남지만 출력은 남지 않는다.
   필요하면 sqlite 이력(청크 export 규약)으로. 롱폴은 엣지당 20초 1회 요청이라 30 엣지 × 인스턴스 3 = 초당 4.5 요청(경미).

### 웹
9. **'(법인 미지정)' 범위가 '전체'로 둔갑** — `dcIdOfName('(법인 미지정)')` → `''` → `filter(Boolean)` 탈락 → 전체 조회.
   서버 쿼리(쉼표 목록)가 '' 를 표현하지 못한다. 권고: `__none__` 센티널을 서버 `storage-summary` 가 인식하게.
10. **DcStoragePerf 빈 상태 문구** — 창 안에서 범위를 바꿔도 초기 `dcPerf.label` 기준 문구. (이번에 `dcSet.size` 기준으로
    바꿨으나 라벨 자체는 초기값.) 권고: `scopeLabel` 사용.
11. `StorageMonTool.jsx:180` 도 W8 과 같은 인라인 컴포넌트 패턴(범위 밖, 동일 조치 권고).

## 3. 원격 명령 에이전트(RMA) 설계 요약 (v2.416 신규)

- 참고 요청 페이지(ks-soft.net HostMonitor RMA)는 이 실행 환경에서 외부 접속이 차단되어 **직접 읽지 못했다**.
  RMA 의 일반적으로 알려진 모델(감시 대상 망에 별도 서비스로 상주, active/passive 접속, 외부 명령 실행 허용 옵션,
  에이전트 비밀번호)에 근거해 **passive 모드**(엣지가 NAT 뒤라 아웃바운드만 가능)로 설계했다.
- 구성: `server/src/rma/{commands,jobs,settings,signing,agentSecrets,exec,agent,deploy,unitTemplate}.js`,
  `routes/api/rma.js`(admin), `routes/central.js /rma-poll·/rma-result`(개별 토큰 전용),
  `web/src/views/tools/RemoteCommand.jsx`, `packaging/offline/vmware-portal-rma@.service` + `install.sh`.
- 다중 인스턴스: 법인(agent 토큰) 아래 `instance`(RMA_INSTANCE, 템플릿 유닛 `%i`)가 여러 개. 분배 방식
  active-active / balance / active-backup(설정 › 원격 명령, 전역 기본 + 법인별). 오프라인 페일오버 공통.
- 불변조건은 `server/CLAUDE.md` 'RMA 불변조건' 절에 고정.
