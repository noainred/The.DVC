## 1. 설치와 업그레이드

- **설치**: [INSTALL.md](INSTALL.md) — 중앙/엣지/수집기 구성, 토큰·방화벽 포함 전 절차.
  오프라인(에어갭) 상세는 [packaging/offline/OFFLINE-INSTALL.md](../packaging/offline/OFFLINE-INSTALL.md).
- **업그레이드**: **설정 › ⬆ 업그레이드**(`#/settings/upgrade`) → [최신 버전 확인] → [적용]. 포탈이 번들을 받아
  sha256 검증 후 적용·자동 재시작합니다(롤백 지원). 상단 '업그레이드' 탭은 기본 숨김이며
  `SHOW_UPGRADE_TAB=true` 일 때만 보입니다. 엣지는 **엣지 푸시**로 일괄 배포.
  릴리스 절차(개발자용)는 [RELEASES.md](RELEASES.md).
- **서비스 허브**는 자동 업그레이드 대상이 아닙니다 — 포탈 업그레이드 후 코드 복사 3줄:
  ```bash
  sudo systemctl stop dc-service-hub
  sudo cp -a /opt/vmware-portal/app/pyportal/. /opt/dc-service-hub/
  sudo systemctl start dc-service-hub    # 확인: cat /opt/dc-service-hub/ver.txt
  ```

- 고RTT 사이트(폴란드·미동부 등)는 **엣지 모드**(`EDGE_MODE=all` + `CENTRAL_URL` + `EDGE_TOKEN`)로
  현지 수집 후 중앙에 push하는 구성을 권장합니다 — [INSTALL.md §3](INSTALL.md).

- **대량 등록 CSV (v2.338+)** — 수집 서버(엣지)·엣지 배포 대상·iDRAC 스캔 대역·베어메탈
  스토리지 서버·**IP 스캔 대역(IP관리 › 대역·스캔, v2.369)** 을 CSV 로 가져오기/내보내기.
  드라이런 검증 → 덮어쓰기 확인 → 커밋 순서라
  잘못된 파일이 기존 등록을 조용히 덮지 않습니다(샘플 다운로드 제공).
- **베어메탈 스토리지 (v2.340, admin 전용)** — 특수기능 카드에서 SSH(df) 로 물리 서버 로컬
  디스크 용량을 주기 수집. 중앙에서 닿지 않는 서버는 엣지 위임으로 점검합니다.
- **베어메탈 사용률 (v2.550~v2.554)** — 특수기능 › 베어메탈 사용률(`#/tools/bm-usage`)의 **수집 설정**에서
  **법인 단위로** 켭니다(기본 전부 꺼짐 — 한꺼번에 켜면 주기마다 SSH·Redfish 세션이 수백 개 열립니다).
  대상은 서버 분석의 Baremetal(미가상화 물리) 분류이고, 경로는 iDRAC 텔레메트리 + OS SSH(OS 계정은
  베어메탈 스토리지 등록을 재사용)입니다. iDRAC 텔레메트리는 Datacenter 라이선스 기능이라, Enterprise
  라이선스 서버용 **대체 경로**(Redfish 센서 + iDRAC SSH `racadm`)는 화면이 부하를 먼저 알리고
  **관리자가 동의해야** 켜집니다.

## 3. 사용자·권한·보안

- **계정/역할** — admin(전체) / operator / viewer. **admin·operator는 OTP 전용**:
  발급 직후 첫 로그인에서 강제 등록 → 비밀번호는 폐기됩니다.
- **기능 권한 매트릭스** — 설정 › 사용자 관리에서 기능 키 18종(v2.506 에 `svcmon` 추가)을 역할별 체크박스로.
  서버(`requirePerm`)가 실제 강제하므로 메뉴만 숨는 게 아닙니다.
- **특수기능 도구별 접근** — 86개 도구(카탈로그 전체 — v2.573 부터 관리자 표시 도구 25개 포함)를 역할별로
  차단(거부 목록). 사용자 단위로는 **허용 목록 모드**(고른 도구만 보이고 나머지는 숨김)와 거부 목록 모드를
  고를 수 있습니다(v2.555). 허용 목록은 **앞으로 추가되는 도구도 차단**하고, 허용 목록 + 빈 목록은
  '특수기능 전면 차단' 입니다. admin 은 재정의 대상이 아니며, 허용 목록을 줘도 상위 `tools` 기능 권한은
  여전히 필요합니다(서버 권한을 넓히지 않습니다).
- **데이터 범위(scope)** — 계정별로 볼 수 있는 vCenter/리전 지정(서버측 강제, 단건 조회 포함).
- **수정 가능 vCenter (v2.369)** — 데이터 범위 편집 창에서 계정별로 **변경 작업이 허용되는
  vCenter** 를 따로 지정. 비우면 조회 범위 전체에서 수정 가능(기존 동작), 지정하면 VM 생성/복제·
  Tools 업그레이드·게스트 계정 추가·VM 콘솔·IP 관리(수동지정/정책)가 그 vCenter 로 제한되고
  나머지는 조회 전용이 됩니다(조회 범위와의 교집합만 유효 — 서버측 강제).
- **외부 포탈 조회 API 연동 키 (v2.562)** — 설정 › Security › **연동 키(외부 포탈 조회 API)** 에서 발급.
  조회 전용(GET) `/api/v1` 허용 목록만 열리고, 키마다 분류(인벤토리 지표 · 용량·사용량 추이 · 장애·알람
  현황)와 vCenter 범위를 지정합니다. 키는 해시로만 보관되고 평문은 **발급 응답에 한 번만** 보입니다.
  발급·수정·폐기는 admin + 설정 소유자만. 연동 문서: [API-PUBLIC.md](API-PUBLIC.md).
- **CSP 기본 켜짐 (v2.577)** — 앱 전체에 Content-Security-Policy 가 걸립니다(`/intro` 데모 페이지만 완화).
  끄려면 `CSP=off`, 바꾸려면 `CSP=<정책문자열>`. 세션 토큰이 브라우저 저장소에 있으므로 끄는 것은 권장하지 않습니다.
- **특수 계정** — `noainred`(수퍼관리자, 강등/삭제 불가) · `thedvcdemp`(데모, viewer 고정).
- **OTP 전원 잠금 복구** — 콘솔에서 `otp-enroll.sh`(번들 래퍼) 실행. 문서의 경고대로
  **root 직접 실행 금지**(파일 소유권 사고). 긴급 해제는 `OTP_ROLE_ENFORCE=false`.
- **호스트 접근 제어 (v2.485)** — 설정 › Security › 호스트 접근 제어. 이 서버의 **SSH**(열림/허용목록/완전 차단,
  선택 시 sshd 중지)·**웹**(포탈 포트·80/443 허용목록)·**OS 방화벽 추가 규칙**을 firewalld 로 적용합니다.
  절차: ① 계획 보기(실행 없음) → ② 적용(런타임, 본인 OTP) → ③ 새 창에서 SSH/포탈 접속 확인 → ④ 확정(OTP).
  확정하지 않으면 N분(기본 5분) 뒤 자동으로 되돌립니다. 웹 허용목록에는 **내 IP(관리자 본인)** 와 **이 호스트의
  4000 으로 들어오는 엣지·수집 에이전트 대역**을 반드시 넣으세요. SSH 완전 차단 전에 콘솔(iDRAC/IPMI) 경로 확보.
  업그레이드로 올라온 서버는 화면이 안내하는 sudoers 줄을 root 가 한 번 추가해야 합니다. 상세·오픈소스 권고:
  [HOST-ACCESS.md](HOST-ACCESS.md).
- 보안 감사 이력·불변조건: [SECURITY-AUDIT.md](../SECURITY-AUDIT.md), [AUDIT-2026-06-27.md](AUDIT-2026-06-27.md).

## 4. 알림 · 일일 리포트

- **채널**: Slack / **Microsoft Teams** / 일반 웹훅 — 설정 › 알림 또는 특수기능 › 알림 채널·이력에서
  URL 등록(+테스트 발송). 저장 시 SSRF 검증을 통과해야 하며, 같은 알림은 쿨다운·**전역 중복 억제
  창**으로 스팸이 되지 않습니다.
- **메일 (v2.454)**: 포탈이 SMTP 로 직접 보냅니다. URL 이 아니라 **설정 › 메일 발송**의 공용 SMTP 설정·수신자를
  쓰므로 ① 설정 › 메일 발송에서 **메일 발송 사용**과 **'알림' 종류**를 켜고 ② 설정 › 알림에서 **메일 사용**을
  켜야 실제로 나갑니다(둘 중 하나만 켜면 발송되지 않습니다). 일일 리포트·폴더 사용량 리포트도 같은 설정을 씁니다.
- **규칙**: 위험 알람·vCenter 다운·호스트 끊김·데이터스토어 임계·RAM 오버커밋·**VM 동시 다운**
  (vCenter별 임계 지정 가능).
- **일일 헬스체크 자동 발송**: 특수기능 › 일일 헬스체크 리포트 상단에서 시각 지정 + [지금 발송(테스트)].

## 5. 백업·로그

- **포탈 백업** — 설정 › 포탈 백업: 중앙+엣지 설정 통합 gzip(정기/변경 자동, 복원).
  ⚠️ 백업엔 자격증명이 담기므로 **다운로드/복원은 설정 소유자만** 가능합니다.
- **vCenter 로그 장기보관** — 이벤트 증분 수집(보관기간·용량 설정), 중앙 연합 조회.
- **감사 로그** — 모든 쓰기 작업 기록. 서버 데이터는 `/etc/vmware-portal` 백업 하나로 보존됩니다.
- **하루 경계·파일명 날짜 (v2.582)** — 일 롤업(스토리지 증가량·베어메탈 사용률·통신 점검), 서버가 만드는
  내려받기 파일명의 날짜, 일일 리포트 발송 시각은 `PORTAL_TZ_OFFSET_MIN`(분, 기본 540 = UTC+9, `0` = UTC)을
  따릅니다. 서버 OS 의 시간대와 무관합니다.

### 7.1 로그로 원인 찾기(폐쇄망)

로그를 서버 밖으로 가져갈 수 없는 현장을 위해, 포탈이 **자기 로그를 직접 읽어** 개선점을 정리합니다(v2.583).

- **설정 › 📋 Log › 로그 분석(개선점)** (`#/settings/log-analysis`) — admin · 전체 범위 계정만 열립니다(로그에 전 법인의
  호스트명·IP·VM 이름이 들어갑니다). 원천은 다섯 가지입니다.

  | 원천 | 내용 |
  |---|---|
  | 누적(이 포탈) | 줄이 들어오는 순간 시간 단위로 집계(최대 7일). `log-analysis-stats.json` 에 남아 재시작해도 이어집니다. `LOGANALYSIS_LIVE=0` 이면 꺼집니다 |
  | 최근 로그(메모리) | 메모리 링 버퍼 1,000줄 — 요청 로그가 섞여 몇 분 분량입니다 |
  | 서비스 저널 | 이 서버의 `journalctl -u <PORTAL_SYSTEMD_UNIT>`(기본 `vmware-portal`)을 포탈이 직접 읽습니다. 서비스 계정이 시스템 저널을 읽을 권한이 있어야 합니다 — [INSTALL.md §10](INSTALL.md) |
  | 붙여넣기 | 다른 서버(엣지 등)의 `journalctl`·`tail` 출력을 붙여넣습니다(8MB · 20만 줄까지) |
  | 엣지 로그 | 특수기능 › 엣지 로그에서 먼저 가져온 그 엣지의 보관분 |

  결과는 **개선점**(규칙 목록에 걸린 문장의 뜻·조치·관련 화면 링크 · HTTP 5xx/413/429/401·403/느린 응답 · 규칙에 없는
  경고·오류 · 로그를 덮는 반복 문장) · 태그별 · 반복 문장 · 규칙 목록 탭으로 봅니다. 원천에 로그 수준이 없으면 경고·오류를
  **키워드로 추정**하고 화면이 그 사실을 밝힙니다. 표본 문장의 비밀처럼 보이는 값은 가리지만 완전할 수는 없습니다.
- **'불러오는 중…' 의 요청 ID** — 화면이 몇 초(기본 3초, 설정 › Log › 서버 성능 측정의 서버 설정값) 넘게 기다리면 작업
  줄 아래에 **실제 요청(메서드 + 식별자를 가린 경로) · 요청 ID · 서버 쪽 상태**가 보입니다. 서버 상태는
  '서버가 처리 중'(지연 주체는 서버의 그 작업) / '서버는 이미 응답'(전송·브라우저 처리 대기) / '기록 없음'(미도달·재시작·완료
  기록 밀림 — 단정하지 않음) 중 하나입니다. 같은 ID 가 **설정 › Log › 서버 성능 측정**(느린 요청·hang 기록 — '요청 ID 찾기'
  입력칸)과 진단·로그의 라이브 로그 줄 끝(`#<ID>`)에도 찍혀 세 곳을 대조할 수 있습니다. 사용자가 그 ID 를 알려 주면 됩니다.

### 7.2 엣지 진단 도구

엣지 쪽 문제는 중앙 화면에서 '조용히 낡는 것' 으로만 보이는 경우가 많습니다. 아래 도구는 전부 admin · 전체 범위 계정 전용입니다.

| 도구 | 무엇을 보나 |
|---|---|
| 특수기능 › **포탈 점검 › 토큰 점검** (`#/tools/portal-check`, v2.560) | 중앙에 저장된 수집 토큰으로 엣지와 실제로 통신되는지(200 이면 중앙 값 = 엣지 값이 증명, 403 이면 다름) · 토큰 중복 · 앞뒤 공백. 엣지의 자기보고는 수집 토큰 게이트(`GET /api/collector/token-check`)라 공유 토큰만 쓰는 현장에서도 동작합니다 |
| 특수기능 › **포탈 점검 › 인벤토리 점검** (같은 화면, v2.570) | 위임(site) vCenter 의 push 가 실제로 들어오는지 — 정상 수신 / 낡음 / 수신 이력 없음 / **거부됨**(mock 차단·소유권 충돌·토큰 불일치). 중앙이 이미 가진 값만 조합해 왕복이 없습니다 |
| 특수기능 › **엣지 로그 · 진행상태** (`#/tools/edge-log`, v2.549) | 누를 때만 엣지의 최근 로그·폴러 상태를 당겨 옵니다(수집 서버와 같은 URL·토큰). 닿지 않으면 엣지가 인출해 가는 폴백 요청을 등록합니다. 가져온 보관분은 7.1 로그 분석의 '엣지 로그' 원천이 됩니다 |
| 특수기능 › **통신 점검** (`#/tools/link-check`, v2.552~) | 기본 꺼짐. 중앙→엣지·중앙→vCenter 는 중앙이, 엣지→중앙 push/설정 pull·엣지→vCenter·엣지↔엣지(관리자가 고른 짝만)는 엣지가 잽니다. '설정 전수 점검' 탭은 설정에 등록된 접속처의 도달성을 장비 계정 로그인 없이 봅니다. ⚠ 엣지 측정 보고는 **엣지별 개별 토큰 전용**이라 공유 `CENTRAL_TOKEN` 만 쓰는 엣지의 링크는 '측정 없음' 으로 남습니다 |
| 특수기능 › **통신 지도** (`#/tools/comm-map`, v2.584~) | 중앙 ↔ 엣지 통신을 라디얼 그래프로 봅니다 — 안쪽 링 엣지(상태색), 바깥 링 위임 자원(vCenter·스토리지·SAN·PDU), 허브↔엣지 선은 pull/push 두 가닥. 흐르는 점은 마지막 두 조회(15초) 사이에 관측된 통신만입니다. pull 상태·수신 통계는 중앙 메모리에만 있어 재시작 직후에는 ‘확인 불가’ 가 정상입니다. admin + 전체 범위 계정 전용 |
