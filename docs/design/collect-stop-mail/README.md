**확인하지 못한 것(구현 전에 조사할 것)**
- 폴러마다 ‘대상별 마지막 성공 시각 · 주기’ 를 어떤 모양으로 들고 있는지 — 19곳을 전수로 읽지 않았다. ‘수집 멈춤’ 판정의 공사량은 여기에 달려 있다.

## 4. 설계(제안 — 컨펌 대상)

1. **‘비번이 달라짐’ = 인증 정지**로 본다. 포탈은 비밀번호가 바뀌었는지 직접 알 수 없고, 장비가 로그인을 거부했다는 것만 안다 — 문구도 그렇게 쓴다. 기준값 없음(가드가 멈춘 사실 그대로).
2. **‘수집 멈춤’ = 마지막 성공이 `max(주기 × 3, 10분)` 을 넘음**(배수 · 최소 시간은 설정). 인증서 변경 · 시한 초과 · 연결 실패 · 엣지 보고 끊김이 여기 든다.
3. **기록이 한 번도 없는 대상은 멈춤이 아니다** — ‘판정 못함’ 으로 따로 센다(중앙 재시작 직후 · 새로 등록한 대상 · 엣지 보고가 끊겨 못 읽은 엣지 안 상태).
4. **보내는 때**: ⓐ 새로 생기면 그때의 전체 목록을 한 통(같은 확인 주기는 묶음 · 같은 대상은 상태가 바뀔 때만) ⓑ 매일 정한 시각에 남은 것 일람(0건이면 안 보냄) ⓒ 회복은 다음 메일의 ‘회복’ 절.
5. **받는 사람**: 통합 관리자(전 법인) + 법인 담당자(그 법인 것만 — 법인 · vCenter · Bareos 1:1:1).
6. **같은 계정이 여러 대에서 한꺼번에 실패하면 한 줄로 묶는다**(iDRAC 12대 예) — 메일이 길어지지 않고 원인(계정)이 먼저 보인다.
7. 메일 종류 id 는 `collect-watch`(가칭) — `mail/kinds.js` 에 추가. SMTP 자체의 인증 정지는 메일로 알릴 수 없으므로 화면에만.
8. 시간당 상한으로 건너뛴 내용은 버리지 않고 다음 메일에 합친다.
