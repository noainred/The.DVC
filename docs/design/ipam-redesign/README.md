### 3.1 현황(2판) — 참고한 제품과 그린 방식

1판(큰 검색 카드 + 글자 위주 타일 4장 + 목록)은 사용자가 "한눈에 안 들어오고 시인성이 좋지 않다" 고 했다. 2판은 제품 문서에서 확인한 대시보드 구성을 따랐다.

| 참고 | 문서에서 확인한 것 | 2판에 옮긴 것 |
|---|---|---|
| SolarWinds IPAM 요약 대시보드 | 기본 위젯: Top 10 Subnets by % IP Address Used · IP Address Conflicts · DNS Records Mismatch · Last 25 IPAM Events · Search for IP Address | 사용률 높은 대역 상위 10 · 충돌 칸 · 이름/DNS 불일치 칸 · 최근 변화 · 머리줄 검색 |
| Infoblox | Top Utilized Networks(가장 많이 찬 네트워크 상위 10) · 네트워크별 사용률 통계 | 상위 10 목록 · 사용률 지도 |

- 출처: [SolarWinds — IP Address Manager Summary Dashboard](https://documentation.solarwinds.com/en/success_center/ipam/content/ipam-ip-address-manager-summary-view.htm) ·
  [SolarWinds — Top 10 Subnets](https://documentation.solarwinds.com/en/success_center/ipam/content/ipam-top-10-subnets-by-ip-address-space-usage-resource.htm) ·
  [SolarWinds — IP Address Conflicts widget](https://documentation.solarwinds.com/en/success_center/ipam/content/ipam-conflict-scenarios.htm) ·
  [Infoblox 문서](https://infoblox-docs.atlassian.net/wiki/x/DgMqKw). 검색 결과 요약으로 확인했고 각 문서 본문 전체를 읽지는 않았다.
- **확인하지 못한 것**: phpIPAM 의 대시보드 위젯 목록과 Infoblox 의 Net Map · IP Map 은 이번 검색에서 문서를 찾지 못했다. '칸 하나가 대역 하나' 인 사용률 지도는 그 제품을 옮긴 것이 아니라 이 시안의 선택이다.
- 차트 형태: 전체에서 차지하는 몫은 도넛 대신 **나눔 막대**(사용 중 · 예약/DHCP · 빈 주소) · 대역별 비교는 **이름 + 막대 + 숫자 목록** · 지도는 **한 색 5단**. 막대 색은 80% 이상 주황 · 90% 이상 빨강.
- 색 검증: 파랑 5단은 `dataviz` 스킬의 `validate_palette.js --ordinal --mode dark --surface #141b2d` 로 전 항목 통과(밝기 단조 · 인접 단 차이 · 가장 어두운 단의 바탕 대비 2.19:1 · 한 색상). 1차 후보(가장 어두운 단 `#1c2f57`)는 바탕 대비 1.30:1 로 떨어져 바꿨다.
- 수치 검산: 사용 중 8,047 + 예약 2,310 + DHCP 10,260 = 20,617 · 전체 312 × 254 = 79,248 · 빈 주소 58,631 · 26.0%. 지도의 80% 이상 칸 9개 = 상위 10 목록의 80% 이상 9개.

### 3.2 엑셀 내보내기(보드 ⑨ · ⑩)

- 지금: `GET /tools/ipam.xlsx` 가 /24 대역마다 시트 하나 · 9열(주소 · Purpose · Hostname · 서버종류 · OS · Notes · 전원 · 분류 · 상태)을 만든다. 시트 조립은 시간 기준 양보, 직렬화는 워커, 동시 1건 가드(`server/src/ipam/excel.js` · `util/exportBusy.js` · 버튼은 `IpamCsv.jsx:317`).
- 시안이 더하는 것: ① 내보내기 **창**(범위 · 시트 · 열을 고른다 — GPU 할당율 내보내기 창 `GpuAllocExportModal.jsx` 와 같은 틀) ② 시트 **요약 · 대역 목록 · 조치 필요 · 안내** ③ 대장 열에 **용도 · 요청자 · 할당자 · 메모 · 사용 이력 · DNS 조회 결과 · 이름 확인 · 서비스 태그** ④ 대장 시트 1~2행에 대역 이름(용도)과 집계, 3행 머리글 고정 + 자동 필터 ⑤ 선택 시트 '한 시트에 전부'(가공용) · '서버별 IP'.
- 들어가는 곳: 머리줄 '내보내기' · 대역/대장의 '엑셀' · 서버 보기의 '엑셀' — 같은 창이 그 화면의 범위를 미리 고른 채로 열린다.
- 칸 색은 지금 파일의 옅은 색 계열을 잇는다(사용 중 옅은 초록 · 문제 옅은 빨강). 예약 · DHCP · 스캔만 확인의 색은 새로 정한 것이다. '복수IP' 는 색이 아니라 안내 시트의 설명으로 옮겼다(지금 파일은 옅은 파랑 칸).
- 수치 검산(요약 시트 · VC-KR1): 1,204 + 412 + 2,340 + 5,696 = 9,652(= 38 × 254) · 사용률 41.0% · 대장 시트 177 + 9 + 55 + 13 = 254.
- 구현 전 확인: 전체 법인이면 대장 시트가 312장이다 — 지금도 대역 수만큼 시트를 만들지만 열이 9 → 13 으로 늘어 크기 · 시간이 늘어난다(재지 않았다). 범위 계정은 자기 법인만, 메모 · 태그는 `ipInWriteScope` 를 통과한 칸만(v2.771 규칙 그대로). 시트 이름 정리 · 31자 · 중복 이름 처리는 `hostSheetNames` 규칙을 따른다.

### 3.3 스캔 대역 추가(보드 ⑪)

- 지금도 같은 계산이 있다: 스캔 대역 편집기의 'iDRAC 대역 가져오기' · 'VM 대역 가져오기' 버튼 2개가 확인 창을 띄워 /24 후보를 보여 준다(`server/src/ipam/vcRangeSuggest.js` · `GET /admin/ipam/scan/import` · 웹 `ScanRangeImportModal.jsx` — v2.690~v2.692). 상태 넷(new · covered · partial · other) · 공인 /24 는 기본 체크 해제 · 호스트 주소 전부가 무시 대역이면 제외 · 이름으로 등록된 장비는 개수만.
- 시안이 바꾸는 것: ① 버튼 2개 + 확인 창 → **추가 화면을 열면 후보가 바로 보인다**(vCenter 와 iDRAC 을 한 목록에, 출처는 줄마다 표시) ② **사설 / 공인 두 묶음**으로 나눠 보이고 묶음마다 '모두 담기' ③ 체크박스 대신 **줄 전체가 버튼** — 누르면 담기고 다시 누르면 빠진다 ④ 오른쪽에 담은 대역(사설 · 공인 따로, 주소 수) ⑤ 대역 용도가 있으면 주소 옆에 보인다.
- 상태 표기: '사용 중인 IP 대역'(담을 수 있음) · '이미 스캔 중'(= covered) · '다른 에이전트와 겹침'(= other) · '숨길 대역'(= 무시 대역으로 제외). 겹침 판정은 저장하지 않은 입력 기준이라 웹이 한다는 기존 규칙(`vcRangeImportText`)을 그대로 쓴다.
- 구현 전 확인: 'vCenter 에서 사용하는 모든 대역' 에 **ESXi 호스트의 vmk 주소**를 넣으려면 §4 의 vmk 전체 파싱이 먼저다(지금 VM 대역 제안은 VM 주소만 읽는다). iDRAC 은 서비스(엔트리)마다 따로 계산한다는 규칙 유지. 범위 계정은 iDRAC 쪽 403(전 법인 설정) 그대로.
- 공인 대역을 담으면 경고를 띄운다 — 우리 것이 아닌 공인 대역을 스캔하지 않게.
