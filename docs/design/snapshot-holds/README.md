# 스냅샷 화면 — 보류 목록(새 탭) · 400px 법인 카드(시안)

- 상태: **구현됨 — v3.35.0**(2026-11-23 사용자 '시안 권장안대로 구현해줘' — §5 의 기본값 넷 그대로). 아래 §6 이 시안과 달라진 것. 사용자 요청 2026-11-20 ‘7. 시안 만들어서 보여줘’ · ‘9. 시안 보여줘’(버그 점검 152~162회차가 남긴 결정 7 · 9).
- 캔버스: https://claude.ai/artifact/E7RGUQQWYhDGuVGAd8prTa — ⑫ ⑬ ⑭ ⑮(⑪ 스냅샷 화면 오른쪽). 이 폴더의 `.dc.html` 4개가 그 아트보드의 사본이다.
- 앞선 시안 · 설계: `docs/design/snapshots/`(⑪ · 보류 = §8 ⑥).

## 1. 왜

- **보류를 풀 길이 없는 경우가 있다**(153회차가 남긴 것). 보류는 VM 줄에서만 걸고 푼다. VM 이 인벤토리에서 사라지면 줄이 없고,
  `PUT /tools/snapshots/holds` 도 VM 을 못 찾아 404 를 낸다(`routes/api/vcTools.js` — `if (!vm || !inUserScope(...)) 404`).
  그 보류는 기한(최대 90일)이 지날 때까지 남아 상한(2,000건 — `vmhygiene/holds.js HOLDS_MAX`)에 들어간다.
- **보류 전체를 보는 곳이 없다.** `GET /tools/snapshots/holds` 는 목록을 주지만 화면은 VM 줄의 표시에만 쓴다 — 곧 끝나는 보류 · 스냅샷이 이미 없는 VM 의 보류를 한눈에 볼 수 없다.
- **400px 에서 법인 카드 글자가 잘린다**(136~145회차 관찰 — 고치지 않고 남긴 것). `snapshots.css` 가 720px 아래에서 카드를 2열로 놓아
  카드 바깥 폭 약 171px · 글자 자리 약 143px(v3.28.0 목 서버 400px 캡처 실측)이라 법인 이름 · 크기 줄(모든 카드) · 못 읽음 안내가 말줄임이 된다. 휴대폰에는 말풍선(title)이 없다.

## 2. 지금 코드에서 확인한 것

- 보류 한 건이 가진 것: `vcenterId · vmId · vmName(걸 때의 이름) · until · reason(필수 · 200자) · by · at`. **클러스터 · 데이터센터는 없다** —
  사라진 VM 은 법인 · vCenter 이름(등록부에서)과 걸 때의 이름까지만 보일 수 있다.
- 기한이 지난 보류는 읽을 때 빠진다(`loadHolds` — `until > now`). 연장(`setHold` days 1~90)은 그 항목을 새로 쓴다 → `by` · `at` 이 연장한 사람 · 지금으로 바뀐다.
- 조회는 범위 안 보류만 · `by` 는 관리자 판본만(`isAdminDetailUser`) · 쓰기는 관리자 · 조회 밖 404 → 쓰기 밖 403 · 감사 `snapshot.hold`.
- 보류 파일을 못 읽으면 `unreadable: true` 이고 저장은 503 으로 거절된다.

‘지금 상태’ 는 넷이다 — 스냅샷 N개 · 크기 · 나이 / 스냅샷 없음 / VM 없음 / **확인 못 함**. 그 vCenter 를 지금 못 읽고 있으면 ‘VM 없음’ 이 아니라
‘확인 못 함’ 이다(못 읽은 값은 없음이 아니다 — 대상 없음에 세지 않는다).

## 4. 구현에 필요한 것(추정 — 컨펌 뒤 다시 본다)

- 서버: `PUT /tools/snapshots/holds` 가 **풀기(days 0)에 한해** 인벤토리에 없는 VM 도 받는다 — 그 보류가 목록에 있고 `vcenterId` 가 조회 · 쓰기 범위 안일 때만
  (걸기 · 연장은 지금처럼 VM 이 있어야 한다). 감사 대상 이름은 보류의 `vmName`. 여러 건 풀기는 한 요청에 목록을 받는 쪽이 낫다(파일을 건마다 다시 쓰지 않게).
- 서버: 목록 응답에 ‘지금 상태’ 를 붙인다 — 인벤토리 대조(있음/없음/그 vCenter 를 못 읽음)와 스냅샷 요약. 범위 · 관리자 판본 가림은 지금 규칙 그대로.
- 웹: `SnapshotTool.jsx` 탭 하나 + 표(`STable`) + 400px 카드. 연장 · 풀기 뒤에는 화면 응답 캐시가 보류 세대(`holdsGeneration`)로 갈린다(지금 그대로).
- 웹(⑮): `snapshots.css` 720px 아래 `.snp-cards` 1열 + 카드 안 2칸 배치. 길이는 어림으로 법인 20곳에서 약 1,550px → 약 1,940px(25%쯤 길어짐 — 시안 CSS 로 잰 값이고 실제 화면 실측이 아니다).

## 5. 정할 것(기본값 = 첫 번째)

1. 보류 목록의 자리 — **표 위 탭 ‘보류’**(시안) / 설정 상자 안 / 별도 도구.
2. 대상이 사라진 보류 — **사람이 푼다(목록에서)** / 사라진 지 N일이면 자동으로 지운다(옮겨진 VM 의 보류가 말없이 사라질 수 있다).
3. 여러 건 풀기 — **넣는다** / 한 건씩만.
4. 400px 법인 카드 — **1열(⑮)** / 지금 2열을 두고 이름 · 크기 줄만 두 줄로 접는다(카드 높이가 들쭉날쭉해진다).

## 6. 구현(v3.35.0)에서 정한 것 · 시안과 달라진 것

- 정한 것: §5 의 기본값 넷 그대로(표 위 탭 · 사람이 목록에서 푼다 · 여러 건 풀기 넣음 · 400px 카드 1열).
- 서버: 상태 판정 `snaphist/view.js holdRows` · 풀기는 `PUT`(한 건 — VM 이 없어도) · `POST /tools/snapshots/holds/release`(여러 건 — 전부 아니면 0). 화면은 한 건도 여러 건 경로로 푼다(한 경로).
- 시안과 다른 것:
  - ‘확인 못 함’ 칩은 그런 보류가 있을 때만 보인다 · 확인 줄은 탭 안 한 줄(시안의 ‘그 자리에서 한 번 더’ 를 줄 아래가 아니라 표 위에 — 표 줄 사이에 끼우면 제목 정렬이 짝을 잃는다). 연장 창도 같은 이유로 표 위.
  - 연장은 ‘스냅샷 있음’ 상태에만(시안은 ‘대상 없음 · 스냅샷 없음’ 에만 두지 않았다 — ‘확인 못 함’ 도 VM 이 있는지 모르므로 뺐다).
  - 표의 사유 칸은 바닥 폭 220px(Chromium 1440 판독 — 줄바꿈 금지 칸들에 밀려 약 70px 이 됐다).
  - 400px 법인 카드는 시안처럼 왼쪽 글자 · 오른쪽 막대와 추이 그림이지만, 카드 첫 줄(이름 · 넘김 수)은 두 칸을 걸친다(넘김 수가 이름 옆에 그대로).
