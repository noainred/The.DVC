보존 정리. ts 인덱스 + 청크 삭제, N틱마다 1회(기동 첫 틱 금지) — capacity_history 와 같은 규칙. 원시 보존 일수는 설정 › 수집 › 스토리지 보존 기간 옆에 ‘노드 부하 원시 보존(기본 30일)’ 한 칸. 일 롤업은 용량과 같은 5년.
규모 산수(클러스터 1개 · 1시간 주기). 8 노드 → 192행/일, 64 노드 → 1,536행/일. 원시 30일 = 5.8천~4.6만 행. 일 롤업은 노드 수 = 8~64행/일(5년 ≈ 1.5만~12만 행). 읽기는 24h·7d 원시(7d 는 버킷 평균), 30d·90d 는 일 롤업 — 원시 폴백 없음.
옵션 ② 디스크 I/O(이번 범위 밖). REST 는 같은 statistics/current 호출에 node.disk.bytes.in.rate · out.rate 키를 더하면 왕복 0. SSH 는 세션 안에 ‘isi statistics query current --nodes all --keys …’ 1개 추가. 키 이름 · CLI JSON 모양은 실장비 미확인. 엣지 export + 중앙 정제 화이트리스트(NODE_NUM_KEYS)에 같이 넣는다.
