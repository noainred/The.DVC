## 4. 설계 결정(시안에 그린 것)

### 4.1 배치 — 별도 특수 기능(안 B)

- `#/tools/server-cmd`(안) — ‘서버 정보’ 옆. 접속 · 계정 · 비밀 · 잠금 방지는 코어가 하고, 새 모듈은 **프리셋 목록 · 값 검사 · 명령 만들기 · 출력 다듬기 · 메모리 보관**만 맡는다.
- 안 A(서버 정보에 탭)는 ‘원문은 저장하지 않고 해석한 값만’ 이라는 서버 정보의 규칙에 원문 출력이 섞이고, 계정의 허용 기능을 따로 켤 수 없다.
- 안 C(RMA 에 합침)는 에이전트 경유라 그 법인에서 켜야 하고(에이전트가 없는 곳의 서버에는 길이 없다), 통합 계정과 계층 계정 두 체계가 섞인다.
- 자유 명령은 넣지 않는다 — 이미 있는 길(RMA 의 SSH 원격 실행 · 터미널)이 있다.

### 4.2 값이 명령에 들어가는 길(여섯 겹)

1. 화면은 프리셋 id 와 값만 보낸다(명령 글자를 받는 칸이 API 에 없다).
2. 프리셋 id 는 서버 코드의 목록에 있는 것만.
3. 값은 종류별 허용 글자만 — 이름: 영숫자로 시작 · 영숫자와 `@ . _ -` · 80자 / 경로(Linux): `/` 로 시작 · 영숫자와 `. _ - /` · 200자 · `..` 조각 없음. 공백 · 따옴표 · `$ ; |` · 줄바꿈 · 선행 `-` 가 들어갈 수 없다.
4. 그래도 작은따옴표로 감싸고 `--` 뒤에 둔다(PowerShell 은 작은따옴표 글자열).
5. 코어에는 완성된 문자열만 넘긴다(코어는 지금처럼 이어 붙이지 않는다).
6. Linux 명령은 `timeout N` 으로 감싼다(포탈 시한 뒤 서버에 프로세스가 남지 않게).

### 4.3 프리셋 규칙

- 읽기 전용 · sudo 없음 · 프로세스는 이름만(`ps -eo …,comm` · `pgrep -l` · `systemctl show` — `status` · `ps aux` 는 인자를 보여 줘서 쓰지 않는다).
- 값으로 받은 경로의 파일 **내용**은 읽지 않는다(목록 · 크기만). 정해진 파일 하나(`/etc/resolv.conf`)는 값이 아니라 고정 명령이다.
- ‘서버 정보’ 가 이미 읽는 것(OS · CPU · 메모리 구성 · 디스크 목록)은 넣지 않는다.
- 프리셋마다 시한(10초 · 20초)과 출력 상한(기본 64KB). 시한의 합이 서버 한 대의 시한보다 작다는 것을 시험이 고정한다.
- Windows 는 PowerShell `-EncodedCommand`(SSH · WinRM 공통) · 값은 이름만. **실제 서버로 확인하지 못했다** — ‘시험’ 표시(D9).

### 4.4 출력

- 받기: 상한을 넘으면 끊고 ‘잘림’. 다듬기: 제어문자 · 색 코드 제거(줄바꿈 · 탭만) · 화면에는 서버당 2,000줄까지 · 글자로만 그린다.
- 보관: **메모리에만 · 마지막 실행 한 건 · 30분 뒤 지움**(D6) — 파일 · 백업 · 엣지 push 에 싣지 않는다.
- 감사: 누가 · 프리셋 · 값 · 대상 · 서버별 결과 코드. **출력은 싣지 않는다.**
- 출력 속 비밀을 자동으로 가리지는 못한다 — 목록에서 그런 명령을 빼는 것으로 대신한다.
- 끝 코드가 0 이 아니어도 실패가 아니다(출력과 끝 코드를 그대로) — 코어가 이미 돌려주는 `exit` 를 그대로 쓴다(§2 정정).

### 4.5 권한 · 계정

- 실행 · 조회 모두 관리자 + 전체 범위(D7 — 서버 정보와 같음). 카탈로그 `adminOnly` 를 게이트와 맞춘다.
- 새 허용 기능 id `server-cmd`(안) — `KEY_FEATURES` · `FEATURE_CATALOG` · `placement.FEATURE_LABEL`. **직접 켠 계정 · 키만**(D8 — 기능 목록이 없는 예전 키를 어떻게 볼지는 `disk-audit-install` 의 ‘직접 켠 것만’ 선례를 따른다).
- 엣지가 수집하는 서버는 그 엣지 포탈의 같은 화면에서(D10).

## 7. 확인하지 못한 것 · 한계

- Windows 프리셋은 실제 Windows 서버 출력을 보지 못했다(이 환경에 없음). `w32tm` · 이벤트 로그 · `quser` 는 권한에 따라 거절될 수 있다(추정).
- Linux 의 권한(로그 읽기 — `systemd-journal` 그룹 · 리슨 포트의 프로세스 이름)은 배포판 · 설정마다 다르다. 못 읽으면 서버가 낸 문구가 그대로 보인다.
- WinRM 은 시한에 걸리면 받은 만큼을 돌려주지 못한다(전부 아니면 실패 — `readServer.js` 머리말의 한계).
- sudo 를 쓰지 않으므로 root 가 필요한 정보는 볼 수 없다.
- 아트보드의 명령 22개는 안이다 — 선택 항목(`ps -eo` 열 · `systemctl show -p` 속성)은 구현 때 실제 출력으로 확정한다.
- 예상 구현 시간 2~3시간은 추정이다(앞 2 · 3단계 실적에서 WinRM 을 뺀 규모로 어림).
