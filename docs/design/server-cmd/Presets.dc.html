서버 명령 실행 · 프리셋

프리셋 목록(안) — 1차에 넣을 명령 22개

‘서버 정보’ 가 이미 읽는 것(OS · CPU · 메모리 구성 · 디스크 목록)은 빼고, 지금 상태를 묻는 명령으로 골랐습니다. 전부 읽기 전용이고 일반 계정으로 돕니다.

읽기 전용 sudo 를 쓰지 않음 프로세스는 이름만(인자 · 환경 없음) 값은 이름과 경로 두 종류 명령마다 시한 · 출력 상한 Windows 는 실제 서버로 확인 전(안)

검사는 서버가 합니다(화면의 검사는 안내용). Windows 는 1차에 이름 값만 받습니다 — 경로의 공백 · 역슬래시 규칙은 실제 서버로 확인한 뒤에.

넣지 않는 것(1차)

  • 상태를 바꾸는 명령 — 서비스 시작 · 중지 · 재시작, 프로세스 종료, 재부팅(④ 의 D2)
  • 자유 명령 — 지금 있는 길(에이전트의 SSH 원격 실행 · 터미널)을 씁니다
  • 그 서버에서 다른 주소로 가는 탐침(ping · 포트 확인 · HTTP) — 서버를 발판으로 한 내부망 탐색이 됩니다(④ 의 D4)
  • 값으로 받은 경로의 파일 내용 읽기(cat · tail · grep) — 설정 파일의 비밀이 화면으로 나옵니다
  • 프로세스 인자 · 환경 변수(ps aux · systemctl status) — 인자에 비밀번호가 실린 경우가 있습니다
  • sudo — root 가 필요한 항목은 서버가 낸 거절 문구가 그대로 보입니다

명령을 감싸는 틀 · 목록의 모양(안)

// Linux — 프리셋 ‘서비스 상태’ · 값 chronyd
LC_ALL=C timeout 10 systemctl show -p Id,LoadState,... -- 'chronyd'

// Windows — 같은 프리셋(스크립트를 Base64 로 바꿔 넘긴다)
powershell -NoProfile -NonInteractive -EncodedCommand (Base64)
  Get-Service -Name 'chronyd' | Select Name, Status, StartType
    | Format-Table -AutoSize | Out-String -Width 200

// servercmd/presets.js — 순수 모듈(목록 · 값 검사 · 명령 만들기)
{ id: 'svc-state', group: '서비스 · 로그', label: '서비스 상태',
  params: [ { name: 'unit', kind: 'name', label: '서비스 이름' } ],
  linux:   { make: (p) => 'systemctl show -p ... -- ' + q(p.unit),
             timeoutS: 10 },
  windows: { make: (p) => 'Get-Service -Name ' + psq(p.unit) + ' | ...',
             timeoutS: 10 },
  maxBytes: 65536 }

// 화면이 보내는 것 — 명령 글자는 없다
POST /api/tools/server-cmd/run
  { preset: 'svc-state', params: { unit: 'chronyd' }, ids: [ ... ] }

파일 · 함수 · 칸 이름은 안입니다. 시한의 합(로그인 15초 + 명령 시한)이 서버 한 대의 시한 60초보다 작다는 것을 시험이 고정합니다(지금 서버 정보와 같은 방식).

기록감사 로그에 누가 · 프리셋 · 값 · 대상 서버 · 서버별 결과 코드 — 출력은 싣지 않음
가리지 못하는 것출력 속 비밀을 자동으로 가리지는 못합니다 — 그래서 비밀이 나올 수 있는 명령을 목록에서 뺐습니다
확인하지 못한 것 — Windows 명령은 실제 Windows 서버에서 돌려 보지 못했습니다(이 환경에 없음). 구현 때 실제 출력으로 확정하고, 그 전까지 화면에 ‘시험’ 표시를 답니다(④ 의 D9). Linux 의 권한 메모(로그 읽기 · 리슨 포트의 프로세스 이름)도 배포판 설정에 따라 달라집니다.
