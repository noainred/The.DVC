D1배치별도 특수 기능 — 접속 코어를 불러 쓴다서버 정보에 탭으로 · 원격 명령 에이전트에 합침계정마다 허용 기능을 따로 켤 수 있고, 서버 정보의 ‘원문은 저장하지 않는다’ 는 규칙과 섞이지 않음(①)
D2프리셋 범위읽기 전용만 — 22개(②)서비스 재시작 같은 상태 변경도 포함상태 변경은 대상 서버의 sudo 설정, 설정 소유자 등급 + 본인 OTP, ‘운영 작업’ 소속이 함께 필요 — 별도 단계로 다룸
D3프리셋을 더하는 방법코드에 고정 — 릴리스로 추가설정 소유자가 화면에서 추가화면에서 더하게 하면 그 사람에게는 자유 명령과 같아짐. 필요한 명령은 알려 주시면 목록에 넣음

ping · 포트 확인		1차에서 뺌넣음(대상 주소를 값으로 받음)등록된 모든 서버가 내부망 탐색의 발판이 됨. 넣는다면 대상 제한 규칙과 함께 다음 단계로
D5로그 조회
서비스 로그 · 최근 경고 · 오류		넣음 — 줄 수 상한(100줄 · 50줄)뺌장애 확인에 자주 쓰는 명령. 대신 로그에 찍힌 내용은 그대로 보임(비밀이 찍혀 있으면 그것도)
D6출력 보관메모리에만 · 마지막 실행 한 건 · 30분 뒤 지움디스크에 이력을 남김(예: 7일)출력에 무엇이 실릴지 장담할 수 없어 남기지 않는 쪽. 이력을 남기려면 보관 기간 · 암호화 · 백업 포함 여부를 함께 정해야 함
D7실행 권한관리자 + 전체 범위 · 실행마다 OTP 는 묻지 않음설정 소유자 등급 + 본인 OTP읽기 전용 프리셋만이라 서버 정보와 같은 등급으로. OTP 를 걸면 확인 한 번마다 코드를 넣어야 함
D8어느 계정으로 쓸 수 있나‘서버 명령’ 을 직접 켠 계정 · 키만서버 정보를 켠 계정이면 함께 허용원문 출력이 나오는 기능이라 계정마다 따로 허락하게 함(켜는 것은 지금 설정 규칙대로 설정 소유자 등급 + 본인 OTP). 처음 한 번 켜는 수고가 있음
D9WindowsLinux 와 함께 넣고 ‘시험’ 표시Linux 먼저 — Windows 는 실제 서버 확인 뒤실제 Windows 서버로 확인하지 못했음. 표시를 달고 열어 두면 첫 실행이 곧 확인이 됨
D10엣지 법인의 서버그 엣지 포탈의 같은 화면에서 실행 — 중앙은 붙지 않음중앙이 엣지에 작업을 보내 대신 실행지금 규칙(비밀은 법인 밖으로 나가지 않는다) 그대로. 대신 실행은 엣지 수신 계약을 새로 만들어야 함 — 다음 단계 후보
D11값을 받는 프리셋이름 · 경로 두 종류 — 프리셋 5개값 없는 프리셋만(17개)서비스 상태 · 서비스 로그가 빠지면 쓸모가 크게 줄어듦. 값은 여섯 겹으로 막음(①)
