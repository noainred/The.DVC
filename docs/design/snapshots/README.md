여기서 나오는 어긋남:

1. 카드는 11대(기준을 넘긴 VM)인데 ‘모두 보기’ 로 간 도구는 18대(스냅샷이 있는 VM 전부)다. 도구 화면에는 어느 VM 이 그 11대인지 알 길이 없다(일수 열이 없다).
2. 카드에서 법인을 골라도 도구는 늘 전체 범위로 열린다(범위를 받는 쪽이 없다 — `insight-tools/ToolParts.jsx ToolLink` 주석).
3. 나이를 보려면 다른 도구(‘스냅샷 나이 감시’)로 가야 하고, 거기 기준(3일)은 카드 기준(7일)과 다르다.
4. 정리는 법인 쪽(그 법인의 vCenter)에서 하는데, 화면에는 법인 단위 묶음도, 법인에 넘길 목록도 없다.

일부러 넣지 않은 것:

- **지우기 · 되돌리기 · 자동 삭제** — 이 화면은 보기 전용으로 둔다(지금도 그렇다). 자동 삭제를 쓰는 곳도 있지만(위 사례) 백업 데이터와 작업은 법인 안에서 한다는 운영 원칙과, 잘못 지웠을 때 되돌릴 수 없다는 점 때문에 뺐다.
- **스냅샷 하나하나의 크기 · 커지는 속도 순위** — 수집하지 않는 값이라 그리지 않았다.
- 좁은 화면(400px) 보드 — 보드 CSS 에 규칙(카드 2열 · 그림 위아래 · 표 가로 스크롤)만 넣었다.

## 5. VM 별 스냅샷 이력 DB(설계 초안 — 새로 만드는 것)

지금 포탈은 스냅샷 값을 ‘가장 최근 수집분’ 하나만 갖는다(§2). 그래서 **지난주에 없어진 스냅샷 · VM 별 증가 속도 · 대수 추이 · 정리 실적** 은 답할 수 없다. 이를 메우는 전용 DB 다.

**틀 — `vmtrack`(VM 수량 추이 DB)과 같은 방식**(`server/src/vmtrack/db.js` — 슬롯 기록 · 바뀐 것만 · 현재 집합 표):

| 표 | 한 줄 | 무엇에 쓰나 | 크기 어림 |
|---|---|---|---|
| `snap_day(day, vcenterId, vmId, name, count, gb, oldestTs, power, judged)` — 기본키 (day, vcenterId, vmId) | 그날 스냅샷이 **있던 VM** 한 대 | VM 별 추이 · 7일 변화 · 법인별 대수 / 크기 / 기준 넘김 추이 | 스냅샷이 있는 VM 수 × 보관 일수. 지금 캡처 규모(18대)면 400일에 약 7천 줄, 수백 대여도 십수만 줄 |
| `snap_item(vcenterId, vmId, key, name, createTs, firstSeen, lastSeen, goneAt, kind, desc)` — 기본키 (vcenterId, vmId, key) | 스냅샷 **하나의 생애**(처음 본 날 · 마지막으로 본 날 · 없어진 날) | ‘정리된 것’ 탭 · VM 이력의 사건 줄 · 있었던 기간 | 스냅샷 수 + 없어진 것(보관 기간 안) |
| `snap_meta(k, v)` | 기록 시작일 · 마지막 기록 · vCenter 별 빠진 날 | 이력 상태 칸 | 수십 줄 |

- **기록**: 하루 1번(시각은 §8 ⑧). 스냅샷이 있는 VM 만 한 트랜잭션으로 넣는다 — 전체 VM 을 매번 적재하지 않는다(5,850 VM × 400일 = 234만 줄을 피한다).
- **못 읽은 것은 0 이 아니다**: 그 vCenter 를 그날 수집하지 못했으면(오래됨) 그 vCenter 는 **건너뛰고 빠진 날로 적는다** — ‘스냅샷이 없어졌다’ 로 적지 않는다. `gb` · `oldestTs` 를 못 읽었으면 null 로 넣는다. `goneAt` 은 ‘그 vCenter 를 새로 읽었는데 그 스냅샷이 없을 때’ 만 찍는다.
- **없어진 VM**: VM 자체가 지워진 경우와 스냅샷만 지운 경우를 가른다(`goneAt` 사유 — ‘스냅샷 정리’ / ‘VM 삭제’). VM 삭제는 ‘정리 실적’ 에 넣지 않는다.
- **보관**: 기본 400일(설정). 정리는 스로틀 + 청크(`util/chunkedPrune.js`) + `day` 단독 인덱스 — 기동 첫 틱에 돌리지 않는다.
- **조회**: ‘VM 별 최신값’ 을 `GROUP BY + MAX(day)` 로 만들지 않는다 — 최신은 지금 인벤토리(`store.get()`)에서 읽고, DB 는 과거만 답한다. 추이 집계는 날짜 범위 + vCenter 조건으로 자르고 `memoJson` + `scopeKey`.
- **범위 · 권한**: 조회는 `requirePerm('tools')` + 계정의 vCenter 범위 교집합(`parseVcenterIds`). DB 에는 범위와 무관하게 전부 쌓고, 응답에서 자른다.
- **엣지 위임 법인**: 중앙 인벤토리에 그 법인 VM 의 스냅샷 수 · 크기 · 생성 시각이 이미 들어온다(카드가 전 법인의 일수 · 이름을 보이는 것이 근거). 그래서 **중앙이 자기 인벤토리로 기록**하면 엣지를 고칠 필요가 없다 — 단 스냅샷 줄기(`snapshotTree`)까지 중앙에 오는지는 확인하지 못했다(추정). 안 오면 `snap_item` 은 이름 목록(`snapshotNames`) 기준으로 줄어든다.
- **거슬러 채우기**: 기록 시작 전의 값은 없다. 지금 남아 있는 스냅샷은 생성 시각으로 ‘언제부터 있었나’ 를 알 수 있지만, 그사이 없어진 스냅샷과 그때의 크기는 알 수 없다 — 섞어 그리면 과거가 실제보다 작게 보인다(§8 ⑨).
- **성능**: 하루 1번 · 수백 줄 · 한 트랜잭션이라 이벤트 루프 부담은 작다(추정 — 실측 필요). 요청 경로에서 큰 집계를 하지 않도록 법인별 일 합계를 기록할 때 같이 넣는 방안(`snap_corp_day`)은 구현 때 판단.

## 6. 구현에 필요한 것(추정 포함)

- 서버: `GET /api/tools/snapshots` 응답에 `oldestTs` · `ageDays` · `snapshotNames` · `tree`(펼칠 때만 받거나 상한) · `findings` · 기준값 · 법인(DataCenter) · 클러스터 · 데이터스토어 사용률 · `consolidationNeeded` · 백업 임시 스냅샷 여부를 더한다. 판정은 `hygieneFindings` 를 그대로 부른다(복제하지 않는다). 못 읽은 값은 null 로 내리고 합에 넣지 않는다.
- 범위: 도구가 `vcenterIds`(v3.20.0 `parseVcenterIds`)를 받게 하고, 카드의 링크가 고른 법인을 들고 가게 한다.
- 링크: 카드의 ‘모두 보기’ 를 ‘사내 기준 넘김’ 이 켜진 주소로(하위 탭 주소 — `useHashTab`).
- 추이 · 지난 7일 · 7일 변화 · VM 이력 · 정리된 것: §5 의 이력 DB 에서 읽는다. 기록을 시작한 뒤부터만 값이 있다.
- 만든 계정: 저장된 vCenter 이벤트에서 VM 별 마지막 ‘스냅샷 생성’ 이벤트의 계정(이벤트에 스냅샷 이름이 없을 수 있어 **VM 단위로만** 잇는다 — `veeam/snapEvents.js` 주석). 엣지 위임 vCenter 는 그 엣지가 계산해 올려야 한다(엣지 export 필드 → 중앙 정제 화이트리스트).
- 보류(기한 있는 예외): `vmhygiene/settings.js` 의 `exceptions` 는 문자열 목록이라 기한 · 사유를 담지 못한다 — 새 저장 구조와 관리자 전용 쓰기 라우트가 필요하다(범위 계정 쓰기 규칙 적용).
- 한 번에 다 하면 크다 — §8 의 1번에서 단계를 고른다.

## 7. 밝혀 둘 것

- 보드의 VM · 법인 · 클러스터 · 계정 이름과 수치(추이 · 이력 · 정리된 것 목록 포함)는 **지어낸 가상 값**이다(대수 18 · 기준 넘김 11 · 90일 넘김 4 · 합 1.7 TB 만 캡처와 비슷하게 맞췄다).
- 보드는 **띄워서 눌러 보지 않았다.** 계산과 단추 동작(빠른 보기 · 신호 수 · 법인 / 클러스터 / 나이 / 계정 묶음 · 묶음 접기 · 정리 요청 글 · 고르기 · 조건 풀기 · 정렬 · 못 읽은 값이 뒤로 · 펼침 · 찾기 · 들어온 길 3가지 · 7일 변화 · 추이 계열 / 기간 · VM 이력 · 정리된 것 탭 · 템플릿 구멍 대조 — 36항목)만 스텁으로 실행해 확인했다. 카드 줄의 추이 그림과 묶음 머리줄의 막대는 CSS(`clip-path` · `linear-gradient`)로 그렸는데, **캔버스에서 실제로 그려지는지는 확인하지 못했다.**
- VMware 권고 수치(72시간 · 2~3개 · 32개)는 원문 대조를 하지 못했다(§3).
- 이력 DB 의 크기 · 부하 어림은 계산이지 실측이 아니다. 엣지 위임 법인의 스냅샷 줄기가 중앙에 오는지는 확인하지 못했다(§5).
- 그림은 로그 눈금이다 — 낯설면 읽기 어렵다(§8 ④).
- 스냅샷이 있는 VM 이 수백 대일 때의 모양(점 겹침 · 묶음 길이)은 그려 보지 않았다.
- 법인 묶음은 보드에서 법인 1 = 묶음 1 로 그렸다. 실제 묶음 단위는 DataCenter(법인)이고 한 법인에 vCenter 가 여럿일 수 있다.

## 8. 정할 것(기본값 = 첫 번째)

1. **범위 · 단계** — ① 세 단계: (가) 이력 DB 기록부터 켠다(화면보다 먼저 — 하루라도 일찍 쌓이게) + 값이 이미 있는 화면(법인 묶음 · 일수 · 신호 · 줄기 · 정리 요청 · CSV · 범위 인계) (나) 이력 화면(추이 · 7일 변화 · VM 이력 · 정리된 것) (다) 만든 계정 · 보류 ② 한 번에 전부 ③ 표만(그림 · 카드 줄 없이).
2. **VMware 권고선(72시간)** — ① 참고로만 보인다(판정은 사내 기준 7일) ② 사내 기준을 72시간으로 바꾼다(‘VM 구성 점검’ 설정 · 알림도 같이 바뀐다) ③ 보이지 않는다.
3. **‘스냅샷 나이 감시’ 도구** — ① 그대로 둔다 ② 같은 화면으로 합친다(키는 남긴다).
4. **그림** — ① 로그 눈금 산점도 ② 그림 없이 나이 구간 막대만.
5. **카드의 ‘모두 보기’ 가 열리는 상태** — ① ‘사내 기준 넘김’ 이 켜진 채로 + 고른 법인을 들고 간다 ② 지금처럼 전체로.
6. **보류(기한 있는 예외)** — ① 넣는다(2단계 · 관리자만) ② 넣지 않는다(지금의 예외 목록만).
7. **이름** — ① ‘스냅샷 있는 VM’ 그대로 ② ‘스냅샷’.
8. **이력 기록 시각 · 횟수** — ① 하루 1번(새벽) ② 하루 2번(`vmtrack` 과 같은 00시 · 12시) — 하루 안에 만들고 지운 스냅샷은 ① 에서 안 잡힌다.
9. **기록 시작 전의 과거** — ① 채우지 않는다(기록 시작일부터만 그린다) ② 남아 있는 스냅샷의 생성 시각으로 대수만 거슬러 채우고 ‘추정’ 으로 표시한다.
10. **보관 기간** — ① 400일 ② 180일 ③ 무기한.
11. **하루 안에 생겼다 없어진 스냅샷(백업 도구)** — ① 이력에 넣지 않는다(이벤트 DB 가 따로 센다) ② 이벤트 DB 를 읽어 ‘하루 안 생성 · 삭제 n회’ 로 같이 보인다.

## 9. 구현에서 바뀐 것(1단계 v3.26.0)

- **법인 묶음** = DataCenter(`datacenter/store.js`) — 배정이 없는 vCenter 는 vCenter 하나가 한 법인(이름 = vCenter 이름).
- **줄 펼침은 표 안 줄**(시안 그대로) — 표 제목 정렬은 화면이 직접 한다(STable 의 ‘자체 정렬’ — 묶음 머리줄 · 펼친 줄이 정렬에 섞이지 않게). 못 읽은 값은 방향과 무관하게 뒤.
- **숫자 5번째 칸** 은 이 판에서 ‘지난 7일’ 대신 ‘유령 스냅샷 후보’(값이 이미 있다). ‘지난 7일’ 은 이력이 쌓인 뒤 2단계에서.
- **반증 1회(이력 DB) 확정 9건**을 고쳤다 — REST 폴백 날을 ‘0개’ 로 적던 것(높음) · 기록 시작 판정 · 점검중 한 곳이 전 함대 추이를 비우던 것 · 이름 변경을 ‘없어짐’ 으로 보던 것 · 이름만 ↔ 줄기 짝짓기 · 같은 이름 여럿 · 없어진 목록의 조용한 상한 · 백업 도구 임시 스냅샷이 매일 ‘정리됨’ 으로 쌓이던 것 · 지난 일수 기준 두 갈래(규칙 `docs/rules/vcenter.md` v3.26.0).
- 크기를 못 읽은 VM 이 있는 날의 크기 추이는 비운다(부분 합 금지 — 개수 · 기준 넘김 수는 그대로).
- 좁은 화면(720px 이하): 그림의 72시간 · 1,000일 글자와 ‘먼저 볼 것’ 글자는 감춘다(선은 남는다 — 이웃 글자와 겹쳤다).

### 2 · 3단계(v3.27.0 · v3.28.0)에서 바뀐 것

- ‘정리된 것’ 탭에는 **회수 크기를 적지 않는다** — 스냅샷 하나하나의 크기를 수집하지 않는다. 대신 숫자 칸 ‘지난 7일’ 은 ‘스냅샷을 다 지운 VM’ 의 7일 전 크기 합을 회수량으로 적는다(그 VM 의 합계라 맞는 값).
- ‘없어진 날’ 은 ‘마지막으로 본 날 ~ 없어진 것을 처음 본 날’ 범위로 적는다(하루 1번 기록이라 정확한 시각을 모른다).
- **만든 계정은 ‘그 VM 에 최근 31일 안 스냅샷을 만든 계정’** 이다 — 이벤트에 스냅샷 이름이 없을 수 있어 스냅샷 하나와 잇지 못한다. 계정 이름은 관리자 판본만, 엣지 위임 법인은 ‘모름’.
- **보류는 스냅샷 정책 판정 전체에서 빠진다**(카드 · VM 구성 점검 · 알림 포함 — 판정 코어 하나). 시안의 ‘30일 보류…’ 단추는 기간 7 · 14 · 30 · 60 · 90일과 사유(필수)를 고르는 양식이 됐다.
