🧩 서비스 인벤토리 시안 A · 3차 · 목 데이터 전체 범위 관리자 판본

VM(vCenter)과 베어메탈(iDRAC/OS)을 법인 › 폴더 › 서비스 로 묶어 봅니다. ESXi 호스트는 구성원이 아니라 그 서비스 VM 이 올라간 호스트로 파생됩니다(호스트·베어메탈 장애 → 영향 서비스가 거꾸로 나옵니다). 소속은 고정(수동) → vCenter 폴더 규칙 → iDRAC 스캔 엔트리 라벨 → 태그(선택) → 이름 규칙(선택) 순이고, 어디에도 안 걸리면 (미지정) 으로 따로 셉니다. 서비스는 사람이 만들고 자동 규칙은 기존 서비스에만 붙습니다.
미지정은 출처별(vCenter 폴더 · 스캔 엔트리)로 묶어 한 번에 연결합니다. 고정이 자동 판정과 다르면 드리프트 로 검토 목록에 오릅니다. 범위 계정은 자기 법인만 보고, 쓰기 범위가 있는 법인 관리자가 자기 법인을 바꿉니다. 못 읽은 값은 '—'(0 아님).

영향 호스트(파생)

서비스를 고르면 그 VM 이 올라간 호스트와, 그 호스트가 함께 떠받치는 다른 서비스가 나옵니다.

(미지정) — 출처별 묶음

묶음 단위로 연결하면 같은 출처의 서버가 앞으로도 자동으로 들어온다
법인 귀속이 없는 베어메탈은 통합 서버 인벤토리에서 법인을 먼저 정한다(범위 계정에는 보이지 않는다).한 대씩 예외 지정은 '⊕ 한 대씩 추가'.

매핑 안 된 값

자동 규칙이 가리키는 값인데 서비스가 없다 — 서비스는 자동으로 만들지 않는다
출처값법인대수어떻게 생겼나조치
'서비스로 만들기' = 그 값 이름의 서비스를 루트에 만들고 규칙을 붙인다(감사). '기존 서비스에 연결' = 별칭 규칙(값 → 서비스).

드리프트(고정 ≠ 자동 판정)

구성원고정된 서비스자동 판정근거조치
어느 쪽이 조용히 이기지 않는다 — 관리자가 고른다. '고정 유지' 는 검토 표지를 남긴다.

유령 키(고정이 가리키는 서버가 없음)

키고정된 서비스고정한 사람 · 시각왜
VM 키는 iu:<vCenter>:<instanceUuid>(수집 속성 추가 — instanceUuid 는 vCenter 안에서만 유일), 물리는 서비스태그. 읽지 못한 vCenter·엣지 만료 법인의 고정은 유령으로 보지 않고 '판정 보류' — 통합 서버 인벤토리 유령 키 정리(blocked)와 같은 규칙.
