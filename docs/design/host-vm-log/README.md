## 3. 정직하게 밝혀야 하는 것

1. **정각 기록은 최대 59분 전 것이다.** 14:00 기록 뒤 14:37 에 호스트가 멈추면, 그 37분 사이 DRS · 수동 이동으로 들어오거나 나간 VM 은 목록과 다를 수 있다 — 화면이 그대로 말한다(①). 줄이는 길은 질문 1(기록 간격) · 질문 2(끊김을 본 순간의 기록).
2. **기록만으로는 ‘지금 다른 호스트에서 구동 중’ 의 까닭을 모른다.** HA 재시작인지 사람이 옮긴 것인지는 vCenter 이벤트로만 가른다(§5.1 #1 — 이벤트를 받지 못했으면 ‘HA 결과 모름’, ③ 상태 7).
3. **기록 사이에 들어왔다 나간 VM 은 남지 않는다**(관측 방식의 한계 — 전원 이력과 같다).
4. **이동 빈도(DRS)를 실측하지 못했다** — 저장량은 ‘VM 수(약 5,850행) + 호스트 · 전원이 바뀔 때마다 1행’ 이라는 구조만 확실하고, 1년 뒤 행 수는 추정도 적지 않았다(구현 뒤 실측해 설정 화면에 보인다).
5. 기능을 켜기 **전**의 과거는 채울 수 없다 — 첫 기록에 이미 있던 VM 의 ‘이 호스트에 온 시각’ 은 ‘기록 시작 전부터’ 로 적고 첫 기록 시각을 도착 시각처럼 보이지 않는다(⑤ · ⑥ — 첫 기록보다 앞 시각을 고르면 ‘기록 시작 전’ 이라고 말한다 · ③ 상태 3) (VM 수량 추이의 `changes` 에 호스트 칸이 있지만 생성 · 삭제 · 전원 전환 때의 값뿐이라 ‘그 시각의 전체 목록’ 을 되살릴 수 없다 — 소급하지 않는다).
6. 호스트 이름이 바뀌면 이어 보려면 **VM 레코드에 호스트 ref 가 필요하다** — 지금은 이름뿐이다(§2). 구현 때 `hostId` 를 싣거나(엣지 정제 화이트리스트에도 추가) 이름 기준으로 두고 ‘이름이 바뀌면 끊긴다’ 고 말하거나 — 질문 6.
7. vCenter 가 그 호스트 위에서 돌다가 같이 멈추면 ‘지금’ 열은 전부 ‘모름’ 이다(③ 상태 2). 그때 목록 · IP 는 포탈 DB 에 있어 그대로 보인다. 이때 포탈에는 ‘vCenter 연결 불가’ 로 보여 **끊김 직전 기록은 남지 않는다**(정각 기록만).

## 4. 데이터 · 서버(새 vCenter 호출 없음 — 수집 결과를 읽기만 한다)

### 4.1 저장 — ‘구간’ 모델(전원 이력과 같은 방식 · 권장)
매시 5,850행을 통째로 복사하면 90일에 약 1,260만 행(5,850 × 24 × 90)이다. 대신 **VM 이 한 호스트에 같은 전원 상태로 머문 구간을 한 행**으로 둔다 — 화면이 보는 결과(‘그 시각 그 호스트의 VM’)는 같다.

- `place_spans(vcenter_id, vm_id, name, host, host_id?, cluster, power, conn, ip, guest_os, cpu, mem_mb, instance_uuid, from_ts, to_ts NULL=진행 중)` — 호스트 또는 전원이 바뀌면 앞 구간을 닫고 새 구간을 연다. 이름 · IP 는 구간 안에서 마지막으로 본 값.
- `place_slots(slot, vcenter_id, ts, hosts, vms_on, vms_total)` — **그 시각을 실제로 기록한 vCenter** 만 한 행(28 × 24 = 하루 672행). 행이 없으면 ‘기록 없음’(0대가 아니다).
- `host_spans(vcenter_id, host_id, name, cluster, state, from_ts, to_ts)` — 호스트 연결 상태 구간(끊김을 처음 본 시각 · ‘호스트가 연결돼 있던 마지막 기록’ 계산).
- 조회: `host = ? AND from_ts <= S AND (to_ts IS NULL OR to_ts >= S)` + 그 vCenter 의 슬롯 S 가 있는지. 인덱스 `(vcenter_id, host, from_ts)` · prune 용 `to_ts` 단독.
- 규약(perf-db): 한 번의 기록은 vCenter 하나당 트랜잭션 하나 + 사이사이 양보 · prune 은 스로틀(기동 첫 틱 금지) + 청크 · WAL · `util/sqliteOpen.js`. 못 읽은 vCenter 는 `samplingUnreadReasons` 로 빼고 **열린 구간을 닫지 않는다**.

### 4.2 기록기(`server/src/hostvmlog/` — 가칭)
60초 틱 + 재진입 가드(수동 실행과 공유) · 정각 슬롯 키(포탈 시각 `util/dayKey.js`) · 그 슬롯이 비어 있으면 1회 기록(포탈이 정각에 꺼져 있었으면 켜진 뒤 늦게 채운다 — `vmtrack/poller.js` 와 같은 모양) · 첫 수집 중(pending) vCenter 는 기다린다.
정각 기록이 2번 빠지면(마지막 기록이 2시간 넘게 지나면) 화면 머리가 경고한다(무음 실패 금지 — ③ 상태 6).

### 4.3 API(가칭 · 조회는 `requirePerm('tools')` + 범위)
- `GET /tools/host-vm-log` — 상태(마지막 슬롯 · 기록한 vCenter 수 · 보관) + 호스트 목록(마지막 기록의 구동 VM 수 · 지금 연결 상태) + **지금 끊긴 호스트**(끊김을 처음 본 시각 · 직전 기록 · VM 수).
- `GET /tools/host-vm-log/host?hostId&slot` — 그 시각 그 호스트의 VM + **지금 대조**(요청 때 store 스냅샷과 맞춘다: 응답 없음 · 다른 호스트 구동 · 꺼짐 · 인벤토리에 없음 · 모름) + 그 24시간의 슬롯별 수 · 변화. 범위 밖 호스트는 404.
- `POST /tools/host-vm-log/run`(지금 기록) · 보관 설정 — 관리자 + 전체 범위(`fullScopeOnly`) · 감사 로그.
- 상시 폴링하지 않는다(마운트 1회 + ‘지금 다시 조회’). ‘VM 이름 복사’ 는 화면이 받은 행으로 만든다.

### 4.4 내보내기(보드 ⑤ — 2026-11-26 18:08 추가 요구)
선례(2026-11-26 18:08 확인): ‘호스트 · 클러스터 엑셀’(v2.802 — 요약 · 호스트 목록(링크) · **호스트 1대 = 시트 1장** · 읽는 법 · 수식/조건부 서식 없음 `server/src/vcenter/hostExportXlsx.js`) ·
워커 스레드 조립(`util/xlsxWorkerRun.js`) · 시트 안 링크(`util/xlsxInternalLink.js`) · 무거운 내보내기 동시 1건(`util/exportBusy.js`) · CSV 수식 인젝션 가드 + BOM(`util/csv.js` · 웹 `util/csv.js`). 새로 만들지 않고 이것들을 쓴다.

- 조건 5가지: ① 묶는 기준(**서버별** · **날짜별**) ② 대상 호스트(이 호스트 · 이 클러스터 · 이 vCenter · 직접 고르기(‘호스트 전체’ 탭의 체크) · 볼 수 있는 전부) ③ 시각 · 기간(정각 기록 하나 · 하루 · 최근 7일 · 30일 · 직접 — 끊김 직전 기록은 멈춘 호스트 몫만 있어 ‘장애 보고’ 시트로) ④ 넣을 것(그때 꺼진 VM · 지금 위치/상태 · 서비스 · 규칙 · HA 결과 · vmx 경로 · 장애 보고 시트) ⑤ 형식(Excel · CSV).
- **서버별 Excel**: `요약` · `호스트 목록`(한 줄 = 호스트 · 이름 = 그 호스트 시트 링크 · 합계 줄) · 호스트마다 한 장(머리: ← 호스트 목록 · 이전/다음 · 합계 / VM 표 — 화면과 같은 순서) · `전체 목록`(호스트 열을 붙인 한 장 — 필터 · 피벗 · CSV 원본) · `장애 보고`(그 시각에 멈춘 호스트가 있을 때만 — 타임라인 · 멈춘 서비스 · 영향 VM) · `읽는 법`.
  호스트가 많으면 호스트 시트 대신 **클러스터마다 한 장**(상한은 서버 값 — 화면에 숫자를 박지 않는다 · 시트 이름 31자 규칙은 기존 호스트 엑셀과 같게). 여러 날을 고르면 ‘하루 한 번 · 고른 시각’ 을 호스트 시트 안 날짜 구역으로.
- **날짜별 Excel**: `요약` · `날짜별 수`(날짜 한 줄 — 기록된 시각 수 · 구동 VM 최소/최대 · 들어옴/나감) · `VM × 날짜`(칸 = 그 날 그 호스트에서 구동 중으로 **기록된 시각 수** · 빈칸 = 없었음 · 둘째 머리 행 = 그 날 기록된 시각 수 — 24 가 아닌 날을 숨기지 않는다) ·
  `배치 구간`(VM · 호스트 · 부터 · 까지 · 머문 시간 — 피벗용 원자료 · CSV 원본) · `변화` · `기록 없는 시각` · `읽는 법`. 호스트 여럿이면 `호스트 × 날짜`(칸 = 그 날 구동 VM 최대) 한 장 더 · 하루만 고르면 열이 00~23시.
- **줄 수 한도**: ‘시각마다 한 줄’ 로 풀면 5,850 VM × 24 × 30일 ≈ 421만 줄 — Excel 한 장 한도(1,048,576줄)를 넘는다. 그래서 긴 기간은 구간(`배치 구간`)과 날짜 열 표로만 낸다(저장 모델이 구간이라 그대로 나온다). 예상 줄 수는 서버가 세어 창에 보인다.
- API(가칭): `GET /tools/host-vm-log/export/plan?…`(시트 · 줄 수 · 파일 이름 — 내려받기 전 미리 계산) · `GET /tools/host-vm-log/export?…&format=xlsx|csv`(범위 강제 · 동시 1건 · 감사 로그 · 워커 조립 · 조각 + 시간 기준 양보).

6. 시안의 장면(Oracle 필수 규칙 · ERP 분리 위반 등)은 설명용으로 지은 것이다 — 실제 환경에 그런 규칙이 있는지는 모른다.

11. **1차 구현 범위** — 기본: **기록 + 끊김 직전 기록 + 내보내기 + #1(HA 결과) · #2(vmx) · 규칙 표시(분리 · 함께) · #7 · #10** 을 먼저(재료가 이미 있거나 작다). **#3 · #4 · #5 · #6 · #8 · #9 와 호스트 규칙 표시는 2차 릴리스**(수집 확장 · 메일/파일 경로 · 판정 설계가 필요). ‘한 번에 전부’ 를 고르면 규모가 크게 늘어 착수 전에 시간을 다시 추정해 묻는다.
12. **관리 VM 지정 방식** — 기본: vCenter VM 은 자동 + 나머지는 설정에서 고르기. 대안: vSphere 태그 · 이름 규칙으로 자동.
13. **오프라인 사본을 받는 곳** — 기본: 메일(받는 사람은 설정) + 포탈 서버의 파일. 대안: 법인 엣지에도 그 법인 몫을 저장(중앙이 멈춰도 법인에서 볼 수 있다 — 엣지 계약이 늘어난다).

## 6. 컨펌 질문(기본값 — ‘기본값대로’ 면 이대로 구현)

1. **기록 간격** — 기본: **1시간(요청대로 · 매시 정각)**. 대안: 10분(전원 이력과 같은 관측기 — 저장은 바뀐 것만이라 용량 차이는 작고, ‘직전 기록’ 이 최대 59분 전 → 최대 9분 전이 된다. 화면의 시각 줄은 그대로 1시간 칸으로 보이고 칸 안에서 더 가까운 기록을 고른다).
2. **끊김을 본 순간의 기록** — 기본: **남긴다**(호스트가 연결됨 → 끊김으로 바뀐 것을 본 순간, 그 직전 수집의 그 호스트 VM 목록을 한 번 더 남긴다. 메모리에 직전 배치만 들고 있다가 그때만 쓴다). 빼면 정각 기록만.
3. **끊김 알림 메일에 VM 이름** — 기본: **넣지 않는다**(알림 화면에 링크만). 넣으면 메일 본문에 직전 기록의 VM 이름(상한 있음) — 알림 경로를 고치므로 검증 범위가 늘어난다.
4. **보관 기간** — 기본: **90일**(설정에서 30일 · 90일 · 180일 · 1년). VM 수량 추이처럼 1,095일로 둘 수도 있다.
5. **내보내기** — 기본: **⑤ 대로**(서버별 · 날짜별 × Excel · CSV + 이름 복사). 창을 열면 처음 값은 서버별 · 지금 보는 호스트의 클러스터 · 마지막 정각 기록 · Excel(끊김 직전 기록은 ‘장애 보고’ 시트로).
6. **호스트 이름이 바뀐 경우** — 기본: **VM 레코드에 `hostId` 를 싣고 식별자로 잇는다**(수집 · 엣지 정제 화이트리스트 수정 포함). 대안: 이름 기준(수집을 건드리지 않는다 · 이름이 바뀌면 기록이 끊긴다).
7. **검증 수준** — 기본: **표준**(관련 테스트 + Chromium 1440/400 + 전량 verify) + 범위 404 · 못 읽은 vCenter 를 빈 목록으로 닫지 않는지 **변이 검증 1회**. ‘전체 검증’ 이면 반증 1인 추가.
8. **날짜별 표의 칸 값** — 기본: **그 날 기록된 시각 수(0~24)**. 대안: 있었음 표시만(●) — 표는 단순해지지만 ‘하루 중 얼마나’ 가 사라진다.
9. **내보내기 조건 저장**(자주 쓰는 조건을 계정별로 — VM 목록 내보내기의 ‘내 저장값’ `util/exportPrefs.js` 선례) — 기본: **넣지 않는다**(먼저 써 보고 필요하면).
10. **정기 내보내기** — §5.1 #3 ‘오프라인 사본’ 으로 대체(2026-11-27 — 시안에 그렸다. 범위는 질문 11 · 받는 곳은 질문 13).
