## 4. 설계 요지(시안의 기본값)

1. **틀은 VM 드로어 그대로**: 폭 640 · 화면 높이 전체 · 뒤 화면 가림 · 머리(상태 점 · 이름 18px · ‹ › × · 신호 배지 · 경로 줄) · 단추 줄 · 스크롤 본문 · 고정 바닥 줄. 720px 미만은 전체 화면 시트.
2. **단추 줄**: ‘iDRAC 접속’(지금의 접속 상자 `IdracConnect` 를 그대로 연다 — 웹 · 포탈 SSH · 내 PC SSH) + 폴더 고르기 · 옮기기 · 폴더에서 빼기. 지금은 폴더 구역이 본문 맨 아래라 스크롤 끝에 있다.
3. **본문 구역 순서**: 한눈에(타일 4 — CPU · 메모리 · 전력 · 부품 장애) → 24시간 추이(폭 604 · 시각 눈금 · 못 읽은 구간 표시) → 신호 → 식별 · 배치(2열 값 표) → iDRAC · 관리 → 하드웨어 요약(5칸) → 부품 목록(종류 칸 + 개수 · 모델 · 사양 정렬).
4. **바닥 줄**: 바로가기 4개(지금과 같은 링크)를 고정 — 스크롤하지 않아도 보인다. 오른쪽에 키 안내.
5. **값이 없을 때**: 타일에 ‘—’ 와 사유 버튼(지금의 `WhyTip`) · 신호 줄에 서버가 정한 사유 문구 전문(`whyText.js` 그대로) · 추이 자리에 지금 문구 그대로. 0 으로 그리지 않고 단위를 붙이지 않는다.
6. **가림 규칙은 그대로**: 범위 계정에는 서비스 태그 · 관리 주소 · 엣지 이름을 싣지 않는다(서버가 이미 그렇게 준다) · 조회 전용 법인은 폴더 단추 대신 안내 한 줄.
7. **기본값에는 서버 변경이 없다** — 응답 · 수집 · 권한은 지금 그대로, 화면 배치만 바꾼다.

## 5. 결정 필요(사용자) — 괄호 안이 시안의 기본값

1. 뒤 화면을 가릴 것인가 — (**가린다** · VM 과 같음). 가리면 드로어를 연 채 표의 다른 행을 눌러 바꾸는 지금 동작이 없어지고 ‹ › · ↑↓ 로 넘긴다. 대안: 폭 · 높이만 640 × 전체로 하고 가리지 않는다.
2. 폴더 옮기기 · 빼기 자리 — (**단추 줄**). 대안: 지금처럼 본문 맨 아래 구역.
3. ‘신호’ 구역 — (**넣는다**: 부품 장애 건수 · 사용률 값 없음 사유 · 전원 꺼짐/모름 · 임시 키). 새 판정이 아니라 행에 이미 있는 값을 줄로 옮긴 것이다. 대안: 빼고 타일만.
4. ‘추가 후보’ 7칸 중 넣을 것 — (**이번에는 없음**). 온도 · 전원 공급 장치 · 부품 상태 배지 · BIOS/펌웨어 · GPU · 랙 위치 · 성능 상세로 가기. 포탈이 이미 수집하는 값이지만 `/tools/bm-folders/hw` 응답을 넓혀야 하고 엣지 요약 서버는 빌 수 있다.
5. 부품 목록 모양 — (**줄 목록** · 종류마다 1~3줄이라 정렬할 것이 없다). 대안: `STable`(머리글 정렬).
6. 맵 보기 · 좁은 화면 카드에서 여는 창 — (**같은 드로어** · 여는 곳이 `setPanel` 하나다).

**컨펌(2026-11-26 10:39 KST)**: ‘드로어 기본값대로’ — 1 가린다 · 2 단추 줄 · 3 신호 구역 넣는다 · 4 추가 후보 없음 · 5 줄 목록 · 6 같은 드로어. 다시 묻지 않는다.

## 6. 정직 기록 — 확인하지 못한 것 · 주의

- 시안의 이름 · 주소 · 태그 · 숫자(`SELSBPDPS09` · `10.20.42.98` · `7XK4P93` · 37% …)는 **전부 그림용 가상값**이다. 첨부 화면의 실제 서버 이름 · 주소는 옮겨 적지 않았다. 부품 모델명은 첨부 화면에 보인 제품명을 썼다.
- 캔버스를 브라우저로 열어 렌더를 확인하지 않았다(Design 유형 규칙). 줄 넘침 · 겹침이 있을 수 있다 — 구현 때 Chromium 1440 · 400 으로 본다.
- 전력 타일의 출처 글자(iDRAC 실측인지)는 행 값에 표지가 없어 쓰지 않았다(‘전원 켜짐’ 만).
- 하드웨어 요약 NIC 칸의 ‘어댑터 3’ 은 상세 목록 길이다 — 요약만 있는 서버는 지금 요약(`nicText`)이 주는 글자만 쓴다(상태 B).
- ‹ › · ↑↓ 의 순서: VM 표는 화면에 보이는 정렬 순서를 `onVisible` 로 받아 넘긴다(`Vms.jsx:98 · 326`). Bare Metal Server 표는 `STable` 이 안에서 정렬한다 — **보이는 순서를 받는 길이 있는지 확인하지 않았다**(구현 때 확인).
- 값 없음 사유 상자 · iDRAC 접속 상자는 z-index 60 이다 — 드로어(z 151) 아래에 깔리므로 구현 때 올려야 한다.
- 가림막을 쓰면 드로어를 연 채 표에서 여러 대를 고르는(체크) 흐름이 끊긴다 — 결정 1 에 달려 있다.
- 실제 iDRAC · 엣지에서는 확인할 수 없다(이 컨테이너) — 구현 검증은 목 서버 + 응답 주입이다.

**시안과 달라진 점**
- 부품 줄의 개수 표지는 2개 이상일 때만(‘2 ×’) — 옛 패널과 같다. 시안은 1개에도 ‘1 ×’ 를 그렸다.
- 요약 NIC 칸: 속도 묶음이 여럿이면 값 칸에 첫 묶음만 · 나머지는 아래 줄(‘25G×2’ / ‘1G×2 · 어댑터 2’) — 1440px 에서 ‘25G×2 · 1…’ 로 잘렸다.
- 부품 장애를 못 읽은 서버는 ‘부품 장애 못 읽음’ 신호를 낸다(시안에는 없던 줄 — 못 읽었는데 ‘신호 없음’ 이라고 쓰지 않으려고).
- 상세를 받기 전에는 목록 행의 요약으로 5칸을 먼저 그린다(같은 값) · 넘기는 동안은 조회를 0.35초 미룬다(처음 열 때는 바로).
- 좁은 화면 요약은 2열 격자(시안은 1열 값 줄).
