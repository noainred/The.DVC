어떻게 재나(구현 계획)

  • 대상 서버: 수집 반복문(bash)이 30초마다 자기 /proc/$$/stat 의 utime · stime · cutime · cstime(끝난 자식 cat · grep · awk 포함)과 부모 sshd 세션의 utime · stime 을 함께 보냅니다 — 앞 값과의 차이 ÷ 경과 시간 = CPU %. 원격 명령은 그대로 상수입니다(한 줄 추가 · 사용자 입력 없음).
  • 보내는 양: 노드가 서버별로 받은 바이트를 셉니다(원격에서 따로 재지 않습니다).
  • 노드: 포탈 프로세스 CPU(process.cpuUsage) · 메모리 · 이벤트 루프 지연 · 열린 SSH 세션 수 · 서버별 해석 시간 · 기록 DB 쓰기량. 엣지는 동기화 때 이 값을 함께 보냅니다(정제 · 상한).
  • 구획별 비용: ‘부하 측정’ 을 누르면 1분 동안만 구획마다 bash 내장 times 로 앞뒤 CPU 를 재는 측정용 상수 스크립트로 바꿨다가 돌아옵니다(평소에는 재지 않습니다 — 재는 일도 비용이라).

정직하게 밝힐 것

  • CPU % 는 코어 1개 기준입니다. 서버 전체 대비는 코어 수로 나눈 값입니다.
  • ‘주기를 바꾸면’ 은 잰 구획 비용에 횟수를 곱한 추정입니다. 실제는 캐시 · 다른 부하에 따라 다릅니다.
  • sshd 몫(암호화)은 보내는 양 · 암호 방식에 따라 다릅니다. 같은 계정의 다른 SSH 세션과는 PID 로 가려 섞이지 않습니다.
  • 측정 자체도 비용입니다 — 30초마다 /proc 파일 두 개를 더 읽습니다(구획별 측정은 누른 1분만).
  • 이 시안의 서버 · 수치는 가상입니다. 모형의 기준값만 이 개발 환경(실 RHEL 아님)에서 잰 것입니다.
