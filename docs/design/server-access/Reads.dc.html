읽는 정보와 다른 기능이 쓰는 법

무엇을 읽을지는 기능이 ‘읽기 묶음’ 으로 정하고, 코어는 그 묶음을 로그인한 연결에서 돌려 줍니다. 명령은 전부 읽기 전용이고 서버 설정을 바꾸지 않습니다.

기능이 코어를 부르는 모양(안)

// 기능 쪽 — 읽기 묶음을 고정 값으로 등록(명령 + 해석)
export const DISK = defineProfile('disk', {
  linux:   { sections: { LSBLK: 'lsblk -J -b', DF: 'timeout 6 df -P -k' },
             parse: parseLinuxDisk },
  windows: { script: WIN_DISK_PS, parse: parseWinDisk },
  timeoutMs: 20000, maxBytes: 262144,
});

// 부르기 — 계정 · 비밀번호는 넘기지 않는다
const r = await readServer(
  { corp: 'KR-본사', serverId: 'kr-db-01' },
  { feature: 'server-info', profiles: [BASE, DISK], signal },
);

// 돌려받는 것

읽기 묶음의 규칙

  • 명령은 기능이 고정 값으로 등록합니다. 부를 때 글자를 이어 붙여 만들지 않습니다. 마운트 경로 같은 값은 허용 글자 검사를 통과한 것만 넣습니다.
  • 멈출 수 있는 명령에는 안쪽 시한을 걸고, 안쪽 시한의 합이 바깥 시한보다 작게 둡니다(지금 사용률 수집의 규칙과 같습니다).
  • 구획마다 줄 수 · 글자 수 상한을 둡니다. 잘린 구획은 값으로 쓰지 않습니다.
  • root 가 필요한 항목은 권한이 없으면 그 칸만 ‘못 읽음 · 권한’ 이고 나머지는 읽습니다. sudo 를 쓸지는 정해 주실 것입니다.
  • 서버 한 대에 한 번 로그인해 여러 묶음을 함께 돌립니다. 기능마다 따로 로그인하지 않습니다.
