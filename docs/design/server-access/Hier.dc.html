작동 방식 · 새로 만드는 부분

계층 관리 — 법인 › OS 종류 › 서버

계정을 서버마다 붙이지 않고, 법인이나 OS 종류 단계에 한 번 정하면 그 아래 서버가 물려받습니다. 서버에서 따로 정하면 그 서버만 다르게 씁니다. 비밀번호와 키는 지금처럼 계정 쪽에 있고, 단계에는 ‘어느 계정을 쓰는가’ 만 적습니다.

서버는 가장 가까운 단계에 정해 둔 것 하나를 씁니다. Linux 는 따로 정하지 않아 법인 것을 물려받고, Windows 는 따로 정했으므로 법인 것이 닿지 않습니다. 그림의 법인 · 서버 · 계정은 가상값입니다.

단계마다 정할 수 있는 것

정하는 것법인OS 종류서버

OS 종류는 Linux · Windows 두 가지와 ‘미지정’ 입니다. OS 마다 계정이 다르면 법인 단계는 비워 두고 OS 종류 단계에 정합니다. 법인 단계에 정한 것은 OS 를 가리지 않고 아래 전부에 닿기 때문입니다.

지금과 달라지는 점

항목지금바뀐 뒤
계정을 붙이는 곳서버마다 공통 계정을 골라 붙인다. 위에서 저절로 물려받지 않는다법인 · OS 종류 단계에 한 번 정하면 아래 서버가 물려받는다
서버의 OS 종류서버 등록부에 칸이 없다. 수집 때 알아낸 값은 메모리에만 있다서버 등록 값(Linux · Windows · 미지정)
서버 여러 대의 계정 바꾸기서버마다 고치거나 공통 계정 자체를 고친다단계 한 곳을 고친다

처음 켤 때 지금 서버들의 계정은 그대로 ‘따로 정함’ 으로 남습니다. OS 종류는 수집으로 확인된 값을 제안으로 보여 주고 관리자가 한꺼번에 승인합니다. 저절로 바꾸지 않습니다.

물려받는 규칙 일곱 가지

규칙내용지금
가까운 단계 하나가 이긴다서버에 정한 것 → 법인 › OS 종류에 정한 것 → 법인에 정한 것 순으로 처음 나오는 하나를 쓴다. 어디에도 없으면 ‘미설정’ 이고 붙지 않는다. 단계끼리 섞지 않는다새로
위를 바꾸면 물려받는 서버가 함께 바뀐다저장하기 전에 영향받는 서버 수를 보여 주고, 한 대에서 먼저 확인한 뒤에 적용한다새로
따로 정한 서버는 그대로다위 단계를 바꿔도 영향받지 않는다. ‘물려받기로 되돌리기’ 로 푼다새로
물려받기도 비밀을 주소에 묶는 일이다위 단계에 계정을 정하는 일과, 물려받는 자리에 서버를 더하는 일은 설정 소유자 등급과 본인 OTP 가 필요하다. 그 권한이 없는 관리자가 더한 서버는 ‘승인 대기’ 로 두고 물려받지 않는다넓힘 지금의 묶음 규칙과 같은 판정
OS 종류는 등록한 값으로 정한다추측해서 Linux 계정과 Windows 계정을 차례로 대 보지 않는다. 수집에서 알아낸 OS 가 등록과 다르면 ‘등록과 다름’ 으로 알리기만 한다새로
법인 경계를 넘지 않는다다른 법인의 계정 · 키는 고를 수 없다있음
정지는 계정을 따라간다계정이 로그인 거부로 정지되면 그 계정을 물려받는 서버 전부가 ‘계정 정지로 대기’ 가 된다새로

저장 모양(안)

// 단계의 지정 — 비밀은 여기에 없다(계정 id 만)
assign: {
  'KR-본사':         { account: 'a_3f21', auth: 'key' },
  'KR-본사/windows': { account: 'a_9c07', auth: 'password',
                       transport: 'winrm', port: 5986 },
}

// 서버 — 지금 등록부에 os 칸을 더한다
{ id, host, port, vcenterId: 'KR-본사',
  os: 'linux' | 'windows' | '',
  credRef, keyRef, osAuth }   // 값이 있으면 이 서버만의 지정

칸 이름은 안입니다. 서버의 credRef · keyRef · osAuth 는 지금 있는 칸이고, 비어 있을 때 위 단계를 찾아 올라가는 것이 새 동작입니다.

계정을 고르는 순서(코어)

순서보는 곳있으면
1서버에 정한 것그것을 쓴다(따로 정함)
2법인 › OS 종류에 정한 것그것을 쓴다. OS 미지정 서버는 건너뛴다
3법인에 정한 것그것을 쓴다
4없음‘미설정’ — 붙지 않는다
