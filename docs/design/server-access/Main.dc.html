서버 접속 기능 — 공통 모듈에 넣을까, 별도 기능으로 뺄까

결론: 한 덩어리로 넣지 않고 셋으로 나눕니다. 로그인에 필요한 것(접속 · 계정 · 비밀)만 공통 모듈에 두고, 무엇을 읽어 어떻게 보여 줄지는 별도 기능으로 둡니다. 요청하신 것의 절반가량은 v3.9.0 ‘SSH 공용 접속’ 에 이미 있어 새로 만들지 않고 넓힙니다.

1

공통 모듈 — 접속 · 계정 · 비밀

어느 계정으로, 어떤 방식으로, 붙어도 되는지를 정하고 실제로 로그인합니다. 모든 기능이 이 한 곳을 지납니다.

SSH 계정 · 비밀번호 / 키 로그인 · Windows 로컬 / AD · 법인 공통 계정 · 비밀번호 보관 · 로그인 실패 정지

2

별도 기능 — 서버 정보 읽기

무엇을 읽고(구성 · 디스크), 어떻게 해석하고, 얼마나 보관하고, 어디에 보여 줄지는 그 기능의 지식입니다.

읽기 묶음(명령) · 해석 · 저장 · 화면 — 공통 모듈을 불러서 씁니다

3

설정 화면 — 서버 접속

지금의 설정 › 보안 › ‘SSH 공용 접속’ 을 ‘서버 접속(SSH · Windows)’ 으로 넓힙니다. 새 메뉴를 만들지 않습니다.

비밀번호 특별 관리 부분 봉인 저장(정책: 평문 / 암호화) · 화면 가림 · 본인 OTP · 접속처가 바뀌면 승계 금지 · 로그인 실패 정지. 로그인 키는 암호화 정책에서만 받지만 비밀번호는 아직 그렇지 않다. 비밀번호도 키와 같은 수준으로 올리고 장치를 더한다 — ⑥

접속은 한 벌이어야 한다

비밀번호가 한 곳에만 있고, 한 기능에서 로그인이 거부되면 다른 기능도 그 서버에 다시 시도하지 않습니다. 같은 판정이 두 벌이면 한쪽만 고쳐지는 일이 되풀이됐습니다.

읽기는 기능마다 다르다

디스크 점검이 읽는 것과 사용률 수집이 읽는 것은 다릅니다. 이것을 공통에 넣으면 항목이 늘 때마다 공통 모듈이 바뀌고, 쓰는 기능 전부를 다시 확인해야 합니다.

이미 절반은 있다

SSH 계정 · 키 · 법인 공통 계정 · 키 보안은 v3.9.0 에 들어갔습니다. 새 모듈을 따로 만들면 저장소와 판정이 두 벌이 됩니다. 새로 만들 것은 Windows 로그인과 비밀번호 관리 장치입니다.

이 캔버스 읽는 순서 — ② 구조(누가 무엇을 맡나) → ③ 접속 한 번의 흐름 → ④ Windows 로그인 → ⑤ 설정 화면 → ⑥ 비밀번호 특별 관리 → ⑦ 읽는 정보와 다른 기능이 쓰는 법 → ⑧ 계층 관리(법인 › OS 종류 › 서버). 화면 시안의 법인 · 서버 · 주소 · 지문 · 날짜는 전부 그림용 가상값입니다.
