## 1. 요구 (사용자 2026-11-17)

> "이런 기능을 공통 모듈에 넣으면 좋은지, 별도의 기능으로 빼야 하는지 검토해줘
> 공통 모듈에 다른 모듈에서 서버에 ssh, windows 로 로그인해서 서버 구성정보,디스크 정보 등의 상세한 정보를 읽어오는 기능 만들고 싶어, ssh 는 id/pw 로그인과 password less 로그인 기능 만들어주고,
> windows 는 local 계정, ad 계정으로 로그인 하는 기능 만들어줘, 법인마다 공통 비밀번호 사용하는 긴으 만들어주고, 비밀번호는 특별하게 관리하는 기능도 만들어줘
> 세안 만들어서 보여줘, 그리고 구체적으로 어떻게 작동하는지도 기술적으로 설명해줘, 그림과 표로 설명하면 좋겠다."

읽은 뜻(추정 — 다르면 고친다): ‘세안’ = 시안 · ‘긴으’ = 기능. 배치 검토는 세 가지 안으로 비교했다(§4.1).

추가 요구(같은 날 · 시안을 본 뒤): "계정 관리는 법인/OS종류/서버 이렇게 계층적으로 관리할 수 있는 기능 추가" → ⑤ 를 트리 방식으로 바꾸고 ⑧(계층 관리)을 더했다(§4.6).

## 4. 설계 결정(시안에 그린 것)

### 4.1 배치 — 안 C: 셋으로 나눈다

- **공통 모듈**: 접속 · 계정 · 비밀(어느 계정으로 · 어떤 방식으로 · 붙어도 되는가 · 로그인 · 실행 집행 · 실패 정지 · 기록). 새 모듈을 따로 만들지 않고 **지금의 7b 키 저장소 + `sshaccess/` 를 넓힌다**
  (저장소 · 판정이 두 벌이 되지 않게 — `sshaccess/CLAUDE.md` ‘새 저장소가 아니다’).
- **별도 기능 ‘서버 정보’**: 무엇을 읽나(읽기 묶음) · 해석 · 보관 · 화면. 공통 코어를 불러 쓴다.
- **설정 화면**: 설정 › 보안 › ‘SSH 공용 접속’ 을 ‘서버 접속(SSH · Windows)’ 으로 넓힌다(설정 키 `ssh-access` 는 그대로).

안 A(전부 공통)는 공용 규칙(공용은 도메인을 모른다)과 어긋나고 읽을 항목이 늘 때마다 공통이 바뀐다. 안 B(전부 별도 기능)는 계정 저장소가 하나 더 늘고 로그인 실패 정지를 함께 보지 못한다(계정 잠금).

### 4.2 코어가 하는 일(③)

1 요청(법인 · 서버 · 기능 이름 · 읽기 묶음 — 계정은 넘기지 않는다) → 2 계정 고르기(서버 단독 → 법인 공통) → 3 로그인 방식(서버 고정 키 → 공통 계정 기본 키 → 공통 비밀번호 → 서버 비밀번호 → 없음) →
4 검사(저장소 손상 · 법인 사용 중지 · 포탈 밖 변경 · 허용 기능 · 서버 정지 · **계정 정지**) → 5 상대 확인(호스트 키 / 인증서 지문) → 6 로그인 한 번 → 7 읽기 묶음 실행(시한 · 상한) → 8 결과 · 기록.

- 키가 거부되면 비밀번호로 넘어가지 않는다(지금 규칙). WinRM 방식은 비밀번호만.
- 실행 위치: 엣지가 있는 법인은 그 엣지에서, 비밀도 그 엣지에(루트 CLAUDE.md ‘백업은 법인 로컬’ 과 같은 원칙 — WAN 왕복을 서버 수만큼 만들지 않는다).

### 4.3 Windows(④) — 1단계 SSH, 2단계 WinRM HTTPS + NTLM

- 1단계: Windows 의 OpenSSH Server + PowerShell. 새 전송 코드가 없고 로컬 · AD 계정 모두 된다(계정명 표기만 다르다). 키 로그인도 된다.
- 2단계: WinRM HTTPS(5986) + NTLM — 의존성 추가 없이 직접 구현(원격 관리 요청 · NTLM 응답). HTTP(5985) 메시지 암호화 · Kerberos 는 하지 않는다.
- AD 계정은 서버가 도메인 컨트롤러에 넘겨 확인한다 — 포탈은 도메인 컨트롤러에 붙지 않는다.

### 4.4 비밀번호 특별 관리(⑥)

키에 이미 있는 보호(암호화 정책에서만 받기 · 허용 기능 · 사용 기록)를 비밀번호 계정에도 건다. 새 장치 셋:
**한 대 먼저 확인**(저장 전 로그인 한 번) · **계정 단위 정지**(거부 한 번이면 그 계정으로 가는 접속 전부 정지 — AD 잠금 방지) · **나이 · 교체 예정일**(알리기만).
포탈은 서버 · 도메인의 비밀번호를 바꾸지 않는다.

### 4.5 읽기 묶음(⑦)

기능이 명령 + 해석을 고정 값으로 등록하고 코어는 실행 · 시한 · 상한만 집행한다. 못 읽은 구획은 값 없음(0 아님) + 이유. 서버 한 대에 한 번 로그인해 여러 묶음을 함께 돌린다.

### 4.6 계층 관리 — 법인 › OS 종류 › 서버(⑤ ⑧ · 추가 요구)

- **비밀은 계정에, 단계에는 ‘어느 계정을 쓰는가’ 만**: 공통 계정(비밀번호 · 기본 키)은 지금처럼 키 저장소에 두고, 새로 **지정**(법인 / 법인 › OS 종류 → 계정 id · 로그인 방식 · 접속 방식 · 포트)을 둔다. 서버의 `credRef` · `keyRef` · `osAuth` 는 ‘이 서버만의 지정’ 이 된다.
- **고르는 순서**: 서버에 정한 것 → 법인 › OS 종류에 정한 것 → 법인에 정한 것 → 없음(‘미설정’ — 붙지 않는다). 가까운 단계 하나가 이기고 단계끼리 섞지 않는다. 화면과 수집이 같은 함수 하나로 고른다.
- **OS 종류 = Linux · Windows · 미지정** — 서버 등록 값(새 칸). 추측해서 두 OS 의 계정을 차례로 대 보지 않는다(계정 잠금 · 다른 OS 의 비밀을 엉뚱한 서버에 보내지 않게). 수집에서 알아낸 OS 가 등록과 다르면 알리기만 한다.
  OS 마다 계정이 다르면 법인 단계는 비우고 OS 종류 단계에 정한다(법인 단계의 지정은 OS 를 가리지 않고 아래 전부에 닿는다).
- **물려받기도 묶음이다**: 위 단계에 계정을 정하는 일 · 물려받는 자리에 서버를 더하는 일은 지금의 묶음 규칙과 **같은 판정**(설정 소유자 등급 + 본인 OTP)을 지난다. 그 권한이 없는 관리자가 더한 서버는 ‘승인 대기’ 로 두고 물려받지 않는다.
- **위를 바꾸면 아래가 함께 바뀐다**: 저장 전에 영향받는 서버 수를 보이고 한 대에서 먼저 확인한다. 따로 정한 서버는 영향받지 않고 ‘물려받기로 되돌리기’ 로 푼다.
- **정지는 계정을 따라간다**: 계정이 로그인 거부로 정지되면 그 계정을 물려받는 서버 전부가 ‘계정 정지로 대기’.
- **처음 켤 때**: 지금 서버들의 계정은 그대로 ‘따로 정함’ 으로 남는다(동작이 바뀌지 않는다). OS 종류는 수집으로 확인된 값을 제안으로 보이고 관리자가 한꺼번에 승인한다 — 저절로 바꾸지 않는다.

## 7. 확인하지 못한 것 · 한계

- **Windows 쪽 동작 전부** — 이 개발 환경에 Windows 서버가 없고 저장소에도 실장비 출력 기록이 없다. ④ 의 원격 UAC 제한 · 일반 계정의 원격 조회 범위 · NTLM 정책은 일반 지식이다. 구현 뒤 실제 서버로 확인해야 한다.
- 읽기 묶음의 명령 · 항목(⑦)은 안이다 — 실제 출력으로 확정한다.
- 아트보드 높이는 어림값이다(브라우저 렌더 확인 없음).
- 코드 예의 함수 · 칸 이름(`readServer` · `defineProfile` · `win-local` · `win-ad` 등)은 안이다.
