작동 방식

접속 한 번에 일어나는 일

기능은 ‘어느 법인의 어느 서버에서 무엇을 읽을지’ 만 말합니다. 계정과 비밀번호는 기능이 만지지 않고, 아래 여덟 단계를 코어가 순서대로 합니다.

1

요청

기능이 법인 · 서버 · 기능 이름 · 읽기 묶음을 넘깁니다. 계정 · 비밀번호는 넘기지 않습니다.

2

계정 고르기

서버 → 법인 › OS 종류 → 법인 순으로, 가장 가까운 단계에 정해 둔 계정을 씁니다(⑧).

3

로그인 방식 고르기

키가 있으면 키, 없으면 비밀번호입니다. 둘 다 없으면 ‘미설정’ 으로 끝내고 붙지 않습니다.

4

붙어도 되는지 검사

법인 사용 중지, 로그인 실패 정지, 이 기능에 허용된 계정인지, 저장소를 읽을 수 있는지를 봅니다.

5

상대 확인

SSH 는 호스트 키 지문, WinRM 은 인증서 지문이 승인된 것과 같은지 봅니다. 다르면 비밀번호를 보내지 않습니다.

6

로그인

한 번만 시도합니다. 거부되면 다시 시도하지 않고 정지 기록을 남깁니다(계정 잠금 방지).

7

읽기 묶음 실행

기능이 미리 등록한 고정 명령만 돌립니다. 시한과 출력 상한이 있고, 서버를 바꾸는 명령은 없습니다.

8

결과 · 기록

구획별 값과 실패 사유를 돌려주고 사용 기록을 남깁니다. 못 읽은 구획은 0 이 아니라 값 없음입니다.

계정과 로그인 방식을 고르는 순서 — 위에서부터 먼저 맞는 것 하나

먼저 단계를 고릅니다. 서버에 정한 것이 있으면 그것, 없으면 법인 › OS 종류, 그것도 없으면 법인에 정한 것입니다(⑧). 아래 표의 ‘공통 계정’ 은 그렇게 물려받은 계정을 뜻합니다.

순서쓰는 것언제지금
1서버에 고정한 키그 서버에 쓸 키를 이름으로 지정했을 때(SSH 방식)있음
2공통 계정의 기본 키서버가 법인 공통 계정을 쓰고 그 계정에 기본 키가 있을 때있음
3공통 계정의 비밀번호키가 없거나, 그 서버를 ‘비밀번호로 고정’ 했을 때있음
4서버 단독 비밀번호공통 계정을 쓰지 않는 서버있음
5없음 — 붙지 않는다위가 전부 비었을 때. 화면에는 ‘미설정’있음
  • 키가 거부되면 비밀번호로 몰래 넘어가지 않습니다. 로그인 방식은 한 번에 하나입니다.
  • 공통 계정을 쓰는 서버는 계정명도 공통 계정의 것을 씁니다. 서버 칸의 기본 계정명으로 공통 비밀번호를 보내지 않기 위해서입니다.
  • Windows 를 WinRM 으로 붙을 때는 비밀번호만 씁니다. 키 로그인은 SSH 방식에서만 됩니다 새로

붙지 않는 경우 — 4 · 5단계에서 막힘

사유뜻푸는 방법지금
저장소를 읽지 못함키 · 계정 파일이 손상됐거나 암호를 풀지 못했다설정 소유자가 OTP 로 ‘다시 읽기’있음
법인 사용 중지관리자가 그 법인의 저장 계정 · 키 사용을 긴급히 멈췄다사용 재개있음
포탈 밖에서 바뀜계정 · 키 파일이 화면을 거치지 않고 고쳐졌다확인한 뒤 받아들이기있음
허용 기능이 아님이 계정 · 키를 이 기능에 쓰도록 허락하지 않았다허용 기능 수정넓힘 키에만 있다 → 비밀번호 계정에도
서버 로그인 실패 정지직전에 이 서버가 로그인을 거부했다계정을 고치거나 ‘다시 확인’있음
계정 로그인 실패 정지같은 공통 계정이 거부됐다. 다른 서버에도 같은 비밀번호를 보내면 AD 계정이 잠긴다비밀번호를 확인한 뒤 한 대로 다시 확인새로
상대가 다름호스트 키 · 인증서 지문이 승인된 것과 다르다설정 › 장비 신뢰에서 확인 · 승인넓힘 SSH 는 있다 → WinRM 인증서도

실패했을 때

실패코어가 하는 일기능이 받는 것
로그인 거부다시 시도하지 않는다. 서버와 계정에 정지 기록사유 ‘인증 거부’ · 값 없음
연결 불가로그인 실패로 세지 않는다(정지하지 않는다)사유 ‘연결 불가’ · 값 없음
시한 초과세션을 실제로 끊는다. 잘린 출력은 쓰지 않는다사유 ‘시한’ · 값 없음
명령 없음 · 권한 부족그 구획만 ‘없음’ 또는 ‘못 읽음’ 으로 표시나머지 구획은 정상 값

어디서 접속하나

법인접속하는 곳비밀이 있는 곳중앙이 받는 것
엣지가 있는 법인그 법인의 엣지엣지의 설정 폴더결과 · 상태 · 지문(비밀 없음)
엣지가 없는 법인중앙중앙의 설정 폴더해당 없음

일부 법인은 왕복 지연이 800ms 를 넘습니다. 서버 수만큼 중앙에서 왕복하지 않도록 작업 하나를 엣지에 보내 그 안에서 묶어 돌리고 요약만 올립니다. 비밀번호도 법인 밖으로 나가지 않습니다.
