비밀번호 특별 관리

법인 공통 비밀번호는 하나가 새면 그 법인 서버 전체가 열립니다. 그래서 로그인 키에 이미 걸려 있는 보호를 비밀번호에도 똑같이 걸고, 비밀번호에만 필요한 장치 세 가지를 더합니다.

공통 계정 — 비밀번호 바꾸기

KR-본사 · 그림용 가상값
종류
서버에 보내는 이름 CORP\svc-portal
접속 방식
저장한 뒤에는 누구도 다시 볼 수 없습니다. 틀렸으면 새로 넣습니다.
이 서버에 한 번만 로그인해 봅니다. 실패하면 저장하지 않고 다시 시도하지도 않습니다.
이 계정을 쓸 수 있는 기능
누르면 하는 일 — 저장 정책이 암호화인지 확인 → 고른 서버 한 대에 로그인 한 번 → 성공하면 봉인해 저장하고 계정 정지를 풉니다 → 나머지 15대는 다음 수집 때부터 새 비밀번호를 씁니다.

보호 장치 열두 가지

장치하는 일지금
암호화해서만 받는다저장 정책이 암호화일 때만 새 공통 비밀번호를 받는다. 평문 정책이면 거절하고 이유를 말한다넓힘 키에만 있다
다시 보여 주지 않는다화면 · 응답 · 로그 · 감사 기록 · 백업 묶음 · 엣지 전송 어디에도 원문이 없다있음
본인 OTP등록 · 변경 · 삭제는 설정 소유자 등급과 본인 OTP 를 함께 요구한다있음
한 대 먼저 확인저장하기 전에 고른 서버 한 대에서 로그인이 되는지 본다새로
계정 단위 정지로그인 거부가 한 번 나오면 그 계정으로 가는 접속을 전부 멈춘다. 자동으로 다시 시도하지 않는다새로 서버 단위는 있다
승계 금지법인 · 종류 · 계정명 · 접속처가 바뀌면 저장된 비밀번호를 이어 쓰지 않는다있음
허용 기능이 계정을 쓸 수 있는 기능을 정한다. 목록에 없는 기능은 이 계정으로 붙지 못한다넓힘 키에만 있다
사용 기록언제 · 어느 기능이 · 어느 서버에 · 성공인지 실패인지. 비밀번호는 기록하지 않는다넓힘 키에만 있다
나이 · 교체 예정일등록한 지 며칠인지, 교체 예정일이 지났는지 보여 준다. 알려 주기만 한다새로
바꿔치기 감시계정 파일이 화면을 거치지 않고 바뀌면 그 계정을 쓰지 않고 사건으로 남긴다있음
긴급 사용 중지법인 단위로 저장 계정 · 키 사용을 한 번에 멈춘다있음
백업 가림백업 묶음에는 이름과 지문만 싣고 비밀은 가린다있음

막지 못하는 것

  • 포탈 서버의 관리자 권한을 빼앗기면 봉인 파일과 열쇠를 함께 읽을 수 있습니다.
  • 대상 서버가 비밀번호 로그인을 받는 한, 비밀번호가 다른 길로 새면 포탈은 알 수 없습니다. 가능한 서버는 키 로그인으로 옮기는 것이 근본 대책입니다.
  • 포탈이 다시 시작하면 그때의 파일이 새 기준이 됩니다(바꿔치기 감시의 한계).

하지 않는 것

  • 서버나 도메인의 비밀번호를 포탈이 바꾸지 않습니다. 교체는 사람이 하고 포탈에는 새 값을 넣습니다.
  • 비밀번호를 여러 개 차례로 대 보지 않습니다.
  • 중앙에서 넣은 비밀번호를 엣지로 내려보내지 않습니다. 엣지가 있는 법인은 그 엣지 화면에서 넣습니다(지금 규칙 — 바꿀지는 정해 주실 것).

저장 모양(안)

// 키 저장소의 공통 계정 한 건
// 새 칸: win 종류 · domain · transport · features · rotateBy · verified
{
  kind: 'os' | 'idrac' | 'win-local' | 'win-ad',
  corp, name, username,
  domain,        // win-ad 만
  transport,     // 'ssh' | 'winrm'
  keyRef,        // 기본 키(SSH 방식)
  password,      // 봉인 — 응답에 없음
  features: [],  // 허용 기능
  rotateBy,      // 교체 예정일
  verifiedAt, verifiedOn  // 한 대 확인
}

칸 이름은 안입니다. 저장 파일과 봉인 방식은 지금 키 저장소를 그대로 씁니다.
