# 지도 칸 글자 — 작은 칸도 읽히게(시안)

- 상태: **시안(컨펌 대기)** — 제품 코드 변경 없음. 구현은 컨펌 뒤 Opus.
- 캔버스(Claude Design · 비공개): https://claude.ai/artifact/E7RGUQQWYhDGuVGAd8prTa — 아래 줄 오른쪽 **⑩ `TileText.dc.html`**(눌러 보는 보드). 보드 사본은 이 폴더의 `TileText.dc.html`.
- 대상: `web/src/views/insight/` 의 묶음 지도(‘가상화 호스트 현황’ · ‘VM 현황’ 공용 — `treemap.js` · `Treemap.jsx` · `insight.css`).

## 1. 요구(사용자 2026-11-18 21:04 KST · 캡처 2장)

> "너무 작은 곳은 글자가 너무 작게 나와, 개선해줘, 클로드 디자인으로 페이블로 디자인해줘"

캡처는 ‘가상화 호스트 현황’ 을 자동 높이(1,200px)로 본 것 — 한 지역에 클러스터가 20개 넘게 몰려 아래쪽 칸이 얇은 띠가 되고 글이 반쯤 잘려 있다. (같은 메시지의 2번 ‘크기 조정 메뉴는 설정을 누를 때만’ 은 v3.22.1 에 반영했다.)
캡처의 실제 클러스터 이름은 시안 · 이 문서에 옮기지 않았다.

## 2. 지금 코드에서 확인한 것(v3.22.1)

| 무엇 | 어디 | 사실 |
|---|---|---|
| 배치 | `insight/treemap.js treemapLayout` | 지역 = 세로 한 줄(폭 = 지역 몫) · 그 안에서 칸은 **가로 띠**(높이 = 그 지역 안의 몫). 칸의 폭은 늘 지역 폭 전체다. |
| 글자 | `insight.css .ins-tl b · span` | 이름 12.5px · 값 11.5px **고정**. 칸 높이가 46px 아래면 한 줄(`tileLineMode`). 더 낮아도 글을 그대로 그려 위아래가 잘린다. |
| 지도 높이 | `insightPrefs.js` | 300 ~ 1,200px. 자동 = 가장 긴 지역의 칸 수 × 64(360 ~ 1,200). |
| 좁은 화면 | `Treemap.jsx` | 720px 이하는 지역을 세로 띠로(v3.21.0) — 이번 시안은 넓은 화면만 다룬다. |

## 3. 시안 — ⑩ 한 보드에서 여섯 방식을 바꿔 본다

노란 상자(시안용)의 단추: **보기 방식** 지금 · A · B · C · D · 추천 / **클러스터 수** 25(목 서버 규모) · 39(캡처와 비슷한 모양) · 80(한 지역에 46개) / **지도 높이** 520 · 760 · 1,200.

| 방식 | 무엇을 바꾸나 |
|---|---|
| 지금 | 비교 기준 |
| A · 네모 배치 | 지역 안을 가로세로로 나눠 칸을 네모에 가깝게(squarified treemap) |
| B · 글자 크기 | 배치는 그대로 · 칸 크기에 따라 네 단계(16/13 · 13.5/12 · 한 줄 12.5 + 값 · 글 없음) — 12px 아래로 내려가지 않는다 |
| C · 작은 칸 묶기 | 배치는 그대로 · 이름이 안 들어가는 칸이 한 지역에 둘 이상이면 ‘그 밖 N개’ 한 칸으로 — 누르면 아래에 목록 |
| D · 여러 열 | 칸이 많은 지역만 두세 열로 나눈다(열 폭 170px 아래로는 나누지 않음 · 가장 낮은 칸이 30px 이상이 되는 가장 적은 열 수) |
| **추천 · B + C + D** | 여러 열 → 글자 단계 → 그래도 남는 작은 칸만 묶기 |

묶음 칸: 빗금 무늬 · 색은 묶음 안에서 **가장 높은 값** · ‘못 버팀’ 이 있으면 수를 적는다 · 목록은 값이 높은 순.

클러스터 25개(목 서버 규모)는 어느 방식 · 높이에서도 25개가 다 보인다(A 의 760 에서만 1개 잘림).

읽는 법:
- **D(여러 열)가 가장 크게 듣는다** — 캡처와 비슷한 39개에서는 520px 에서도 전부 읽힌다. 지금 배치의 문제는 폭이 아니라 **높이**다.
- B 만으로는 읽히는 수가 늘지 않는다(잘린 글이 ‘글 없음’ 으로 바뀔 뿐) — 잘린 글자를 없애고 큰 칸을 더 잘 보이게 하는 몫이다.
- C 는 D 로도 모자랄 때(80개 · 낮은 지도)의 안전망이다 — ‘잘림 · 글 없음’ 을 0 에 가깝게 만들고 나머지는 목록으로 읽는다.

## 5. 정직하게 밝혀야 하는 것

- **정정 — A(네모 배치)는 틀린 가설이었다.** 2026-11-18 21:10 조사 보고에서 ‘지역 안을 2차원으로 나누면 얇은 띠가 사라지고 글이 들어갈 폭이 생긴다’ 를 첫 안으로 적었다. 세어 보니 칸 폭이 60 ~ 100px 로 좁아져 이름이 **더 많이** 잘렸다(39개 · 520px 에서 31 → 17). 추천에서 뺐고, 비교할 수 있게 보드에만 남겼다.
- 수는 **추정**이다 — 글자 폭을 어림해(영문 굵은 글자 = 글자 크기 × 0.62 · 한글 × 0.95) 칸 안쪽 폭 · 높이와 견준 것이고, 브라우저가 그린 폭을 잰 것이 아니다. 경계에 걸린 칸은 한두 개 달라질 수 있다. 이름 길이가 다르면(실제 이름이 더 길면) 수가 달라진다.
- 클러스터 이름 · 값은 **지어낸 가상 값**이다. 39개 · 80개 모양은 내가 만든 것이고 실제 환경(28 vCenter)의 분포가 아니다.
- **캔버스에서 띄워 눌러 보지 않았다**(Design 캔버스는 요청이 있을 때만 검증). 확인한 것은 보드 스크립트의 논리다 — node 에서 3규모 × 3높이 × 6방식 54가지를 돌려: 칸이 지도 밖으로 나가지 않음 · 겹침 0 · 넓이 합 = 지도 넓이 · 칸 넓이가 호스트 수에 비례 · 읽힘 분류의 합 = 클러스터 수 · 템플릿 값 누락 0 · 단추(방식 · 규모 · 높이 · 묶음 열기/닫기 · 칸 선택) 동작. 글자가 실제로 어떻게 그려지는지는 재생으로 봐야 안다.
- D 는 칸의 **넓이**가 호스트 수에 비례한다(지금은 높이가 비례). 열 폭은 그 열에 든 칸의 몫이라 열마다 조금씩 다르다. 큰 것부터 왼쪽 열 위에서 아래로 놓인다.
- 400px(세로 띠)는 이번 시안에 넣지 않았다 — v3.22.0 의 ‘좁은 칸은 색과 표만’ 규칙 그대로다.

## 7. 구현 메모(컨펌 뒤 · Opus)

- `treemap.js treemapLayout`: 열 안 배치를 ‘여러 열’ 로(순수 함수 · 시험: 넓이 합 · 비례 · 겹침 0 · 열 폭 하한 · 열 수 상한). 반환 모양(`cols[].tiles[]` 의 left · top · width · height %)은 그대로 두면 `Treemap.jsx` 와 좁은 화면 띠가 깨지지 않는다 — 좁은 화면은 지금처럼 한 열 배치를 쓴다.
- 글 판정은 칸의 **실제 px**(폭 % × 지도 폭 · 높이 % × 지도 높이)로 — 지도 폭은 `ResizeObserver` 또는 컨테이너 쿼리. 글자 폭을 어림식으로 재지 말고, 넘치면 말줄임에 맡기되 단계(16/13 · 13.5/12 · 한 줄 · 없음)만 px 로 고른다.
- 묶음은 화면에서 만든다(서버 응답은 그대로) — 묶음 칸의 값 = 구성원의 최댓값, ‘못 버팀’ 수, 목록은 `STable`(제목 클릭 정렬). 묶음 칸을 눌러도 법인 선택은 바뀌지 않는다(목록의 줄을 누르면 그 법인 선택).
- 접근성: 묶음 칸 `aria-expanded` · 목록 패널에 제목 · 글 없는 칸도 `title` · `aria-label` 에 이름과 값.
- 기준값(170px · 30px · 220×96 등)은 한 곳의 상수로 · 시험으로 고정.
