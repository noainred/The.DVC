## 3. 새로 필요한 수집 — LLDP 이웃(부품 주기)

- 후보 경로(⚠ **실장비 미확인 추정** — 기존 규약대로 후보 체인 + ‘읽은 경로’ · 원문 표본으로 좁힌다. 기본값으로 굳히지 않는다):
  `/api/v1/rest/{serial}/Sysdb/l2discovery/lldp/status/local/1/portStatus`(포트별 `remoteSystem` 아래 `sysName` · 상대 포트 id). CVP 자체의 토폴로지 조회 API 가 있으면 그쪽이 장비당 왕복이 적다 — 미확인.
- 주기: 설명 · 트랜시버와 같은 **부품 주기**(기본 30분) — 매 수집 주기에 싣지 않는다(장비당 요청 수 · 800ms+ 법인).
- 저장: `port_latest` 에 `lldp_sys` · `lldp_port` · `lldp_at` 열 추가(NULL = 못 읽음 · `''` = 이웃 없음 — 설명과 같은 규약). push 레코드 해시에 들어가므로 바뀐 장비만 간다.
- 엣지 push 필드가 늘면 **중앙 정제 화이트리스트에도** 넣는다(길이 상한 · 문자열만). 판정(§4)은 **중앙에서 조회 시** 한다(엣지는 원본만 올린다 — 엣지 업그레이드 전에도 사용/예비는 나온다).
- 알아 둘 것(일반 지식 — 이 환경에서 미확인): Arista EOS 는 CDP 를 처리하지 않고 LLDP 만 쓴다 · ESXi 표준 vSwitch 는 CDP 만 보내고 LLDP 는 분산 스위치(vDS)에서 켜야 한다 ·
  스토리지 포트는 LLDP 를 안 보내는 경우가 있다. → **LLDP 이웃이 비는 포트가 적지 않을 수 있고**, 그때는 설명이 유일한 근거다(화면이 ‘설명만’ 이라고 말한다).

## 4. 판정 규칙(순수 함수 하나 — 웹 · 서버가 복제하지 않는다)

### 4.1 포트 분류(사용 · 예비)

| 분류 | 조건 | 개수에서 |
|---|---|---|
| 사용 중 | `oper === 'up'` | 사용 |
| 확인 필요 | 링크 없음 + 설명 **있음** + 관리상 켜짐 | 예비 아님 — 끊겼거나 연결 예정(기존 장애 판정 ‘admin up + oper down’ 과 겹친다 — 장애 여부는 기존 장애 화면이 말한다) |
| 예비 · GBIC 꽂힘 | 링크 없음 + 설명 **없음**(`''`) + 관리상 켜짐 + 트랜시버 장착 | 예비(케이블만으로 사용) |
| 예비 · 빈 케이지 | 위와 같고 트랜시버 없음 | 예비(GBIC 필요). 트랜시버 목록을 못 읽은 장비는 둘로 가르지 않고 ‘예비(GBIC 미확인)’ |
| 관리상 꺼짐 | `admin === 'down'` | 따로(켜면 쓸 수 있지만 의도적으로 막은 포트일 수 있다 — 컨펌 질문 ②) |
| 확인 불가 | `oper` 를 모름, 또는 링크 없음인데 설명이 `null`(못 읽음) | 따로 — **예비로 세지 않는다** |

- 대상은 물리 이더넷 포트만(`Ethernet*`). `Management*` 는 그리되 개수에서 뺀다. Port-Channel · Vlan · Loopback 은 그리지 않는다. 브레이크아웃(`Ethernet49/1~/4`)은 한 케이지에 묶어 그린다(시안은 `/1` 만).
- ‘마지막 링크 기록’ 은 참고 표시다. 기본 판정에 넣지 않는다(‘N일 넘게 링크가 없으면 예비’ 는 컨펌 질문 ③).

### 4.2 연결 장비와 근거

| 근거 | 조건(링크 올라온 포트) | 표시하는 장비 |
|---|---|---|
| 설명·LLDP 일치 | 설명 안에 LLDP `sysName`(도메인 제거 · 대소문자 무시)이 토큰으로 들어 있음 | LLDP 이웃 |
| 설명·LLDP 불일치 | 둘 다 있는데 다른 이름 | **LLDP 이웃**(지금 붙어 있는 상대) + ‘설명이 낡았을 수 있음’ |
| LLDP 만 | 설명 없음 | LLDP 이웃 |
| 설명만 | LLDP 이웃 없음(`''`) | 설명에서 뽑은 이름 — **확인한 연결이 아님**을 밝힌다 |
| 근거 없음 | 둘 다 없음 | ‘미확인 장비’ |
| (LLDP 못 읽음) | `lldp_*` 가 NULL | 설명만으로 표시하고 일치/불일치는 판정하지 않는다 |

- 설명에서 이름을 뽑는 규칙은 길이를 먼저 자르고(200자 — 이미 파서 상한) 선형으로 토큰을 나눈다(앵커 없는 무제한 반복 금지 — 장비 출력은 외부 입력이다).
- ‘포탈 인벤토리’ 는 이름이 같은 장비가 있을 때만 종류(ESXi 호스트 · 스위치 · 스토리지 · 서버)를 붙인다. 없으면 ‘같은 이름의 장비 없음’ — 종류를 추측하지 않는다.
  ⚠ CVP 는 vCenter 귀속이 없어 범위 계정은 403 이다(기존 규칙) — 그래서 이 화면에 다른 법인 호스트 이름이 범위 계정에게 새지 않는다. 구현 때 이 게이트를 그대로 둘 것.

## 5. 화면(IA) — 기본 셸, CVP 도구의 새 탭 `portmap`(‘인터페이스 세부 정보’ 다음)

```
CVP › 포트 구성도
 ├ [전 스위치 여유 | 스위치 1대]                    ← 보기 전환(해시에 싣는다)
 ├ 스위치 1대 (Main · Evidence · Narrow)
 │   ├ 장비 검색 · 선택 · 새로고침 · 수집 시각(주기 숫자는 API 값)
 │   ├ 포트 사용 · 예비: 한 줄 요약 · 전체 막대 · 칸 4개 · 속도(포트 종류)별 막대
 │   ├ 전면 포트 구성: 색 기준 ‹사용·예비 | 연결 근거 | 트래픽 사용률› · 구성도 · 범례
 │   ├ 선택한 포트: 연결 장비 · 근거 · 판정 문장 · 설명/LLDP/인벤토리/링크/트랜시버/VLAN·LAG/사용률/마지막 링크
 │   └ 포트별 연결 장비 표(STable — 머리글 정렬 · 필터 칩 6개)
 └ 전 스위치 여유 (Capacity)
     ├ 법인 칩 · ‘여유 부족만’ · 칸 6개
     └ 스위치별 표: 전체 · 사용 · 예비(GBIC 꽂힘 + 빈 케이지) · 확인 필요 · 꺼짐 · 분포 막대 · 100G 예비 · 근거 확인할 것
```

- **구성도는 모델 도면이 아니다** — 포트 번호 규칙으로 그린다: 고정형은 12포트 블록 · 홀수 위/짝수 아래, 속도(또는 트랜시버 폼팩터)가 바뀌는 곳에서 블록을 나눈다.
  모듈형은 포트 이름의 첫 숫자로 슬롯마다 한 줄(`States.dc.html`). 화면이 이 사실을 말한다. 모델별 실물 배치표는 두지 않는다(컨펌 질문 ④).
- 포트 칸은 `<button>`(키보드 이동) · `title`/`aria-label` 에 포트 · 분류 · 연결 장비 · 근거. 색만으로 가르지 않는다(예비 = 파랑 실선/점선 · 꺼짐 = 취소선 · 근거 문제 = 모서리 점).
- 폴링 없음 — 마운트 1회 + 새로고침(무거운 API 규칙). 장비를 바꿀 때 늦게 온 이전 응답은 버린다(`CvpInterfaces.jsx` 와 같은 `active` 가드).
- 400px: 12포트 블록이 한 줄씩 쌓이고(가로 넘침 0) 표만 상자 안에서 가로 스크롤.
- 상태(`States.dc.html`): LLDP 못 읽음 · 설명 못 읽음(예비 ‘—’ · 확인 불가로) · 포트 목록 못 읽음(구성도를 그리지 않음 · 전 스위치 표에서 합계 제외).

## 6. 서버(안)

- `GET /tools/cvp/device` 응답의 `ports[]` 에 `lldp:{sys,port,at}` · `lastLinkDay` 추가 + `portmap:{counts, bySpeed}`(§4 순수 함수 `cvp/portmap.js` — 웹은 이 결과를 그리기만 한다).
- 새 `GET /tools/cvp/portmap/summary` — 전 스위치 개수 표. `port_latest` 한 번 훑기(28 법인 · 수백 대 × 64포트 수준 — `portUsage` 와 같은 규모) · `memoJson` + `extraKey: scopeKey(...)` ·
  게이트는 형제 라우트와 같게(`toolsPerm` + `fullScopeOnly`) · ‘여유 부족’ 기준은 CVP 설정값(기본 4 — 화면에 숫자를 박지 않는다).
- 비-admin 응답: 관리 주소는 기존대로 가림. LLDP `sysName` 은 호스트 이름이라 가리지 않되, LLDP 관리 주소(management address TLV)는 **수집하지 않는다**.

## 7. 컨펌 받을 것(답이 없으면 괄호 값으로)

1. ‘사용량 · 예비량’ = **포트 개수** 기준이 맞는지(기본: 맞다 · 트래픽 사용률은 색 기준 한 칸).
2. 관리상 꺼진(shutdown) 포트를 예비에 넣을지(기본: 넣지 않고 따로).
3. 설명은 있는데 오래 링크가 없는 포트를 예비로 돌릴지(기본: 안 돌림 — ‘확인 필요’ 로 남기고 마지막 링크 날짜만 표시).
4. 구성도 배치: 포트 번호 규칙(기본) vs 주요 모델 실물 배치표를 따로 관리.
5. LLDP 수집 추가(기본: 추가 — 엣지 업그레이드 필요 · 실장비 원문 표본으로 경로 확정 전까지 ‘LLDP 못 읽음’ 상태로 나올 수 있다). 빼면 근거는 설명뿐이고 일치/불일치 검증이 없다.
6. 전 스위치 여유 표(④)를 같이 낼지(기본: 같이) · ‘여유 부족’ 기준(기본: 예비 4개 이하).
7. 검증 수준(기본: 표준 — 관련 테스트 + Chromium 1440/400 + 전량 verify. 엣지 수신 계약이 바뀌므로 **중앙 정제 · push 경로 변이 검증 1회** 포함).

## 8. 시안 확인 기록(이 세션)

- 5장 모두 로컬 Chromium 으로 렌더(런타임 `support.js` + React UMD 를 로컬로 대체): 1440 · 400 에서 pageerror/console error 0 · 가로 넘침 0(States 400 은 648px 넘침을 발견해 슬롯 격자를 상자 스크롤로 고침).
- 판독으로 고친 것: 포트별 표가 비어 있었다(`<table>` 안의 반복 태그가 밀려남 → 격자 행) · 1440 에서 마지막 열이 잘림(열 폭 재배분) · 전체 막대의 ‘꺼짐’ · ‘빈 케이지’ 색이 배경과 구분되지 않음(색 교체).
- 클릭 확인: 색 기준 3종 · 필터 칩 · 포트 선택(구성도 ↔ 표) 동작. ⚠ 캔버스(claude.ai) 안에서의 렌더는 직접 보지 못했다 — 같은 런타임 파일의 로컬 렌더다.
