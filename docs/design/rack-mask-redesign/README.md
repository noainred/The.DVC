## 3. 왜 구조를 바꾸는가

지금 구조의 결함은 코드 품질이 아니라 **구조**에 있다.

1. **기본이 열림이다 — 칸에서도, 재료에서도.** 가릴 칸을 하나씩 지정하므로 잊은 칸은 원문으로 나가고(2절 10종), 가림 재료가 비면 가림도 빈다(재시작 · 엣지 끊김).
2. **글을 고쳐 쓴다.** 낱말 일부만 가리면 꼬리가 남고, 넓히면 평범한 낱말이 지워진다. 못 가림과 과잉 가림이 서로 반대 방향이라 2~5회차 결함 여럿이 ‘앞 회차 수정이 만든 회귀’ 였다.
3. **관리자에게 보이지 않는다.** 관리자는 원문을 보므로 가림이 틀려도 모른다. 틀린 결과는 조회 계정 화면에서만 드러나고, 잘못 가려진 것을 사람이 바로잡을 손잡이도, 놓친 것을 사람이 가릴 손잡이도 없다.

## 5. 안 B′ 설계

### 5.1 불변조건(시험이 고정할 것)

- **J1 화이트리스트 투영**: 조회 계정 응답은 칸 목록에 적힌 칸만 싣는다(객체를 펼쳐 싣지 않는다). 새 칸은 등급(모두 / 시리얼을 보는 판본 / 관리자)을 주기 전에는 나가지 않는다.
- **J2 통째 판정**: 원장의 자유 글은 응답에 실리기 전에 `보이는가(글, 판본)` **하나**를 지난다 — 보이면 원문 그대로, 아니면 대체 표시. 글을 고쳐 쓰지 않는다.
- **J3 기계 판정은 저장하지 않는다**: 판정은 읽을 때 지금 재료로 계산한다(재료 세대별로 기억). 저장하는 것은 사람의 결정뿐이다.
- **J4 재료는 줄지 않는다**: 한 번 본 주소 · 태그는 원장 옆에 남는다 — 재시작 · 엣지 끊김 · 서버 삭제로 가림이 풀리지 않는다. 재료가 늘면 세대가 오르고 다음 조회부터 반영된다.
- **J5 승인은 걸린 키에 묶인다**: 승인 = (글, 그때 걸린 키들). 새 키가 걸리면 그 글은 다시 숨겨진다. 관리자가 본 키와 승인 시점의 키가 다르면 승인을 거절한다.
- **J6 이력은 구조로**: 새 이력 · 판 차이는 `{동작, 대상 id, 그때의 이름 글, 그때의 종류 · 모델 글, 랙 id · 랙 이름 글, U}` 로 저장하고 글마다 J2 를 지난다. 조회 계정 응답에는 이름을 이어 붙인 문장을 싣지 않는다(화면이 그린다).
- **J7 표식 시험**: 공개가 아닌 모든 칸(관리 메모 · 숨겨진 글 · 범위 계정의 시리얼 · 등록 주소 · OS 호스트 이름 · 작업자)에 서로 다른 표식 글자를 심고, 조회 계정 2종의 모든 응답 바이트(오류 본문 · 헤더 포함)에 표식이 한 번도 없는지 본다.

```
  ∧ ( 걸린 키가 없다  ∨  승인이 있고 걸린 키 ⊆ 승인 때의 키 )

걸린 키 = 지금 재료(주소 · 태그)와 꼴 판정(IP · MAC)으로 그 글에서 찾은 것
판본: 주소에 걸린 글은 관리자만 · 태그에만 걸린 글은 시리얼을 보는 판본까지(지금 규칙 그대로)
```

- 검사기는 지금의 판정 조각(`hasIpv4` · `hasIpv6` · 주소 색인 · 태그 색인)을 다시 쓰되 **고쳐 쓰는 부분을 버린다**. 답은 걸린 키의 목록이다.
- 잘못 잡는 값이 ‘조용히 지워짐’ 에서 ‘승인 한 번’ 으로 바뀌므로 경계 규칙은 재현율 쪽으로 다시 맞출 수 있다 — 얼마나 넓힐지는 결정 4.
- 판정에 쓰는 글 = 화면에 그리는 글 = 승인의 키가 같은 글이어야 한다. 쓰기에서 NFKC(전각 → 반각) + 보이지 않는 글자 제거를 한 번 하고, 옛 값은 읽을 때 같은 정규화를 거친 글로 판정 · 표시한다.
- 비용(반증 측정 — 이 컨테이너 · 순수 함수): 재료 7,100대 색인 만들기 38ms(세대마다 한 번) · 글 하나 판정 약 4µs(글마다 처음 한 번 — 세대가 같으면 기억에서 꺼낸다).

### 5.3 저장하는 것

- **사람의 결정 표**: `(법인, 글) → 승인(그때 걸린 키들 · 누가 · 언제)` 또는 `숨김(누가 · 언제)`. ‘숨김’ 은 검사기가 놓친 글을 사람이 막는 손잡이다.
- **본 적 있는 재료 표**: 주소 · 태그 — 늘기만 한다 · 세대 번호(원장 파일 안의 정수 하나 — 재료 표와 같은 트랜잭션에서 올린다). 지금의 `rack_serial_seen` 과 같은 방식.
- **관리 메모**(새 열 · 관리자 전용): 투영 함수에 넘기지 않는다. 판 스냅샷에도 넣어야 한다(빠지면 ‘이 판으로 되돌리기’ 가 관리 메모를 지운다).
- **새 이력의 구조 칸**(J6).
- 기존 글은 옮기지 않는다 — 제자리에 두고 읽을 때 판정한다. **자료 이전 단계가 없다**(되돌리기는 코드 교체만).

### 5.4 재료

- 원장 쪽이 **당긴다**: 조회 계정 응답을 만들기 전에 출처들의 세대 표식을 마지막으로 반영한 값과 대조하고(정수 비교), 다르면 달라진 키를 재료 표에 넣은 뒤 응답한다. 저장 훅은 ‘빨리 알리는’ 최적화로만 둔다 — 훅을 잊은 새 경로 · 재시작 · 설정 복원이 모두 닫힌 쪽으로 떨어진다.
- 출처마다 세대 표식이 필요하다: 중앙 등록부 저장(`insights/fleetRev.js` 가 이미 있다) · 엣지 목록 교체(`collector/remoteInventory.js` — 지금 표식이 없다) · 인벤토리 태그(`idrac/invCache.js` — 지금 표식이 없다) · 원장 시리얼(같은 파일 안).
- 어느 등록부까지 재료로 볼지는 결정 5.

### 5.5 쓰기 경로

- 자유 글을 쓰는 동작(이름을 입력받는 9종 + `version.restore`)은 **하나의 함수**를 지난다: 정규화 → 저장 → 응답에 그 글의 판정을 싣는다. 저장을 막지 않는다(결정 3) — 가져오기 · 되돌리기까지 규칙이 하나다.
- 창은 저장 응답을 보고 ‘조회 계정에 숨겨졌습니다 — 까닭’ 과 선택지를 보인다: 관리 메모로 옮기기 / 직접 고치기 / ‘식별 정보 아님’ 승인 / 그대로 둔다(숨김 유지).
- **범위 관리자에게 보이는 까닭은 그 관리자가 볼 수 있는 서버에 걸린 경우에만 구체적으로** 적는다. 범위 밖 재료에 걸린 글은 ‘식별 정보로 보이는 글자’ 까지만 보이고 승인은 전체 범위 관리자만 한다 — 이름 칸에 후보 글자를 넣어 다른 법인 서버가 등록돼 있는지 알아내는 길을 만들지 않는다.
- 시리얼 칸(`serial` · `extraSerials`)에 주소 꼴이 들어오면 저장을 거절한다(시리얼에 주소가 들어갈 까닭이 없다).

### 5.6 읽기 경로

- 조회 계정 응답 = 칸 목록(J1) + 글마다 판정(J2). 숨겨진 글의 대체 표시: 장비는 ‘종류 · 모델’(모델도 자유 글이므로 판정 — 둘 다 숨겨지면 ‘종류’ 만), 데이터센터 · 전산실 · 랙은 안정된 번호(‘전산실 #3’ — 둘 이상이어도 겹치지 않게).
- 조회 계정에서 빼는 것: 관리 메모 · 판 차이의 ‘되돌리면 바뀌는 것’ · 관리자 전용 칸의 이름(판 차이 `fields`) · 미배치 서버 목록(편집할 수 있는 계정만 — 그 밖에는 개수만) · 등록부 서버 이름(결정 6).
- 관리자 전용 칸만 바뀐 변경도 rev · 시각 · 이력 한 줄은 조회 계정에 보인다(‘정보 수정’ — 무엇이 바뀌었는지는 보이지 않는다). J7 은 **내용**이 새지 않음을 고정하고, 변경이 있었다는 사실은 가리지 않는다.
- 옛 이력 · 판 글(이미 글 한 덩어리로 저장된 것)은 안전하게 쪼갤 수 없다 — 조회 계정에는 **동작 · 시각만** 보인다(결정 7).

### 5.7 검토 화면(관리자)

- **숨겨진 글**: 그 법인의 글에 같은 판정 함수를 돌려 나열(저장한 목록이 아니다) — 건별로 가리기(관리 메모로) / 고치기 / 승인.
- **승인 목록**: 누가 · 언제 · 어떤 키에 대해 승인했는지 · 그 글이 쓰인 곳 수 · 승인 취소.
- **공개 글 전체 보기**: 조회 계정에 실제로 보이는 글 전부 — 검사기가 놓친 글을 관리자가 찾아 ‘숨김’ 으로 막는 자리. 1판에는 없던 화면이다.

### 5.8 시험 계획

- **표식 시험(J7)** — 구조를 고정한다. 새 칸을 추가하고 등급을 잊으면 이 시험이 잡는다.
- **재료 감소 시험(J4)**: 엣지 목록을 비우고 · 서버를 지우고 · 재시작한 뒤에도 같은 글이 숨겨져 있는지.
- 검사기: 지금 표기 행렬 + 5회차 탐침 + 반증이 찾은 우회 표기(전각 · 구분자 바꾼 IP · 첫 마디)를 ‘걸린다 / 안 걸린다’ 로 옮겨 돌린다.
- 구현 단계마다 변이 검증 · 5축 점검 · 반증 1인, 화면은 Chromium 1440 / 400.

## 8. 타협한 것 · 한계(숨기지 않는다)

- 어느 안이든 **검사기가 놓친 글은 막지 못한다**. B′ 가 더하는 것은 놓친 글을 사람이 찾고(공개 글 전체 보기) 막는(숨김) 자리다.
- ‘숨겨짐’ 표시는 ‘이 이름에 주소 · 태그 꼴이 있다’ 는 1비트를 조회 계정에 준다. 공개이던 이름이 숨겨지면 ‘그 글자가 실제로 등록된 주소’ 라는 확인이 된다 — 뒤늦게 가리는 구조에 늘 있는 것이고 지금도 같다.
- 승인은 그 법인에서 **그 글자**에 대한 결정이다 — ‘A-101’ 을 승인하면 다른 칸 · 옛 이력의 ‘A-101’ 도 공개된다. 승인 목록에 쓰인 곳 수를 보이고, 쓰이지 않게 된 승인의 수명은 구현 설계에서 정한다.
- 조회 계정 요청이 판정 함수와 세대별 기억의 정확성에 기댄다(기억을 잘못 비우면 낡은 판정). 세대를 원장 파일 안의 정수 하나로 두는 것이 이 위험을 줄이는 장치다.
- 판 스냅샷 형식에 관리 메모를 넣는 방법(형식 번호를 올리면 옛 코드 · 새 코드가 서로의 판을 손상으로 읽는다) · 구버전으로 내려갔을 때의 동작은 구현 설계에서 정한다.
- 안 B′ · 안 D 는 만들어 보지 않은 설계다. 비용 수치는 순수 함수 측정이고 등록부 읽기 · SQLite 는 빠져 있다.
- 2판(B′)은 반증을 **반영한** 판이고, 반영한 결과를 다시 반증받지는 않았다.
- 이 시안은 그림이다 — 실제 포탈 화면 위에서 그린 것이 아니고, 색 · 간격은 `web/src/styles.css` 토큰과 맞추지 않았다. 건수는 전부 가상값이다.
