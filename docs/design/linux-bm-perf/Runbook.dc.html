진단 플레이북(읽기 전용 런북) 과 목표선(SLO) · 월간 달성률

플레이북은 판정이 ‘후보’ 로 끝난 뒤 사람이 할 다음 조사를 표준화한다 — 명령은 복사용이고 포탈이 실행하지 않는다 · 목표선은 ‘약속을 지켰나’ 를 묻는다(베이스라인 ‘평소와 다른가’ 와 다른 질문)

플레이북 — 지금 판정에 맞는 것이 자동으로 열린다: 교차 ② ‘디스크 await 급등 · SMART 깨끗’

판정다른 플레이북
1
포탈에서 먼저 확인 — 집중 모니터링 결론 · 분별 프로세스 상위 · 구간 비교(어제 같은 시각) · 변경 이벤트 띠(크론 · dnf) · 주석
이미 열린 결과: 원인 후보 pg_dump(11:40 크론 추가) · await 212ms · Dirty 4GB 상한 도달

2
서버에서 지금 I/O 를 누가 내는지 — Netflix 60초 체크리스트 순서(오류·포화 먼저)
dmesg -T | tail -30 iostat -xz 1 5 # await · aqu-sz · %util — 포탈 값과 대조 pidstat -d 1 5 # 프로세스별 kB_rd/s kB_wr/s cat /proc/pressure/io # some/full avg10 avg60
근거 ◐ NF · ◐ USE
복사
3
쓰기 폭주면 writeback 설정과 DB 체크포인트를 본다
grep -E 'Dirty|Writeback' /proc/meminfo sysctl vm.dirty_bytes vm.dirty_background_bytes vm.dirty_ratio vm.dirty_background_ratio # PostgreSQL/GPDB: checkpoint_timeout · checkpoint_completion_target · 최근 checkpoint 로그(DB 담당)
튜닝 탭의 권장값(DB · GPDB 프로파일)과 대조 — 64GB 초과 호스트는 dirty_bytes 방식(G1 ●)
복사
4
디스크 자체를 의심하면 — SMART 가 깨끗해도 펌웨어·온도·큐 설정을 본다
cat /sys/block/nvme1n1/queue/scheduler /sys/block/nvme1n1/queue/nr_requests nvme smart-log /dev/nvme1n1 # 설치돼 있을 때 · iDRAC 디스크 상태와 대조 # 기준선(F — 미도입)이 있으면 처리량 저하 비교
NVMe 스케줄러는 none 유지(H2 ◐)
복사
5
조치 후보와 기록 — 백업 창으로 이동 · 크론 소유자 확인 · 이슈에 결론 카드 첨부 · 주석 남기기
포탈은 적용하지 않는다. 적용했으면 변경 이벤트 띠에 자동으로 잡히고(sysctl · cron 해시) 다음 비교에서 효과를 본다.
주석 · 이슈
플레이북은 파일 하나(판정 id → 단계 · 명령 · 근거 번호)이고 용도 프로파일처럼 카탈로그 테스트가 근거 번호를 검사한다. 현장이 고친 단계는 위키에 덮어쓰기(포탈 버전은 기본값). 명령은 읽기 전용만 싣는다(쓰기·재시작 명령 금지).
