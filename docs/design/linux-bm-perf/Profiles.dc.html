정직하게 적어 둘 것

  • Rocky 9.4 ‘정상 동작 점검’ 의 공식 항목은 적다. 릴리스 노트가 주는 것은 업그레이드 경로(9.x → dnf upgrade · 8 에서 불가), 알려진 문제 분류(상세는 upstream), 폐기 스트림(Node.js 16 · .NET 7 · OpenJDK 11 2024-10 EoL) 뿐이다. 그래서 rocky9-base 점검은 ① 그 세 가지 + ② TuneD 활성 프로파일(⑤) + ③ systemd 실패 유닛·journal 오류·chrony 동기(○ 일반 관행 — 공식 권고 문장 없음) + ④ GPDB 가 요구하는 SELinux·firewalld·RemoveIPC 상태(●) 로 둔다.
  • Airflow 메트릭(import_errors · open_slots · starving)은 StatsD/OTel 로만 나온다. 포탈이 받으려면 수신기가 필요하다 — 이번 범위에 넣지 않고 ‘미수집’ 으로 표시한다. 대신 CLI(jobs check)·HTTP(health) 두 경로로 생존을 본다.
  • GPDB 점검은 gpadmin 계정의 읽기 전용 SQL 이 필요하다. 기존 bmstor OS 계정이 gpadmin 이 아니면 ‘권한 없음’ 으로 비고, gpcheckperf 는 DB 를 멈춰야 하므로 자동 실행하지 않는다.
  • Airflow 3 의 DAG 파싱(parsing_processes · min_file_process_interval)은 dag-processor 로 옮겨 갔을 수 있다 — 공식 설정 참조 원문을 열지 않아 ‘확인 불가’. 구현 때 configurations-ref 를 대조한다.
  • Ubuntu · Windows · Hadoop 프로파일은 이번에 만들지 않았다 — 매트릭스에 ‘프로파일 없음’ 으로 보이고 점검하지 않는다(틀린 판정을 내지 않는다).
