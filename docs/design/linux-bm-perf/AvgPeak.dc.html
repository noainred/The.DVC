평균 화면과 피크 화면 — 시간축 하나로 동기화

왼쪽 축·커서·구간(brush)을 두 화면이 공유한다. 평균 = 5분 주기 평균(지금 bmusage) · 피크 = 같은 5분 안의 최대값과 그 시각(아래 ‘수집 방식’ 중 선택) · 수치는 가상
지표군 CPU — 사용률 · 런큐(큐) · PSI디스크 — busy · await · 대기열 깊이(큐) · IOPS네트워크 — bps · 드롭 · softnet 백로그(큐) · TCP accept 큐 · 재전송버퍼 — Dirty/Writeback 페이지 · 소켓 메모리 · 페이지 캐시 커서 13:35 · 구간 02:00~05:10 선택됨 → 아래 표가 그 구간의 평균/피크로 바뀐다

① 평균 — 5분 주기 평균 (usage_history avg)

출처 OS(SSH) · 결측 3점은 선을 끊는다세로 눈금은 지표마다 · 가로 시간축은 공유

② 피크 — 같은 5분 안의 최대값 + 발생 시각 (usage_history peak · peak_at)

출처 1초 샘플러(옵션 B) · 샘플 300/주기같은 시간축 · 같은 커서 · 같은 선택 구간 — 평균 선을 흐리게 깔아 간격(burst)을 보인다
피크 선 아래 흐린 선이 평균이다. 둘 사이가 넓을수록 ‘짧은 폭주(burst)’ — 평균만 보면 놓치는 구간. 피크 점을 누르면 그 5분 안의 발생 시각(peak_at)과 1초 샘플 300개를 펼친다(엣지 보관 7일).

피크를 어떻게 모으나 — 3안 (정직하게)

안방법피크의 뜻부담판정
A 세션 안 짧은 샘플지금 SSH 1회 안에서 1초 × N(예 10)회 /proc 를 읽어 그 안의 최대5분 중 10초 창의 피크 — 나머지 290초는 모른다추가 설치 없음 · 세션 +10초(예산 50초 안)기본값 — 작게 시작
B 서버 경량 샘플러 권장(옵트인)systemd timer + 셸 스크립트가 1초마다 /proc 를 읽어 5분 avg/max/peak_at 을 로컬 파일에 쓰고, SSH 가 그 파일을 가져간다(원시 1초 샘플은 서버에 7일)5분 전체의 진짜 피크(1초 해상도)서버마다 스크립트 배포(패키지·데몬 아님 — 포탈이 SSH 로 설치·검증 · 법인 단위 옵트인) · CPU 1% 미만 목표(실측 필요)피크가 필요한 서버만
C 커널·BMC 가 주는 근사PSI avg10/avg60(커널 10초·60초 창) · iDRAC 텔레메트리 리포트의 집계(장비·리포트에 따라 Peak 필드가 있을 수 있음 — 미확인)포화의 10초 근사만 · 사용률 피크는 아님추가 없음A·B 의 보조
화면은 피크 값 옆에 어느 안으로 모은 것인지(창 10초 / 1초 샘플 300개 / PSI 근사)를 항상 적는다 — ‘피크’ 라는 한 단어로 다른 세 가지를 섞지 않는다. 평균은 세 안 모두 지금 그대로다.

동기화 규칙 · 저장

  • 한 시간축: 두 화면은 같은 start/end · 같은 롤업(5분 → 7일은 30분, 30일은 2시간 — 롤업은 avg 는 평균의 평균, peak 는 최대의 최대)을 쓰고 응답이 실제 롤업을 돌려준다.
  • 커서·구간 공유: 한쪽에서 hover·brush 하면 다른 쪽이 같은 x 로 움직이고, 아래 표가 선택 구간의 평균/피크로 바뀐다. 동기화 체크를 끄면 각자 움직인다.
  • 결측: 못 읽은 주기는 두 화면 모두 선을 끊는다 · 피크 샘플이 없는 주기(옵트인 전)는 피크 화면에 ‘—’ 띠로 표시(0 으로 그리지 않음).
  • 저장: usage_history 에 지표마다 _avg · _peak · _peak_at 열 — 지표를 열로 두는 기존 판단 그대로(행 수 불변). 일 롤업은 이미 평균+최대를 함께 둔다.
  • 큐·버퍼의 ‘상한’ 은 튜닝 탭(⑤)이 읽는 같은 값(nr_requests · dirty_bytes · netdev_max_backlog · somaxconn · tcp_mem · ring)을 재사용한다 — 두 곳에서 따로 읽지 않는다.
  • 400 폭: 두 화면을 세로로, 표는 가로 스크롤 — ③ 과 같은 규칙.
