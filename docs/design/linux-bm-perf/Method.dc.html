서버 원문(수백 KB)은 법인 밖으로 나가지 않는다 — 엣지가 서버당 한 행(지표 열 20여 개 + 판정)으로 줄여 보관하고, 중앙은 열 때 법인당 봉투 1개를 받는다. 엣지가 없는 법인은 중앙이 직접 SSH 로 붙는 예외(지금 bmusage 와 같다).
네 가지 방식 비교 — 이 현장(법인 28곳 · 등록 서버 1,135대 · 법인 단위 opt-in · 한국에서 조회) 기준
방식얻는 것설치 · 운영 부담WAN · 보안판정
A · 지금 그대로
bmusage 5지표 (CPU·메모리·디스크·네트워크·HBA)		 사용률만. 포화(런큐·스왑아웃·대기열·PSI)와 오류 카운트가 없어 ‘높다’ 는 보여도 ‘병목인지’ 는 못 말한다. 튜닝 포인트 없음. 추가 없음변화 없음부족 — 진단 요구를 못 채움
B · 서버마다 에이전트
node_exporter / Netdata + 중앙 Prometheus·Grafana		 가장 풍부(수백 지표 · 초 단위 · Netdata 는 지표별 이상 탐지). 커뮤니티 대시보드 그대로. 서버 1,135대에 패키지 설치·버전 관리·방화벽 포트(9100 등) 개방 · 별도 저장소(TSDB) 운영 · 포탈과 화면 이원화 법인마다 Prometheus 를 두지 않으면 중앙이 WAN 너머 서버를 직접 스크레이프(28곳 × 수백 대 × 15초) 보류 — 운영 부담이 이번 범위를 넘는다. 이미 쓰는 법인이 있으면 그 값을 읽는 연동은 다음 단계
C · iDRAC 텔레메트리만
Redfish MetricReports		 CPU·메모리·전력·온도·NIC/FC 통계(리포트가 있을 때). 런큐·PSI·프로세스·sysctl 은 구조적으로 없다 — OS 안을 못 본다. 설치 없음iDRAC 등록부 재사용보조 — OS 계정이 없는 서버의 대체 경로로만
D · A 를 넓힌다 (권장)
같은 SSH 1회에 구획 추가 + 온디맨드 진단 스냅샷		 USE 세 칸 전부: loadavg·/proc/stat 분해(iowait·steal)·/proc/pressure/*·vmstat(스왑·폴트)·diskstats 14열(await·IOPS·대기열)·net/dev 오류·드롭·snmp 재전송 + sysctl·/sys 튜닝 항목. 스냅샷은 top 프로세스·ss -s·dmesg 오류. 설치 없음 · 등록부(bmstor OS 계정) 재사용 · 명령 1회 유지(왕복 불변) · 엣지 DB 열 추가 새 포트·새 인증 없음 · 원문은 법인 안 · 중앙은 봉투만 · 읽기 전용(튜닝 자동 적용 없음) 채택 — 5분 주기는 유지(초 단위는 안 한다). 모자라면 B 연동을 그때 검토
USE 방법 (Brendan Gregg)
자원마다 사용률·포화·오류 세 칸을 따로 묻는다. 보드의 매트릭스와 상세의 4면이 이 틀이다. 사용률이 높아도 포화가 없으면 병목이 아니고, 오류가 0 이 아니면 먼저 본다.
node_exporter 수집기 목록
cpu · meminfo · diskstats · netdev · loadavg · pressure · vmstat · filesystem 이 기본 수집기다. 어느 /proc 파일을 읽을지는 이 목록을 그대로 따른다(지표 이름도 가능하면 같게 — 나중에 B 연동이 쉽다).
Grafana ‘Node Exporter Full’ · Netdata
상세 화면의 자원별 묶음(CPU 분해 · 메모리 · 디스크 await/IOPS · 네트워크 오류)은 이 대시보드의 구성을 따른다. Netdata 의 초 단위·지표별 ML 이상 탐지는 이번에 채택하지 않는다(5분 주기 · 에이전트 없음).
정직하게 밝힐 한계
PSI 는 커널 4.20+ (RHEL 8 계열은 부팅 옵션에 따라 없음) → ‘없음’ 을 따로 센다. 프로세스별 I/O 는 root 권한이 필요할 수 있다 → 못 읽으면 그렇게 말한다. 5분 주기라 초 단위 스파이크는 놓친다 — 이 사실을 화면이 말한다.
