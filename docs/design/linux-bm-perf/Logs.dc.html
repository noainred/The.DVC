수집 방식 · 규칙

  • 증분 읽기: 5분 주기 SSH 1회 안에 구획 ##JOURNAL(`journalctl -p warning --since <마지막 커서> -o short-iso --no-pager | head -N`) · ##DMESG · ##SECURE(`/var/log/secure` 는 읽기 권한이 있을 때 — 없으면 ‘권한 없음’) · 용도 로그는 프로파일이 경로를 안다. 커서(journal cursor · 파일 offset+inode)를 엣지가 기억해 같은 줄을 두 번 읽지 않는다. 주기당 줄 상한(기본 5,000 · 설정)과 ‘잘림 n줄’ 표시.
  • 엣지에서 분류·집계·가림: 정규식 매칭 → 서명 해시 → `log_pattern(agent,key,sig,class,severity,count,first,last,rule_id)` + 샘플 5줄(가림) · 시간당 집계 `log_hour(class,count)` · 보안 상위 N(IP · 계정). 원문 전체는 저장하지 않고 법인 밖으로 보내지 않는다 — 중앙은 집계·샘플만 봉투로.
  • 비밀 가림: 샘플은 기존 `edgelog/redact.js` 규칙(토큰·비밀번호 키) + 로그용 추가(`password=`, `Authorization:`, 카드번호 꼴)를 거친다. 가림은 ‘[가림]’ 표식으로 남긴다.
  • 연계: 패턴 행마다 교차 판정 · 장애 기록 · 집중 세션 · 변경 이벤트 · 점검 소모품 · 플레이북 링크 — 같은 시각 ±5분 매칭(인과 아님). 알림 규칙(⑨)에 ‘로그 — 장애/보안 high’ 행 추가(기본 꺼짐).
  • 함대 보기: 보드 KPI ‘로그 장애·보안 n대’ → 법인 · 분류 · 규칙 필터 표(같은 규칙이 여러 서버에서 동시에 뜨면 ‘공통 원인 후보’ 표시 — 예: 같은 외부 IP 의 SSH 실패).
  • 정직하게: 커널·sshd·systemd 메시지 형식은 배포판·버전마다 조금씩 다르다(○ 규칙은 실장비 표본으로 좁힌다) · auditd·SELinux 는 설치·활성일 때만(‘경로 없음’) · `/var/log/secure` 읽기 권한은 계정에 따라 없다 · 로그가 많은 서버는 상한 때문에 ‘잘림’ 이 생기고 그 수를 적는다 · 보안 판정은 알림까지만, 차단·계정 잠금은 포탈이 하지 않는다.
