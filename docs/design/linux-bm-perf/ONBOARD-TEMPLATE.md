# 서버 등록 템플릿 설명서 (리눅스 성능 7b단계)

설정 › 베어메탈 성능 › 서버 등록에서 **템플릿 내려받기(CSV)** 로 받는 표의 설명이다. `.xlsx` 도 받는다(첫 시트 · 값만).
포탈은 **서버에 계정 · 키를 만들지 않고 `authorized_keys` 를 건드리지 않는다** — 아래 ‘서버 쪽 준비’ 는 현장이 한다.

## 1. 열(17개 — `*` 필수)

| 열 | 뜻 | 규칙 |
|---|---|---|
| name* | 서버 이름(호스트명 권장) | 파일 안 중복 거부 · 기존 등록과 이름 · 서비스 태그 · 주소가 서로 다른 서버를 가리키면 거부 |
| corp* | 법인(vCenter 이름 · id · 데이터센터 이름) | 모르면 `미귀속`(전체 범위 계정만 · 기본 수집에서 빠진다) · 범위 계정은 자기 법인만 |
| idrac_host | iDRAC 주소(스킴 없이) | 저장 규칙 그대로(루프백 · 링크로컬 · 우회 표기 거부) |
| idrac_cred | iDRAC 공통 계정 **이름** | 새 iDRAC 행은 필수(개별 계정은 iDRAC 화면에서) · 적용 때 계정 · 비밀번호를 그 항목에 복사(봉인) |
| service_tag | Dell 서비스 태그 | 있으면 식별 키 · class/purposes/role 적용 키 |
| os_host · os_port | SSH 주소 · 포트(기본 22) | 저장 규칙 그대로 |
| os_cred | OS 공통 계정 **이름** 또는 `개별:계정명` | 새 OS 행은 필수 · 비우면(기존 행) 기존 계정 유지 |
| os_key | SSH 키 저장소의 키 **이름** · `password` · 비움 | 비우면 공통 계정의 기본 키 · `password` 는 비밀번호 인증 고정 · **키 내용을 넣으면 그 행 거부** |
| collect_via | `edge` · `central` · `auto`(비우면 auto) | auto = 그 법인 엣지가 지금 접속 중이면 edge, 엣지가 없으면 central, 엣지가 있는데 접속을 모르면 거부 |
| class | `baremetal` · `virtualization` · `exclude` | 비우면 자동 판정 |
| purposes · role | 용도(`;` 구분) · 역할 | 정해진 값만 |
| mounts | 공간 측정 마운트(`;` 구분) | 비우면 `/` 하나 |
| switch_port | `NIC=스위치:포트`(`;` 구분) | 이 단계는 형식만 확인 — 매핑은 수집 뒤 서버 상세에서 |
| enabled · note | 켬/끔 · 메모(500자) | |

머리글은 별칭(한/영)도 받는다(예: 서버명 · 법인 · iDRAC 주소 · OS 주소 · SSH 키 · 수집 경로). 인코딩은 UTF-8(BOM 유무) · UTF-16 · EUC-KR(CP949)을 감지한다.
상한: 파일 4MB · 데이터 5,000행. 업로드 파일은 서버에 보관하지 않는다.

## 2. 비밀은 파일에 넣지 않는다

- `password` · `비밀번호` · `private_key` · `passphrase` · `token` 같은 이름의 열에 값이 있으면 그 행을 거부한다(값은 읽지 않는다).
- 어느 칸이든 키 블록(`BEGIN … PRIVATE KEY`) · 공개키 한 줄 · `password=` / `비밀번호:` 꼴 · 긴 base64 덩어리가 보이면 그 행을 거부한다.
- os_cred · idrac_cred · os_key 칸의 값은 판정 결과 · 결과 CSV 에 다시 싣지 않는다(잘못 넣은 비밀번호가 되돌아 나가지 않게) — 맞은 공통 계정 · 키 이름만 싣는다.
- 비밀은 **공통 계정 · SSH 키 화면에서 한 번만** 입력한다(설정 소유자 + 본인 OTP · 봉인 저장).

## 3. 서버 쪽 준비(현장 — 포탈은 하지 않는다)

- **수집 계정**: 전용 일반 계정을 권한다(root 비권장). 주 수집은 `/proc` · `/sys` · `df` 를 읽는다. 로그 분석(7a)은 권한이 있을 때만 더 읽는다 —
  journald 전체는 `systemd-journal`(또는 `adm`) 그룹, `/var/log/secure` 는 기본 0600(root) · `audit.log` 는 0700 폴더(root)라 비 root 계정이면 보안 합계는 ‘—’ 다(화면이 필요한 권한을 안내한다).
  배포판 기본 권한은 실장비에서 확인하지 않았다(설계 README §6).
- **SSH 키**: ed25519 를 권한다(RSA 는 2048 비트 이상 · DSA 거부). 공개키(키 저장소 화면의 공개키 열)를 그 계정의 `~/.ssh/authorized_keys` 에 넣는다.
  권고(일반 관행 — 포탈이 강제하지 않는다): `restrict,from="<수집 노드 주소>"` 옵션 · 비밀번호 로그인 끄기 · 계정을 수집 명령만 쓰게 제한.
- **호스트키**: 첫 접속은 무음으로 신뢰하지 않는다 — 설정 › 장비 신뢰(peerTrust)에서 지문을 확인 · 승인한다.
- **iDRAC**: 읽기 전용 역할 계정(텔레메트리 · 인벤토리 조회)을 권한다 — 공통 계정 이름으로 등록한다.
- **회전 순서**: 새 키 등록 → 새 공개키를 서버에 배포(현장) → 키 저장소 ‘회전(참조 교체)’ → 서버마다 ‘연결 시험’(자동 재시험 없음) → 옛 키 사용 0 이면 삭제.

## 4. 수집 경로

- `edge` 로 등록한 서버는 중앙 등록부에 두지 않고 **엣지 배포 목록**으로 간다(비밀 없이 이름만). 엣지가 다음 인출(기본 10분)에서 **자기 키 저장소 · 공통 계정의 같은 이름**으로 등록한다 —
  그 엣지에도 같은 이름의 키 · 공통 계정을 먼저 만들어 둔다(키는 법인 밖으로 나가지 않는다). 없으면 엣지가 그 행을 거부하고 수를 중앙에 알린다.
- `central` 행 중 법인 RTT 가 800ms 이상이면 경고한다(수집 건강 보드에도 표시) — 엣지 수집을 권한다.
- 엣지가 끊겨도 자동으로 central 로 옮기지 않는다. 엣지 → 중앙 이동은 배포 목록에서 먼저 뺀 뒤(엣지가 반영한 뒤) central 로 다시 올린다.
