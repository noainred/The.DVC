서버 하나 등록·수정 폼 — 키를 고르는 자리
키를 바꾸면 저장 전에 시험을 권한다 · ‘개별 입력’ 은 비밀번호 또는 이 서버만의 키(저장소에 ‘개별 · 서버명’ 으로 들어간다 — 두 벌을 두지 않는다) · 주소가 바뀌면 저장 비밀·키 참조를 승계하지 않는다.
저장: 키 저장소 `ssh-keys.json`(id · 이름 · 종류 · 지문 · 공개키 · 봉인 개인키 · passphrase 봉인 · 등록자 · 등록일 · 회전 예정일) — 등록부와 같은 계약(원자적 쓰기 · 손상 보존 · 봉인). OS 등록부의 `password` 자리에 `keyRef` 가 더해지고, 기존 비밀번호 항목은 그대로 동작한다. CSV 는 `os_key` 열로 참조. 키 회전은 ‘새 키 등록 → 서버 authorized_keys 에 배포(현장) → 포탈에서 참조 교체 + 전 서버 재시험 → 옛 키 쓰는 서버 0 이면 삭제’ 순서이고 포탈은 authorized_keys 를 건드리지 않는다.

  • 경계는 지금 코드 그대로: 엣지는 자기 agent 의 서버만, 중앙은 agent 없는(= central) 서버만 수집한다(`remoteAgent` — 같은 서버를 두 곳이 열지 않는다). 배정을 바꾸면 중앙 설정이 엣지로 배포되고 다음 주기부터 바뀐 쪽이 읽는다.
  • auto = 법인에 온라인 엣지가 있으면 edge, 없으면 central. 엣지가 사라져도 자동으로 central 로 넘기지 않는다(원문이 법인 밖으로 나가는 결정은 사람이).
  • 중앙 직접은 RTT·동시성을 따로 보여 주고(수집 건강 보드), 800ms+ 법인은 경고한다.
  • 이력은 수집한 쪽 DB 에 쌓인다 — 경로를 바꾸면 이전 이력은 이전 쪽에 남고 화면이 ‘경로 변경 시각’ 을 적는다(합치지 않는다).
