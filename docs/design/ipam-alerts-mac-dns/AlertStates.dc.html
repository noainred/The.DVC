IP 변화 알림 — 알리지 않는 경우와 줄이는 경우 8종 보지 못한 것을 ‘변화’ 로 세지 않습니다 · 주소 · 이름은 가상

1대역을 처음 스캔

기준선10.230.4.0/24
응답 38개 기록 · 알림 없음
대역 한 줄을 처음 끝까지 스캔한 결과는 기준선입니다. 그다음 스캔부터 처음 보이는 IP 가 ‘새 미등록 IP’ 입니다.

2한 번에 너무 많음

새 미등록 IP73개
요약 1건 · 목록 없음
묶음 상한(설정값)을 넘으면 요약 한 건만 보냅니다. 대역을 넓혔거나 장애에서 복구된 경우가 대부분입니다.

3두 MAC 사이를 오감

MAC 변경10.210.5.9
이중화 의심최근 6회 중 4회 전환
같은 두 MAC 을 오가면 처음 한 번만 알리고 ‘이중화 의심’ 으로 표시합니다. 알림 제외는 사람이 정합니다(자동으로 빼지 않음).

4스캔이 끝까지 못 감

스캔 미완료시한 초과
변화 판정 보류
시한에 걸린 스캔은 이름 · MAC 단계에 닿지 못합니다. 비교하지 않고 다음 완료 스캔을 기다립니다(지금의 해제 판정 보류와 같은 규칙).

5다른 서브넷의 IP

10.44.2.17MAC —
충돌 · MAC 변경 판정 안 함
MAC 은 스캐너와 같은 서브넷에서만 보입니다. 모르는 MAC 을 ‘변경 없음’ 으로 읽지 않습니다 — 그 IP 는 새 IP · 예약 · 호스트명 변화만 봅니다.

6이전 버전 에이전트

edge-site-b방식 보고 없음
새 IP · 예약 IP · 역DNS 이름 변경만
MAC · 확인 방식을 보내지 않는 엣지는 알 수 있는 변화만 봅니다. 엣지가 올라오면 그 스캔을 기준선으로 삼아 MAC 을 기록하기 시작합니다.

7보내지 못함

발송 실패Slack 403
IP 변화 페이지 ‘알림’ 칸에 표시
채널이 거부하면 지금의 알림 엔진 규칙대로 다시 시도하고, 끝내 실패하면 실패로 표시합니다. 변화 기록은 발송과 무관하게 남습니다.

8기록만

규칙 꺼짐에이전트 제외
페이지에는 남음
규칙을 껐거나 ‘알리지 않을 에이전트’ 면 보내지 않고 기록만 합니다. 기록은 보존 기간이 지나면 지웁니다(스캔 결과와 같은 보존 일수).
충돌 의심의 해소 — 다음 완료 스캔에서 그 IP 에 vCenter 가 아는 MAC 이 응답하거나, vCenter 에서 그 VM 의 IP 가 바뀌면 해소로 봅니다. 스캔이 그 IP 를 보지 못한 동안은 해소도 유지도 아닌 ‘모름’ 으로 두고 알림을 다시 보내지 않습니다.
