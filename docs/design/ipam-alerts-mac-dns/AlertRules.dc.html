IP 관리 — 스캔이 본 변화 IP관리 › IP 변화에서 기록 보기 ›
IP 스캔이 끝날 때마다 지난 결과와 비교합니다. 알림은 스캔 한 번 · 종류 하나에 한 건으로 묶어 보내고, 끈 종류도 ‘IP 변화’ 페이지에는 기록합니다.
충돌 의심 위험 vCenter 가 아는 VM 의 IP 에, 그 VM 의 NIC 이 아닌 MAC 이 응답합니다. 연속 2회 스캔에서 같게 보일 때 알리고(횟수는 설정값), 해소될 때까지 ‘현재 발생 중’ 에 남으며, 그 VM 의 MAC 이 다시 응답하면 해소 알림을 보냅니다. 스캐너와 같은 서브넷의 IP 만 판정합니다.
MAC 변경 경고 같은 IP 의 MAC 이 지난 스캔과 다릅니다(장비 교체 · IP 재사용 · 충돌). 이중화 장비처럼 정상적으로 바뀌는 IP 는 ‘IP 관리상태 편집 › MAC 변경 알림 제외’ 로 뺍니다.
새 미등록 IP 경고 vCenter 가 모르는 IP 가 처음 응답했습니다. 그 대역을 처음 끝까지 스캔한 결과는 기준선으로만 삼고 알리지 않습니다.
묶음 상한개
예약 · 폐기 IP 사용 시작 경고 관리상태가 ‘예약’ 또는 ‘폐기’ 인 IP(직접 지정 · 대역 정책)가 응답하기 시작했습니다.
호스트명 변경 경고 같은 확인 방식(역DNS · mDNS · NetBIOS)이 지난번과 다른 이름을 답했습니다.
DNS 불일치 기록만 역DNS 이름의 정방향 주소가 그 IP 가 아닙니다. 수가 많고 급하지 않아 알리지 않고 ‘IP 변화’ · 대장의 표시로만 남깁니다.
알리지 않을 에이전트 edge-site-b 고른 에이전트의 변화는 기록만 합니다(대역을 새로 넣는 동안 등).
저장하면 바로 적용됩니다(재시작 불필요). 빈 칸은 이전 값을 유지합니다.
사건과 상태 — ‘충돌 의심’ 은 풀릴 때까지 이어지는 상태라 지금의 알림 엔진(발생 · 쿨다운 재통지 · 해소)에 넣습니다. 나머지 넷은 한 번 일어난 사건이라 ‘현재 발생 중’ 에 남지 않고 ‘최근 통지’ 와 ‘IP 변화’ 페이지에 남습니다.
채널 — 위 통지 채널(Slack · Teams · Webhook · 메일) 그대로입니다. IP 변화만 따로 보내는 채널은 두지 않았습니다.
기본값(제안) — 충돌 의심만 켬, 나머지는 끔. 쿨다운은 ‘충돌 의심’ 에만 적용됩니다.
