제조사 · MAC 칸 — 값이 없거나 믿기 어려운 경우 9종 읽지 못한 MAC 은 ‘—’ 이고, ‘변경 없음’ 으로 세지 않습니다 · 주소는 가상

1다른 서브넷

—다른 서브넷
라우터 너머의 IP 는 이웃 표에 오르지 않습니다. NetBIOS 가 MAC 을 답했으면 그 값을 NetBIOS 표시와 함께 씁니다. 그 서브넷 안에 엣지 에이전트를 두면 그 엣지가 읽습니다.

2게이트웨이 이중화의 가상 MAC

게이트웨이 이중화가상 MAC
00:00:5E:00:01:0A
VRRP · HSRP 가 쓰는 정해진 대역의 MAC 입니다. 제조사를 적지 않고, MAC 변경 · 충돌 판정에서 뺍니다.

3임의 지정 MAC

임의 지정 MAC
7A:3F:11:C0:5D:08
제조사가 받은 대역이 아니라 장비 · 운영체제가 정한 MAC 입니다(컨테이너 · 일부 가상화 · 사생활 보호 MAC). 제조사를 추정하지 않습니다.

4목록에 없는 제조사

제조사 미상
E8:9F:6D:20:41:7C
포탈에 실린 목록에 그 앞자리가 없습니다. 목록은 릴리스 때의 것이라(오프라인 설치 — 실행 중 내려받지 않음) 새 장비는 미상일 수 있습니다.

5응답했는데 MAC 을 못 읽음

—읽지 못함
이웃 표에서 그 항목이 이미 밀려났거나 미완성 상태입니다. 큰 대역에서 생기므로 묶음마다 바로 읽고, 그래도 없으면 ‘—’ 입니다. 지난 MAC 은 지우지 않습니다.

6ARP 와 NetBIOS 가 다름

DellARP
F4:8E:38:2A:91:0CNetBIOS 가 말한 MAC F4:8E:38:2A:91:0D
NIC 이 여러 개인 Windows 는 스캐너 쪽이 아닌 NIC 의 MAC 을 답하기도 합니다. ARP 를 표시하고 NetBIOS 값은 상세 창에 따로 적습니다. 충돌로 보지 않습니다.

7한 MAC 이 여러 IP

Arista Networks같은 MAC 의 IP 14개
28:99:3A:4C:10:02
IP 를 여러 개 가진 장비이거나 대신 답해 주는 라우터(대리 ARP)입니다. 둘을 구분하지 못하므로 수만 적고, 이 MAC 이 VM 의 IP 에 답해도 충돌 의심으로 올리지 않습니다(기준 수는 설정값).

8스캐너가 이웃 표를 못 읽음

edge-site-cMAC 읽기 실패
MAC 0 / 38
스캐너가 컨테이너 안에 있거나(자기 다리 네트워크만 보임) 이웃 표를 읽지 못하는 운영체제입니다(리눅스만 읽습니다). 에이전트 표의 ‘MAC’ 칸에 이유를 올리고, 그 에이전트의 IP 는 MAC 판정을 하지 않습니다.

9이전 버전 에이전트

—보고 없음
MAC 을 보내지 않는 엣지입니다. NetBIOS 가 답한 MAC(v2.991 부터)만 있을 수 있습니다. 엣지가 올라온 뒤 첫 스캔이 기준선입니다.
