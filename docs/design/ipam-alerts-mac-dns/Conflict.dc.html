충돌 감지 — 무엇을 ‘충돌 의심’ 이라고 부르는가 ‘충돌’ 이라고 단정하지 않습니다 — 스캐너는 한 번에 한 MAC 만 봅니다 · 주소 · 이름은 가상

충돌 의심vCenter 가 아는 VM 의 IP 에 다른 MAC 이 응답

vCentererp-db-02 의 NIC 00:50:56:9A:11:04 · IP 10.210.5.14 스캔(ARP)10.210.5.14 에 F4:8E:38:2A:91:0C (Dell) 이 응답
스캔이 본 MAC 이 그 VM 의 어떤 NIC MAC 과도 같지 않을 때만입니다. 같은 IP 를 두 장비가 쓰고 있거나, VM 의 IP 가 바뀌었는데 vCenter(VMware Tools)가 옛 IP 를 아직 보고하는 경우입니다. 위험 알림(상태형 — 풀릴 때까지 ‘현재 발생 중’).

MAC 변경같은 IP 의 MAC 이 지난 스캔과 다름

지난 스캔10.210.5.40 → 00:1B:21:7A:44:10 (Intel) 이번 스캔10.210.5.40 → 3C:EC:EF:12:9B:E2 (Super Micro)
vCenter 가 모르는 IP 라 대조할 기준이 없습니다. 장비 교체 · NIC 교체 · IP 재사용 · 충돌이 모두 같은 모양이라 원인을 적지 않고 ‘변경’ 이라고만 알립니다. 경고 알림(사건형 — 한 번).

판정 못 함 1,204 — 스캐너와 다른 서브넷이라 MAC 을 모르는 IP 수입니다. 이 수를 ‘충돌 없음’ 에 넣지 않고 따로 셉니다. 스캔 대역 밖의 VM IP 는 여기에도 들지 않습니다(스캔하지 않음).

판정 순서 스캔 결과를 저장할 때 한 번 · 중앙에서

1이번 스캔이 끝까지 돌았고 그 IP 의 MAC 을 읽었는가 — 아니면 판정하지 않습니다(유지도 해소도 아님).
2MAC 이 VRRP · HSRP 가상 MAC(00:00:5E:00:01:xx 등)이거나 한 MAC 이 여러 IP 에 답하는 라우터(대리 ARP)면 뺍니다.
3그 IP 를 vCenter 의 VM 이 갖고 있고(전원 켜짐), 스캔 MAC 이 그 VM 의 NIC MAC 목록에 없으면 충돌 의심.
4vCenter 가 모르는 IP 면 지난 스캔의 MAC 과 비교 — 다르면 MAC 변경. 처음 읽은 MAC 은 기준선입니다.
5충돌 의심은 연속 2회 스캔에서 같게 보일 때 알립니다(vMotion · IP 교체 직후의 한 번짜리 엇갈림을 거릅니다 — 횟수는 설정값).

알지 못하는 것 과장하지 않기 위한 한계

두 장비를 동시에 보지 못합니다 — 스캐너는 운영체제 이웃 표에 남은 MAC 하나만 읽습니다. 같은 IP 에 두 MAC 이 번갈아 답하는 것을 한 번의 스캔으로 확정하려면 원시 ARP 패킷이 필요한데(관리자 권한 · 전용 소켓), 이번 범위에 넣지 않았습니다.
ESXi 호스트 관리 IP 는 대조하지 않습니다 — 관리 IP 에는 vmkernel NIC 의 MAC 이 답하는데, 지금 수집에는 물리 NIC MAC 만 있고 vmkernel MAC 은 없습니다. 이 IP 는 MAC 변경만 봅니다.
iDRAC(BMC) 주소 — iDRAC 인벤토리에 BMC NIC 의 MAC 이 있어 대조할 수 있습니다. 다만 대장이 iDRAC 주소를 출처로 갖고 있지 않아 등록부와 잇는 일이 따로 듭니다 — 넣을지는 컨펌 질문입니다.
NAT · 방화벽 너머 — 다른 서브넷의 IP 는 라우터 MAC 만 보여 판정에서 뺍니다. 엣지 에이전트가 그 서브넷 안에 있으면 그 엣지의 스캔으로 판정합니다.
VM 의 IP 는 VMware Tools 가 보고한 값입니다 — Tools 가 없거나 멈춘 VM 은 IP 를 몰라 대조 대상이 아닙니다.
