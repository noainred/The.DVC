## 3. 시안 (아트보드)

1. `Main` — 요약 타일(전체·정상·지연·끊김·못 잼) · 법인 × 종류 격자 · 대상 표(상태·종류·법인·이름·접속처·측정하는 곳·연결 시간·평소·24시간 성공률·24시간 띠·바뀐 때)
2. `Detail` — 대상 상세: 연결 시간 추이 · **같은 주소의 다른 포트**(포트 포워딩에서 한 포트만 나쁜지 대조) · 상태 변화 기록
3. `Settings` — 등록부 4종의 접속처 규칙 · 측정(주기·시한·끊김/지연 판정·보관) · 알림 · 제외 대상
4. `Narrow` — 400px 카드 보기

## 4. 설계 결정 (제안 — 컨펌 대상)

- **대상은 등록부에서 매 주기 계산**한다(시드 1회가 아님). 등록부를 못 읽으면 대상을 지우지 않고 마지막 목록 유지 + 화면 알림.
- **접속처 = 등록된 주소:포트 그대로**. 포트가 없을 때만 기본 포트. ‘포트 포워딩’ 여부는 포탈이 알 수 없으므로 화면은 ‘기본 포트 아님’ 이라고만 적는다.
- **측정하는 곳**: 중앙이 직접 붙는 대상은 중앙, 엣지가 수집하는 대상(vCenter `collectMode=site` · 담당 엣지가 지정된 스토리지·CVP)은 그 법인 엣지가 재서 올린다.
  중앙에서 닿지 않는 주소를 중앙이 재면 늘 ‘끊김’ 이 되기 때문이다. → **엣지 워커가 새로 필요**하고 구버전 엣지는 ‘못 잼’.
- **상태 4종**: 정상 / 지연(평소의 N배) / 끊김(연속 N회 실패) / 못 잼(값이 오지 않음 — 정상에도 끊김에도 세지 않는다).
- **지연 기준은 대상별 ‘평소’**(최근 7일 중앙값). 폴란드·미국 동부처럼 원래 800ms+ 인 대상이 늘 지연으로 뜨지 않게.
- TCP 연결만 본다 — 로그인·API 응답·장비 건강은 보지 않는다(화면 첫 문단에 밝힘).

## 5. 확인하지 못한 것 (구현 전 조사 필요)

- CVP·스토리지 등록부가 포트를 어떤 필드로 갖는지(`host` 에 `주소:포트` 로 들어가는지, 별도 필드인지). 스토리지는 `sshPort` 필드만 확인했다(`storage/registry.js:139`).
- 스토리지 기종별 REST 기본 포트 값 — 시안의 443/8443/8080 은 예시다.
- 시안의 주기 60초·시한 2.5초는 기존 Ping 모니터 값을 옮긴 것이고, 보관 90일·연속 3회·2배는 제안값이다.
- 기존 Ping 모니터의 `vcenter`·`edge` 자동 대상과 합칠지, 별도 저장소로 둘지.
