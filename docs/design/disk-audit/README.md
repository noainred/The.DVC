## 2. 스크립트가 하는 일(코드 근거 — `rhel_disk_audit.py`)

| 항목 | 내용 | 위치 |
|---|---|---|
| 조건 | Linux + root(`os.geteuid() != 0` 이면 종료값 2) · Python 3.6+ 표준 라이브러리만 | `main` |
| 읽는 것 | `journalctl --all --output=json`(전체 부트 스트림) · `/var/log/messages*`(gz · bz2 · xz · zst · lz4 · Z) · `dmesg` · `perccli/storcli`(`show J` · `/cN/vall` · `/cN/eall/sall` · 이벤트) · `lsblk -J` · `udevadm info` · `smartctl -x/-a -j` · `smartctl --scan-open`(RAID 경유) | `Audit.logs` · `raid` · `os_inventory` · `raid_smart` |
| 쓰는 것 | `--output-dir`(기본 현재 폴더)에 `rhel_disk_audit_<시각>.txt` 보고서(0600 — umask 077) · 임시 폴더(`TemporaryDirectory`, 끝나면 삭제 — perccli 이벤트 파일) | `main` |
| 출력 | 표준 출력 = 보고서와 같은 글. 구획: `[로그 수집 범위]` `[PERC/StorCLI 조회]` `[OS/SMART 조회]` `[RAID 경유 물리 SMART 조회]` `[현재 디스크 인벤토리]` `[판정]` `[상세 근거]` `[해석 범위]` | `emit` · `findings` |
| 사건 종류 | 매체 오류 기록 · I/O·경로 오류 기록 · 재할당 기록 · 파일시스템 생성 성공 기록 · 파일시스템 생성 명령 | `classify` · `smart_json` · `smart_text` · `raid_inventory` |
| 판정 꼬리표 | `[확정]` `[추정]` `[불명]` — 인벤토리 일치 · 포맷 후 재사용 · 같은 슬롯 다른 식별자 · 근거 부족 | `findings` |
| 시한 | `--timeout`(기본 120초)은 **개별 명령만**. journal 전체 스트림에는 시한이 없다 | `command` · `logs` |
| 끊겨도 계속 | 표준 출력이 끊기면(`BrokenPipeError`) 출력을 버리고 **수집을 계속한다** | `emit` |

### 포탈에 넣을 때 따라오는 사실(위 표에서 직접 나오는 것)

- **SSH 를 끊는 것만으로는 서버 쪽 실행이 멈추지 않는다**(`emit` 의 BrokenPipe 처리). 시한은 원격에서 걸어야 한다 — `timeout -k 10 900 python3 - …`(coreutils).
- 결과는 사람이 읽는 글뿐이다. 화면의 표 · 숫자를 만들려면 글을 파싱하거나 스크립트가 기계 판독 출력을 내야 한다(§6 D1).
- ‘미검출’ 은 스크립트가 `[불명] 가용 자료에서 대상 오류 패턴 미검출. 과거 무장애 여부는 알 수 없음.` 이라고 쓴다 — 화면이 ‘정상’ · 초록으로 바꿔 말하면 안 된다.
- 건수는 **줄 수**다(`(줄 기준, 중복 가능)` · `건수는 장애 횟수가 아님`).

### 정직 기록 — 확인한 것과 못 한 것

- **확인(이 세션에서 함수 호출)**: `/dev/disk/by-id/wwn-0x…-part1` 은 WWN 으로 잡히지 않는다(`log_ids` → 빈 집합. 정규식 끝의 `(?![\w.-])` 때문). 파티션 없는 `wwn-0x…` 는 잡힌다.
- **추정(코드 읽기 — 실서버 미검증)**: `[추정] 매체 오류 → 동일 ID 파일시스템 생성 성공 기록 → 현재 사용 표시` 는 오류 줄과 mkfs 성공 줄이 **둘 다** 같은 시리얼/WWN 을 글자로 담고 있고 **둘 다** 시각이 있어야 나온다(SMART · RAID 카운터 사건은 `when=None` 이라 `error_times` 에 들지 않는다).
  일반 커널 · smartd 줄은 시리얼을 적지 않으므로 실제 서버에서는 드물 것으로 본다. 시안 ③ 의 근거 줄은 이 판정이 **나오는 경우**를 그린 가상 예다.
- **못 한 것**: 이 스크립트를 실제 RHEL 서버에서 돌려 보지 않았다(이 컨테이너에는 대상 서버가 없다). 소요 시간 · 부하 · 보고서 크기는 실측값이 없다 — 시안의 ‘3분 12초’ 등은 가상.
- **확인 필요(구현 때)**: RHEL 8 에서 `python3` 가 없을 때 `/usr/libexec/platform-python` 으로 돌릴 수 있는지.

## 4. 실행 구조

```
중앙(작업 생성 — 법인마다 1건 · 범위: 전 법인 / 법인 / 서버 목록)
 ├ 엣지가 있는 법인 → 작업 큐(claim→ack — bmstor/jobs.js 와 같은 모양) → 엣지가 현지에서 서버마다 SSH
 └ 엣지가 없는 법인 → 중앙이 직접 SSH
     서버: timeout -k 10 900 [sudo -n] python3 - --output-dir <원격 임시 폴더> < 스크립트(표준 입력)
          → 표준 출력(보고서 글 + 기계 판독 요약) 수신 → 임시 폴더 삭제
 → 결과 정제(아는 칸만 · 상한 · 문자열 수치는 수로) → SQLite(서버당 최근 N회 · 보고서 원문은 상한까지) → 화면
```

- 법인 안에서는 1대씩 차례로, 법인끼리는 동시에(중앙 직접 법인은 중앙 동시 상한을 따로 둔다 — 28개 법인이 전부 중앙 직접이어도 SSH 세션이 한꺼번에 28개 열리지 않게).
- 엣지 법인은 **작업 1건 → 결과 1번**(고지연 회선을 줄 단위로 왕복하지 않는다 — CLAUDE.md ‘백업은 법인 로컬’ 원칙과 같은 모양). 그래서 엣지 법인은 점검 중 단계 표시가 없다.
- 접속 계정 · 키는 `ssh-access`(공용 SSH 접속)에서 꺼낸다. 로그인 실패는 그 모듈의 인증 정지에 기록(자동 재시도 금지).
- 보류(진행 중) 상태에는 시한을 둔다 — 엣지가 가져가지 않거나 답하지 않으면 ‘엣지 응답 없음’ 으로 확정(무한 ‘점검 중’ 금지).
- 권한: 보기 = 관리자(범위 계정은 자기 법인 · 조회 밖 404) · 법인/서버 점검 = 그 법인 쓰기 범위(403) · 전 법인 점검 = `fullScopeOnly` · 전부 `logAudit`. 관리자 판정은 `isAdminDetailUser`.
- 카탈로그: `toolcats/catalog.js` PRESET ‘서버’ · `adminOnly: true` · 키 `disk-audit`(바꾸지 않는다).

## 5. 판정 옮기기(포탈은 다시 판정하지 않는다)

- 서버 판정 = 스크립트 `[판정]` 의 종류별 줄 수에서 가장 무거운 것: 매체 오류 > 재할당 > I/O·경로 > 미검출. 결과를 못 받았으면 점검 실패(사유) — **오류 0 으로 세지 않는다**.
- 디스크 표시 = 스크립트 꼬리표 그대로(장착 중 · 포맷 후 재사용 추정 · 인벤토리에 없음 · 슬롯 교체 추정 · 판정 보류 · 디스크 특정 불가).
- 수집 누락 = `확인하지 못했거나 일부만 수집한 소스/항목 N개` — 판정과 **따로** 센다.
- 못 읽은 SMART 칸은 ‘—’(`numOrNull` — 0 아님).

## 7. 하지 않는 것(1차)

- 디스크를 바꾸는 일(포맷 · 재할당 · 배드 블록 검사 `badblocks` · SMART 자가 진단 실행) — 읽기만 한다.
- Windows · ESXi 호스트 · 스토리지 장비. python3 설치 · RAID 도구 설치.
- 실행 중 중지 단추(원격 `timeout` 에 맡긴다 — 중지하려면 원격 PID 추적이 필요하다).
- 파트 장애(iDRAC) 화면과의 자동 연결 — 같은 서버를 찾는 키가 다르다(iDRAC 주소 vs OS 주소). 다음 단계 후보.
