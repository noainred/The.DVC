### 3.1 문구가 뜨는 조건
- **이 창이 받은 판 ≠ 서버의 판**인 상태에서 오류 경계가 오류를 잡았을 때(종류 무관) + 화면 조각을 못 받은 오류(지금 v2.977 문구를 이 문구로 맞춤). 포탈 전체 · 탭 본문 · 콘솔 화면 세 자리 모두 같은 상자.
- **판이 같으면 지금 문구 그대로**(오류 원문 + 다시 시도) — 진짜 결함을 업그레이드 탓으로 가리지 않는다.
- 판정에 쓸 ‘이 창의 판’: 빌드에 새긴 버전(vite `define`)을 `/health` 버전과 비교하는 안을 권한다. `/health` 폴링(20초) 사이에 난 오류는 오류를 잡은 시점에 `/health` 를 한 번 더 읽어 판정한다(구현 때 확정).

### 3.2 이번 업그레이드에서 바뀐 것
- 내용 = 이 창의 판보다 새 판들의 릴리스 노트 `notes[]` 를 **새 판부터 차례로**.
- 접힘: **앞 3줄만**, 줄마다 한 줄 말줄임. 줄이 3줄을 넘으면 `More · N줄 더`.
- More: 판별로 묶어(버전 칩 + `title`) **전체 문장**을 보이고 상자 안에서 스크롤 · ‘접기’. 3줄 이하면 More 없음.
- 릴리스 노트를 못 읽었으면 이 칸을 그리지 않는다(제목 · 판 · 새로고침은 그대로 — 지어내지 않는다).
- 오류 상자는 **lazy 청크에 기대지 않는다** — 옛 판 창에서는 청크를 못 받을 수 있으므로 상자 · 노트 읽기 코드는 주 번들에 둔다(기존 릴리스 노트 창 `ReleaseNotes.jsx` 를 여는 링크는 넣지 않았다).
- `GET /api/release-notes` 는 1.9MB 전체라 이 용도로 부르지 않는다 → ‘이 판보다 새 판만’ 주는 가벼운 조회(판 수 · 줄 수 상한)가 필요하다(구현 때 설계 — 추정).

## 4. 열린 질문(컨펌 때)

1. **문구**: ‘프로그램이 업그레이드되었으니 새로고침 하세요.’ 로 확정해도 되는지(‘포탈’ 이 아니라 ‘프로그램’).
2. **보신 화면**: ‘페이지 오류’ 가 위 셋 중 어느 화면인지(스크린샷이 있으면 조건을 정확히 맞출 수 있다). 시안은 탭 본문의 일반 오류 상자로 가정했다.
3. **3줄의 출처**: 시안은 릴리스 노트 `notes[]` 의 앞 3줄을 한 줄로 줄여 보인다(지금 있는 자료만 씀). 더 짧고 정돈된 3줄을 원하면 릴리스 때 ‘요약 3줄’ 칸을 따로 적는 방식(릴리스 절차 변경 — 이후 판부터 적용)도 가능하다.
4. **② 알림 변경**(닫기 전까지 유지 · ‘새로고침 필요’ 표시)을 포함할지 — 요청에 없던 제안. 알림에도 ‘바뀐 것’ 을 넣을지도 함께.
5. **여러 판을 건너뛴 경우의 상한**: More 를 눌렀을 때 몇 판까지 보일지(시안은 전부 · 상자 안 스크롤).
