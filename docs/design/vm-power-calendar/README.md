## 3. 시안(아트보드 4장)

**VM 이름 · 법인 · 계정 · 구간 · 수치는 전부 가상**(batch-kr1-014 · VC-KR1 · kr\ops.lee …). 네 장이 같은 가상 VM · 같은 구간을 그리고, 화면의 합계는 그 구간에서 **계산한 값**이다(따로 적어 넣은 숫자가 아니다).
색 · 글자는 `web/src/styles.css` `:root` 토큰. 꺼짐 색 `#64748b` 하나만 새로 썼다(켜짐 `--green` 과 밝기로 구분되게 — 꺼짐은 장애가 아니라 주황 · 빨강을 쓰지 않았다).

### 표시 규칙(두 시안 공통)

1. 상태는 넷: **켜짐 · 꺼짐 · 경계 불확실 · 기록 없음**. 뒤의 둘은 켜짐에도 꺼짐에도 넣지 않고 **‘판정하지 못한 시간’ 으로 따로 센다** — 비율(켜짐 %)의 분모에서 뺀다(‘못 읽은 값은 0 이 아니다’).
2. **경계 불확실**: 주기 점검 · 추적 소급은 ‘두 관측 사이’ 에 바뀌었다는 것만 안다. 그 사이를 꺼짐으로도 켜짐으로도 칠하지 않고 빗금 섞인 흐린 색으로 그린다. 전환 표의 시각도 ‘06:00 ~ 12:00 사이’ 로 적고, 이어진 시간은 ‘6시간 이상’ · ‘약 …’ 으로 적는다.
3. **기록 없음**: 포탈이 그 vCenter 를 수집하지 못한 시간(연결 실패 · 포탈 중지). 빗금.
4. 아직 오지 않은 날 · 기간 밖은 빈 칸(누를 수 없음).
5. 정밀도 숫자(점검 주기 · 슬롯 간격)는 화면에 박지 않고 **API 값**으로 그린다(시안의 ‘6시간’ · ‘12시간’ 은 지금 기본값을 옮긴 것).

## 4. 열린 질문(컨펌 때 정해 주실 것)

1. **시안 A(월 달력)와 B(연간 히트맵)** 중 어느 쪽인지 — 또는 A 를 탭 본문으로, B 의 히트맵을 드로어 · 요약에만(③ 이 그 조합).
2. **넣는 자리**: 개체 보기에 ‘전원 이력’ 탭을 새로 두는 것 + 드로어에 요약 섹션. 둘 다인지 탭만인지.
3. **정밀도**: 지금 점검 주기 기본값은 6시간이다. 그대로 두면 이벤트 로그가 없는 법인에서는 ‘6시간보다 짧게 꺼졌다 켜진 것’ 을 놓친다. ① 주기를 줄인다(점검은 수집 스냅샷만 읽어 가볍다 — 다만 스냅샷 갱신 주기보다 촘촘해질 수는 없다) ② 전원 이벤트를 주 출처로 쓴다(초 단위 · 로그 수집이 켜진 법인만) ③ 둘 다.
4. **과거분 소급**: 릴리스한 날부터만 쌓을지, 이미 있는 추적 기록 · 이벤트 로그로 지난 1년을 채울지(채우면 그 구간은 정밀도가 낮다 — 시안 ① 의 ‘12월 · 소급’ 이 그 모습). 소급하지 않으면 릴리스 직후 달력은 대부분 ‘기록 없음’ 이다.
5. **보관 기간**: 달력은 12개월씩 넘긴다(‹ ›). 몇 년을 둘지(추적 DB 기본 1095일과 맞출지).

## 5. 구현 메모(컨펌 뒤 — 지금은 제안)

- **저장**: `vm-track.db` 에 구간 표 하나(가칭 `power_spans`: vcenter_id · vm_id · state · from_ts · to_ts(진행 중이면 null) · src · gran_ms). **전환이 있을 때만 행이 생긴다** — 상태가 그대로면 진행 중 구간의 마지막 관측 시각만 갱신. 5,850 VM 이 연 몇 번 바뀌는 규모라 작다(실측 아님 — 추정). 쓰기는 점검 1회 = 트랜잭션 1개.
- **수집**: 기존 `powerOffPoller` 를 ‘꺼진 VM 만’ 에서 ‘전 VM 상태 전환’ 으로 넓힌다(스냅샷만 읽음 · 연결 실패 vCenter 는 지금처럼 관측에서 뺀다 → 그 시간은 ‘기록 없음’ 구간으로 남긴다). 이벤트 로그가 있으면 전환 시각을 이벤트 시각으로 좁힌다(이름 키라 동명 VM 은 좁히지 않는다).
- **기존 화면**: ‘꺼진 지 N일’ 판정(`resolveOffSince`)은 이 표의 진행 중 구간을 읽는 것으로 합친다 — 판정 코어를 둘로 두지 않는다.
- **API**: `GET /api/vms/:id/power-history?from&to` — 구간 목록 + 합계 + 출처별 정밀도. 탭 · 드로어를 **열 때 1회**(15초 폴링 금지) · 범위 계정은 조회 밖 404 · 늦게 온 이전 VM 응답은 버린다.
- **화면**: 일별 띠 계산은 순수 모듈 하나(웹) + 테스트(자정 넘는 구간 · 오늘 · 기록 없음 · 경계 불확실 · 분모 제외). 표는 `STable`. 문구에 백틱 없음.
- **테스트**: 구간 병합(전환 없음 = 행 없음) · 수집 중단 뒤 복구(구간이 0 으로 돌아가지 않음) · 소급 변환 · 범위 404 · prune(진행 중 구간은 지우지 않음).
- **검증**: 관련 테스트 + Chromium 1440/400. 수집 · 저장은 데이터 손실 경로라 변이 검증 대상.

### 시안 작성 기록(정직)

- 아트보드는 캔버스에 올렸고 스크립트 계산은 node 로 돌려 값(합계 · 월별 · 선택한 날)이 서로 맞는지 확인했다. **캔버스에 그려진 모습을 Chromium 으로 캡처해 판독하지는 않았다**(이 세션에서는 캔버스 런타임을 로컬로 띄울 수 없었다) — 칸 크기 · 줄바꿈 같은 배치 결함은 사용자 화면에서 처음 드러날 수 있다.
