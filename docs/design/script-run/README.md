## 1. 요구 (사용자 2026-11-14)

- 원문: "설계를 수정해서 서버에서 다른 파이선 스크립트를 실행할 수 있게 해줘, 서버에서 스크립트 실행 하는 부분을 모듈로 빼서 다른 스크립트도 실행 할 수있는 기능으로만들어줘"
- 고른 것: 스크립트 출처 = **포탈 묶음 + 관리자 등록(엄격)** — 서명된 묶음 스크립트 + 설정 소유자가 올린 스크립트(본인 OTP · 두 사람 승인 · 내용 지문 고정 · 바뀌면 다시 승인), **키의 ‘쓸 수 있는 기능’ 에 그 스크립트가 든 서버에서만** 실행.
- 원문(시안 중): "배드섹터 실행 포탈 링크" · "디스크 오류 이력 점검 링크 알려줘" → 읽은 뜻(추정): 포탈의 배드 섹터 화면에서 이 점검을 바로 실행하는 길. 시안 ⑥ 이 그 길이다(다르면 고친다).
- 앞 설계와의 관계: `../disk-audit/README.md`(디스크 오류 이력 점검 — 시안 ①~⑥ · 결정 D1~D8)의 **실행 구조(§4)를 이 모듈로 빼낸다**. 디스크 화면(법인 요약 · 서버 목록 · 상세)은 그대로 두고 실행 · 접속 · 엣지 대행 · 결과 보관만 공용으로 옮긴다.

**컨펌 뒤 확인한 것(2026-11-14 — 코드 읽기)**:
① 릴리스 서명 manifest 는 **산출물(번들 파일) 단위**다 — `manifest.files` 항목은 번들의 이름 · 종류 · sha256 이고 번들 안 파일별 지문은 없다(`server/src/upgrade/signatureCore.js matchArtifact`).
   → 묶음 스크립트는 **지문을 소스 상수로 굳힌다**(그 소스가 서명된 번들 안에 있다). 실행 직전 디스크의 스크립트 파일 지문을 상수와 대조하고 다르면 ‘서명과 다름’ 으로 실행하지 않는다. 시안 문구 ‘서명 확인’ 의 실제 뜻은 이것이다.
② iDRAC 쪽 서버 ↔ OS 등록 항목: `diskbad` 는 iDRAC 등록 항목 id + 서비스 태그로 서버를 잡고(`server/src/diskbad/scan.js:79`), 베어메탈 사용률은 iDRAC 등록 항목(id · 서비스 태그)에서 OS 등록 항목을 `pickOsEntry(os, { regHost, name, vc })` 로 고른다(`server/src/bmusage/targets.js:160 · 200 · 253`).
   → 시안 ⑥ 의 칸은 **같은 `pickOsEntry`** 로 OS 항목을 찾는다(판정을 두 벌 두지 않는다). `diskbad` 행에 그 함수가 필요로 하는 이름 · 법인이 다 실려 있는지는 구현 때 대조한다(없으면 ‘OS 계정 미등록’ 으로 보인다).

## 4. 구조

```
설정 › 보안 › 서버 스크립트(등록 · 승인)          특수기능 › 운영 작업 › 서버 스크립트 실행
        │ 본문 + 선언 + 승인 기록(지문)                    │ 실행 요청(스크립트 · 범위 · 선택지 · 사유[· OTP])
        ▼                                                  ▼
  scriptrun/registry ──────────────► scriptrun/run ── 지문 재계산 = 승인 기록? ── 아니면 거절 + 보안 사건
                                          │ 서버마다 resolveOsAuth(server, { feature: 'script:<id>' })
                                          │   └ 키의 허용 기능 · 폴더 · 법인 사용 중지 · 바꿔치기 — 막히면 ‘실행 안 함’
                                          ├ 엣지 법인 → 작업 1건(본문 + 지문 + 승인 기록) → 엣지가 지문 재확인 → 현지 SSH → 결과 1번
                                          └ 중앙 직접 → SSH: timeout -k 10 <시한> [sudo -n] python3 - <선택지 값>  ← 본문은 표준 입력
                                          ▼
                              결과 정제(상한 · 제어 문자 제거 · 요약은 아는 꼴만) → SQLite(서버 · 스크립트별 최근 N회)
                                          ▼
                 공용 결과 화면(③)  ·  전용 결과 화면이 있는 스크립트는 그 화면(디스크 오류 이력 점검)
```

- **스크립트 = 본문 + 선언**. 선언: 이름 · 하는 일(글) · 성격(읽기 전용 / 서버를 바꿈) · 권한(일반 / root) · 서버당 시한(≤ 30분) · 인자 선택지 · 요약 형식(있으면). 선언은 승인 대상에 포함된다(지문은 본문 + 선언 전체).
- **요약 형식**: 스크립트가 표준 출력 끝에 정한 표지 줄과 JSON 한 덩어리를 내면 공용 결과 화면이 표의 칸으로 보인다. 없으면 출력 글만. 디스크 점검은 이 방식으로 판정 줄 수를 낸다(disk-audit 결정 D1 과 같다).
- **엣지**: 작업 1건 → 결과 1번(고지연 회선을 줄 단위로 왕복하지 않는다). 포탈 묶음 스크립트는 엣지가 자기 판의 사본을 쓰고, 등록 스크립트는 작업에 실려 간 본문을 엣지가 지문으로 확인한다. 엣지의 키가 그 스크립트를 허용해야 한다(키는 법인 밖으로 나가지 않는다 — 엣지 포탈에서 켠다).
- **동시성**: 법인 안 1대씩, 법인끼리 동시, 중앙 직접 법인은 중앙 동시 상한. 보류(진행 중)에는 시한 — 엣지가 가져가지 않거나 답하지 않으면 ‘응답 없음’ 으로 확정.
- **성능**: 출력 저장은 실행이 끝난 뒤 한 번(트랜잭션) · 실행 목록 조회는 요약 표에서(출력 본문을 목록에 싣지 않는다) · prune 은 청크.

## 5. 보호 장치(시안 ⑤)

1. 두 사람 승인 — 올리기 · 승인 모두 설정 소유자 등급 + 본인 OTP, 올린 사람 ≠ 승인한 사람.
2. 승인은 내용 지문(sha256)에 묶임 — 실행 직전 다시 계산, 다르면 실행 안 함 + 보안 사건.
3. 키가 허용한 서버에서만 — 새 스크립트는 어느 키에도 저절로 켜지지 않는다.
4. 법인 키 사용 중지 · 키 바꿔치기 표지가 그대로 적용(같은 `resolveOsAuth`).
5. 자유 입력 인자 없음 — 선택지 값만, 본문은 표준 입력, 명령 줄을 글자로 조립하지 않는다.
6. 서버 쪽 시한 · 출력 상한(2MB).
7. ‘서버를 바꿈’ = 설정 소유자 + 실행마다 OTP + 전 법인 한 번에 불가.
8. 엣지에서 지문 재확인 + 엣지 키의 허용.
9. 감사 로그(올림 · 승인 · 돌려보냄 · 사용 중지 · 실행) + 키 사용 기록.
- 백업 복원은 승인을 되살리지 않는다(복원한 스크립트는 ‘승인 대기’) — `server/CLAUDE.md` ‘복원은 OTP 로만 바꾸는 보안 설정을 되살리지 않는다’ 와 같은 규칙.
- 출력은 신뢰하지 않는 글이다 — 화면은 텍스트로만 그리고 요약 JSON 은 선언된 칸만 받는다.

### 막지 못하는 것(화면에도 그대로 적는다)

- 포탈은 스크립트가 무엇을 하는지 분석하지 않는다. ‘읽기 전용’ 은 올린 사람의 선언이고 확인은 승인자가 내용을 읽는 것이 전부다.
- root 로 도는 스크립트는 그 서버에서 무엇이든 할 수 있다. 잘못 짜인 승인 스크립트는 허용된 모든 서버에 같은 일을 한다.
- 설정 소유자 두 사람의 계정 + OTP 가 함께 넘어가거나 포탈 서버의 관리자 권한이 넘어가면 승인 기록도 넘어간다. 엣지 쪽 키 허용이 그때 남는 두 번째 문이다(엣지가 없는 법인은 그 문이 없다).
- 실행 중 중지 단추는 1차에 없다(서버 쪽 시한).

## 7. 하지 않는 것(1차)

- 스크립트 내용 자동 분석 · 위험 명령 탐지(없는 안전을 있는 것처럼 보이지 않으려고).
- Windows · ESXi · 스토리지 장비. python3 · RAID 도구 설치.
- 대화형 스크립트(입력을 기다리는 것) · 파일 올리기/내려받기(출력 글만) · 서버 사이 복사.
- 실행 중 줄 단위 실시간 출력(엣지 법인은 끝난 뒤 한 번에 · 중앙 직접은 단계 표시만 — disk-audit 시안 ④).

## 8. 구현 때 따라올 것(예상 — 컨펌 뒤 정한다)
