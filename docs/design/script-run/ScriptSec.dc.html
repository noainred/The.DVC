보호 장치 — 스크립트 하나가 서버에 닿기까지

1
두 사람 승인올리기 = 설정 소유자 + 본인 OTP. 승인 = 다른 설정 소유자 + 본인 OTP. 올린 사람은 자기 것을 승인할 수 없습니다.
2
내용 지문에 묶인 승인승인은 sha256 에 묶입니다. 실행 직전에 저장된 본문의 지문을 다시 계산해 다르면 실행하지 않고 보안 사건으로 남깁니다.
3
키가 허용한 서버에서만SSH 공용 접속의 키마다 ‘쓸 수 있는 기능’ 에 스크립트를 하나씩 켭니다. 새 스크립트는 어느 키에도 저절로 켜지지 않습니다(키 쪽 변경도 설정 소유자 + OTP).
4
법인 키 사용 중지가 그대로 먹음접속 자격은 다른 기능과 같은 한 곳에서 풉니다 — 법인을 멈추면 그 법인 서버의 스크립트 실행도 멈춥니다.
5
자유 입력 인자 없음등록할 때 정한 선택지 값만 인자로 넘깁니다. 본문은 표준 입력으로 보내고 명령 줄을 글자로 조립하지 않습니다.
6
시한 · 출력 상한서버 쪽 시한(최대 30분)으로 멈추고, 출력은 2MB 까지만 받습니다. SSH 가 끊겨도 서버에서 계속 돌지 않게 서버 쪽에서 끊습니다.
7
‘서버를 바꿈’ 은 더 좁게설정 소유자만 · 실행할 때마다 본인 OTP · 전 법인 한 번에 실행 불가.
8
엣지에서도 다시 확인엣지는 받은 본문의 지문을 스스로 계산해 승인 기록과 맞을 때만 실행하고, 엣지의 키가 그 스크립트를 허용해야 합니다(키는 법인 밖으로 나가지 않습니다).
9
기록올림 · 승인 · 돌려보냄 · 사용 중지 · 실행(누가 · 사유 · 범위 · 지문)을 감사 로그에, 접속은 키 사용 기록에 남깁니다.

이 보호가 막지 못하는 것

  • 포탈은 스크립트가 실제로 무엇을 하는지 분석하지 않습니다. ‘읽기 전용’ 은 올린 사람의 선언이고, 확인은 승인하는 사람이 내용을 읽는 것이 전부입니다.
  • root 로 도는 스크립트는 그 서버에서 무엇이든 할 수 있습니다. 승인된 스크립트가 잘못 짜였으면 허용된 모든 서버에 같은 일이 일어납니다.
  • 설정 소유자 두 사람의 계정과 OTP 가 함께 넘어가면 승인도 함께 넘어갑니다. 포탈 서버의 관리자 권한이 넘어가면 저장된 승인 기록도 고칠 수 있습니다 — 엣지 쪽 키 허용이 그때 남는 두 번째 문입니다.
  • 실행 중 중지 단추는 1차에 없습니다. 멈추는 것은 서버 쪽 시한입니다.
