## 3. 데이터

### 3-1. 수집 경로 후보 — **전부 실장비 미확인**

| 후보 | 경로 | 근거 수준 |
|---|---|---|
| 1 | `GET /cvpservice/inventory/device/config?netElementId=<systemMac>` → `{ output: '<실행 설정>' }` | **기억에 의존**(Arista cvprac 의 `get_device_configuration` 으로 기억 — 2026-11-26 검색으로는 확인하지 못했다). 구현 전에 cvprac 소스로 다시 확인할 것 |
| 2 | Resource API `configstatus.v1` 의 `Configuration`(키: 장비 + `CONFIG_TYPE_RUNNING_CONFIG`) → `uri` 로 본문을 받는다 | 모델 문서에서 확인: `ConfigType` 에 `CONFIG_TYPE_RUNNING_CONFIG`(1) · `Configuration` 에 `uri` · `ConfigDiff` 에 `running_config_uri`(https://aristanetworks.github.io/cloudvision-apis/models/configstatus.v1/). REST 경로 모양(`/api/resources/configstatus/v1/Configuration`)은 다른 Resource API 관례에서 **추정** |
| 3 | 텔레메트리 `/api/v1/rest/{serial}/Config/running/lines` | **기억에 의존**(검색으로 확인하지 못했다). 줄이 연결 목록으로 오는 것으로 기억 — 다시 맞추는 방법도 미확인 |

- 지금 수집기와 같은 방식(`cvp/client.js` 의 경로 후보 목록 + 경로 탐색 표본)으로 차례로 시도하고, 응답한 경로를 CVP 마다 기억한다. 모두 실패하면 ‘조회 경로 없음’(⑤)이고 응답 코드만 보인다.
- 후보 1 은 장비 MAC(`systemMacAddress` — `parse.js` 가 이미 읽는다)이 필요하다.
- **배포해도 값이 안 나올 수 있다** — v3.41 의 VLAN · LAG 경로와 같은 위험이다. 실장비 ‘읽은 경로’ 원문 표본을 받으면 확정한다.

### 3-2. 흐름

1. **엣지(법인 안)** — 하루 한 번(설정값 · 법인 현지 시각), 장비마다 시각을 흩어서 CVP 에서 읽는다. 동시성 제한(`collectPool`) + 장비당 시한(`withDeadline` + `signal`) + 재진입 가드.
2. 엣지가 **가린다**(§5) → 가린 글의 해시가 직전에 올린 판과 같으면 본문은 올리지 않고 ‘같음 · 읽은 시각’ 만 올린다. 다르면 가린 판을 올린다(gzip + 청크 + 중앙 `BIG_JSON` 등록).
3. 엣지는 **0건이어도 상태를 올린다**(무음 실패 금지 — `_last` + 콘솔 + `edgelog/spec.js` 등재). ‘바뀐 것 없음’ 과 ‘수집이 멈춤’ 을 가르는 근거다.
4. **중앙** — 받은 것을 정제한다(아는 필드만 · 상한 · 엣지 시각은 수신 시각으로 자름 · 이름은 인증된 agent). **같은 가림 함수를 한 번 더 돌린다**(엣지 판본이 낮아 규칙이 옛것일 때의 방어 — 가림은 여러 번 돌려도 결과가 같아야 한다). 그 뒤 저장.
5. 엣지가 없는 법인은 중앙이 직접 읽어 같은 함수로 가린다(예외 경로).

원문은 엣지 메모리에서만 다루고 디스크 · 로그 · 오류 문구에 싣지 않는다.

### 3-3. 저장(초안 — 중앙 SQLite)

- `cfg_version`: (cvp, serial, seq) · 처음 본 시각 · 가린 글 sha · 줄 수 · 가림 규칙 판 번호(`mask_rev`) · 지문 키 세대(`key_gen`) · 본문(gzip BLOB) · 비밀 줄 지문 목록.
- `cfg_state`: (cvp, serial) 당 한 줄 — 마지막 성공 · 마지막 시도 · 마지막 오류 종류 · 최신 판 · 기준 판 · 기준을 정한 사람/시각/메모. ‘키별 최신값’ 을 `GROUP BY + MAX(ts)` 로 만들지 않으려고 따로 둔다.
- 바뀐 판만 저장한다. 보존 = 기간 + 장비당 판 수 상한(설정값), **기준 판은 남긴다**. prune 은 스로틀 + 청크(`util/chunkedPrune.js`).
- 쓰기는 트랜잭션 하나로 묶는다. 포탈 백업 묶음(`/api/admin/backup`)에는 넣지 않는다.
- 크기는 모른다(장비 설정 크기를 실측하지 못했다). 시안의 ‘1,912판 · 84MB’ 는 가상 숫자다.

### 3-4. 판정 규칙

- **기준 대비**: 같음 / 다름(+줄 · −줄 · 비밀 n) / 기준 없음 / 받지 못함. **받지 못함은 같음에도 다름에도 넣지 않고 따로 센다**. 마지막으로 받은 판은 계속 보인다.
- **직전 대비**: 최신 판과 그 앞 판. 첫 판은 ‘비교할 직전 판 없음’(전체를 더해진 줄로 세지 않는다).
- **정규화**: 읽을 때마다 달라지는 머리 주석 줄(명령 · 시각 · 장비 표기)과 줄 끝 공백은 비교 전에 뺀다. 무엇을 빼는지는 실장비 원문을 보고 확정한다(추정).
- **줄 비교**: 줄 단위. 줄 수 상한을 두고, 넘으면 구획 단위로 나눠 비교한다. 요청 경로의 계산은 조각 + 시간 기준 양보(`createYielder`).
- **구획**: 들여쓰기 없는 줄이 구획 머리. 분류는 interface · 라우팅 · 관리(계정 · SNMP · NTP · 로그) · ACL · 그 밖.
- **묶음(변경 흐름)**: 같은 날 판에서 ‘더해진 줄 · 빠진 줄’ 집합이 같은 장비끼리 한 묶음. 장비마다 값이 다른 줄(주소 등)이 섞이면 묶이지 않는다 — 그대로 둔다.
- **시각**: 하루 한 번 받으므로 ‘바뀐 것을 처음 본 판’ 의 시각이다. 실제로 바꾼 시각 · 사람은 CVP 감사 기록을 읽을 수 있을 때만 붙인다(경로 미확인 — 1차에서는 비운다). 하루 안에 바꿨다 되돌린 변경은 보이지 않는다.
- **찾기**: 최신 판만. 글자 그대로(정규식 아님) · 길이 3~120자 · 결과 상한. ‘없는 장비’ = 받은 최신 판에 줄이 없음, 받지 못한 장비 = ‘알 수 없음’(없음으로 세지 않는다). 동시 1건(`heavyGate`).

## 4. 화면 문구 원칙

- 못 받음 · 비교 못 함 · 알 수 없음은 0 이나 ‘같음’ 으로 쓰지 않는다. 이유는 아는 만큼만(응답 코드) 말하고 단정하지 않는다.
- 주기 · 보존 숫자는 화면에 박지 않고 API 값을 보인다. 문구에 백틱을 쓰지 않는다(값 인용은 ‘ ’).
- 표는 `STable`(제목 클릭 정렬 · `minWidth`), 버튼 줄은 `flexWrap`, 그리드 · 플렉스 자식 `min-width: 0`.

## 5. 가림

- **어디서**: 법인 엣지. 중앙은 가린 판과 지문만 받는다(중앙에서 한 번 더 가림 — §3-2).
- **규칙**(시안 ④ 의 표 9줄): 계정 secret/password · enable · aaa root · SNMP 커뮤니티/v3 auth·priv · TACACS+/RADIUS key · 라우팅 이웃 인증 · NTP 인증 키 · TerminAttr 의 `-cvauth`/`-ingestauth` · MACsec/키 체인/개인 키 구획 · **그 밖에 password · secret · key · community · token 이 든 줄은 낱말 뒤 전부**.
  모르는 형식은 **가리는 쪽**(과하게 가림)으로 간다. EOS 문법 표기는 기억에 의존했다 — 실장비 설정 표본으로 규칙을 맞춰야 한다.
- **낱말 추가**: 관리자가 낱말을 더할 수 있다(정규식을 받지 않는다 — 외부 입력 정규식은 O(n²) 위험). **낱말을 빼는 것 · 기본 규칙을 줄이는 것은 소유자 등급 + OTP**.
- **지문**: 비밀 값이 ‘바뀌었는지’ 만 알기 위한 것. 평문 해시는 쓰지 않는다 — SNMP 커뮤니티처럼 짧은 값은 해시만으로 값을 맞혀 볼 수 있다. **엣지가 가진 키로 HMAC** 을 만들고 잘라서 올린다. 키는 엣지의 비밀 보관(secretVault)에 두고 중앙에 올리지 않는다.
  키가 바뀌면(엣지 재설치) 세대 번호가 달라진다 → 그 판은 비밀 줄을 ‘비교할 수 없음’ 으로 보이고 ‘바뀜’ 으로 세지 않는다.
- **규칙이 바뀐 뒤 첫 판**: 예전 판은 다시 가릴 수 없다(원문이 없다). 판마다 규칙 판 번호를 남기고, 새로 가려진 줄은 설정 변경으로 세지 않는다.
- **남는 위험**: 규칙이 놓친 비밀이 중앙에 올 수 있다. 그래서 화면 · 내려받기는 관리자 전용이고 묶음 백업에서 뺀다. 가림 미리보기(붙여 넣은 글은 저장하지 않음 — 읽기성 POST)로 규칙을 미리 확인할 수 있게 했다.

## 6. 권한 · 감사

| 동작 | 게이트 |
|---|---|
| 조회(세 보기 · 판 전체 보기) | `toolsPerm` + `fullScopeOnly` + 관리자 판본(`isAdminDetailUser`). 비관리자 · 범위 계정은 탭은 보이되 권한 안내(403 → `ErrorBox`) |
| 지금 받기 | 관리자 · 동시 1건 |
| 기준으로 삼기 | 관리자 · 감사 기록(누가 · 언제 · 메모) |
| 가린 판 내려받기 · 찾기 결과 CSV | 관리자 · 감사 기록 |
| 수집 켬/끔 · 보존 · 낱말 더하기 | 관리자(설정 쓰기 = 조회 ∧ 쓰기 전체) |
| 낱말 빼기 · 가림 줄이기 | 소유자 등급 + 본인 OTP |

- 외부 API(`publicapi`) · 통합 검색 · 내보내기 묶음에는 싣지 않는다.
- 새 엣지 push 필드는 중앙 정제 화이트리스트에 넣는다. 엣지 등록부 · 설정을 못 읽었으면 빈 목록이 아니라 503.

## 7. 성능 (운영 환경 기준)

- 읽기는 법인 안(엣지 ↔ CVP)에서 끝난다. WAN 으로는 **바뀐 판만**(대부분의 날은 0건) + 장비별 상태 한 줄이 올라온다.
- 장비 수 × 설정 한 벌을 한꺼번에 읽지 않는다 — 흩어서, 동시성 제한 안에서, 장비당 시한을 두고.
- 중앙의 찾기 · 묶음 계산은 요청 경로에서 조각 + 시간 기준 양보, 동시 1건.
- 상시 폴링 라우트가 아니다(마운트 1회 + 버튼). 15초 폴링에 넣지 않는다.

## 8. 컨펌 질문

1. **범위**(기본: 1차 = 수집 + 가림 + ① 장비별 + ④ 설정 + ⑤ 상태, 2차 = ② 변경 흐름 + ③ 찾기). 한 번에 전부 할 수도 있다.
2. **변경 알림**(기본: 끔 — 화면에서만. 대안: 하루 한 번 메일 요약).
3. **기준 판**(기본: 장비마다 하나 · 관리자가 정함). ‘기준 없는 장비 전부 지금 판을 기준으로’ 한 번에 정하는 단추를 넣을지(시안에는 없다).
4. **보존**(기본: 400일 · 장비당 60판 · 기준 판은 남김 — 숫자는 설정으로 바꿀 수 있다).
5. **지문 키를 엣지에 둔다**(기본). 그러면 엣지를 다시 설치한 날은 비밀 줄 비교가 한 번 끊긴다. 대안: 중앙이 키를 내려 준다(끊기지 않지만 중앙이 키를 가진다).
6. **저장 안 한 변경(실행 설정 ≠ 시작 설정)** 을 볼지(기본: 넣지 않음 — 시작 설정을 읽는 경로를 모른다).
7. **MLAG 쌍끼리 설정 비교**(v3.53 에서 확정한 쌍을 써서 ‘쌍인데 줄이 다른 곳’) — 다음 차수 제안(시안에는 없다).
8. **검증 수준**(기본: 표준 + 가림 · 권한 · 엣지 수신 계약에 반증 1인 + 변이 검증).

## 9. 하지 않는 것 · 한계

- 설정을 고치거나 되돌리지 않는다(읽기 전용). 이 백업으로 장비를 통째로 복구할 수 없다(비밀 값이 없다) — 복구 원본은 CVP.
- 원문을 어디에도 저장하지 않는다.
- 하루 한 번이라 그 사이의 왕복 변경은 못 본다. ‘누가 · 정확히 언제’ 는 1차에서 비운다.
- CVP 조회 경로 3개는 실장비로 확인하지 못했다. 배포 뒤 ‘조회 경로 없음’ 이 나올 수 있다.
- 가림 규칙의 EOS 문법은 기억에 의존했다. 규칙이 놓친 비밀이 중앙에 올 수 있다(§5 남는 위험).
