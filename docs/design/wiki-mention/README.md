## 4. 설계 결정(시안에 그대로 그린 것)

### 4.1 자동완성
- **후보 API** `GET /wiki/pages/:id/mentionables?q=` · `GET /issues/:key/mentionables?q=`(서버가 거른다 — 화면에 전 계정 목록을 내려주지 않는다). 1자부터 · 150ms 디바운스 · 최대 8명 · 계정은 접두/포함, 이름은 포함(대소문자 무시).
- **후보 범위 = A3-02 그대로 + 그 문서(이슈)의 참여자**: 전체 범위 쓰기 계정 → 로컬 계정 전부(데모 제외) + 메일 주소 표 + 참여자(글쓴이 · 댓글 · 지켜보기 / 담당 · 보고 · 관찰 · 댓글) ·
  범위 계정 · 요청 권한 계정 → 자기 자신 + 참여자 + 볼 수 있는 이슈에 나온 이름. **역할 · 범위 · 메일 여부는 전체 범위 쓰기 계정에게만** 싣는다(그 밖은 계정 · 이름만).
- 조회 실패(403 · 네트워크)면 ‘후보를 읽지 못했습니다 — 계정을 직접 치세요’ · 후보 0명이면 ‘맞는 사람이 없습니다’(그대로 두면 글자로 남고 알림 대상이 아님 — 지금과 같음).
- 한 벌(`web/src/components/MentionBox.jsx` — textarea 래퍼)을 위키 댓글 · 이슈 댓글 · 이슈 설명 · 위키 본문 편집기(슬래시 명령과 나란히)에서 쓴다. 폴링 없음.

### 4.2 ‘계정/이름’ 표시 — 글자 그대로 저장
- 고르면 글 안에 **`@kim.lee/김이령 `** 글자가 들어간다(직접 쳐도 같음). 이름의 띄어쓰기는 뺀다(파서가 공백에서 끊는다).
- **파서 · 알림 해석 · 저장 형식은 바꾸지 않는다**: `mentionsOf` 는 `kim.lee/김이령` 을 토큰으로 잡고 `resolveMentions` 가 가장 긴 접두 `kim.lee` 로 푼다(`/` 는 NAME_TAIL_RE 가 아니라 끝으로 본다). 화면 칩은 첫 `/` 에서 갈라 계정(모노) + 이름으로 그린다.
  `.md` 내보내기 · 메일 본문 · 이슈 본문에 모두 같은 글자 → 어디서 봐도 같다. 이름은 **쓴 그때의 이름**(바뀌어도 옛 댓글은 그대로 — 의도).
- 이름 없이 친 `@kim.lee` 도 서버가 아는 계정이면 칩에 이름을 붙여 **보여만** 준다(글자는 그대로). 모르는 이름은 회색 칩.

### 4.3 언급한 사람에게 이슈 등록
- 댓글 상자에 @ 가 있을 때만 ‘이슈로 등록’ 줄이 펼쳐진다. 체크 기본 **켬**(요청의 본뜻) · 마지막 선택을 브라우저가 기억(localStorage). 끄면 지금과 같다(댓글 + 언급 메일).
- **댓글 1개 → 이슈 1건**: 담당자 = 첫 @(언급한 사람 중에서 고칠 수 있음) · 나머지 @ = 관찰자 · 유형 작업(장애 · 요청 선택) · 우선순위 P2 · **법인 = 문서의 스페이스**(공용 → 공용 — 바꿀 수 없음) ·
  제목 `[위키] <문서 제목> — <댓글 첫 60자>`(고칠 수 있음) · 본문 = 인용(있으면) + 댓글 원문 + 문서 링크 `[[제목]]` · 라벨 `wiki` · `origin: { kind: 'wiki-comment', pageId, commentId }` · 보고자 = 댓글 쓴 사람.
- **한 요청**: `POST /wiki/pages/:id/comments { body, quote, issue: { assignee, watchers, type, priority, title } }` — 댓글 저장 → 멘션 해석(기존) → 이슈 생성 → 댓글에 `issueKey` 기록 → 두 알림을 같은 묶음에.
  담당자가 그 법인 이슈를 볼 수 없으면(`issueViewers().canSee`) **400 + 사유, 댓글도 저장하지 않는다**(반쪽 저장 없음). 응답은 `{ comment, issue: { key } }`.
- **중복 방지**: 같은 `origin(pageId · commentId)` 의 열린 이슈가 있으면 만들지 않고 그 키를 돌려준다. 완료된 뒤라면 ‘다시 등록’ 이 열리고 새 이슈에 ‘관련’ 연결. 체크를 끄고 단 댓글은 나중에 댓글의 ‘등록’ 버튼으로 만들 수 있다(쓴 사람 · 운영자).
- **권한**: 담당자를 지정하는 이슈 = admin · operator(쓰기 범위 안 법인 — 기존 createIssue 판정). 요청 권한(viewer) 계정은 줄이 잠기고 사유를 보이며 ‘요청’ 으로 등록(담당자 없음 · 자동 할당 규칙이 있으면 그것이 정함)을 고를 수 있다 — 언급 메일은 그대로.
- 위키 ‘관련 이슈’ 색인에 댓글의 `issueKey` 도 넣는다(본문의 ISS 키와 같은 자리). 이슈 상세는 출처 배지 ‘위키 댓글’ + 문서/댓글 링크 · 검색식 `origin = wiki-comment`.
- 이슈 댓글의 멘션은 새 이슈를 만들지 않는다(이미 이슈 안) — 선택으로 ‘언급한 사람을 관찰자로 추가’(기본 끔).

### 4.4 메일
- **새 메일 종류 · 템플릿 없음.** 위키 댓글 줄(언급)과 이슈 할당/관찰 줄이 사람별 1분 묶음에 함께 들어가 **한 통**. 줄에 이슈 · 댓글 앵커 링크만 덧붙인다. 팀 채팅에는 이슈 생성 줄만(위키 댓글은 기존대로 안 보냄).
- 보이는 조건을 화면이 미리 말한다(`/issues/meta` 의 notify 상태 · `emailOf`): 알림 꺼짐 → ‘메일은 가지 않습니다 — 이슈는 만듭니다’ · 주소 없음 → ‘kimsh 주소 없음 · 포탈 안 알림만’. 결과 안내에도 같은 수를 밝힌다.

## 5. 결정이 필요한 것(컨펌 때)

1. ‘이슈로 등록’ 체크 **기본값** — 켬(시안 · 요청의 본뜻) vs 끔(멘션마다 이슈가 쌓이는 소음을 줄임). 시안은 켬 + 브라우저가 마지막 선택을 기억.
2. 요청 권한(viewer) 계정의 처리 — ⓐ 줄 숨김 ⓑ 잠그고 사유만 ⓒ ‘요청’ 으로 등록(시안 · 추천).
3. 후보 범위 — A3-02 그대로(시안)인지, 전 계정을 모두에게 열지(계정 열거 — 추천하지 않음).
4. 이름 표기 — 글자 그대로 `@계정/이름`(시안 · 파서 무변경)인지, `@계정` 만 저장하고 그릴 때 이름을 붙일지(이름이 바뀌면 따라가지만 .md · 메일에는 이름이 없다).
5. 이슈 댓글의 ‘관찰자로 추가’ 선택 — 넣을지(시안 · 작음) 말지.

    ④ 메일 줄에 이슈 · 댓글 링크를 덧붙이는 것(§4.4)은 넣지 않았습니다. 기존 묶음 문구만 씁니다(언급 줄 + 할당 줄이 한 통으로 가는 것은 테스트로 확인했습니다).
