## 5. 정직하게 밝혀야 하는 것

- 값은 **목(mock, 가상) 서버**의 것이다 — `/api/hosts` · `/api/hosts/corp` · `/api/hosts/checks` · `/api/platform/summary` 를 2026-11-18 12:34:03 KST 에 한 번 받아 법인별로 집계했다(호스트 186 · 클러스터 25). 하드웨어 · 재부팅 수만 12:35 에 다시 받았다(처음에 ‘장애’ 만 세어 제품의 합 13 과 맞지 않았다 — 장애 6 + 경고 7 = 13 으로 고쳤다).
- 받은 시점의 목 서버는 **호스트가 전부 연결 상태**였다(점검 0 · 끊김 0). 같은 날 10:52 에는 연결 170 · 점검 11 · 끊김 5 였다 — 목 서버 값이 주기마다 흔들린다. 그래서 이 보드의 ‘확인 대상 19’ 는 과부하 19 뿐이다.
- 합계는 제품 응답과 대조했다: 과부하 19 · 하드웨어 13 · 예기치 않은 재부팅 19 · 못 버티는 클러스터 3 · HA 꺼짐 1 · 수용 제어 꺼짐 9.
- **vCPU 비율이 같은 탭의 두 보기에서 다르다(2026-11-18 12:50 코드로 확인 — 실제 결함)**: 이 보드는 법인별 보기의 값(vCPU 11,253 ÷ 코어 6,936 = 1.62)을 썼다. 호스트 목록 위 타일 ‘할당 vCore’(`web/src/views/hostChecksText.js:160` ← `/api/hosts` `summary.vcoreAllocated`)는 1.72(vCPU 11,957)다.
  원인: 목록 요약은 호스트에 올라간 VM 을 **템플릿까지** 더한다(`routes/api/inventory.js:365-366` — `snap.vms` 를 그대로, 못 읽은 `cpuCount` 는 0 으로). 법인별은 **템플릿을 빼고** 못 읽은 값을 따로 센다(`vcenter/hostChecks.js:50-53` `templates` · `vcpuUnknown`). 목 서버에서 템플릿 138대 · vCPU 704 차이. 템플릿은 켤 수 없어 CPU 를 쓰지 않으므로 빼는 쪽이 맞다 — 목록 요약을 같은 집계로 맞추는 것을 제안한다(§8).
- 목 서버의 ‘가장 바쁜 호스트 CPU’ 는 클러스터 25개 중 19개가 90% 이상이다(97 ~ 98%)(법인마다 같은 모양의 가상 값) — 지도의 처음 색이 거의 한 단계로 보인다. ‘한 대 빠진 뒤 메모리’ 로 바꾸면 68 ~ 92% 로 갈린다.
- **캔버스에서 띄워 눌러 보지 않았다**. 보드 스크립트의 동작 논리만 node 에서 실행해 합계 · 지도 배치(열 폭 합 100% · 열마다 높이 합 100% · 칸 25개) · 누름(칸 · 칩 · 지역 · 색/크기 기준 · 찾기 · 보기 줄) · 템플릿 값 누락 0 을 확인했다. 배치가 겹치거나 넘치는지는 재생으로 봐야 안다.
- 위 숫자 3장 중 VM 수(2,242)는 11:09 값이다.
- 400px 보드는 만들지 않았다.
- 넣지 않은 것: ESXi 지원 종료 표시(새 판정) · 온도 · 전력 추이 · HBA/NIC 링크 끊김 수 · GPU — 값은 모으고 있다. 필요하면 §6 ⑤ 로.

## 7. 구현 메모(컨펌 뒤 · Opus)

- **새 집계가 거의 없다**: `/api/hosts/corp` 가 법인 · 클러스터 줄을 이미 준다(사용률 구간 · 과부하 · 여유 · HA · 한 대 빠진 뒤). 더할 것은 법인 줄의 ESXi 버전별 수 · 모델별 수 · 호스트당 VM 수 구간 · 사용률 10% 칸(지금은 5구간 `buckets`) · 하드웨어/재부팅 수(지금은 `/hosts/checks` 가 호스트별로 준다)뿐 — 화면이 호스트 658대를 받아 세지 않게 서버 응답에 넣는다.
- 상시 폴링 경로이므로 `memoJson` + `extraKey: scopeKey(...)`(+ 역할) — `docs/rules/perf-db.md`. 범위 계정은 조회 범위 안의 법인 줄만.
- **못 읽은 값은 0 이 아니다**: 사용률을 못 읽은 호스트(`buckets.na`) · 용량 모름(`capUnknown`) · 여유 계산에서 뺀 호스트(`headroomExcluded`) · 클러스터 설정 미수집(`cfgCollected: false`)은 평균 · 히스토그램 · 안전성 판정에서 빼고 **따로 센다**. 이 시안의 목 값에는 그런 줄이 0 이라 자리를 그리지 않았다 — 구현 때 각 패널에 ‘모름 N’ 을 둔다.
- `/hosts/checks` 는 권한에 따라 일부가 빈다(`access.hw` · `access.hygiene` · `access.cluster`) — 없는 권한의 줄은 0 이 아니라 숨긴다.
- 클러스터 지도의 칸 · 지역 줄을 누르면 바로가기 선택으로, 버전 · 사용률 칸을 누르면 ‘목록’ 의 조건으로 이어진다. 못 버티는 클러스터 이름은 ‘법인별’ 의 그 클러스터로.
- 보기 키 `insight` 를 Hypervisor 탭 보기의 맨 앞에 — 지금 주소(`#/hosts` · `#/hosts/<id>`)는 그대로 열린다.
- ‘지금 볼 호스트’ 는 `STable` · 문구에 백틱 금지 · 그리드 자식 `min-width:0` · Chromium 1440 · 400.
- 바로가기 복수 선택(`docs/design/vm-menu/` 의 `vcenterIds`)이 먼저 있어야 위 숫자 3장 · 다른 탭과 범위가 맞는다.

| S5 | **지도의 묶는 기준 전환** — 지역 › 법인 외에 OS · 클러스터 · ESXi 버전으로 | Datadog Host Map 의 핵심 기능 · ⑧(법인 칸)과 ⑨(클러스터 칸)의 단위가 달라 헷갈릴 수 있다 | 서버 응답에 그 기준의 합 |
| S6 | **경계를 넘은 칸에만 경고색** — 지도는 파랑 단계로 두되 90% 이상 · 못 버팀만 빨강 | 파랑이 진해질수록 나쁜지 좋은지 색만으로는 모른다 | 화면만 |

## 9. S1 · S2 · S6 반영(2026-11-18 13:01 사용자 지시 "S1 S6 S2 시안에 반영해줘" · "반영된 부분 강조해서 내가 식별할 수있게")

⑧(`docs/design/vm-insight/VmInsight.dc.html`)과 ⑨(이 폴더)에 반영했다. **노란 표(‘S1 반영’ 등)와 노란 점선**이 반영한 자리다 — 시안에서만 보이는 표시이고 구현에는 들어가지 않는다. 보드 맨 위에 그 뜻을 적은 줄이 있다.

| # | ⑧ VM 탭 | ⑨ Hypervisor 탭 |
|---|---|---|
| S1 확인할 것을 맨 위로 | 요약 6장 바로 아래 한 줄 — 과부하 VM · 디스크가 차 가는 VM · 오래된 스냅샷 · Tools 업그레이드 필요 · 고아/접근 불가 · 정지 VM | 같은 자리 한 줄 — 과부하 호스트 · 하드웨어 장애/경고 · 예기치 않은 재부팅 · 못 버티는 클러스터 · HA 꺼진 클러스터 · 끊김/점검 중. 아래에 있던 ‘확인할 것’ 패널은 없앴다(같은 내용) |
| S1 분포 접기 | ‘분포 · 구성 · 회수 후보’ 머리줄 + 접기 단추 — 접으면 한 줄 요약만 남는다(OS · 전원 · Tools · 사용률 · 크기 · 회수 후보 6개 패널) | ‘분포 · 구성’ 머리줄 + 접기 단추(ESXi 버전 · 서버 모델 · 클러스터 안전성 · 사용률 · 통합 비율 5개 패널) |
| S6 경계를 넘은 칸만 경고색 | 법인 지도 — ‘평균 CPU’ · ‘평균 메모리’ 기준에서 90% 이상인 법인만 빨강(그 밖은 파랑 단계). ‘조치 필요 비율’ · ‘디스크 초과 VM 비율’ 은 정해진 경계가 없어 파랑만 | 클러스터 지도 — 파랑 3단(50 미만 · 50–75 · 75–90) + **90% 이상만 빨강**. ‘한 대 빠지면 못 버팀’ 은 색이 아니라 칸 안의 **‘못 버팀’ 표**로(빨강과 뜻이 겹치지 않게) |
| S2 호스트 몇 대분 | ‘과할당’ 의 메모리(미사용 13.6 TB ≈ 호스트 약 23.6대분) · 분석의 회수 후보 ‘유휴 후보’(메모리 1,134 GB ≈ 약 1.9대분) | 통합 비율의 메모리 여유(30.6 TB ≈ 호스트 약 53.3대분) |

밝혀 둘 것:
- **S2 는 메모리에만 넣었다(정정)**. §8 에서 ‘미사용 메모리 · 회수 가능 스토리지 옆에’ 라고 제안했지만 스토리지와 CPU 는 넣지 않았다 — 스토리지는 호스트가 아니라 데이터스토어의 것이라 호스트 대수로 바꿀 수 없고, CPU 는 여러 VM 이 물리 코어를 나눠 쓰는 값이라(목 값: 할당 25,476 GHz > 물리 18,289 GHz) 대수로 바꾸면 부풀려진다. 환산 기준은 고른 범위 호스트 한 대의 평균 메모리다(전체 589 GB — 법인을 고르면 그 법인의 평균으로 바뀐다).
- **⑨ 의 처음 색 기준을 ‘한 대 빠진 뒤 메모리’ 로 바꿔 두었다**. ‘가장 바쁜 호스트 CPU’ 로 두면 목 값에서 25칸 중 19칸이 90% 이상이라 지도가 거의 전부 빨강이 된다(S6 을 넣으니 드러난 것). 컨펌 질문 ③(처음 색)은 그대로 열려 있다 — 실제 값에서 어느 쪽이 맞는지는 실제 분포를 봐야 한다.
- ⑧ 의 목 값에는 평균 CPU · 메모리가 90% 를 넘는 법인이 없어(50 ~ 53%) **빨강 칸이 하나도 없다** — 눈금 범례와 안내 줄로만 보인다. 색이 바뀌는 것은 ⑨ 에서 볼 수 있다(색 기준을 바꿔 보면 1칸 ↔ 19칸).
- 접기는 처음에 **펼친 상태**다. 구현 때는 접힘을 브라우저에 기억한다.
- 캔버스에서 띄워 눌러 보지 않았다 — 동작 논리만 실행해 확인했다(확인할 것 6칸의 수 · 접기 전환 · 색 기준별 빨강 칸 수 · 환산 값 · 템플릿 값 누락 0).

## 10. 이름 변경 · 지도 크기 지정(2026-11-18 13:11 사용자 지시 — 조절 줄 캡처 2장)

> "VM 화면의 법인 지도를 VM 현황 으로 변경하고, 하이퍼바이저 화면의 크러스터 지도를 가상화 호스트 현황 이라고 변경, 그리고 지도를 좀 크게 그려줘 vcenter 가 28개, VM 6000 개라서 지도가 작을 수 있어, 첨부한 그림의 맨 끝에 지도 크기를 사용자가 지정할 수 있는 기능 추가하고, 설정 시안 보여줘"

| 무엇 | ⑧ VM 탭 | ⑨ Hypervisor 탭 |
|---|---|---|
| 패널 이름 | ‘법인 지도’ → **‘VM 현황’** | ‘클러스터 지도’ → **‘가상화 호스트 현황’** |
| 지도 높이 | 330px → **처음 520px** | 392px → **처음 520px** |
| 조절 줄의 맨 끝 | 색 · 크기 기준 뒤에 **‘지도 크기’**: 자동 · 보통 · 크게 · 아주 크게 + ‘직접 지정 · 520px ▾’ 단추 | 같다 |
| 설정 상자(‘직접 지정’ 을 누르면 조절 줄 아래에 열린다 — 시안에서는 처음부터 열어 두었다) | **높이**(− · 슬라이더 · ＋ · 지금 값 — 300 ~ 1,200px · 20px 단위) / **미리 정한 크기** 4종 / **폭**(기본 폭 · 전체 폭 — 전체 폭이면 ‘지역별 분포’ 가 아래로 내려가고 지도가 화면 폭 전체를 쓴다) / **기억**(브라우저마다 · 화면마다 따로) + ‘기본값으로’ | 같다 |

- 미리 정한 크기: 보통 360 · 크게 520 · 아주 크게 760 · **자동 = 가장 긴 줄(지역)의 칸 수 × 64px**(360 ~ 1,200 사이). 목 값으로는 ⑧ 360px(한 지역에 법인 최대 3곳) · ⑨ 448px(한 지역에 클러스터 최대 7개). 법인 28곳이면 한 지역에 10곳쯤 들어가 640px 안팎이 된다 — **28곳을 그린 것은 아니다**(목 서버는 법인 11곳이다. 28곳을 지어 그리지 않았다).
- 칸 안의 글(한 줄/두 줄)은 칸의 실제 높이(px)로 정한다 — 지도를 키우면 작은 칸도 두 줄로 바뀐다.
- 이름은 패널 제목 · 접근성 이름 · 안내 글을 바꿨다. 조절 줄의 말은 사용자 표현대로 ‘지도 크기’ 로 뒀다(‘크기’ 는 이미 칸 넓이의 기준 이름이라 겹치지 않게).
- 앞 절(§3 · §8 · §9)에 적힌 ‘법인 지도’ · ‘클러스터 지도’ 는 이 패널의 옛 이름이다(기록이라 고치지 않았다).
- 구현 메모: 크기 · 폭은 `localStorage` 에 화면별 키로(읽기 · 쓰기는 try/catch — 못 읽으면 기본값) · 범위(300 ~ 1,200)는 화면에서 다시 자른다 · 400px 화면에서는 폭 선택을 숨기고(이미 한 열) 높이만 · 설정 상자는 `aria-expanded` 를 가진 단추로 연다 · 슬라이더는 키보드(← →)로도 20px 씩.
- 확인한 범위: 캔버스에서 띄워 눌러 보지 않았다. 동작 논리만 실행했다(처음 520px · 자동 360/448 · 아주 크게 760 · ＋ 두 번 800(직접) · 상한 1,200 · 20px 맞춤 · 전체 폭 · 설정 닫기 · 기본값으로 · 옛 이름 0건 · 템플릿 값 누락 0). **슬라이더가 재생 화면에서 실제로 움직이는지는 확인하지 못했다** — 안 되면 − · ＋ 단추와 미리 정한 크기로는 바뀐다.
