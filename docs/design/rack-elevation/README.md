## 4. 설계 결정(시안에 그린 것)

- **원장이 기준, iDRAC 값은 제안**: 자동값이 원장과 다르면 덮어쓰지 않고 ‘불일치’ 로 따로 센다. 사람이 고른다.
- **못 읽은 값은 0 이 아니다**: 위치를 모르면 ‘미배치’ 로 따로(사용 U · 랙 전력 합에 넣지 않음) · 상태/온도/전력을 못 읽으면 빗금 + ‘—’ ·
  랙 전력은 ‘9.6 kW (9대 중 8대)’ 처럼 읽은 대수를 함께 · 높이를 모르면 1U 로 가정하지 않고 묻는다.
- **등록 장비와 잇기**: 시리얼 일치 → 연결 · 이름 일치(후보 1) → 확인 필요 · 그 밖 → 감시하지 않는 수동 장비. 비슷한 이름을 알아서 잇지 않는다.
- **모든 인프라 장비**: 서버 · 스토리지 · SAN · 네트워크 + 포탈에 등록되지 않는 장비(패치패널 · UPS · KVM)도 수동 등록으로 자리를 그린다. PDU 는 랙 옆 띠(0U).
- **편집은 초안 → 저장**: 끌어 놓기 · 가져오기 모두 초안이고 저장해야 반영. 저장 충돌은 조용히 덮어쓰지 않는다. 변경 이력 · 되돌리기.
- **범위**: 법인 단위(법인 = vCenter = 그 전산실). 범위 계정은 자기 법인만, 밖은 404. 편집 · 가져오기는 쓰기 권한.
- **좁은 화면 · 키보드**: 끌어 놓기의 대안으로 위치 지정 칸을 항상 둔다.

### 추가 요구(2026-11-17, 시안 중)

- **세로 PDU 2 · 4 · 6개 + 액티브/스탠바이 구분**: 랙마다 등록한 수만큼 랙 옆 띠로. 액티브(A) = 실선 + 부하만큼 채움 · 스탠바이(S) = 점선 + ‘대기’ ·
  액티브가 꺼져 스탠바이가 넘겨받으면 둘 다 빨간 테두리(절체). 색만으로 가르지 않게 글자 A/S 와 선 모양을 함께 쓴다. 못 읽은 PDU 는 빗금, 합계에 ‘n개 중 m개’.
  ⚠ 시안의 가정(확인 필요): 절반이 액티브 · 절반이 스탠바이, 왼쪽이 액티브 · 오른쪽이 스탠바이. 액티브/스탠바이 역할은 수집값이 아니라 **랙 속성으로 사람이 정한다**
  (PDU 가 자기 역할을 알려 주는지 확인하지 못했다). ‘절체’ 판정은 스탠바이에 부하가 실렸는지로 하며 임계값은 구현 때 정한다.
- **PDU 색 = 소비전력**: PDU 는 전력 측정이 되는 APC 다(사용자). 포탈은 이미 APC PDU 의 `powerW` · `energyKwh` · 뱅크 부하(A) · 상 전류를 수집한다
  (`server/src/pdu/types.js` · `collectors/apcSsh.js`). 띠 색을 소비전력 4단(1 kW 미만 · 1–2 · 2–3 · 3 kW 이상 — **단계 값은 그림용**, 구현 때 절대 kW 로 할지
  정격(샘플의 32A) 대비 %로 할지 정한다)으로 칠하고, 채움 높이는 정격 대비 부하. 액티브/스탠바이는 글자 · 선 모양, 절체는 빨간 테두리라 색과 겹치지 않는다.
  ⚠ 포탈의 PDU 등록 단위는 NMC 한 대(데이지체인 본체 1~4대)다 — 랙의 세로 PDU 한 개를 어느 등록 장비의 몇 번째 본체에 잇는지가 구현 전 결정 사항.
- **데이터센터 요약(14곳)**: ⓪. 사용자가 ‘14개 데이터 센터’ 라고 했다 — 루트 CLAUDE.md 의 ‘법인 28곳’ 과 수가 다르다. 데이터센터와 법인의 관계
  (한 데이터센터에 법인 여럿인지)는 **확인하지 못했다** — 구현 전에 물을 것. 합계 규칙: 수집이 끊긴 곳은 흐리게 그리고 마지막 값임을 밝히며 측정 합계(전력 · 장애)에 넣지 않는다
  (‘13곳 중 12곳의 합’). 원장 값(랙 · 사용 U · 장비)은 중앙 원장이라 그대로 센다. 실장도 미등록인 곳은 ‘—’ + 가져오기 유도. 범위 계정에는 자기 범위의 행만.
- **평면도는 지금 없다 — 나중에 만든다**(사용자 2026-11-17): 기존 도면 자료가 없으므로 평면도는 **선택 기능**이다. 실장도 · 가져오기 · 끌어 놓기는 평면도 없이 전부 동작해야 하고,
  평면도가 없는 전산실은 처음 화면이 ‘실장도’ 로 열린다(④ States m). 나중에 ⑦에서 그리면 이미 있는 랙을 ‘평면도에 없는 랙’ 목록에서 끌어 놓는다.
  구현 순서도 실장도(1단계)를 먼저, 평면도는 그 뒤 단계로 둔다.
- **평면도 그리기 · 수정**: ⑦. 랙을 옮겨도 장비 배치는 그대로, ‘평면도에서 빼기’ 는 위치만 지운다(랙 삭제는 빈 랙만). 편집은 초안 → 저장.
- **평면도와 함께 보기**: ⑥. 평면도 원본(랙 좌표)은 수집되는 값이 없어 포탈에서 직접 배치한다(‘평면도 편집’).
- **엑셀 샘플 반영 + 가져오기**: 샘플 구조 — 랙 블록 제목 ‘A4 DVC SERVER(ESX2)’ · 열 `U | Rack | 무게 | 운전전력량 | 정격전력량` · U 42→1 ·
  2U 장비는 윗줄 표시 이름 + 아랫줄 `모델/시리얼/호스트 이름/IP` · 1U 는 `모델 (역할)/시리얼` · 아래 합계 줄(Rack 자체 무게 · 실장율 · 전력량 합계 정격/운전 ·
  발열량 · 필요 전류량 · PDU 필요개수 · 이중화 고려 PDU 개수 · Rack당 전체 무게). 장비별 무게 · 운전 · 정격은 계획값으로 저장하고, 합계 줄은 가져오지 않고 다시 계산해 대조한다.
  ⚠ 샘플은 **그림(스크린샷)으로만** 받았다 — 병합 셀 범위 · 시트 구성 · 한 시트의 랙 블록 수는 실제 .xlsx 로 확인해야 파서를 만들 수 있다.
  시안에는 샘플의 실제 호스트 이름 · IP · 시리얼을 옮기지 않았다(가상값).
- **호스트 이름 클릭 → iDRAC 정보**: ① 오른쪽 상세에 iDRAC 블록(서비스 태그 · 관리 주소(관리자만) · 전원 · CPU/메모리 · 펌웨어 · 부품 상태 칩 · 수집 시각).
  부품 판정은 기존 `idrac/invView.js`(partState · 롤업)를 그대로 쓴다. 수집 실패면 이전 값임을 밝힌다.

### 결정(2026-11-19 사용자)

- **서버는 서비스 태그로 구분한다**("서버는 서비스 테그로 하자"). 실장도의 서버 칸 ↔ 포탈 등록 서버(iDRAC)를 잇는 키는 서비스 태그 하나다.
  엑셀 아랫줄 `모델/서비스 태그/호스트 이름/IP` 의 둘째 칸이 그 값이다. 호스트 이름 · IP 는 표시 · 확인용이고 연결 키가 아니다(서비스 태그로 못 찾을 때만 ‘확인 필요’ 후보).
  비교는 기존 시리얼 색인의 정규화(`insights/serialLookup.js normKey`)를 그대로 쓴다. 화면 문구도 서버는 ‘서비스 태그’, 그 밖의 장비는 ‘시리얼’.
  남은 확인: 서버가 아닌 장비(스토리지 선반 · CVP 스위치)의 키, 서비스 태그가 바뀌는 교체 작업 뒤 같은 자리로 이어 주는 동작.
- **저장소**: 미정 — 권장은 SQLite 파일 하나(`rack.db`, 기존 `node:sqlite` 방식) · 원장은 중앙. 측정값은 넣지 않고 수집 모듈에서 서비스 태그/시리얼로 이어 읽는다.

## 5. 구현 단계(컨펌 뒤)

1. **1단계**: 랙 원장(법인 → 전산실 → 랙 → 배치) 저장 · 가져오기/내보내기 · 조회 화면 · 끌어 놓기 편집 · 수동 장비 · 변경 이력.
2. **2단계**: iDRAC 위치 속성 수집(엣지 → 중앙 정제 화이트리스트 포함) · 자동 채움 · 불일치 표시.
3. **3단계**: 평면도 보기(⑥) · 그리기/수정(⑦) — 평면도가 없어도 1 · 2단계 기능은 그대로 동작.

## 6. 열린 결정

- 실제 .xlsx 파일(그림이 아닌 원본) — 병합 셀 · 시트 구조 확인용.
- 세로 PDU 의 좌우 배치와 계통(A/B) 표기, 포탈에 등록된 PDU 와 랙을 잇는 기준.
- 전산실(방) 단계가 필요한지, 법인당 전산실이 하나뿐이면 생략할지.
- 편집 권한을 누구에게 줄지(관리자만 / 법인 운영자까지).
- 평면도에 기존 도면 이미지를 배경으로 깔 필요가 있는지(시안은 격자 위 직접 배치).

## 7. 시안 점검(2026-11-17 — Chromium 으로 직접 렌더링)

런타임(`docs/design/server-temp/support.js`) + React 를 로컬로 연결해 8장을 1440px(일부 400px)로 띄워 스크린샷을 판독했다. 글꼴은 대체 글꼴이었다(웹 글꼴 차단).

**고친 결함(시안이 깨져 있던 것)**
- ⓪ 요약 표 · ③ 합계 대조 표가 **비어 있었다** — `<table>` 안의 반복(`sc-for`)이 렌더링되지 않는다. 격자(div) 행으로 바꿨다. → 시안에서 반복 행은 표 태그 안에 두지 말 것.
- ⑥ 평면도 패널이 줄어들어 랙 10개 중 7개만 보였다(항온항습기 2 · 출입문 가림) → 패널 폭 고정.
- ② 끌어 놓기의 놓을 자리(A-06)가 가로 스크롤 밖이라 보이지 않았다 → 편집 화면은 랙 6개가 한 화면에 들어오게.
- ② 랙 이름이 두 줄로 꺾여 랙 높이가 어긋났다 → 줄바꿈 금지(재측정: 6개 랙 상단 y 동일).

## 8. DCIM 참고 자료 반영(2026-11-19 — 사용자가 붙여 준 추천 글)

사용자가 DCIM 제품 추천 글(Sunbird dcTrack · Device42 · Nlyte · NetBox · openDCIM · NetZoom, NetBox 플러그인들)을 주고 ‘참고해서 업데이트’ 를 요청했다.
⚠ 글 속 제품 설명 · 플러그인 이름은 **이 세션에서 원문(공식 사이트 · GitHub)을 확인하지 않았다** — 아래는 글이 말한 기능 방향을 설계에 옮긴 것이지 제품을 분석한 결과가 아니다.
구현 때 오픈소스 코드를 옮겨 오지 않는다(라이선스 확인 전 — 아이디어 · 자료 구조만 참고).

**받아들인 것**
- **계층**: 데이터센터 → 전산실 → 구역(Zone, 선택) → 줄(Row) → 랙 → 장비. ① 조회 화면에 경로 표시. 구역은 없는 곳이 많을 것이라 선택 단계.
- **단일 자료 모델**: 평면도와 실장도는 같은 랙 · 배치 자료를 다르게 그린다(랙 표에 좌표 · 방향을 함께 둔 기존 설계와 같다 — 문구로 명시).
- **전면 · 후면**: ① 의 전면/후면 전환을 실제로 동작하게. 배치에 ‘면(전면/후면)’ 과 ‘깊이(전체/반)’ 를 둔다 — 후면에서는 전체 깊이 장비의 뒷면(회색) + 후면 전용 장비(청록), 앞쪽 반깊이 장비(패치패널)는 숨김.
- **랙 높이 42 · 45 · 48U**: 랙 속성의 높이(U)로 이미 가능 — 시안 그림은 42U 만.
- **장비 모델 표**(NetBox 의 device type 에 해당): 모델 → 높이(U) · 깊이 · 정격/운전 전력 · 무게. 엑셀 가져오기 값으로 채우고, 계획 점검 · ‘높이 모름’ 판정이 이 표를 쓴다.
- **배치 계획 → 승인 → 반영**(글의 ‘가상 배치 후 승인’ · ‘이동 · 추가 · 변경 절차’): 새 화면 ⑧ Plan. 계획은 원장을 바꾸지 않고, 잡은 자리는 ‘예약’ 으로 보인다.
  자동 점검 = 자리 · 실장율 · 전력 · PDU 이중화 · 서비스 태그 · 무게 · 온도. **판단할 값이 없으면 ‘통과’ 가 아니라 ‘판정 안 함’**(무게 한도 미입력 등).
  반영 시점에 실장도가 달라졌으면 다시 점검하고 겹치면 반영하지 않는다. 현장 작업 목록 · 작업 지시서 인쇄.

**받아들이지 않은 것(이유)**
- **기술 스택(TypeScript · FastAPI · PostgreSQL · Konva/Fabric)**: 이 포탈은 Node/Express + React(Vite, JS) + `node:sqlite` 다. 한 기능 때문에 언어 · DB 서버를 늘리면 오프라인 패키지 · 업그레이드 경로가 갈라진다.
  끌어 놓기는 랙 20~50개 · 장비 수백 개 규모라 DOM/SVG 로 충분하다고 본다(추정 — 구현 때 실측).
- **3D 평면도**: 운영 판단(빈 자리 · 전력 · 장애 위치)에 2D 로 충분하고 구현 · 유지 비용이 크다. 요청이 있으면 다시 본다.
- **자동 발견(SNMP 등) 신규 도입**: 포탈이 이미 iDRAC · 스토리지 · SAN · CVP · PDU 를 수집한다. 새 수집기는 만들지 않는다.
- **포트 · 케이블 모델**: 범위가 커서 별도 논의(앞서 제안한 ‘케이블 연결 표시’ 와 같은 항목).

## 9. 결정 · 두 번째 엑셀 샘플(2026-11-20 사용자)

### 결정
- **법인 1 = 데이터센터 1, vCenter 는 여럿**. 코드 모델과 같다(`datacenter/store.js` — DataCenter(법인) 아래 0개 이상의 vCenter). 요약 ⓪ 의 14곳 = 법인 14곳.
  ⚠ 루트 CLAUDE.md ‘법인 · vCenter · Bareos 는 1:1:1(법인 28곳마다 vCenter 1개)’ 과 **어긋난다** — 어느 쪽이 맞는지 사용자 확인 전(CLAUDE.md 는 고치지 않았다).
- **원장은 중앙 한 곳**. 엣지는 원장을 갖지 않는다(측정값은 기존처럼 엣지 → 중앙).
- **편집은 관리자만**(판정은 `auth/demoGuest.js isAdminDetailUser` 하나 — 루트 CLAUDE.md 규약). 그 밖의 계정은 조회 · 겹쳐 보기만.
- **PDU 는 액티브-액티브, 장비가 전원공급장치(PSU) 둘을 액티브-스탠바이로 쓴다**. 시안의 ‘PDU 자체가 액티브/스탠바이’ 표기(A/S 띠 · 스탠바이 대기 0 kW · 절체)는 **틀린 모델**이라 고쳐야 한다:
  · PDU 띠는 계통(A/B)만 표시하고 둘 다 ‘사용 중’. 색 = 소비전력(그대로).
  · 장비마다 ‘주 전원 PDU A/B’ — 액티브 PSU 가 꽂힌 쪽. 장비들의 주 전원이 한쪽에 몰리면 그 PDU 만 무거워진다 → **‘PDU 편중’** 표시.
  · 이중화 점검 = ‘PDU 한 대가 꺼지면 남은 한 대가 그 랙(그 PDU 쌍)의 전체 부하를 감당하는가’.
  · 근거 자료: iDRAC 는 PSU 별 `inputWatts` · `outputWatts` 를 이미 수집한다(`idrac/redfish.js:691-693`) — 입력이 0 에 가까운 PSU 를 스탠바이로 판정할 수 있다(임계값은 구현 때 실측).
    **PSU ↔ PDU 연결(케이블)은 수집되지 않는다** — 기본값 PSU1→A · PSU2→B, 장비별로 고칠 수 있게. iDRAC 가 없는 장비(스토리지 · 스위치)는 ‘모름’.

### 두 번째 샘플(스토리지 랙 ‘S38 DVC STORAGE(ISILON)’) — 첫 샘플과 다른 점
- **열이 다르다**: 첫 샘플 `무게 | 운전전력량 | 정격전력량`, 이번 `무게 | 전력량 | 발열량`. 합계 줄에서 정격 합계는 비고 운전 합계가 채워져 있어 이번 ‘전력량’ = 운전 전력.
  → 파서는 **열 위치가 아니라 머리글 글자로** 열을 찾는다. 발열량(BTU/h)은 전력 × 3.412 로 계산되는 값이라 가져오지 않는다(합계 32,420 = 9,502 × 3.412 로 확인).
- **장비 글자 형식**이 여러 가지다(구분자 ‘/’ 앞뒤 공백 유무 포함):
  · 1U `모델 #번호 / 서비스 태그` (Dell 스위치) · 2U 윗줄 표시 이름 + 아랫줄 `모델 #번호 / 시리얼`
  · **4U 섀시 하나에 노드 여러 대**: 윗줄 표시 이름 + `모델 #1-4` + 아랫줄들에 노드 시리얼 2개씩(‘/’ 구분). 노드가 2대뿐인 섀시도 있다(#9-10).
  · 첫 샘플의 서버 `모델/서비스 태그/호스트 이름/IP`(공백 없음, 4칸).
  → 한 배치(섀시)에 시리얼 **여러 개**를 둘 수 있어야 한다. 아이실론은 노드별 `serial` · `chassisSerial` 을 이미 수집한다(`storage/collectors/isilon.js:155-158`) — 노드 단위로 이을 수 있다.
  → 칸을 ‘/’ 로 나눈 뒤 모양으로 분류(IP · 7자리 서비스 태그 · 긴 시리얼 · 호스트 이름). 분류가 애매하면 추측하지 않고 ‘확인 필요’.
- **연결 대상이 없는 장비**: Dell 스위치(S5232F · N3248TE-ON)는 포탈이 수집하지 않는다(소스에 해당 수집기 없음) → 서비스 태그만 적힌 수동 장비. Arista 는 CVP 가 `serialNumber` 를 수집한다(`cvp/parse.js:265`) → 시리얼로 연결 가능.
- **합계 검증**: 운전 합계 9,502 W = 장비 합과 일치 · 필요 전류 43.19 A = 9,502 ÷ 220 · 전체 무게 636.59 kg ≈ 장비 + 랙(144) 합 636.6(반올림 차이 추정).
  **실장율은 파일 45%, 그림 판독으로는 23U(약 55%)** — 첫 샘플(파일 90% · 판독 88%)에 이어 두 번째 불일치. 판독 착오일 수 있으나, 파일 수식이 낡았을 가능성이 있어 ‘다시 계산해 나란히 보여 준다’ 설계를 유지한다.
- **랙 높이**: 표는 U40 부터 보이는데 실장율 분모는 42 — 캡처에서 위 두 줄이 잘렸는지 40U 랙인지 원본 확인 필요.
