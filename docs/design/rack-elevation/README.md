## 4. 설계 결정(시안에 그린 것)

- **원장이 기준, iDRAC 값은 제안**: 자동값이 원장과 다르면 덮어쓰지 않고 ‘불일치’ 로 따로 센다. 사람이 고른다.
- **못 읽은 값은 0 이 아니다**: 위치를 모르면 ‘미배치’ 로 따로(사용 U · 랙 전력 합에 넣지 않음) · 상태/온도/전력을 못 읽으면 빗금 + ‘—’ ·
  랙 전력은 ‘9.6 kW (9대 중 8대)’ 처럼 읽은 대수를 함께 · 높이를 모르면 1U 로 가정하지 않고 묻는다.
- **등록 장비와 잇기**: 시리얼 일치 → 연결 · 이름 일치(후보 1) → 확인 필요 · 그 밖 → 감시하지 않는 수동 장비. 비슷한 이름을 알아서 잇지 않는다.
- **모든 인프라 장비**: 서버 · 스토리지 · SAN · 네트워크 + 포탈에 등록되지 않는 장비(패치패널 · UPS · KVM)도 수동 등록으로 자리를 그린다. PDU 는 랙 옆 띠(0U).
- **편집은 초안 → 저장**: 끌어 놓기 · 가져오기 모두 초안이고 저장해야 반영. 저장 충돌은 조용히 덮어쓰지 않는다. 변경 이력 · 되돌리기.
- **범위**: 법인 단위(법인 = vCenter = 그 전산실). 범위 계정은 자기 법인만, 밖은 404. 편집 · 가져오기는 쓰기 권한.
- **좁은 화면 · 키보드**: 끌어 놓기의 대안으로 위치 지정 칸을 항상 둔다.

### 추가 요구(2026-11-17, 시안 중)

- **세로 PDU 2 · 4 · 6개 + 액티브/스탠바이 구분**: 랙마다 등록한 수만큼 랙 옆 띠로. 액티브(A) = 실선 + 부하만큼 채움 · 스탠바이(S) = 점선 + ‘대기’ ·
  액티브가 꺼져 스탠바이가 넘겨받으면 둘 다 빨간 테두리(절체). 색만으로 가르지 않게 글자 A/S 와 선 모양을 함께 쓴다. 못 읽은 PDU 는 빗금, 합계에 ‘n개 중 m개’.
  ⚠ 시안의 가정(확인 필요): 절반이 액티브 · 절반이 스탠바이, 왼쪽이 액티브 · 오른쪽이 스탠바이. 액티브/스탠바이 역할은 수집값이 아니라 **랙 속성으로 사람이 정한다**
  (PDU 가 자기 역할을 알려 주는지 확인하지 못했다). ‘절체’ 판정은 스탠바이에 부하가 실렸는지로 하며 임계값은 구현 때 정한다.
- **평면도 그리기 · 수정**: ⑦. 랙을 옮겨도 장비 배치는 그대로, ‘평면도에서 빼기’ 는 위치만 지운다(랙 삭제는 빈 랙만). 편집은 초안 → 저장.
- **평면도와 함께 보기**: ⑥. 평면도 원본(랙 좌표)은 수집되는 값이 없어 포탈에서 직접 배치한다(‘평면도 편집’).
- **엑셀 샘플 반영 + 가져오기**: 샘플 구조 — 랙 블록 제목 ‘A4 DVC SERVER(ESX2)’ · 열 `U | Rack | 무게 | 운전전력량 | 정격전력량` · U 42→1 ·
  2U 장비는 윗줄 표시 이름 + 아랫줄 `모델/시리얼/호스트 이름/IP` · 1U 는 `모델 (역할)/시리얼` · 아래 합계 줄(Rack 자체 무게 · 실장율 · 전력량 합계 정격/운전 ·
  발열량 · 필요 전류량 · PDU 필요개수 · 이중화 고려 PDU 개수 · Rack당 전체 무게). 장비별 무게 · 운전 · 정격은 계획값으로 저장하고, 합계 줄은 가져오지 않고 다시 계산해 대조한다.
  ⚠ 샘플은 **그림(스크린샷)으로만** 받았다 — 병합 셀 범위 · 시트 구성 · 한 시트의 랙 블록 수는 실제 .xlsx 로 확인해야 파서를 만들 수 있다.
  시안에는 샘플의 실제 호스트 이름 · IP · 시리얼을 옮기지 않았다(가상값).
- **호스트 이름 클릭 → iDRAC 정보**: ① 오른쪽 상세에 iDRAC 블록(서비스 태그 · 관리 주소(관리자만) · 전원 · CPU/메모리 · 펌웨어 · 부품 상태 칩 · 수집 시각).
  부품 판정은 기존 `idrac/invView.js`(partState · 롤업)를 그대로 쓴다. 수집 실패면 이전 값임을 밝힌다.

## 5. 구현 단계(컨펌 뒤)

1. **1단계**: 랙 원장(법인 → 전산실 → 랙 → 배치) 저장 · 가져오기/내보내기 · 조회 화면 · 끌어 놓기 편집 · 수동 장비 · 변경 이력.
2. **2단계**: iDRAC 위치 속성 수집(엣지 → 중앙 정제 화이트리스트 포함) · 자동 채움 · 불일치 표시.

## 6. 열린 결정

- 실제 .xlsx 파일(그림이 아닌 원본) — 병합 셀 · 시트 구조 확인용.
- 세로 PDU 의 좌우 배치와 계통(A/B) 표기, 포탈에 등록된 PDU 와 랙을 잇는 기준.
- 전산실(방) 단계가 필요한지, 법인당 전산실이 하나뿐이면 생략할지.
- 편집 권한을 누구에게 줄지(관리자만 / 법인 운영자까지).
- 평면도에 기존 도면 이미지를 배경으로 깔 필요가 있는지(시안은 격자 위 직접 배치).
