## 4. 설계 결정(시안에 그린 것)

- **원장이 기준, iDRAC 값은 제안**: 자동값이 원장과 다르면 덮어쓰지 않고 ‘불일치’ 로 따로 센다. 사람이 고른다.
- **못 읽은 값은 0 이 아니다**: 위치를 모르면 ‘미배치’ 로 따로(사용 U · 랙 전력 합에 넣지 않음) · 상태/온도/전력을 못 읽으면 빗금 + ‘—’ ·
  랙 전력은 ‘9.6 kW (9대 중 8대)’ 처럼 읽은 대수를 함께 · 높이를 모르면 1U 로 가정하지 않고 묻는다.
- **등록 장비와 잇기**: 시리얼 일치 → 연결 · 이름 일치(후보 1) → 확인 필요 · 그 밖 → 감시하지 않는 수동 장비. 비슷한 이름을 알아서 잇지 않는다.
- **모든 인프라 장비**: 서버 · 스토리지 · SAN · 네트워크 + 포탈에 등록되지 않는 장비(패치패널 · UPS · KVM)도 수동 등록으로 자리를 그린다. PDU 는 랙 옆 띠(0U).
- **편집은 초안 → 저장**: 끌어 놓기 · 가져오기 모두 초안이고 저장해야 반영. 저장 충돌은 조용히 덮어쓰지 않는다. 변경 이력 · 되돌리기.
- **범위**: 법인 단위(법인 = vCenter = 그 전산실). 범위 계정은 자기 법인만, 밖은 404. 편집 · 가져오기는 쓰기 권한.
- **좁은 화면 · 키보드**: 끌어 놓기의 대안으로 위치 지정 칸을 항상 둔다.

## 5. 구현 단계(컨펌 뒤)

1. **1단계**: 랙 원장(법인 → 전산실 → 랙 → 배치) 저장 · 가져오기/내보내기 · 조회 화면 · 끌어 놓기 편집 · 수동 장비 · 변경 이력.
2. **2단계**: iDRAC 위치 속성 수집(엣지 → 중앙 정제 화이트리스트 포함) · 자동 채움 · 불일치 표시.

## 6. 열린 결정

- 기존 실장도 파일 형식(샘플 필요) — ③의 열 맞추기는 ‘행 목록’ 형식을 가정했다.
- 전산실(방) 단계가 필요한지, 법인당 전산실이 하나뿐이면 생략할지.
- 편집 권한을 누구에게 줄지(관리자만 / 법인 운영자까지).
- 랙 줄 배치도(평면도)까지 필요한지 — 이번 시안에는 넣지 않았다.
