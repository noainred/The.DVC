## 3. 정보 구조(IA) — 시안 ⓪

```
Backup 현황 (VeeamHeader — 그대로: Summary · Detail · Veeam · Bareos)
 └ Bareos — BareosNav 하나(5탭 · 어느 도구 키로 들어와도 같은 자리·같은 모양)
    ① 현황        #/tools/bareos-summary            ← 통합 현황 + 우선 확인                (조회 · 운영자도)
    ② 법인        #/tools/bareos-detail             ← 법인별 현황                          (조회 · 운영자도)
    ③ 운영        #/tools/bareos-backup             ← 세그먼트 4: 백업 대상 · 백업 그룹 · 복원 · 진행·이력   (관리자)
         백업 대상   …/targets   ← 백업 대상(행 버튼 6개 → 오른쪽 패널)
         백업 그룹   …/groups    ← 백업 그룹(그대로)
         복원        …/restore   ← 복원 허브 + 3단계 마법사(…/restore/<대상 id>) — 복원 창 + 복원 이력 표가 여기로(§10)
         진행·이력   …/runs      ← 진행 현황 + 실행 현황·이력(열린 동안만 Director 조회)
    ④ 정책 · 보존  #/tools/bareos-summary/policy     ← 정책·일정 + 보존·풀(한 페이지 구획 5개 · 수집 상태 한 줄)   (조회)
    ⑤ 설정        #/tools/bareos-backup/settings    ← 설정 4탭 → 왼쪽 목록 5항목(Director · 완전 설치 · 법인별 설정 · 계정 통합 · 공통 기본값·수집)   (전체 범위 관리자)
```

- 도구 키 3개(`bareos-summary` · `bareos-detail` · `bareos-backup`)와 권한·서버 집행은 그대로다(CLAUDE.md '도구 키는 바꾸지 않는다').
- **옛 주소는 새 자리로 넘긴다**(`hooks/hashTab.js MOVED_SUBS` 규약 — v2.827 엣지 토큰과 같은 방식):
  `…/bareos-backup/live` → `…/runs` · `…/bareos-backup/history` → `…/runs` · `…/bareos-summary/pools` → `…/policy`(풀 구획으로 스크롤).
  `…/targets` · `…/groups` · `…/settings` · `…/policy` 는 그대로.
- 설정의 구획은 주소 셋째 조각(`…/settings/<director|install|corp|accounts|defaults>`)으로 — 지금은 `useState` 라 새로 고치면 첫 탭으로 돌아간다.

## 4. 공통 뼈대 (5화면 모두 같은 순서 — 캔버스 파란 메모)

1. Backup 상단 탭(그대로).
2. **BareosNav** — 알약 5개(Veeam 하위 탭 `veeamSubTabs` 와 같은 모양: `panel-deep` 바탕 · 고른 탭은 `accent` 채움). 권한 없는 탭은 숨김(서버가 집행 · 탭은 UX 게이팅 — 지금 규칙 그대로).
3. **한 줄 맥락** — 같은 줄 오른쪽에 기준 시각 · 화면별 선택(법인/Director/기준일) · CSV · 새로고침 · 화면의 1차 동작 버튼 1개.
4. **얇은 알림 한 줄** — 데모·범위 밖·설정/원장 읽기 실패는 아이콘 + 한 문장(박스 배너를 쌓지 않는다). 내용은 지금 문구 그대로.
5. **상태 띠** — 카드 **4장까지**: (법인·Director 상태) · (보호 VM) · (마지막 결과 **막대**) · (확인 필요). 나머지 수치는 카드 안 작은 글자. '결과 모름' 법인 수는 확인 필요 카드에 `결과 모름 N곳 제외` 태그로.
6. **표 하나 + 필터 칩 한 줄 + 검색** — 칩은 6개까지, 나머지는 '더 보기 ▾'. 열은 6~8개.
7. **행을 누르면 오른쪽 패널**(1280px 이상 옆, 그보다 좁으면 표 아래) — 동작 버튼은 전부 패널 안. 잠긴 버튼은 지금처럼 `title` 로 이유.
8. **각주 한 문장 + '읽는 법 ⓘ' 토글**(기본 접힘) — 지금의 '칸 읽는 법'·범례·값 출처 문단은 토글 안으로 옮긴다(지우지 않는다).

색은 토큰만: 성공 `#4ade80` · 경고 `#fbbf24` · 실패 `#f87171` · 진행 `#60a5fa` · 모름 = 점선 회색 · Bareos 칩 `#fdba74`(v2.828 그대로). 카드 왼쪽 색 테두리(주황·파랑)는 없앤다 — 상태는 점과 태그로.

## 5. 화면별 설계

### ① 현황 (`Main.dc.html`)
- 상태 띠 4장: 법인·Director 28(정상·조회 실패·인증 정지·미설정) · 보호 VM(잡 등록 · 켜짐/꺼짐 · 전체 VM 중) · 마지막 결과 막대(성공·경고·실패·진행) · 확인 필요(실패·미등록·오래됨 + 결과 모름 제외 태그).
- 법인별 표 **8열**: 법인(+VM 수) · Director(점 + 상태 + 법인 · 담당) · 보호 VM(등록 / 방식) · 마지막 결과(막대 + 한 줄) · 확인 필요(수 + 내역) · 용량 · 마지막 백업 · 열기. 결과를 모르는 법인은 막대 대신 이유 한 줄, 확인 필요는 `모름` 태그(0 이 아니다).
  칩: 전체 · 확인 필요 · 정상 · 모름 + 법인 찾기. 바로가기 칩 바(11개)는 없앤다 — 표가 곧 바로가기다.
- 지금 확인할 것: 칩 5(전체 · 실패 · 미등록 · 오래됨 · 백업 없음) · 표 5열 · 8건 + '전체 N건 보기'. 권한이 없어 목록을 못 받은 계정은 지금처럼 `—` + 권한 안내(`PRIORITY_WITHHELD_TEXT`).
- 없어지는 것: KPI 3장(잡 등록 · 지금 백업 중 · 미등록·방식 불일치 — 값은 카드 안 작은 글자로 남는다) · 바로가기 바 · 주의/잡 있는 법인 칩(확인 필요 · 정상 · 모름 셋으로).

### ② 법인 (`Corp.dc.html`)
- 맥락 카드 한 줄: ‹ [법인 선택] › · Director 점 + 이름 · 상태 · 담당 · 마지막 조회 · 기본 스케줄 · 풀 · 레벨 · 이 법인 VM 수. 오른쪽 1차 동작 '고른 VM 을 백업 대상으로 →'(관리자 · 지금의 handoff 그대로).
- 상태 띠 4장: Bareos 방식 VM · 잡 등록(켜짐/꺼짐 · 복원 지점) · 마지막 결과 막대 · 확인 필요(실패 · 미등록 · 오래됨 · 백업 없음).
- 칩 6 + 더 보기(잡 꺼짐 · 방식 불일치 · 인벤토리에 없음) + 검색. 10개 필터는 전부 남는다(판정 `rowMatches` 그대로).
- 트리 표 **6열**: 폴더 › VM · 전원 · 용량 · 마지막 실행(태그 + 레벨 · 바이트) · 마지막 백업 · 상태(태그). 폴더 줄 = `잡 n / N` + 작은 막대 + 미등록·오래됨 수.
- 오른쪽 패널: VM 이름 + 태그 · 동작 줄(관리자 — 지금 백업 ▾ · 결과 · 로그 · 복원… · 비활성) · 잡·Director·클라이언트·스케줄·레벨·적용 정책·복원 지점·위치·등록 · 최근 실행 5건 · '운영 › 백업 대상에서 보기'. 동작은 기존 `bareos-backup` POST 라우트·OTP·`targetLocks` 를 **그대로 호출**(관리 권한이 있을 때만 그린다).
- '칸 읽는 법' 패널은 '읽는 법 ⓘ' 토글로.

### ③ 운영 (`Operate.dc.html`)
- 세그먼트 4: 백업 대상(N) · 백업 그룹(N) · 복원(● N 진행 중 — §10) · 진행·이력(● N 진행 중). 오른쪽 '+ 백업 대상 추가'(기존 `AddForm` — 인라인 카드 대신 모달로 여는 것은 선택, 기본은 지금 그대로 인라인).
- **진행 띠**(얇은 카드 한 줄): 지금 N건 진행 중 — VM(법인) 진행률 · 대기 사유 · 오늘 끝남 성공/경고/실패 · '진행·이력에서 보기'. 값은 **원장**(`pending` · `lastRun.state` running/queued/waiting — 이미 10초 폴링 응답에 있다)으로만 — Director 에 묻지 않는다. 속도·진행률은 진행 현황판 조회값이 있을 때만(없으면 쓰지 않는다).
- 필터 한 줄: Director 칩(점 + 이름 + 수 + 인증 정지 태그) · vCenter 선택 · OS 칩 · 검색.
- 백업 대상 표 **6열**: VM(+OS 배지 · 비활성 · 등록 뒤 바뀜 · Director 에 없음 · 데모 태그) · 법인 · Director · 위치 · 정책(레벨 · 스케줄 · 적용 정책 판정 한 줄) · 최근 실행(태그 + 시각 · 레벨 · 바이트 · 오류 한 줄) · 용량. **작업 열은 없다.**
- 오른쪽 패널: 동작 줄(실행 중이면 취소 · 아니면 지금 백업 ▾(레벨 선택) · 결과 · 로그 · 복원… · 비활성/활성 · 삭제 — 잠김 사유 `title`) · 진행률(있을 때) · 잡 · jobid · Director · 클라이언트 · 스케줄 · 레벨 · 적용 정책 · 복원 지점 · 등록 · 최근 실행 5건 · '법인 화면에서 보기'. 결과·로그·복원 창(`LogModal` · `RestoreModal`)은 그대로 쓴다.
- 진행·이력 세그먼트 = 지금의 `BareosLiveTab`(전체 법인 · 단일 법인 · 속도 상태 — 열린 동안만 30초 Director 조회) 위에, 지금의 `HistoryTab`(실행 중 · 대상별 최근 실행 필터 · 복원 이력) 아래에. 두 화면의 내용은 바꾸지 않는다.

진단: 복원이 **백업 대상 표의 행 버튼 6개 중 하나** 뒤에 숨어 있고 VM 1대씩만 된다. 체인(무엇을 얼마나 읽는지)과 전제(왜 덮어쓰기를 고를 수 없는지)는 **실행을 눌러 봐야** 안다(서버가 400 으로 알려 준다). 복원 이력은 다른 탭 아래쪽에 있다. 사용자 요청대로 **백업할 때와 같은 폴더 트리에서 여러 대를 골라** 복원하는 입구가 없다. audits.md v2.839·v2.840 의 '3차: 복원 탭' 항목이 이 작업이다.

### 10.2 바뀌는 것 — 있는 것 위에 얹는다(판정 · 라우트 순서 · OTP 는 그대로)

- **운영 › 복원 세그먼트(허브, 시안 ⑦) — 백업처럼 폴더에서 고른다**: 법인 선택 줄(vCenter = Director · 상태 · 복원 FD · 전체 VM/백업 대상/복원 가능/성공 백업 없음/진행 중 수) → **폴더 트리**(백업 그룹 편집의 트리와 같은 모양 · 열 6: 체크 · 폴더 › VM · 전원 · 용량 · 마지막 성공 백업(시각 · 레벨 · 크기 · 성공 10건 중 N) · 복원(가능 · 진행 중 · 성공 백업 없음 · 잡 꺼짐)) · 폴더 칸은 3상태 체크(그 아래 복원 가능 VM 전부) · 칩 4(전체 · 복원 가능 · 백업 없음 · 진행 중) + 검색 · **선택 바**(N대 · 마지막 백업 기준 읽을 양(추정) · 선택 해제 · 복원 시작 (N대) →) · 오른쪽에 진행 중 복원 · 최근 7일 카드 · 아래에 '진행 중 · 최근 복원' 표(전 법인 · 묶음은 한 줄로 접힘 · 진행/결과/로그/VM 보기/다시 복원).
  트리 값은 **원장**(lastRun · finishedRuns · restores)과 인벤토리만 — Director 에 묻지 않는다. 고를 수 없는 VM(복원 진행 중 · 성공 백업 없음)은 체크가 비활성이고 이유를 칸에 적는다. 묶음은 **한 법인 안에서만**(법인 · vCenter · Bareos 1:1:1) · 한 번에 최대 50대(사용자 결정 ⓑ).
- **마법사 3단계(시안 ⑧~⑩, 주소 `…/restore/<묶음>`)** — 창이 아니라 운영 본문을 차지하는 카드(단계 레일 3칸 · 오른쪽 요약 패널 · 여러 대를 한 번에):
  1. **복원 시점** — 시점 정하기 3택: 각 VM 의 마지막 성공 백업(기본) · 기준 시각 이전의 마지막 성공 백업(장애 직전으로) · VM 마다 직접 고르기. VM 마다 한 줄(고른 지점 · **읽을 백업 체인** N건 · 바이트 · 백업 당시 위치 같은지(`placementAt`) · 판정 · 바꾸기 ▾ — 펼치면 그 VM 의 지점 목록 · 레벨 태그 · 체인). 오른쪽 합계(VM 수 · 체인 합 · 바이트 합 · 예상 소요 **추정** 표기 · 제외된 VM 과 이유). 등록 전 위치로 백업된 지점은 '덮어쓰기 불가 · 새 VM 만'. 지점 목록은 `restore-points/bulk` 로 **한 Director 세션**에서 읽는다(엣지 대행이면 엣지가 로컬에서).
  2. **방식 · 대상** — 카드 3장. **새 VM 으로(권장)**: 이름 규칙 `{원래 이름}-restored-{날짜}`(한 대씩 고치기 · 동명 검사 VM 마다) · **데이터스토어는 전체에 하나 적용 + VM 마다 바꾸기**(사용자 요청 2026-11-03 — 표에 백업 당시 DS · 복원할 DS 선택 · 여유 판정 열. 여유 검사는 백업 센터 클론과 같은 규칙 `vmclone/capacity.js capacityShortfall` — 같은 DS 로 가는 VM 의 필요량 합 + 남겨 둘 하한 max(10 GiB, 전체의 5%) · 못 읽은 여유는 검사하지 않고 '모름' · 부족하면 그 VM 은 '막힘' 이라 DS 를 바꾸거나 빼야 넘어간다) · 놓을 곳 하나 · 전원 꺼진 채 고정 · **네트워크**: '어댑터 끊은 채로 만들기(권장 — 켜도 연결 안 됨)' / '백업 당시 포트그룹에 연결된 채로'(사용자 요청 2026-11-03). 네트워크 끊기는 **플러그인 옵션이 아니다**(`names.js` 화이트리스트 = 플러그인 복원 옵션: powerstate · vmname · datastore · esxhost · cluster · resourcepool · localvmdk · folder · dc) — 복원 잡이 끝난 뒤 포탈(담당 엣지가 있으면 엣지)이 vCenter 에서 새 VM 의 NIC 를 '연결 끊음 · 켤 때 연결 안 함' 으로 바꾸는 **마무리 단계**이고 VM 백업 센터 클론의 `vmclone/vsphere.js disconnectAllNics`(v2.793 — 장치는 읽은 그대로 돌려보내고 connectable 만 바꾼다)를 그대로 쓴다. **원래 VM 에 덮어쓰기**: 되돌릴 수 없어 **묶음(2대 이상)에서는 고를 수 없고 1대씩**(VM 이름 재입력 — 지금 규칙 그대로 · 사용자 결정 ⓐ) · 전제 판정(켜짐 · 스냅샷 · 위치 · 동명)은 참고용으로 VM 마다 ✓ ✕ 표시 + '다시 확인' · 네트워크 끊기는 덮어쓰기에도 고를 수 있다(기본은 그대로) · 데이터스토어는 원래 자리라 고르지 않는다. **FD 로컬 VMDK**: VM 마다 VMDK 로 · FD 여유는 포탈이 모른다 · 파일 단위 복원은 플러그인 미지원(마운트는 사람이) · 네트워크 · DS 선택 없음. 사전 점검은 `restore-check/bulk`(restorePlan dry-run + 여유 검사 · OTP 없음).
  3. **확인 · 실행** — '이렇게 복원합니다' 표(VM · 지점 · 체인 · 새 VM 이름 · 데이터스토어(여유 ✓) · 놓을 곳 · 전원 · 네트워크) + 실행 위치(Director · FD · 복원 잡 · 복원 잡 N개 — VM 마다 따로 jobid) + 마무리(네트워크 끊기 — 실패하면 '손으로 확인' · 켜지 않는다) · 예상 소요(추정) · 감사 · 영향 안내 · **본인 OTP 6자리는 묶음에 한 번** · 복원 시작 (N대). 시작 뒤 같은 자리가 **묶음 진행 카드**(묶음 번호 · 전체 막대 = 읽은 바이트 ÷ 체인 합(추정) · VM 마다 성공 · 실행 중 % · 대기(Director 차례) · 실패 · NIC 끊김 ✓ + 로그/결과/취소)가 되고, 끝나면 성공 N/N · NIC 끊김 N/N · 소요 · 실패한 대는 원인과 '다시 복원' · 새 VM 은 인벤토리 반영 뒤 'VM 보기'. 켜기와 네트워크 연결은 안을 확인한 뒤 vCenter 에서 사람이 한다.
- **400px(시안 ⑪)**: 트리가 카드 줄(체크 · 이름 · 한 줄 수치 · 태그)로, 선택 바는 트리 위에, 칩은 가로 스크롤.
- VM 패널(② 법인 · ③ 백업 대상)의 '복원…' 버튼은 이 마법사(1대 묶음)로 간다 — `RestoreModal` 은 지운다(창을 두 벌 두지 않는다).

### 10.3 서버에 더하는 것(판정은 이미 순수 함수 — 묶음 실행만 새 라우트)

| 추가 | 하는 일 | 근거 |
|---|---|---|
| `POST …/restore-points/bulk {ids}` | VM 여러 대(같은 Director · 최대 50)의 지점 + `chain`(jobid 목록 · `chainFromHistory`) + `chainBytes` 를 **한 Director 세션**으로(`ops` 작업 하나 · 엣지 대행이면 큐 작업 하나) | 지금은 대상마다 `restore-points` 한 번씩 · 체인은 실행 때만 |
| `POST …/restore-check/bulk {mode, items:[{id, jobid, newVm?}]}` | `restorePlan` 을 VM 마다 **OTP 없이** 돌려 체크리스트(전원 · 스냅샷 · 위치 · 동명 · 데이터스토어 존재 · 이름 규칙)를 ok/issue 로. 읽기 전용(인벤토리 스냅샷만) · admin · 쓰기 범위 | 지금은 POST 때 400 으로만 안다 |
| `POST …/restore/bulk {items:[{id, jobid, mode, newVm?}], otp}` | OTP **한 번**(라우트 순서는 지금과 같다 — VM 마다 전제 판정이 전부 끝난 뒤에 OTP) · 같은 Director 의 대상만(아니면 400) · 한 세션에서 **차례로** 기존 `ops restore` 호출 · VM 마다 성공 · 실패 · 결과 모름 · 보내지 않음(명령 도중 끊김은 결과 모름 — v2.847 E2-1 규칙) · `batchId` 를 원장 `restores[]` 항목에 · 대상 잠금은 지금 `oneAtATime`/`restoreOpen` 그대로(진행 중인 대상은 409 대신 그 VM 만 '보내지 않음') · 덮어쓰기는 items 가 1개일 때만 허용 | 지금은 대상 1개 `restore` |
| `GET …/restores?vcenterId=&batchId=&state=` | 전 법인 복원 이력(원장 `restores[]` 평탄화 · 최근 200 · 묶음 묶기) — 허브 표 | 지금은 대상별 `history` 안에만 |
| 진행 % | 진행 현황판(`liveStatus`)이 열려 있을 때 FD 상태의 JobBytes ÷ `chainBytes`(**추정** 표기) — 닫혀 있으면 상태만 | Director 에 새로 묻지 않는다 |
| 데이터스토어 여유 검사(`restore-check/bulk` 안) | 같은 DS 로 가는 VM 들의 필요량(백업 당시 VM 크기 — 체인 바이트가 아니라 디스크 프로비저닝 크기)을 합쳐 `vmclone/capacity.js capacityShortfall({free, capacity, need})` — 하한 max(10 GiB, 5%) · 못 읽으면 검사 안 함('모름') | VMFS/NFS 가 100% 면 그 DS 의 운영 VM 이 멈춘다(v2.795 규약) — 같은 함수 재사용 |
| 복원 마무리 `disconnectNics`(항목 플래그) | 복원 잡 성공을 폴러/로그 반영(`applyRestoreRow`)이 확인하면 vCenter 에서 새 VM(또는 덮어쓴 VM)을 **이름 + 폴더**로 찾아 `vmclone/vsphere.js disconnectAllNics` 호출 → `allNicsDisconnected` 로 확인 → `restores[]` 항목에 `nic: 'ok'|'failed'|'skipped'`. 담당 엣지가 있는 vCenter(`collectMode:'site'`)는 `vmclone/dispatch.js` 와 같은 길로 엣지가 한다(중앙은 vCenter 비밀번호가 없다). 이름이 둘이면 하지 않고 'failed — 동명 VM' | 플러그인에 NIC 옵션이 없다 · 포탈은 이미 클론 VM 의 NIC 를 끊는다(v2.793) — 두 벌 만들지 않는다 |

묶음 실행은 Director 가 FD 마다 차례로(Maximum Concurrent Jobs 만큼 겹쳐) 돌린다 — 포탈 쪽 큐를 새로 두지 않고 Director 의 대기에 맡긴다(화면은 '대기(Director 차례)' 로 표시). 일괄 등록(`jobs/bulk` · 200대 상한)이 쓰는 '한 세션 · 차례로 · VM 마다 결과' 모양과 같다.

### 10.4 그대로 두는 규칙(bareos/CLAUDE.md — 되돌리지 않는다)

복원은 jobid 목록으로만(select 금지) · 체인은 이 잡의 이력으로만(VM 마다 자기 잡) · 라우트 순서(전제 실패가 OTP 를 태우지 않게 — 묶음도 VM 마다 판정을 전부 끝낸 뒤 OTP 한 번) · 덮어쓰기 전제(못 읽은 값은 거부) · 새 VM 은 꺼진 채 · 같은 vCenter 로만 · 데모 계정은 실행 불가 · 법인 Director 에서 실행(엣지 대행이면 `withRelayWait` 만큼 기다리고 시한은 결과 모름) · 진행 중이면 같은 대상 복원·삭제 409.
새 규칙(복원 마무리): 네트워크 끊기는 **복원 잡이 성공한 뒤에만** · 장치는 읽은 그대로 돌려보내고 connectable 만 바꾼다(backing 을 비우면 DVS 포트가 풀린다 — vmclone 규약) · 실패해도 VM 을 켜지 않고 '손으로 확인' 으로 남긴다(조용히 넘어가지 않는다) · 포탈은 어떤 경우에도 복원한 VM 을 **켜지 않는다**. 데이터스토어 여유를 못 읽으면 막지도 통과시키지도 않고 '모름' 으로 두고 사람이 고른다.

### 10.5 하지 않는 것(정직 기록)

- **파일 단위 복원** — Bareos VMware 플러그인은 VM(VMDK) 단위다. 로컬 VMDK 로 풀어 마운트하는 안내만 둔다.
- **다른 vCenter 로 복원** — 플러그인 제약(문서 'Current limitations').
- **포탈이 VM 을 끄거나 지우기** — 덮어쓰기 전제를 맞추는 일은 vCenter 에서 사람이 한다('다시 확인' 버튼만).
- **묶음 덮어쓰기** — 되돌릴 수 없는 작업을 여러 대에 한 번에 걸지 않는다(1대씩 · VM 이름 재입력). 사용자 결정 ⓐ.
- **법인을 넘는 묶음** — 한 묶음은 한 법인(= 한 Director). 여러 법인을 복원하려면 법인마다 묶음을 만든다.
- 예상 소요 · 진행 % · 데이터스토어 여유는 전부 **추정 · 마지막 수집값**이고 화면이 그렇게 적는다(여유는 `restore-check/bulk` 때 인벤토리 스냅샷 값 — 실시간 조회는 하지 않는다. 백업 센터 클론은 실시간 statfs 를 보지만 복원은 Director 가 쓰므로 포탈이 그 순간을 잡을 수 없다 · 추정).
- **네트워크 끊기는 플러그인이 아니라 포탈의 마무리**다 — 복원 잡 성공과 NIC 끊기 사이에 짧은 틈이 있다(VM 은 꺼져 있어 그 틈에 네트워크에 붙지 않는다). 플러그인에 NIC 옵션이 생기면 그쪽으로 바꾼다(names.js 화이트리스트 기준 지금은 없음).
- (정정) 이 문서의 첫 판은 '여러 VM 일괄 복원은 2차 후보' 라고 적었다 — 사용자 요청(폴더에서 골라 복원)으로 이번 범위에 넣었다.

### 10.6 테스트 계획

- 서버: `restore-check/bulk` 가 `restorePlan` 과 같은 입력에서 같은 issue 를 내는지(한 함수) · OTP 를 소비하지 않는지 · `restore/bulk` 가 다른 Director 의 대상이 섞이면 400 · 덮어쓰기 2대 이상 400 · 진행 중 대상은 '보내지 않음' · 도중 끊김은 결과 모름 · OTP 는 판정 뒤 한 번 · 범위(조회 밖 404 · 쓰기 밖 403) · 데모 403 · `restore-points/bulk` 의 chain 이 실행 때 체인과 같은지 · `/restores` 범위 절단 · batchId 로 묶임.
- 웹: 트리 3상태 체크·폴더 선택(백업 그룹 `bareosGroupText` 의 pickable·check state 와 같은 함수 재사용 가능한지 먼저 본다 — 복제 금지) · 시점 3택 판정(기준 시각 이전 마지막 성공 · 없으면 제외 + 이유) · 이름 규칙 치환 · 체인 합 · 체크리스트 문구(백틱 0) · 잠금 사유 · 400px 줄바꿈. Chromium: 허브 트리 → 3단계 → 묶음 진행 카드(데모 Director 로 실제 시작 — 데모 대상 시드의 vCenter id 불일치(§9)를 먼저 고쳐야 트리가 찬다).
- 마무리·여유: `capacityShortfall` 에 같은 DS 로 가는 VM 합을 넣는지(한 대씩 넣으면 합이 넘어도 통과한다) · 못 읽은 여유는 '모름' · `disconnectNics` 가 복원 성공 뒤에만 돌고 실패를 `nic:'failed'` 로 남기는지 · 동명 VM 이면 하지 않는지 · 엣지 vCenter 는 중앙이 vCenter 에 붙지 않는지(dispatch) · `allNicsDisconnected` 로 확인하는지 · 포탈이 VM 을 켜는 경로가 0건인지(소스 스윕).
- 변이 검증 + 반증 1인(쓰기 경로 · OTP · 덮어쓰기 금지 규칙 · 마무리 단계).

### 11.3 서버에 더하는 것

- 복원 검증: 법인마다 정책 파일(`bareos-verify.json` — 주기 · 요일/시각 · 대상 폴더 · 대수 · 삭제 여부) · 러너는 그룹 러너와 같은 틱에서 돈다(한 법인 한 번에 1대 · Director 백업 창과 겹치지 않는 시각만) · 흐름은 복원 마무리 함수에 `verify` 플래그 — `disconnectAllNics → powerOnVm → waitToolsRunning(10분) → powerOffVm → (성공 ∧ 지우기) destroyClone(expectedName)` · 결과는 원장 `restores[]` 의 `verify: 'ok'|'failed'|'skipped'(Tools 없음)|'unknown'` · 담당 엣지가 있으면 엣지가(vCenter 비밀번호는 엣지에만).
- 검증용 VM 이름은 `{원래}-verify-{날짜}` 로 고정하고 **그 이름이 포탈이 이 검증에서 만든 것일 때만** 지운다(destroyClone 의 expectedName 규칙 · 이름이 둘이면 지우지 않는다). 실패한 검증용 VM 은 지우지 않고 남긴다(조사용) — 다음 검증이 같은 이름을 쓰지 않게 날짜를 붙인다.
- 일일 요약: 메일 종류 `bareos-digest` · 발송 시각 설정 · 본문은 통합 현황 집계 그대로(법인 단위 '결과 모름' 은 모름) · 발송 실패는 기준을 옮기지 않는다(`vmclone/notify.js` 규칙과 같다).
- `names.js` 화이트리스트에 `restore_allow_disks_mismatch` 한 줄 · `restorePlan` 에 `allowDisksMismatch` 옵션 · 기본 꺼짐.
- `issueHint` 두 줄(quiesce · new full required) — 문구는 테스트가 고정 · 백틱 없음.
- 첫 실행 Full: 등록 라우트의 `firstLevel: 'Full'` — 원장에 `nextLevel` 을 두고 다음 실행이 그 값으로 한 번 돌면 지운다(Bareos 에 잡 수정 명령이 없어 잡 정의를 바꾸지 않고 실행 레벨만).

### 11.4 하지 않는 것(정직 기록)

- 즉시 복구(Instant Recovery) · 파일 단위 복원 · 다른 vCenter 복원 — 플러그인이 지원하지 않는다.
- 검증의 핑 · 앱 테스트 — 네트워크를 끊은 채라 할 수 없다. 격리 포트그룹을 만들어 붙이는 방식은 vCenter 네트워크를 바꾸는 일이라 2차.
- 레딧 스레드 자체를 근거로 적지 못했다(위 11.1).

### 11.5 테스트 계획

- 검증 러너: 켜기 전에 NIC 가 전부 끊겼는지(`allNicsDisconnected`) 확인하지 못하면 켜지 않는다 · Tools 하트비트 시한 · 실패면 지우지 않는다 · 성공이어도 이름이 다르면 지우지 않는다 · 백업 창과 겹치면 미룬다 · 한 법인 동시 1대.
- 일일 요약: '결과 모름' 법인이 0 으로 들어가지 않는다 · 발송 실패 시 기준 유지.
- issueHint 두 줄 · `restore_allow_disks_mismatch` 화이트리스트 · 첫 실행 Full 이 한 번만 적용되는지.
