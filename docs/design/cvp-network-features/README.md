## 3. 기능별 판정 규칙(요지 — 구현 때 순수 함수 하나씩, 웹 · 서버 복제 금지)

- **링크 품질**: 순위 대상은 링크 올라온 포트뿐. 오류 = 누적 카운터 차이(리셋 구간 제외 — 기존 `portDelta`). 판정 4종 — 교체 후보(오류 증가 + Rx ≤ 주의 임계) · 상대 확인(오류 증가 + Rx 정상 또는 구리) ·
  플랩(기간 내 N회 이상) · 관찰. 임계는 CVP 설정값. 카운터를 못 읽은 포트는 ‘판정 못 함’ 으로 따로 센다.
- **회수**: 후보 = 링크 없음 + 마지막 사용일이 N일(30/90/180) 넘음. 기록에 한 번도 없으면 일수로 세지 않는다. 포탈은 회수하지 않는다(읽기 전용 — 권고 문구만).
- **예측**: 최근 6개월 직선 추세 · 기록 90일 미만이면 ‘기록 부족’ · 늘지 않으면 ‘예측 없음’. 부분 수집일의 값은 추이에 넣지 않는다.
- **전후 비교**: 한쪽이 못 읽은 값은 ‘달라짐’ 이 아니라 ‘비교 못 함’. BGP 피어 주소 가림은 기존 세 응답과 같은 규칙. 스냅샷은 보관 기간(설정)·개수 상한.
- **GBIC 추세**: 일 최저 Rx(링크 없는 날 제외 · 다레인은 최저 레인) · 최근 30일 직선으로 임계 도달 예상 · 30일 미만은 ‘기록 부족’ · 값이 계단식으로 회복되면 그날부터 다시.
- **토폴로지**: 양쪽이 서로 본 링크 = 실선, 한쪽만 · 설명만 = 점선 ‘추정’. 층은 이웃 수로 자동(설정에서 고정 가능). 서버 · 스토리지는 리프 쌍 아래 종류별 개수.
- **양끝 불일치**: 양쪽 다 CVP 관리 스위치인 링크만 — MTU · 속도 · Duplex · 관리 상태 · 포트 채널 멤버 수 · 설명이 가리키는 상대. 한쪽 못 읽음 = ‘비교 못 함’.
- **위치 찾기**: 답은 ‘가장자리 포트’(상대가 스위치가 아닌 포트 — LLDP 로 판정)에서 본 MAC 만. 업링크는 뺀다. VM 은 vCenter 인벤토리로 호스트에 잇는다. 저장은 가장자리 포트 MAC 만 + 포트당 상한
  (**행 수를 먼저 계산할 것** — 5,850 VM + 서버 수준이면 수만 행 · 이동 이력은 변할 때만 적재). 찾지 못함 ≠ 없음(못 읽은 장비 수를 함께 말한다).
- **설정 백업**: 비밀 줄(해시 · 커뮤니티 · 키)은 값을 저장하지 않고 지문만 — ‘바뀜’ 만 안다. 관리자 전용(`isAdminDetailUser`) · 내려받기 감사 로그 · 복원 기능 없음. 받지 못한 장비는 ‘같음’ 이 아니다.
- **버전 준수**: CVP 판정을 그대로 가져온다(포탈이 판정하지 않음) · 목록 날짜를 항상 함께 · ‘공지 없음’ 과 ‘못 읽음’ 구분 · 지원 종료일을 지어내지 않는다.
- **이중화**: 설정된 멤버 수 대비 올라온 수. 이중화 상실(일부만) · 양쪽 내려감 · 확인 불가. 새 장애 종류로 열면 기존 `faults.js` 6규칙(판정은 중앙만).

## 4. 공통 구조

- 수집은 엣지(법인 안) → 엣지 DB → 변경분 push → 중앙 DB. 새 수집 항목은 전부 **부품 주기**(매 수집 주기에 싣지 않는다) + 장비당 시한 · 예산 안에서. 새 push 필드는 **중앙 정제 화이트리스트에도** 넣는다.
- 판정 · 순위 · 예측은 중앙에서 조회 시 한 번. 요청 경로의 큰 집계는 `memoJson` + `extraKey: scopeKey(...)` · 조각 + 시간 기준 양보.
- 게이트: 기존 CVP 라우트와 같다(`toolsPerm` + `fullScopeOnly` — 범위 계정 403). 설정 백업만 관리자 전용 추가.
- ‘새 수집’ 5종(MAC · ARP · 설정 · 준수 판정 · MLAG)의 CVP 조회 경로는 **실장비 미확인** — 후보 체인 + ‘읽은 경로’ + 원문 표본(관리자)으로 좁힌 뒤 굳힌다(v2.608 규약).
