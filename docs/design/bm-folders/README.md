## 4. 설계 결정(시안에 그린 것 — 컨펌 대상)

1. **새 도구 ‘물리서버 폴더’**(도구 키 가칭 `bm-folders`). 통합 서버 인벤토리(분류 · 법인 귀속)와 서비스 인벤토리(서비스 · 규칙) 사이에 놓인다.
2. **트리는 법인 › 폴더(여러 단계)** — vCenter › 클러스터와 같은 꼴이고, 법인 단위 범위 · 쓰기 권한이 그대로 선다. 법인을 넘는 보기는 ‘폴더 이름별(전 법인)’ 읽기 전용 합산으로 준다.
3. **한 서버는 한 폴더에만**(호스트 ↔ 클러스터와 같은 규칙) — 대수 합이 항상 맞고(전체 = 등록 + 미분류 + 법인 미지정) ‘추가’ 가 아니라 ‘이동’ 이다.
4. **대상은 베어메탈이 기본**, ‘ESXi 호스트 포함’ 은 찾기에서 고르는 선택(ESXi 호스트는 이미 vCenter 클러스터로 나뉜다).
5. **검색 일괄 등록**: 정규식이 아니라 ‘포함’(대소문자 무시 · 길이 상한 · 선형 — 정규식 규약) · 쉼표로 여러 글자 · 제외 글자 · 찾는 곳(이름 · 호스트명 · 서비스 태그 · 모델 · iDRAC 주소는 관리자만).
   전 법인으로 찾으면 서버는 **자기 법인의 같은 이름 폴더**로 들어가고 없는 법인에는 폴더를 만든다. 이미 다른 폴더에 있는 서버는 기본으로 건드리지 않는다. 등록 전에 법인별 증감을 미리 보인다.
6. **자동 규칙(선택)**: 검색 조건을 ‘이름에 포함 → 폴더’ 규칙으로 저장하면 새로 인식되는 서버도 들어간다. 손으로 넣은 등록이 규칙보다 우선.
7. **엣지 서버도 중앙에서 등록**: 등록 정보는 **중앙에만** 저장한다(`CONFIG_DIR/bm-folders.json` 가칭 — 비밀 없음 · 원자 쓰기 · rev). 엣지 push 계약은 바꾸지 않는다(엣지가 올린 베어메탈 목록의 키로 조인).
   엣지 보고가 만료되면 등록은 두고 흐리게 · 측정값 ‘—’ · 없어진 서버 판정은 보류.
8. **서비스 인벤토리 연결(2단계)**: ‘물리서버 폴더 규칙’(폴더 경로 → 서비스)을 VM 의 vCenter 폴더 규칙과 같은 순위에 둔다. 판정 순서가 바뀌므로 옮겨 가는 구성원을 검토 큐에 먼저 보이고 릴리스 노트에 고지한다.

9. **화면 패턴(2차 — 모니터링 솔루션에서 흔한 것을 포탈 토큰으로)**: 색 · 글자 · 셸은 포탈 그대로 두고 **정보 구조만** 가져왔다(다른 회사 화면을 베끼지 않는다).
   - **질의 막대 + 토큰**(`폴더:DB/Oracle RAC` · `포함:db` · `제외:bak`) — 지금 무엇으로 걸렀는지가 항상 보인다. 값은 ‘포함’ 이고 정규식이 아니다.
   - **조건별 개수(패싯)** — 일괄 등록에서 법인 · 받는 길 · 지금 폴더 · 모델별 일치 대수를 먼저 보이고 체크로 좁힌다.
   - **서버 맵** — 폴더 = 상자, 서버 = 칸. 색은 한 색상의 밝기 5단(사용률), 못 읽음 = 점선 빈 칸, 꺼짐 = 회색, 장애 = 빨간 테. 미분류에서 같은 성격의 서버가 붙어 보이는 것이 등록 단서가 된다.
   - **인라인 막대** — 표의 CPU · 메모리 · 등록 비율을 숫자 + 막대로. 못 읽은 값은 막대 없이 ‘—’.
   - **옆 패널** — 서버를 누르면 화면을 떠나지 않고 태그 · 지표 · 장애 · 폴더 이동을 본다. 24시간 CPU 추이는 `bmusage/db.js usageHistory` 가 근거(엣지 서버는 중앙에 이력이 있는지 구현 때 확인).
   - **저장한 보기** — 거르기 · 묶기 · 색 조합을 이름 붙여 저장(브라우저 저장으로 시작 — 결정 ⑦).
   - 쓰지 않은 것: 대문자 라벨(`text-transform: uppercase` 금지 규약) · 육각 칸(둥근 사각으로) · 밝은 테마.

시안과 달라진 점(정직 기록):
- **맵 보기(②)와 '저장한 보기' 는 2단계** — 사용자 기본값 ⑦. 화면의 보기 전환(목록/맵) · 보기 고르기 버튼은 그리지 않았다.

  → 별칭은 같은 법인 등록만 · 다른 구성원의 지금 키 · 둘 이상이 주장하는 별칭은 쓰지 않음(`aliasGuardOf`) · 쓰기 경로 · 서비스 인벤토리 배치도 같은 가드.
- A2(낮음): 지금 키 등록과 옛 키 등록이 함께 있으면 옛 등록이 어디에도 안 보였다 → 쓰지 않은 별칭 등록은 목록에 없는 등록 · 다시 쓰면 같은 법인 별칭 등록을 모두 정리.
- A3(낮음): 다른 법인 별칭 등록이 불일치(경로 빈칸 · 범위 계정이 못 지움)로 보였다 → 그 법인의 목록에 없는 등록으로(그 법인 계정이 지운다).
- B1(낮음): 분류 예외(exclude)로 뺀 서버도 보류됐다 → 신선한 전력 항목이 있는 서버 · exclude/virtualization 분류는 보류하지 않음. B2(낮음): ESXi 대조가 태그 · 표시 이름만 → 호스트 이름 전부(짧은 이름 포함).
- 반증 B 3(낮음): 릴리스 노트가 영향 범위를 좁게 적었다(이름에 IPv4 포함 · iDRAC 주소와 같은 이름 · 2~3자 태그) → 노트를 실제 범위로 · 태그 임계를 화면 가림과 같은 4자로(2~3자 태그는 화면이 가리지 않는데 규칙만 걷어 내 기능만 잃었다).
- 반증 B 4(낮음): 화면 문구에 '하루' 를 박았다 → 숫자 대신 '보류 시한(설정값)'. 반증 B 5(낮음): 화면 가림과 규칙의 소문자화가 달랐다('Σ') → 같은 `lowSameLen`.
- 반증 B 7(낮음 · 문서): service-map 설계 문서가 4차 반증 4 를 '잔여 위험' 으로 둔 채였다 → 정정.
- 별건(이 판본 전부터): 폴더 삭제 확인 수(화면 = 손 등록 서버 행)와 서버 셈(목록에 없는 등록 포함)이 달라 늘 409 → 폴더 노드 `regs` 로 같은 셈 · 목록에 없는 등록 한 건씩 지우기.
- 사소: 해제 수가 서버 수가 아니라 항목 수였다 → `removed` = 서버 수 · `entries` = 항목 수.
- **남긴 것(반증 B 6 — 낮음 · 기존 동작 · 이번 범위 밖)**: 범위 계정 응답(물리서버 폴더 `servers` · 서비스 인벤토리 `members` · `candidates` · CSV)의 순서가 함대 정렬(전력 → **원문 이름**)을 따라
  가린 태그의 순서를 드러낸다(반증 6 은 `/search` 만 고쳤다). 순서로 태그를 좁히는 악용은 추정(시험 안 함). 다음 점검 후보.
- 변이 검증: 1차 12/12 · 반증 반영 14건(처음 9/14 — 같은 법인 겹침 · 해제 수 · 태그 소문자화 · 배치 가드 시험을 보강해 14/14).

### 11.2 아트보드

```
① Main        엣지 포탈 목록 — 사본 띠(판본 · 받은 시각 · 다음 받기 · [지금 받기] · [중앙에서 편집]) · 요약 띠(이 엣지 목록 44 = 등록 38 · 미분류 6 + 이 엣지 밖 등록 3)
              · 트리(법인 하나 › 폴더 · 맨 아래 ‘이 엣지 밖 등록’) · 폴더 요약 칸과 표는 이 엣지가 수집한 지금 값 · ‘읽기 전용’ 표지
② States      ⓐ 정상 ⓑ 방금 받음(바뀐 것 요약) ⓒ 중앙과 끊김(마지막 사본 + 나이) ⓓ 받은 적 없음(이유 하나) ⓔ 중앙이 이전 판본
              ⓕ 이 엣지에서 예전에 만든 폴더 ⓖ 두 목록이 다를 때(이 엣지 밖 등록 · 중앙이 아직 모르는 서버) ⓗ 조회 계정 ⓘ 법인 둘을 수집하는 엣지
```

### 11.3 설계 요지(시안에 그린 기본값)

- **저장소는 중앙 하나 그대로.** 엣지는 자기 법인 것만 주기적으로 받아 **읽기 전용 사본**(`bm-folders-central.json` — 설정 변경 감시 밖)으로 두고, 그 위에 **이 엣지의 지금 값**(서버 목록 · 사용률 · 전력 · 부품 장애 · 추이)을 얹어 그린다.
  서버 값이 WAN 을 왕복하지 않는다(법인 로컬 원칙 · 폴란드/미국 동부 RTT 800ms+).
- **판정은 중앙이 한 결과를 내려보낸다**(서버 → 폴더 · 손 등록/자동 규칙). 엣지가 규칙으로 다시 판정하지 않는다 — 판정 코어 하나(`bmfolders/build.js`) 유지 · 자동 규칙 값이 엣지로 나가지 않는다.
- **키는 중앙이 엣지 키로 바꿔 보낸다**(태그 있으면 그대로 · 태그 없으면 엣지 보고의 `fleetId` 로 `fl:` 를 만든다). 중앙이 직접 수집하거나 수집 서버 경로로 받는 그 법인 서버는 엣지 목록에 없으므로 **‘이 엣지 밖 등록’** 으로 따로 센다(합계 · 평균에 넣지 않는다).
- **끊겨도 마지막 사본을 지우지 않고 나이를 보인다**(기존 설정 당김 워커 규약). 못 받은 것과 폴더가 없는 것을 가른다(받은 적 없음 = 이유 하나를 말한다).
- **엣지 → 중앙**: 받아 간 판본 · 시각을 다음 받기 요청에 실어 보내고, 중앙 법인 표에 **‘엣지 전달’ 칸**으로 보인다(무음 실패 금지 — 바꾼 사람이 ‘엣지에 갔는가’ 를 본다).
- 내려보내는 범위는 그 엣지의 법인만(엣지별 토큰 ↔ agent 바인딩 — `routes/central.js` 미들웨어) · 다른 법인 · 법인 미지정 · 등록한 사람 · 감사 기록 · 자동 규칙 값은 싣지 않는다.

### 11.4 결정 필요(사용자) — 괄호 안이 시안의 기본값

1. **엣지에서 편집**: (가) 읽기 전용 + ‘중앙에서 편집’ 링크 **[기본]** · (나) 엣지에서도 편집(③ — 중앙에 전달해 저장 · 끊기면 못 바꿈).
   (나)는 엣지 계정을 중앙 쓰기 권한에 대응시키는 규칙 · 엣지 사용자 쓰기를 중앙에 전달하는 통로 · 엣지 이름이 남는 감사가 더 필요하다(이 도구에는 지금 없다).
2. **이 엣지에서 예전에 만든 폴더**(v2.984 ~ v2.989 에 엣지 포탈에서 직접 만든 것): (가) 지우지 않고 쓰지도 않음 + 목록 · CSV 내려받기 **[기본]** · (나) 중앙에 ‘엣지 폴더 가져오기’ 를 만든다 · (다) 중앙 사본을 받기 전까지만 로컬 것을 보인다.
3. **받기 주기**: 10분 + ‘지금 받기’ **[기본 — 다른 설정 당김 워커와 같다]**.
4. **오래된 사본**: 지우지 않고 나이만 보임 **[기본]** · 또는 일정 기간(예: 30일)이 넘으면 화면을 ‘받은 적 없음’ 처럼 바꾼다.
5. **폴더에 연결된 서비스 이름**을 엣지에도 보일지: 보임 **[기본 — 그 법인 것만]**.
6. **‘이 엣지 밖 등록’** 을 엣지에 보일지: 이름과 함께 보임 **[기본]** · 개수만 · 숨김.
7. **중앙 법인 표의 ‘엣지 전달’ 칸**: 넣는다 **[기본]**.

### 11.5 정직 기록 — 확인하지 못한 것

- 렌더 확인은 앞 시안과 같이 **정적 판본**(`<x-dc>` 를 `<div>` 로 바꾼 것)을 로컬 Chromium 으로 본 것이다(1440 · 1000 · 400 폭 — 넘침 · 잘림 0 측정 · 스크린샷 5장 판독 · 판독에서 3건 고침:
  링크 버튼 밑줄 · 파일 이름 잘림 · 긴 문장이 아이콘 아래로 떨어짐). 실제 캔버스에서는 웹 글꼴 폭이 달라 줄바꿈이 다를 수 있다.
- 키 대응(11.1 넷째 줄)은 **양쪽 식을 코드로 읽어** 확인한 것이다 — 실제 엣지 보고 값으로 두 키가 맞는지는 구현 때 시험으로 고정해야 한다(ESXi 를 베어메탈로 강제한 `host:` 행 · OME 장치 · 구버전 엣지는 따로 본다).
- 한 엣지가 법인 둘을 수집하는 경우(ⓘ)가 운영에 실제로 있는지는 확인하지 않았다(법인 · vCenter 1:1 원칙상 드물다고 본다 — 추정).
- 구현 규모 · 시간은 재지 않았다. 기본값 (가) 기준으로 필요한 것: 중앙 묶음 라우트(엣지별) · 엣지 받기 워커(+ `edgelog/spec.js` 등재) · 사본 저장소 · 엣지 판본 화면 · 중앙 ‘엣지 전달’ 칸 · 회귀 시험.
