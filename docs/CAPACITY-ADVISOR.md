# 리소스 적정성 진단 (Capacity Advisor)

**신규 v2.254.0.** 포탈이 실제로 도는 서버 — **중앙(이 서버)과 각 엣지 에이전트** — 의 리소스가
현재 부하에 적절한지 상시 실측하고, **1일/1주/1달** 창별 통계로 **증설/적정/감축**을 조언합니다.

화면 위치: **특수 기능 → 📊 리소스 적정성 진단** (관리자 전용).

- 목적: "이 포탈 인프라를 늘려야 하나, 지금이 적절한가, 과한가"를 감(感)이 아니라 **실측 근거**로 판단.
- 대상: vCenter 인벤토리가 아니라 **포탈/엣지 호스트 자신**의 자원(자가 진단).

---

## 1. 무엇을 측정하나 (수집기)

운영 중인 포탈 프로세스 안에서 **기본 30초마다** 자기 호스트를 실측합니다(별도 벤치마크 없음 —
실제 운영 부하가 그대로 측정 대상). Node 내장(`os`/`process`/`perf_hooks`/`fs.statfs`)만 사용하며
외부 의존성을 새로 들이지 않습니다.

| 지표 | 그룹 | 단위 | 경고 / 위험 | 비고 |
|---|---|---|---|---|
| CPU 사용률(시스템) | cpu | % | 70 / 85 | `os.cpus()` times 차분 |
| CPU 사용률(포탈 프로세스) | cpu | % | (정보) | `process.cpuUsage` 델타 ÷ 코어 |
| 부하평균/코어(1분) | cpu | ratio | 1.0 / 2.0 | `os.loadavg()`/코어 수 |
| **이벤트 루프 지연(p99)** | runtime | ms | 100 / 300 | `perf_hooks.monitorEventLoopDelay` — 응답 지연 직결 |
| 메모리 사용률(시스템) | memory | % | 80 / 92 | 리눅스는 **MemAvailable** 기준(MemFree 는 캐시로 오판) |
| 포탈 RSS | memory | MB | (정보) | 1주 추세로 누수 의심 경고 |
| 디스크 사용률(데이터) | disk | % | 80 / 90 | `capacity.db` 가 놓인 파일시스템 |
| 수신/송신 처리량 | network | bps | (정보) | 리눅스 `/proc/net/dev` 차분(비리눅스 미측정) |

수집기는 **등록형**입니다(`server/src/capacity/collectors.js` 의 `registerCollector`). 향후 모니터링
지표를 추가할 때 한 곳에 등록하면 저장·평가·게이지·추세·권고에 자동 편입됩니다.

## 2. 저장 — 이원 보존 (원본 + 시간당 롤업)

`capacity.db`(CONFIG_DIR, 업그레이드에 보존). 스키마·PRAGMA(WAL+synchronous=NORMAL+busy_timeout)·
ts 인덱스·prune 스로틀·재진입 가드는 기존 시계열 DB(metrics/idrac) 규약을 그대로 따릅니다.

- **원본**: 30초 샘플을 기본 **72시간** 보존(1일 창의 정확한 p95 계산용).
- **시간당 롤업**: `samples_hourly` 에 1시간 1행으로 약 **13개월** 보존(1주/1달 창 — 화면에 '롤업 근사' 표기).
- 적재 트랜잭션 안에서 롤업을 함께 upsert(둘이 어긋나지 않게), `prune` 은 원본·롤업을 함께 정리.

## 3. 판정 규칙 (실측 근거 필수)

각 창(1일/1주/1달)의 지표 통계로 판정합니다. **모든 권고에 p50/p95/max·표본 수를 함께** 냅니다 —
표본이 부족하면 판정하지 않고 **측정 중**으로 표시합니다(데이터 없는 단정 금지).

- **증설 필요** = 창의 **p95 ≥ 위험 임계**. 지속적으로 위험 구간.
- **경계** = p95 ≥ 경고 임계. 추세를 지켜보고 확장을 준비.
- **감축 검토** = **1달 창**에서 **피크(max)조차 경고 임계의 절반 미만**일 때만. 하루 이틀 한가한
  것으로 감축을 권하지 않습니다(월말 배치 피크에서 사고 방지).
- **급성 악화**: 1달 창은 괜찮은데 최근 1일이 위험이면 그것을 우선 경보.
- **RSS 누수 의심**: 포탈 RSS 가 최근 1주 하루 20MB+ 지속 증가(선형회귀)면 경고.

리소스 축(cpu/memory/disk/runtime) 종합 = 그 축 지표들의 최악값.

## 4. 중앙 + 엣지

- **중앙(이 서버)**: 로컬 샘플러가 `k='local'` 로 적재.
- **엣지 에이전트**: 자기 리소스를 1분마다 중앙으로 push — `POST /api/central/capacity-report`.
  **엣지별 개별 토큰 전용**이며 저장 키는 토큰에서 해석한 agent(사칭 403). 시각은 중앙 수신 시각이
  진실(엣지 시계 오차에 둔감). 화면 상단 호스트 탭에서 중앙·전 엣지를 전환하며, 5분 이상 무보고면
  '무보고 N분 전'으로 표시합니다.

## 5. API (모두 admin 전용 — 서버가 `requireRole('admin')` 강제)

- `GET /api/capacity/summary` — 전 호스트 1달 창 축 종합 + 샘플러/push 상태 + 수집기 메타.
- `GET /api/capacity/host?k=<local|agent>` — 호스트 1대의 창별 지표 통계·판정·권고 문장.
- `GET /api/capacity/history?k=&metric=&window=` — 추세 차트용 버킷 시계열.

## 6. 환경변수

| 변수 | 기본 | 뜻 |
|---|---|---|
| `CAPACITY_MON_ENABLED` | on | 진단 전체 킬스위치(`=false` 로 끔) |
| `CAPACITY_SAMPLE_INTERVAL_MS` | 30000 | 로컬 샘플 주기(최소 10초) |
| `CAPACITY_RAW_RETENTION_HOURS` | 72 | 원본 샘플 보존(시간) |
| `CAPACITY_ROLLUP_RETENTION_DAYS` | 400 | 시간당 롤업 보존(일) |
| `CAPACITY_PUSH` | on | 엣지→중앙 push(엣지가 CENTRAL_URL·토큰 갖췄을 때만 실기동) |
| `CAPACITY_PUSH_INTERVAL_MS` | 60000 | 엣지 push 주기 |

## 7. 알려진 한계 (정직한 기록)

- 설치 직후에는 표본이 쌓일 때까지 **측정 중**으로 표시됩니다(1일 판정은 수십 분, 1달 판정은 축적 필요).
- 네트워크 처리량은 리눅스(`/proc/net/dev`)에서만 측정합니다. 대역 상한을 서버가 모르므로 임계 없는
  **정보 지표**입니다(추세만).
- 리눅스 메모리는 MemAvailable 기준입니다. 그 외 OS 는 `os.freemem()` 폴백이라 파일캐시를 사용 중으로
  세어 과대평가될 수 있습니다(개발 환경 참고치).
- 미해결 후속: 전력 대시보드식 시간당 롤업 최적화(첫 요청 윈도우 스캔 제거)와 공통.
