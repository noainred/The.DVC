# 물리서버 폴더(`bmfolders/` · 라우트 `routes/api/bmFolders.js` · 도구 키 `bm-folders`) 불변조건 — v2.984

> 설계 · 시안 · 결정 기록은 `docs/design/bm-folders/README.md`. 사용자 선택: 기본값대로(법인 › 폴더 · 한 서버 한 폴더 · 베어메탈 기본 + ESXi 선택 ·
> 자동 규칙 꺼진 채 포함 · 서비스 인벤토리 연결 · 맵 · 저장한 보기 · 엣지 화면은 2단계).

- **입력은 서비스 인벤토리 입력 수집 하나**(`svcInventory.js sharedGather` — 같은 단일 비행 · 같은 키): 함대 분류 · 법인 귀속 · 사용률 · 부품 장애를 두 벌 만들지 않는다.
  베어메탈 키는 `bmKeyOf`(`st:<태그>` · 없으면 `fl:<sha1 16자>`) · ESXi 호스트는 태그가 있으면 같은 `st:` 키(분류가 바뀌어도 같은 박스는 같은 키),
  **태그가 없으면 `host:<법인>:<이름>` 의 해시**(반증 4: 이름만이면 두 법인의 같은 이름 — 사설 IP 재사용 — 호스트가 한 키로 겹쳐 한쪽이 사라졌다). 그래도 겹치면 `dupKeys` 로 센다.
  서비스 태그에는 공백이 들어갈 수 있다(자리표시 태그) — 키 검사는 제어 문자만 막는다.
  입력에 새 필드가 필요하면 `gatherNowInner` 의 구성원에 **덧붙이고** 서비스 인벤토리 응답(`memberRow`)에는 싣지 않는다.
- **판정 코어는 `build.js` 하나**(순수): 손 등록(법인이 지금 법인과 같을 때만) → 자동 규칙(`settings.autoRules` 켜짐 · 베어메탈만 · 법인 규칙 먼저 · 긴 값 먼저 · 포함 — 정규식 아님) → (미분류).
  손 등록의 법인과 지금 법인이 다르면 **놓지 않고** `mismatch` 로 센다(다른 법인 폴더에 조용히 남기지 않는다). 법인이 없는 서버는 폴더에 넣을 수 없다.
  화면 합계(용량 가중 CPU · 메모리 · 전력 · 장애)는 웹 `bmFoldersText.js aggregate` 하나 — 못 읽은 값 · 용량 모름은 빼고 따로 센다.
- **목록에 없는 등록**: 출처를 다 읽었을 때만 `ghost`. 베어메탈 출처 중 못 읽은 것(`g.bmBlocked`) · 수집 전/꺼진 법인(`g.corpHold`) · 골격 스냅샷이면 `held` — 보류는 지우지 않는다.
  정리(`ghost.prune`)는 dry 의 **키**를 받아 키 ∩ 지금 없어짐 ∩ 쓰기 범위만 지운다.
- **저장소(`store.js`)** — 디스크 쓰기가 실패하면 5초 뒤 다시 쓴다(반증 10) · 바뀐 것이 없는 쓰기 응답도 `flushStore` 를 거친다. 파일 둘 — `bm-folders.json`(폴더 · 규칙 · 설정, 설정 변경 감시 대상) · `bm-folders-assign.json`(등록, **`backup/service.js CHANGE_WATCH_EXCLUDE`** — 등록 한 번이
  '설정 변경' 백업을 만들지 않게. 번들에는 들어간다). 메모리가 진실 · 200ms 디바운스 원자 쓰기 · 손상이면 빈 트리로 시작하지 않고 503 · 쓰기 차단(두 파일 중 하나라도 손상이면 전부) ·
  초기화는 전체 범위 관리자 + 손상본 보존. 폴더 경로 검증은 `servicemap/store.js cleanFolderPath` 하나(구분자 '\\' · 60자 · 10단계) · 경로는 글자만 받는다.
  넘침(법인당 폴더 · 규칙 · 등록 수)은 조용히 자르지 않고 400.
- **범위 · 가림**: 조회는 `scopedVcenterIds` 교집합이 요청 필터보다 먼저 · 법인 미지정 서버 · 엣지 이름은 범위 계정에 싣지 않는다 ·
  **범위 계정 판본은 서비스 태그를 싣지 않는다**(키 `pubKey` 토큰 · 이름 `maskName` · 쓰기는 `keyResolverFor` — 원문 st:/fl: 키 거부 · 서비스 태그 찾기 끔 ·
  찾기 · 이름 앞부분 묶음은 **가린 이름으로만** 맞춘다 · 목록에서 사라진 등록의 이름은 키의 태그로 가리고 등록 순간 주소였으면(`addr`) 비관리자 판본에서 가린다).
  새 응답 필드를 만들면 이 셋(키 · 이름 · 태그)을 지나는지 먼저 볼 것. 찾기 결과 순서도 **보이는 이름 → 토큰** 순이다(원문 이름 순이면 가린 태그 순서가 드러난다 — 반증 6).
  범위 계정에는 함대 전체 개수(`dupKeys` · 못 읽은 출처 수)를 싣지 않는다(`blocked.any` 만) · 법인 귀속이 빠진 서버의 예전 등록(불일치)도 싣지 않는다(반증 7 · 8).
  **v2.986 잔여 위험 완화(1차 반증 5)**: 자동 규칙은 **가린 뒤 이름**(`build.js ruleNameOf` — 이름 속 서비스 태그를 걷어 내고 · 관리 주소처럼 보이는 이름은 대상 밖)으로만 판정한다.
  예전에는 원문 이름으로 맞춰서 쓰기 계정이 규칙 값을 바꿔 가며 가린 태그 · 주소를 맞혀 볼 수 있었다(재현 204회). 판정은 판본마다 바꾸지 않는다(모든 계정에 같은 '가린 뒤 이름').
  서비스 인벤토리의 이름 규칙에는 같은 계열의 잔여 위험이 그대로 남아 있다(servicemap 4차 반증 4 — 그 판정을 바꾸면 기존 소속이 옮겨 간다).
- **쓰기**: admin/operator · 데모 아님 · 법인 쓰기는 `corpWriteAccess`('조회 밖 404 → 쓰기 밖 403'). 여러 법인을 한 번에 등록하면 쓰기 밖 법인 서버는 건너뛰고 `skipped.readOnly` 로 센다
  (전부 쓰기 밖이면 403). **다른 법인에 남은 예전 등록**(서버 귀속이 바뀜)은 그 법인에 쓸 수 있을 때만 덮어쓴다(`skipped.otherCorpReg` — 반증 2: unassign 은 막는데 assign 이 덮어썼다).
  저장할 수 없는 키는 `skipped.badKey` 로 센다(응답이 센 만큼 저장된다 — 반증 3). 전 법인('*') 규칙 · 자동 규칙 켜기 · 초기화는 **조회 ∧ 쓰기 무제한 관리자**(`fleetAdmin`). 폴더 삭제는 미리 본 등록 수(`expect`)가 다르면 409 —
  서버는 지우지 않고 (미분류)로 돌린다. 두 파일을 함께 바꾸는 연산(이름 바꾸기 · 삭제 · 등록)은 시작 전에 두 파일이 정상인지 본다.
- **v2.986 화면 지원 라우트**: 24시간 추이 `GET /tools/bm-folders/trend`(범위 안 키만 · 범위 계정은 토큰 · **서버 비교(6단계)와 같은 대상 해석 `resolvePerfTarget` · 같은 경로** — 이 노드 수집 = 로컬 비교 계열 · 엣지 수집 = `pullEdgeCompareSeries` 서버당 요청 1개 · 숫자 · 시각만 · 못 읽은 칸 null · 범위 계정에는 엣지 실패 사유를 싣지 않는다) ·
  입력 다시 읽기 `?fresh=1`(쓰기 계정 · 서비스 인벤토리와 **같은 상한 하나** `sharedFresh` · 429 + 대기 초) · 관리 주소 `addr`(등록부 iDRAC 호스트 — **관리자 판본만** · 범위 지정 관리자에게는 `stripTag` 로 태그를 가린다(2차 반증 1 — 'idrac-<태그>' DNS) · 주소로 찾기는 **전체 범위 관리자만**) ·
  서비스 연결 `svcLinks`(서비스 인벤토리 물리서버 폴더 규칙 — **서비스 인벤토리 도구 접근(`userToolAllowed`)이 있는 계정만** · 응답 캐시 열쇠에 그 저장소 세대 `s…` · 도구 접근 `v…`).
  추이의 엣지 실패 사유는 **전체 범위 관리자 판본만**(fetch 오류 원문에 엣지 주소) · 같은 (엣지, 서버, 구간)은 `trendOnce` 로 합친다(진행 중 공유 · 성공 60초 · 실패 15초 · 200건).
- **이름 바꾸기 ↔ 서비스 인벤토리 규칙**: 쓰기 전에 `svcRulePlan` 으로 ① 바뀐 경로가 남는 규칙과 겹치면 409 ② 옮길 규칙이 있는데 서비스 인벤토리 도구 접근이 없으면 403 ③ 그 저장소를 못 읽으면 503 —
  아무것도 쓰지 않고 멈춘다(2차 반증 2 · 3: 겹치면 옮기던 규칙을 버리고도 '옮겼다' 고 했다). 저장 단계(`svcRuleRename`)에서 다시 겹치면 버리지 않고 오류. 화면 알림은 응답 값(`renameNote` · `removeNote`).
- **엣지**: 엣지 push 계약은 바꾸지 않았다 — 엣지가 올린 베어메탈 목록(`central/fleet.js`)의 키로 중앙이 등록한다. 엣지 보고가 만료되면 그 서버들은 목록에서 빠지고 등록은 보류로 남는다.

- **서비스 인벤토리의 물리서버 폴더 규칙(v2.986 — `servicemap/CLAUDE.md` 에서 옮김, 그 파일 크기 상한)**: 업그레이드 때 규칙이 없으면 판정이 예전과 같다(테스트가 고정). 규칙으로 정해졌는데 스캔 라벨 · 이름 규칙이 다른 서비스를 가리키면 `ruleOverlap`(src 'bmfolder') 으로 검토 큐.
  만들기 전 미리보기(`bmrule.add` + `dry`)가 그 폴더 베어메탈의 지금 소속을 센다. **판정 memo(`inventoryFor`) · 응답 캐시 열쇠에 물리서버 폴더 저장소 세대(`bmfRevSafe`)** — 물리서버 폴더 등록만 바뀌어도 소속이 따라온다.

  미리보기는 저장과 같은 `cleanFolderPath` 를 거치고, 더 긴 기존 물리서버 폴더 규칙이 잡은 서버는 `kept` 로 따로 센다(옮겨 가지 않는다 — 2차 반증 4).
